# v2026.10.01.497 — App/Site/Economy Core Security Architecture

This documentation-only draft security-reviews the approved multi-core direction.

Highlights:
- separate native App Core and browser Site Core BFF contracts;
- one authoritative Economy Core and financial ledger/database authority;
- independently validated workload identity and user/admin/automation actor context;
- replacement direction for the shared static internal bearer token;
- no protected economic-table writes from BFFs or AI model runtimes;
- typed Economy Command Envelope with request digest, policy version and replay/idempotency controls;
- generated method/path/scope API inventory as a security authority;
- mobile high-value request binding through Play Integrity where enabled;
- one Economy Policy Registry / one policy executor for all adaptive economy tuning;
- explicit initial AI numeric change-size/cooldown/drift limits;
- human approval retained for tax, policy rate, macro credit buffer and WLD issuance/retirement;
- prompt-injection/excessive-agency containment and controlled model egress;
- zero-downtime phased migration while App API v1 remains compatible.

Research evidence records 118,490 newly collected Crossref unique records across twelve topic families and 149,691 final unique discovery candidates after merging prior Moneyverse economy/AI corpora. Discovery counts are not represented as full-text reading.

No runtime, migration, Test or Production change is included. Written-spec approval is required before an implementation/integration plan.
