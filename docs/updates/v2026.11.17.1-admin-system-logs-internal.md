# Internal update — v2026.11.17.1 — Admin runtime log viewer

**State:** isolated security remediation candidate, NOT production deployed.

## Baseline
- #3201 already introduced `/admin/logs/system` with Nginx error/access, Spring and Next.js log tabs in main SHA `86777fb2d5`.
- Real Production page, Production Spring API and official Test page returned HTTP 404 at inspection time. Old deployed artifacts do not contain this feature.
- The previous Spring API accepted any nonblank `x-internal-token` without validating a user/admin session, creating an authorization bypass if deployed as-is; no production exploitation established.
- Error paths could look like empty success and log output could expose credentials/identifiers.

## Remediation
- Require signed-in `SUPERADMIN` identity, and revalidate the existing session-bound `public.admin_session_touch(session, actor)` open-console state at Spring handler, without schema or balance mutation.
- Independently gate each Next.js server action by `requireAdminConsole('/admin/logs/system')`; validate source/line count/filter.
- Allowlisted OS log paths and systemd units; bounded child-process lifetime/output/line size; sanitize known cookies, auth headers, bearer strings, URL query values, email/IP/UUID and known secret fields before filtering/copying/exporting.
- Explicit `UNAVAILABLE` instead of false `EMPTY` status, and no "zero errors implies health" messaging. Server-side no-store/noindex/no-referrer.
- Prevent stale log result display on failed or out-of-order requests. Preserve four sources, interactive search, refresh, export and copy.
