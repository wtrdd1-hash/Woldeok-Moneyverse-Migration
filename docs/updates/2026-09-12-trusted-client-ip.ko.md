# 신뢰 클라이언트 IP 보강

업데이트 버전: **2026.09.12-10**
상태: **후보 / 테스트 서버 검증 필요**
브랜치: `fix/trusted-client-ip-v2026.09.12.10`

## 요약

신뢰 프록시 모드에서 Cloudflare가 엣지에서 덮어쓰는 `CF-Connecting-IP`가 없으면 `X-Forwarded-For`를 대신 사용하는 경로가 있었습니다. append 방식의 전달 체인에서는 첫 항목이 방문자가 직접 넣은 값일 수 있으므로, 공격자가 감사 로그 IP와 레이트리밋 식별값을 조작할 가능성이 있었습니다.

## 변경 사항

- 백엔드는 신뢰 프록시 모드에서 문법적으로 유효한 `CF-Connecting-IP`만 클라이언트 IP로 사용합니다.
- `X-Forwarded-For`는 애플리케이션 식별값으로 더 이상 사용하지 않습니다.
- 신뢰 엣지 IP가 없거나 잘못된 형식이면 소켓 피어 IP로 fail-closed 처리하고, 그 값도 유효한 IP가 아니면 `unknown`을 사용합니다.
- Next.js 서버 API 호출과 공개 앱 API 게이트웨이 모두 `X-Forwarded-For`를 내부 백엔드로 전달하지 않습니다.
- 레이트리밋, 감사 컨텍스트, 관리자 보안, 활동 기록, 로비가 동일한 강화된 IP 판별기를 계속 공유합니다.

## 검증

위조된 전달 체인, 중복 헤더, 잘못된 엣지 값, Cloudflare 우선순위, 소켓 폴백, 감사 컨텍스트, 계층형 레이트리밋을 집중 보안 테스트로 검증합니다.

정확한 후보 SHA가 CI를 통과하고 `wdmv-test`에 배포된 뒤 백엔드가 정상 기동하며, 실제 요청에서 Cloudflare 확정 IP가 기록되고 사용자가 넣은 `X-Forwarded-For`가 무시되는 것을 확인하기 전에는 운영 배포하지 않습니다.
