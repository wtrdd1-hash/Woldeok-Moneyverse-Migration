# GitHub update — Runtime log retention and admin console v2026.11.17.3

**DRAFT / DOCUMENTATION ONLY / RELEASE HOLD** · [한국어](v2026.11.17.3-runtime-log-policy-github.ko.md)

Owner-requested operations/admin planning for Nginx, Spring Boot, Next.js frontend server and legacy NestJS until cutover.

- **Routine 7 days / important 30 days**, measured from each UTC log event timestamp; security, admin action, material error and incident events are important.
- Rotate by day or file size; compress completed segments with zstd (gzip fallback), preserve checksum/time index, purge at expiration without losing unexpired critical events.
- Storage utilization alarms, collector/compression integrity states, bounded queries, per-environment isolation and no premature important-log deletion when capacity is tight.
- Admin `/admin/logs/system`: secure historical search, severity/time/source filters, cursor pagination and live SSE with a 5-second polling fallback; superadmin authorization plus recent step-up OTP for important/security logs and export.
- Sanitize personal data, cookies, credentials, tokens and OTP before storage and again on view; audit accesses and exports.
- **Not in scope:** changing database backups, deleting financial/audit tables, running live log rotation or deploying unverified code.
