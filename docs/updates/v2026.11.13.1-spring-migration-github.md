# v2026.11.13.1 — Plan the complete Spring Boot backend transition

**Status: DRAFT / documentation only / not deployed**

The Spring transition architecture begins with a versioned plan covering the **entire** NestJS application backend, not a single treasury feature. The target is a modular Java/Spring Boot backend that ultimately replaces all APIs, admin controls, game/finance, background jobs, realtime and integrations while preserving public Next.js page contracts, Android application compatibility and PostgreSQL's audited double-entry ledger.

The proposed G0–G6 waves start with a complete source/route and actual deployment inventory, isolated test environment and independent recovery evidence. Subsequent waves migrate safe read paths, then community/auth, games/integrations, and only then protected financial commands. No concurrent financial writers, direct ledger table mutation, balance reset, broken second-factor auth or unverified production promotion is permitted.

**What changed:** bilingual canonical design, living/integrated plan references, task worklog, changelog and planning release notes. **What did not change:** application code, database, deployment manifests, test server, production services, member balances, and main branch.

The architecture is pending owner review; executable implementation plans, their PRs, independent Test QA, and production releases will be versioned separately.
