- Root cause corroborated by actual PostgreSQL migration 244: supported order types MINT/RETIRE/FREEZE/UNFREEZE, and supported target envelopes WORK_REWARD/QUEST_REWARD/EVENT_REWARD/INCIDENT_COMPENSATION/STABILIZATION_POOL/HARD_SINK_PURGE/GENERAL_CIRCULATION; neither TREASURY nor EXPAND_LIMIT nor REBALANCE is allowed. A real network-none PostgreSQL 17 restored clone confirmed `MINT/WORK_REWARD` INSERT accepted inside an immediately rolled-back app-role transaction, and `MINT/TREASURY` rejected by `monetary_policy_orders_target_envelope_check`; no persisted mutations.
- Fix: bind the controlled mint SELECT and submit to the same computed active order after asynchronous fetches/refresh; default proposal fields to valid MINT/WORK_REWARD or RETIRE/HARD_SINK_PURGE. Validate policy type/target/duration/amount/reason at Next BFF and backend (422/400) before DB writes. Avoid leaking opaque 500 detail.
- Responsive mobile: stack proposal selects at narrow viewports, allow amount presets to wrap, shorten long order labels. Clear stale error messages on selection change, associate visible label with select.
- **Finance scope truth:** current MintBureauService only reserves a policy limit and creates `mint_certificates`. It does not post a canonical Treasury journal or increment `VAULT_MAIN`. UI claim of automatic deposit was false and is removed; certificate recording and canonical fiscal issuance are not interchangeable. TREASURY option stays unsupported until distinct finance design, proven mint settlement and compatible public release receipt. This patch performs no money movement, DB schema mutation, admin auth bypass or lowering of financial safeguards.
