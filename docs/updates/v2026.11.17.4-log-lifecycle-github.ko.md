# GitHub 업데이트 — 서버 로그 보관 및 관리자 조회 구현 v2026.11.17.4

**Implementation review:** [Draft PR #3212](https://github.com/wtrdd1-hash/Woldeok-Moneyverse-Migration/pull/3212). No Test/Production release.

**코드 구현 후보 / 미병합 / 미배포 / 운영 승격 보류**
[영문 정본](v2026.11.17.4-log-lifecycle-github.md)

사용자의 구현 진행 승인에 따라 기존 관리자 로그 보안 수정 커밋과 v2026.11.17.3 기획에 기반한 독립 구현 브랜치를 작성했다.

- Python 표준 라이브러리 수집기가 Nginx 접근/오류 및 Spring/Next/기존 백엔드 systemd 유닛에서 허용된 로그만 수집한다. UTC 이벤트 시각·소스·등급별 일반 7일/중요 30일 보관, 닫힌 파일 gzip 압축, SHA256 체크섬, 이벤트 시간 만료, HMAC 커서, 저장 전 개인정보 마스킹 및 수집기 장애 구분.
- systemd 1분 수집/1시간 압축·정리 유닛과 Nginx logrotate 교체안은 **코드로만 추가**. 운영 서버에는 설치하지 않았다. 금융원장 및 중요 감사 기록을 용량 부족으로 조기 삭제하지 않는다.
- Spring 이력 API는 인증된 최고관리자 및 열려 있는 관리자 세션만 허용한다. 중요 로그는 사용자/세션에 묶인 5분 유효 채널 OTP 및 검증 횟수 제한이 필요하다.
- Next.js 관리자 화면은 소스·분류·기간·문자열 검색·커서 페이지 이동을 지원한다. 기존 5초 자동 조회를 실시간 대체로 유지하며, 별도의 SSE 구현/검증은 아직 하지 않았다.
- DB 백업·금융원장·불변 감사 데이터 보관 기준은 변경하지 않았다.

**검증:** Python 단위 테스트 10개 PASS, Spring 집중 JUnit 및 인증 보안 테스트 PASS(서버 JDK 25 Byte Buddy 호환 옵션), 프론트 타입 검사 PASS, Vitest 전체 586파일/3,074테스트 PASS, 변경 파일 ESLint PASS, systemd-analyze 및 logrotate 디버그 검증 PASS. Next.js 전체 빌드는 1GiB 힙 제한에서 메모리 부족으로 FAILED. 현재 웹/Test 사이트의 해당 경로는 후보 배포 전 404였으며 실제 관리자 로그인 E2E·독립 복원·공식 Test 배포는 실행하지 않았다. **운영 승격 보류**.

다른 작업트리는 변경하지 않았으며 새 브랜치를 공식 검토/QA 대상에 둔다.
