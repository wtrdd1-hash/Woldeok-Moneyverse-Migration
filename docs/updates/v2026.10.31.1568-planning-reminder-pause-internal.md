### Intent, alternatives and user journey
- **Purpose:** A member may want a short break from inventory expiry reminders without permanently turning off global opt-in or individually muting each holding. This affects **only inventory expiry in-app alerts**, never authentication, security, transactional or administrative notifications. No push/email, renewal, equip, purchase, WLD or ledger writes.
- **Alternatives:** (1) reuse global OFF/ON requires manual return and loses intent; (2) per-holding mutes are tedious and persist past a break; (3) scheduling an unpause job introduces duplicate/retry races. **Chosen:** a DB timestamp with automatic read-time expiry and immutable preference transitions; no resume cron. Presets are **24, 72, 168 elapsed UTC hours**, not local calendar dates; maximum 7 days. No arbitrary unbounded duration or stacked pauses in V1.
- **Audience/entry:** authenticated consent-current owner, /inventory/expiring/reminders → /inventory/expiring/reminders/pause. Show effective status, local KST display plus UTC tooltip, exact pause end, remaining time, what is/not silenced, and explicit warning **missed windows are not replayed**. CTA Pause 24h / 72h / 7d → Review → Confirm, Resume now → Confirm, Refresh status and View activity. If already paused, new Pause is 409 ALREADY_PAUSED (no silent extension); Resume now only while active, otherwise 409 NOT_PAUSED. Global OFF prevents new Pause but allows clearing an existing pause. Global ON after OFF does not cancel an unexpired pause. Never claim a past inbox receipt has been unsent.
- **UI states:** GLOBAL_OFF (explain preference precedence), ACTIVE_PAUSE (untilUtc and live countdown, read from DB asOfUtc), RESUMED_BY_TIME (past pause_until; no DB auto-write), NOT_PAUSED, STALE_REVISION (409 reload), VERIFYING_RESULT / UNKNOWN_COMMIT (timeout or ambiguous receipt), SOURCE_UNAVAILABLE (503), and VERIFIED_COMMITTED (receipt evidence, historical only). A verified empty holdings list is not a pause status. Countdown is presentation only: server DB decides. Clear keyboard focus, aria-live, 320px/200% zoom, WCAG 2.2 AA, reduced motion; Android parity and account-switch response fencing.

### API, permissions and response contracts
- Owner-only, authenticated, current consent and CSRF-validated POST `/api/v1/shop/expiry-reminders/pause/status` (read-only), `/pause/set` body `{durationHours:24|72|168,expectedRevision:int64,idempotencyKey:UUID}`, `/pause/resume` body `{expectedRevision:int64,idempotencyKey:UUID}`, and `/pause/receipt-status` body `{idempotencyKey:UUID}`. Derive actor from session; never accept client owner_id. Same semantics through Next server boundary and Android `/app-api/v1/shop/expiry-reminders/pause/...`. No GET tokens/IDs in URLs, no direct external link from notification.
- Status 200 `{state,asOfUtc,pauseUntilUtc?,revision,globalOptIn,mode,canPause,canResume}` only on a successful primary owner DB read. Set/resume 200 `{status:'VERIFIED_COMMITTED',receiptId,committedAtUtc,pauseUntilUtc,revision}` only on an immutable owner receipt; ambiguous commit/status lookup 202 `{status:'UNKNOWN'}` without pretending no commit. 400 malformed/oversize, 401 auth, 403 consent/CSRF, 409 revision/active state/key conflict, 429 per-owner quota, 503 schema/ACL/primary DB/lock uncertainty. Failed owner read is never NOT_PAUSED or empty. Body <=2KiB, max 5 **new** writes per owner/minute, separate bounded status and receipt-read quotas (proposed 20/min, measure).
- Every Nest/Next/Android success and failure must emit `Cache-Control: private, no-store`, `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer`, `Vary: Cookie` where applicable. Page metadata robots noindex, sitemap exclusion; no token, member ID, pauseUntil or receipt payload in analytics/URLs/logs. Server-side session binding; fail closed on account switch.

### DB schema, lock order, idempotency and time truth
- Before implementation, prove existing reminder preference/receipt/inbox DDL and app ACL on disposable clean PostgreSQL 17. No invented migration number; forward-only extension after verified schema: owner preference `pause_until_utc timestamptz NULL`, `revision bigint NOT NULL` with nonnegative CHECK, DB-owned transition timestamps; append-only owner-scoped pause transition/receipt evidence with `UNIQUE(owner_id,idempotency_key)`, `request_digest`, action, committedAtUtc, exact pause start/end and early resume evidence. Do not overwrite event history; retention and idempotency-key reuse safety must be proven. Index `(owner_id, committed_at_utc DESC)` for bounded owner event reads; avoid an unproven `pause_until` index until EXPLAIN/BUFFERS shows benefit. No owner event table read grant to moneyverse_app.
- SECURITY DEFINER owner-scoped functions, fixed search_path, explicit actor/consent, `EXECUTE` only for moneyverse_app; deny direct SELECT/INSERT/UPDATE/DELETE on preferences/events/receipts and financial tables. In one bounded READ COMMITTED transaction, serialize `(owner,idempotencyKey)`, inspect immutable receipt first (same intent returns original receipt even after pause elapsed or session rotated; different intent same key 409), lock owner preference row (shared with individual/digest workers), verify global opt-in for new Pause and expectedRevision, sample one post-lock DB `clock_timestamp()`, set `pause_until_utc=decisionAtUtc + interval '24/72/168 hours'`, increment revision and insert transition+receipt atomically. Resume while active sets effective pause end to post-lock decision time with immutable event; never delete prior evidence. Lock timeout → 503 UNKNOWN, no false saved/failed. Stable canonical domain-separated digest covers owner/action/duration/expectedRevision, excludes token/nonce/arrival time. Do not compute write preconditions using JavaScript Date.
- **Boundary:** pause is active iff DB decision `now < effective_pause_until`; at equality it is inactive. Set applies at its committed preference transition; a worker that commits first cannot be retroactively unsent. A worker must lock preference before evaluating any expiry, then use one post-lock DB time and the same transaction for receipt+inbox. Eligibility: global ON AND not paused AND holding generation/expiry valid AND not per-item muted AND current 7d/1d half-open threshold window. If a window expires while paused, **never backfill**; resuming inside a still-open window permits one new decision subject to shared unique receipt, not a duplicate. Pause does not modify existing receipts, inbox entries or item state.
- **Digest interaction:** F675-196 fixed 09:00 KST slot; pause interval `[pause_start, effective_end)` overlapping the slot suppresses that day's digest, even if early-resumed at 09:07 before a delayed worker runs. Pause starting after 09:00 but before worker commit suppresses the not-yet-committed batch. Pause ending exactly 09:00 is inactive at slot; pause ending 09:00+1µs suppresses. Early resume after the slot never creates a catch-up digest. An append-only owner transition ledger is needed to prove the pause-at-slot truth after manual resume; a lone nullable pause_until field is **insufficient**. If provenance cannot be established for every writer, keep flag OFF.
