## v1440 / F675-166 — Verified private glossary study list (FEATURE ADDITION / DRAFT / RELEASE HOLD)

### Product gap, purpose and source of truth
Main currently publishes public /guide/glossary and /guide/glossary/[term] from frontend/src/config/pseo-glossary.config.ts GLOSSARY_TERMS; detail pages use 86400-second revalidation and indexable DefinedTerm/FAQ structured data. No owner-private glossary saved-list, manual read marker, or matching NestJS/DB owner endpoints was found in main. Existing CalculatorSaveAction stores calculator simulations in localStorage and advertises account sync; it does NOT prove that a glossary learning list exists. GitHub issue search found no matching glossary bookmark/learning-list issue. This feature enables active members to save a real glossary term for later study and voluntarily mark it "read"; it must never infer comprehension, educational achievement, investment outcome, financial reward, or automatic reading activity.

### Target, entry points, CTA and states
Public glossary and term pages remain readable and indexable for guests. On /guide/glossary/[term], show explicit "Save term" / "Remove saved term" and "Mark as read" / "Mark unread" for authenticated active consenting members; guests see "Sign in to save" without background persistence. A private /account/learning/glossary screen provides saved-only list, filter SAVED/READ/UNREAD, search over verified public titles, remove, reopen and a non-authoritative self-marked progress counter. Do not silently save on view, backfill localStorage, or treat a click as mastery. States: UNAUTHENTICATED, LOADING, UNSAVED, SAVING, SAVED_UNREAD, SAVED_READ, REMOVING, NETWORK_UNKNOWN (receipt lookup), CONFLICT (409 revision/version), UNAVAILABLE_TERM (tombstone with Remove), RATE_LIMITED (429), ERROR (retry without false success). Always wait for server receipt before displaying "saved" or "read". On logout/account switch, invalidate cache, in-flight response and stored request keys; never show another user's list. No push, email, points, achievements or WLD change.

### Source revision and content retirement
Use the exact deployed immutable glossary slug manifest, generated in the reviewed build from GLOSSARY_TERMS and bound to release SHA plus per-term editorial digest; a frontend-only array cannot be trusted by the backend without a reviewed artifact. This can share the manifest contract proposed by F675-165 after independent review but must not assume that PR is merged. If no trusted manifest/registry exists, feature remains OFF while public glossary works. A stale but verifiable term revision yields 409 CONTENT_CHANGED and asks the user to reopen/reconfirm; unknown frontend/backend registry consistency yields 503 REVISION_UNAVAILABLE and disables writes. On slug removal/rename, preserve owner-only unavailable tombstone and allow Remove without redirecting to an unrelated term. Existing "read" mark is tied to the exact term revision; a content change resets its *current-revision* presentation to "needs reread" without erasing historical self-mark. Do not index private activity or expose private count in public metadata.

### API and Android parity
NestJS authenticated endpoints: GET /api/v1/guide/glossary-learning?state=&cursor=&limit= (owner keyset, max 50/page), GET /api/v1/guide/glossary-learning/:slug, PUT /api/v1/guide/glossary-learning/:slug (save with termRevision, expectedVersion, requestId), POST /api/v1/guide/glossary-learning/:slug/read-state (read:boolean, termRevision, expectedVersion, requestId), DELETE /api/v1/guide/glossary-learning/:slug (requestId, expectedVersion), GET /api/v1/guide/glossary-learning/receipts/:requestId. Return original immutable operation receipt {requestId, slug, operation, version, committedAt, state, termRevision}; on uncertain timeout read receipt before retry. Distinguish 400 malformed, 401 guest, 403 inactive/consent/CSRF, 404 foreign or absent, 409 revision/version/reused-key payload mismatch, 429 quota, 503 unverified manifest/DB. Browser uses Next server actions/BFF and CSRF with HttpOnly same-origin session; Android /app-api/v1 uses independent verified mobile authentication and equivalent DTO/status semantics, not the internal web API token. All private responses Cache-Control: private, no-store and Vary: Cookie where appropriate; avoid secret-bearing URLs. Admin can only inspect aggregate anonymized counts, not individual saved terms.

### PostgreSQL constraints, ownership, transactions and abuse prevention
Add additive glossary_term_registry (slug PK, schemaVersion, revision, contentDigest, releaseSha, active), glossary_learning_entries (user_id, slug, saved_at, read_revision NULLABLE, read_at NULLABLE, version positive, removed_at NULLABLE, updated_at) with PK(user_id,slug), FK(slug) to immutable/retained registry keys, and glossary_learning_receipts (user_id, request_id, operation, slug, canonical_payload_digest, original_result, committed_at) UNIQUE(user_id,request_id). CHECK allowed operations/states, nonnegative version and canonical slug format; owner index (user_id,removed_at,saved_at DESC,slug) and (user_id,read_revision) as justified by EXPLAIN. No volatile now() in partial index. 100 active saved terms per member (not 10,001: that is isolated synthetic test volume); removals do not erase immutable receipts, and repeat saves cannot bypass cap. A locked authenticated owner row followed by term/entry rows serializes save/read/remove; CAS expectedVersion and uniqueness enforce one winner in concurrent changes. Same requestId+canonical payload digest replays original receipt; different operation/body returns 409, including after logout/relogin. Do not use client-provided actor IDs; DB SECURITY DEFINER functions must check owner/role and narrowly grant EXECUTE, revoke PUBLIC, no direct table grants to moneyverse_app. Shared DB principal p_actor alone is not proof of authenticated user: enforce SessionGuard, AuthenticatedGuard, ConsentGuard, CsrfGuard, session-derived actor, strict Android token boundary and real-DB negative ACL tests. Rate limit per member/device/IP without leaking cross-member existence; reject slug injection, oversized payloads and arbitrary URLs; avoid storing finance/account identifiers.

### Admin, SEO, privacy, analytics, accessibility
Admin dashboard may show only coarse aggregates (saves, voluntary read marks, 409/503 errors, 95p response time, receipts verified, unavailable-slug removals), with minimum cohort threshold and no member-level browsing. Public glossary metadata, canonical URLs, FAQ/DefinedTerm JSON-LD, sitemap and OG must remain identical except reviewed public editorial changes; private account screen is noindex/nofollow, no sitemap, no public SSR data and no ad targeting. Minimize retained activity, document data retention and user deletion/erasure with receipt de-identification compatible with audit requirements. Keyboard-only, 320px, 200% zoom, WCAG 2.2 AA, aria-live operation outcomes, stable focus after list removal, non-color status, reduced motion, Android TalkBack and offline retry; no fabricated success. KPI: verified save receipt rate, seven-day voluntary revisit rate (aggregate), cross-device consistency, stale revision rate, privacy violations (target zero), duplicate mutation rate; never claim learning mastery from self-marks.

### Engineering acceptance and rollout
Developers own a separate branch, write RED tests first, then implement and prove with isolated actual PostgreSQL: 10,001 synthetic entry rows for pagination/index load (NOT 10,001 independent external sources), 100 simultaneous save/read/remove and replay requests, 100 cross-account/CSRF/invalid slug/reused requestId negatives, 100-term cap under race, removed/renamed slug, stale 24h ISR build A/B, exact SHA manifest mismatch 409 vs 503, owner logout/account switch, mobile/API/a11y/SEO/no-store and zero-ledger-delta regression. No skipped DB tests may count as PASS. Feature OFF by default; additive reviewed migrations, off-host encrypted backup and independent restore, read-only shadow then canary, verified Test exact-SHA authenticated owner/admin/finance E2E and explicit authorized promotion/rollback. No build-only auto-merge (#1088). On rollback disable writes, preserve private receipts and public glossary; never delete records to conceal failed writes.
