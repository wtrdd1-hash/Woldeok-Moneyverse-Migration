# v2026.09.15.121 — Wide WLD Numeric Storage

## Scope
- Removes implementation-only WLD magnitude ceilings from wallet transfer, bank movement, loan repayment, and the shared money contract.
- Changes authoritative ledger balances/postings and banking money columns from `bigint` / `numeric(38,0)` to PostgreSQL arbitrary-precision integer `numeric` storage.
- Keeps WLD on API boundaries as canonical decimal strings so JavaScript never rounds money above `Number.MAX_SAFE_INTEGER`.
- Removes the hard-coded 500,000 WLD loan request ceiling and 1,000,000,000 WLD bank movement/repayment ceiling. Credit-grade, casino, stock-risk, and other gameplay/safety policy limits remain authoritative.

## Compatibility and safety
- Existing safe integer internal callers remain accepted, but public DTOs require decimal strings.
- The ledger primitive remains unavailable to the runtime DB role.
- Idempotency, non-negative balance guards, credit-grade lending policy, and account locking are unchanged.
- Views depending on ledger amount types are recreated in the same migration.
