## 실제 원인
운영 금융 DB에 SQL333(근로 소득세·국고 수입)이 적용됐으나 GitHub `main`에는 빠져 있어 다음 SQL334 조폐국 실측 조회·SQL335 KDIC 권한 복구를 연속적으로 배포할 수 없었다. 동시에 Test의 KDIC 공개 API는 기금/부보기관 테이블의 앱 조회권한 부재로 HTTP500을 반환했다. 과거 공기업 배당·연금 정기지급·KDIC 현금지급·국부펀드·실제 발권의 미증빙 지급은 별도의 실제 금융 장애이다.

## 코드 수정 및 기존 개발 충돌 방지
최신 main 기반 별도 v1760 브랜치에 기존 개발자의 SQL333 세금 기능 커밋, SQL334 조폐국 DB 증빙 조회, KDIC 모형 자산 오표시 수정을 원래 기록과 함께 이식했다. 기존 PR/브랜치 강제 변경 없음. 선행 KDIC SQL335 전용 SECURITY DEFINER 4개 조회 함수를 통합하고, 관리자 역할 검증을 보강했다. 원본 민감 금융 테이블 직접 조회권·쓰기권 확대 없음.
운영에 적용된 SQL333 체크섬과 소스 779ffa2df40bad476c87fad8b9c8f350dff272b8f05ec3969ff84b50179941e1 바이트 동일.
