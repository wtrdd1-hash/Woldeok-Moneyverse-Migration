## 4. UI 정밀 QA·종결 규칙

문제별로 **경로, 화면 폭, 언어, 로그인/권한, 기대 화면, 실제 화면, 비교 이미지, 프론트 SHA, API/백엔드 출처, 재현 방법, 담당자, 중요도, 관찰 일시, Test와 운영 검증 결과**를 남긴다. `OPEN`, `BLOCKED`, `TEST_VERIFIED`, `PRODUCTION_VERIFIED`를 명확히 구별한다.

겉모양 동일 = 기능 정상 아님. 실제 API 요청·응답과 저장 상태까지 확인하고 금융은 안전한 Test 데이터로 원장 대조. 401/403/404/429/5xx, 세션 만료, API 장애, 오프라인, 재연결, 큰 정수, 5언어 및 모바일 경계값을 포함한다. 소스 수정 시 별도 브랜치·PR, 검토, 정확 SHA 테스트, 독립 Test 검증, 무중단 운영승격/롤백 규정 준수. 금융·보안·관리자 권한 보호 규칙은 UI 변경을 이유로 해제하지 않는다.

## 7. 2026-11-23 예금 입출금 스크린샷 추가 요구 — v2026.11.23.2

- **증거:** 사용자 제공 은행 예금 입금·출금 화면. 긴 제목과 배지가 서로 좁게 배치되고, 입력창의 기본 회색 스타일과 브라우저 기본 필수 입력 말풍선이 다크 디자인에 섞임. 금액 프리셋/전액/확인 버튼의 높이·여백이 일정하지 않고, 완료 메시지와 입력 상태가 어색하게 분리됨. 이는 **첨부 화면 관찰**이지 현재 운영 SHA의 재현 완료가 아니다.
- **개선 목표:** 카드 제목·금리 설명·보유 현금/예금 잔액·금액 입력·빠른 선택·확인·결과를 수직 정보 계층으로 배치. 동일 너비·라운딩·보라 포커스·충분한 대비·44px 이상 클릭 영역, 모바일 한 열. 입력 오류는 해당 필드 아래 inline `role=alert`로 보여주고 브라우저 기본 말풍선/화면 이동/성공 토스트 남발 금지. 입력 전에는 성공 메시지 없음, 거래 성공은 서버 영수증으로만 판단. 사용자 수동 입력은 버튼 조작에 의해 예기치 않게 지워지지 않아야 함.
- **금리 표기:** 일 기준 금리(`daily_interest_rate_pct`)와 연 기준 수익률(`annual_yield_pct`)은 서버의 **서로 다른 필드**로 확인됨. 화면에서 단위/복리 및 지급 주기/정산 시간 기준을 분리해서 설명. 임의의 365배 환산·하드코딩 APR/APY·게임 1일=현실 1일 가정 금지. 서버 게임 시간과 현실 시간의 변환은 현행 권위 기획 및 실제 정산 구현을 확인한 후에만 표시. 실제 계좌의 적용값을 읽을 수 없으면 `확인 필요`로 표시.
- **추가 조사:** 프론트 과거 화면의 일/연 별도 금리 계약은 `frontend/src/app/bank/types.ts`, `frontend/src/app/bank/page.tsx`에 있다. Spring `BankService.java`에는 일부 고정 기본 응답이 확인되어 실제 금리 출처 보증이 아직 미완료. 해당 코드와 운영 정산이 같다고 추정하지 않는다.
- **구현 회차 분리:** [은행 표현 개선 후보 PR](https://github.com/wtrdd1-hash/Woldeok-Moneyverse-Migration/tree/fix/bank-ui-rate-basis-20261123)에서 Spring 정적 은행 화면의 설명/카드 스타일을 변경. **첨부 입출금 폼 자체의 실행 중 코드 경로와 실제 서버 출력은 여전히 미확인**, 폼 오류·실거래 데이터·정산 로직 수정 완료라고 표시하지 않는다. 민감한 금융 POST/원장 규칙은 건드리지 않는다.

### GPT 수행 오류 및 재발 방지 (투명한 기록)
1. 이전 응답에서 *정적* `spring-backend/src/main/resources/static/bank.html`의 CSS/설명 영역만 수정했으면서, 사용자가 캡처한 **실제 예금 입출금 컴포넌트 자체를 개선한 것처럼 읽힐 수 있게 설명**했다. 화면 식별·운영 검증이 되지 않았다는 사실을 이후에 명확하게 정정했다. 이 작업은 PR [#3394](https://github.com/wtrdd1-hash/Woldeok-Moneyverse-Migration/pull/3394)의 **초안 후보**이고 실제 입출금 폼/정산 완료 증거가 아니다.

3. **검증 순서:** ① 최신 통합 기획과 시간 명세 ② 승인 11/18 PC/mobile 원본 이미지 ③ 실제 렌더 경로/코드 ④ 공식 로고 ⑤ 실제 서버 데이터·정책 ⑥ 정확 SHA Test/운영 브라우저 검증. 작업 증거 없이 “전체 UI 완료/운영 적용” 표현 금지.
