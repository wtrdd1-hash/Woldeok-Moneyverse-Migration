# 내부 변경 기록 — v2026.09.16.156

## 장애 증거

- 사용자 화면: 주사위 홀짝에서 정상적으로 보이는 `10 WLD` 입력이 공통 HTTP 400 문구 “입력한 내용을 다시 확인해 주세요.”로 실패했습니다.
- 프론트엔드 증거: `playCoin()`과 `rollDie()`가 `stake`를 문자열을 반환하는 `wholeAmount()`로 정규화했습니다.
- 백엔드 증거: `CasinoPlayDto`/`CasinoDicePlayDto`는 `@IsInt()` 숫자를 요구하고 전역 `ValidationPipe`는 암시적 변환을 끄며, 카지노 E2E 테스트도 숫자 문자열 베팅을 명시적으로 거부합니다.
- UX 증거: 동전 게임에는 서버 결과 비주얼 영역이 있지만 두 주사위 폼은 입력/버튼만 있는 상태였습니다.

## 코드 변경

1. 동전/주사위 베팅 금액을 `wholeNumber()`로 파싱해 유효한 제한 범위 금액을 JSON 숫자로 전송합니다.
2. 두 카지노 액션 경로가 숫자 파싱을 유지하고 `wholeAmount(formData.get('stake'))`로 회귀하지 않도록 회귀 검증을 추가했습니다.
3. 주사위 홀짝/숫자 맞히기에서 서버 액션의 `outcomeFace`만을 사용하는 공용 비주얼 결과 영역을 추가했습니다.
4. 처리 중 주사위 굴림 효과와 `prefers-reduced-motion` 대체 동작을 추가했습니다.
5. RNG, 승패 판정, 배당, 원장 정산은 계속 서버 권한으로 유지합니다.

## 검증 증거

- 프론트엔드: 68개 테스트 파일 / 609개 테스트 통과.
- TypeScript 검사 통과.
- Next.js 프로덕션 빌드 통과.
- 백엔드 계약 재검토에서 숫자 문자열 거부가 DTO/E2E에 명시돼 있어 이번 FE/BE 계약 불일치 원인을 확인했습니다.
