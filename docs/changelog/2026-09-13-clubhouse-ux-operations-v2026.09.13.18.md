# Clubhouse UX & Operations v2026.09.13.18

## Why this changed

The existing Clubs & Cooperative Economy specification already defines club identity, unlimited-by-default membership, capability-based roles, project contributions, clubhouse sinks, season behavior and accounting. Its own follow-up work still called out clubhouse screen-level UX and large-club pagination/sharding as unfinished implementation planning.

This pass closes that product-contract gap without changing the parent economy or introducing a member-count hard cap.

## Changes

- Added English canonical `CLUBHOUSE_UX_OPERATIONS_SPEC.md` and synchronized Korean counterpart.
- Defined route/IA for discovery, overview, members, projects, clubhouse, editor, season, archive, feed, settings and moderation.
- Defined desktop/tablet/mobile layouts and default/loading/empty/error/offline/maintenance/permission/stale states.
- Defined join onboarding with a small number of healthy first actions; WLD contribution is never a mandatory first step.
- Defined large-club server cursor pagination, indexed search, aggregate read models and accessible virtualization without membership caps.
- Defined capability-driven role management and fail-closed high-risk actions.
- Added clubhouse draft -> preview -> validate -> publish revision workflow with optimistic concurrency and audit history.
- Required non-drag keyboard/button placement alternatives.
- Defined project confirmation UX for HOLD/HARD_SINK meaning, authoritative accepted amount and finite-target overfund protection.
- Added season, feed, report/moderation, operator, analytics, privacy/legal, monetization and SEO contracts.
- Added QA for 0/1/50/1,000/synthetic-large member datasets, cursor integrity, concurrent publish/role edits and accessibility.

## Default-limit impact

No arbitrary membership, contribution, project-count, archive-count or browsing cap was added. UI scale is handled with pagination, indexes, virtualization, caching and infrastructure safeguards. Positive capacity remains permitted only for documented security, integrity, infrastructure, true scarcity or legal purposes.

## Economy impact

No mandatory tax was added. Existing voluntary clubhouse/archive/city prestige sinks remain authoritative. User-to-user movement remains `TRANSFER`; only actual system removal is `HARD_SINK`. Finite project overfund protection is a completion-boundary rule, not a general spending limit.

## Legal / revenue / SEO impact

- Legal/privacy: risk-reducing. Public/private visibility, minor-restricted defaults, sponsored-content disclosure and sensitive-data boundaries are explicit. Real-money trading, externally redeemable club value, paid random club rewards or real financial products remain `legal review required`.
- Revenue: preserves non-P2W cosmetic/profile/club visual monetization and clearly disclosed sponsorship, while prohibiting sale of officer power, season score, financial advantage or moderation priority.
- SEO: explicitly public club profiles/tours/archive/community guides may be indexable; member directories, private feed, contribution details, roles, moderation, editor/drafts and admin/audit remain authenticated/noindex. Thin autogenerated club pages must not be indexed merely for volume.
