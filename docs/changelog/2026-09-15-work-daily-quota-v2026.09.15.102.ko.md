# v2026.09.15.102 — 작업 일일 한도 계약 복구

## 요약

작업 목록과 보상 경로가 다시 DB 작업 카탈로그의 일일 한도를 단일 기준으로 사용합니다.

## 변경 사항

- `work_task_board()`가 `0` 대신 각 작업의 실제 `daily_limit`을 반환합니다.
- `taken_today`는 단순 배정 생성 수가 아니라 서울 기준 당일 실제 완료·보상 횟수를 계산합니다.
- `work_complete_task_v2()`는 설정된 일일 횟수까지 정상 수행을 허용하고, 한도를 채운 다음 요청부터 거부합니다.
- assignment → submit → verify 경로의 `work_verify_and_reward()`도 동일한 한도를 적용합니다.
- 직접 완료와 기존 검증 경로가 사용자/작업 단위 advisory lock을 공유해 동시 요청으로 제한을 우회하지 못하게 합니다.
- 관리자 `work` 기능 상태는 운영 안전 스위치로 유지하고, 회원 일일 quota는 별도 DB 정책으로 분리합니다.

## 호환성

모바일/웹 API 필드명은 그대로 유지합니다. 기존 `daily_limit`, `taken_today` 스키마가 의도된 실제 값을 반환하도록 복구됩니다.

## 검증

병합 전 CI에서 PostgreSQL 마이그레이션과 작업 목록/quota DB 테스트를 통과해야 합니다. 운영 승격은 격리 Test 서버 exact-SHA 검증 후에만 진행합니다.

## 롤백

적용된 마이그레이션은 수정하지 않습니다. 운영 롤백이 필요하면 영수증·배정·원장·직업 진행도 기록을 보존하는 새 마이그레이션으로만 되돌립니다.
