## 최종 계약 생성 환경 완전성 점검

첫 로컬 문서 생성은 격리 환경의 백엔드 의존성 링크가 일부 깨져 있어 WLD 브랜드 금융 금액 반환형이 `any`로 약화되었다. 커밋 HEAD와의 재비교로 이를 확인했고, 격리 환경에서만 온전한 읽기 전용 백엔드 의존성으로 변경한 뒤 연속 2회 재생성 결과 SHA-256 동일성을 확인했다. **WLD 타입 구조를 보존한 최종 계약 산출물만 GitHub에 게시한다.** 필수 TypeScript 의존성 누락을 허용해 계약을 생성하면 안 된다.

## GitHub 백엔드 CI 추가 실패 및 불변 마이그레이션 보완

GitHub 커밋 d007d8a6 런타임 검사에서 백엔드 7건 실패: 기존 가짜 금융 성공을 기대한 컨트롤러 테스트 4건은 v629의 의도적 HTTP 503 차단을 검증하도록 정정해 집중 테스트 9/9를 통과했다. 나머지 **DB 권한 보안 실패 3건은 테스트를 완화하면 안 되는 실질적 문제**다. SECURITY DEFINER 함수 4개가 PUBLIC에서 실행 가능했고, 마이그레이션 269가 의도적으로 제거한 원장 직접 기입 권한을 구형 테스트가 요구했으며, 260/261/267/268 마이그레이션에서 카지노·블랙마켓·주식·AI·중앙은행·복권·국고기부 테이블에 앱 계정 직접 쓰기 권한을 광범위하게 부여했다.

기존 적용 SQL은 수정하지 않고 새 `270-reconcile-post-233-security-boundaries.sql`에서 SECURITY DEFINER 함수의 PUBLIC 실행권한을 회수하고 기본 ACL을 재확인했으며 12개 테이블 INSERT/UPDATE/DELETE와 treasury_donations 직접 INSERT를 앱 계정에서 회수한다. 원장 직접 분개 함수는 migration 269의 거부 상태를 유지한다. **주의:** 기존 직접 테이블 쓰기에 의존하던 일부 기능은 감사된 도메인별 SECURITY DEFINER 원장 처리와 영수증이 구현될 때까지 실패 시 차단될 수 있다. 임의 재활성화하지 않는다.

운영/개발/공유 Test DB에는 이 SQL을 적용하지 않았다. 일회용 CI PostgreSQL의 권한 검사, 분리 Test 백엔드 역할·사용자 흐름·원장·롤백 검증 후에만 배포할 수 있다.

### CI DB 보안 게이트 2차 조정
270번 마이그레이션 1차 재검증에서 백엔드 실패가 7건에서 2건으로 줄었다. 253번 마이그레이션의 `treasury_bond_repo_loans` 앱 계정 직접 쓰기 권한이 추가로 확인돼 270번 전진 마이그레이션에서 회수한다. 국채 Repo 수정은 원자적 원장 명령이 구현될 때까지 안전 차단 상태로 유지해야 한다. 관리자 권한이 없는 잘못된 요청은 인수 오류(22023)보다 먼저 인가 거부(42501)를 반환하는 것이 정보 노출을 막으므로 회귀 검사도 거부 우선으로 정정한다. 일회용 CI DB 외 가동 중인 DB에는 SQL 미적용.
