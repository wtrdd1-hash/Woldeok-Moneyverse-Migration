## Correct / partially working
- `locale.ts` default is `ko`. Production `/` without Accept-Language yielded `x-moneyverse-locale: ko`; explicit `/ja/stocks` yielded `ja`; manual `wdmv_locale=ja` request was preserved; explicit `/en/stocks` overrode a JA cookie. However *locale selection working is not content translation working*.
- Both web dictionary files have all four nonempty values for their registered entries; no direct `t('known.key')` syntax misses found by the AST scan. This only checks registered/observed keys, not strings never fed to a translation function.
- Focused regression: Vitest **5 suites, 35/35 passed** (`locale.test`, `locale-first-render.test`, `i18n-dictionary.test`, `locale-routing.test`, `locale-provider-navigation.test.tsx`). Existing tests do not inspect SSR visible language purity or editorial fluency; **do not report full multilingual QA as passed**.
- Root `/en`,`/ja`,`/zh` H1 changes and matching HTML `lang`, but each still contains ~345 Korean Hangul characters in rendered readable text.

## Editorial naturalness examples — proposals, not approved copy
- EN `Finance & Invest` -> **Finance & Investing**; `Real-time 10-Depth Orderbook` -> **Live 10-Level Order Book**. Avoid developer jargon such as `idempotent WLD transfers` in end-user actions unless explained in plain terms.
- KO `가상 주식 거래소` -> EN **Virtual Stock Exchange**, JA **仮想株式取引所**, ZH-Hans **虚拟股票交易所**; these values already exist in the glossary and must be used at every stock H1.
- JA financial labels must be reviewed by a Japanese finance editor; ZH-Hans and ZH-Hant must be reviewed separately. Respect WLD as virtual simulation, not regulated real-currency claims. No machine translation for legal/financial advice disclosures without native and legal review.

## Remediation order and acceptance gate
1. P0: legal/privacy consent and financial simulation warnings. For foreign locale routes lacking reviewed primary content, use honest original-language fallback with appropriate SEO noindex (subject to product/legal decision), not false translated title/metadata.
2. P1: shared header/footer/home, `/stocks`, `/tools` and children, `/guide`, then bank/wallet/bonds/loan/order flow, calculator outputs/units, blog labels and country editions; ensure distinct state copy (loading, failure, empty, validation, mobile, a11y).
3. P1: consolidate both web dictionaries; add runtime telemetry + build-time per-route literal inventories, fallback counters and CI gates. Separate locale from market/jurisdiction and script variations.
4. P1/P2: Android parity and authenticated admin/role views, backend error messages, Discord notices, UGC opt-in translation; review independently rather than claiming this unauthenticated read-only audit validates them.
5. Gate: 4 supported locales × every published route, including 320px/200% text, SSR `lang`+H1+title+description+hreflang+canonical consistency; native editorial sign-off, legal sign-off for sensitive claims, browser Playwright screenshot/diff, unit/integration/E2E, exact-SHA Test backend/front smoke before any zero-downtime Production approval.
