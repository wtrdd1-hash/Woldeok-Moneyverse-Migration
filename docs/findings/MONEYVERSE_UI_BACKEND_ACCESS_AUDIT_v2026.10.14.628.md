## Scope, counts, verification

- Enumerated 3,945 Git tree files; 164 Next page templates (135 non-dynamic), 80 NestJS controller files, and 541 controller method decorators; 852 relevant frontend source files under a non-test extension filter; 73 explicit `routes.config.ts` entries.
- Inspected global/member/mobile/admin navigation, Next UI pages, their source API calls, selected Nest controller implementations and prior risk reports. **This was automated inventory with targeted manual review, not manual reading of every source line.**
- Compared SHA-256 content of the eight core files covering venture, derivatives, auction, quant, admin blog/nav: identical between audited source, `prod-v600`, and `test-v618-7fa3f245bbc3` release directories.
- Read-only HTTP smoke: `/health` was 200 on both production and test. Anonymous GET of `/admin/blog` and `/admin/treasury/grants` was 200; this does not establish authorization or working user flows. No logged-in admin E2E, DB transaction proof, or exact-SHA Test release acceptance executed.
- The automated unmatched-API candidate count is **NOT** a defect count. Files with multiple `@Controller` classes and deliberately retired (410 Gone) routes cause false positives. No assertion that all 541 endpoints require UI exposure.

## Functional verification and release plan

1. **P0 contain truthfulness and role boundaries:** fail closed on mock money actions and grants authorization; add negative tests.
2. **API↔UI contract matrix:** every publicly available functional endpoint needs an authorized user path, loading/empty/error state and feedback/receipt; operator/internal APIs need explicit "no UI by design" annotations. Retired endpoints (e.g. `/api/v1/admin/approvals`) should not be treated as missing buttons.
3. **Test first:** isolate exact SHA, run lint/typecheck/unit, database SECURITY DEFINER/permission and idempotency tests, then Playwright at 320/390/430/768/1280/1440, normal/user/admin roles, accessible navigation, keyboard, zoom and flows.
4. **Production:** only after a verified isolated Test backend/database/identity, approval, migration/rollback and zero-downtime promotion; no production change in this audit.

**Snapshot limits:** page existence ≠ accessible UX; HTTP status 200 ≠ authenticated correctness; source hashes ≠ compiled runtime behavior; mock results ≠ real ledger balances. Android repository was inventoried, not end-to-end audited. Operations, Test and production were left unchanged.
