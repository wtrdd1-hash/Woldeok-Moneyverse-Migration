## 실제 개발 DB 진단

2026-10-14 KST PostgreSQL 17.11, 개발 DB 957MB. 사용자 활동 424MB(약 65.9만 행), Outbox 213MB(활성 약 26.7만 행·dead tuples 추정 46,941개), 주식 틱 105MB, 콘텐츠 상태 기록 88MB, 분봉 71MB.

Outbox의 실제 7일 초과 배송 완료 행은 9,612개, 아직 배송되지 않은 행은 2,313개로 확인했다. **미배송 이벤트는 절대 청소 대상이 아니다.** 기존에는 배송 완료 시각 순으로 2,000개 조회할 때 인덱스를 쓰지 못하고 병렬 전체 스캔(약 25,883 shared buffers, 36.158ms)이 발생했다.

## 구현 내용

1. 새 순차 마이그레이션 270: 배송 완료 시각·ID 복합 부분 인덱스를 CONCURRENTLY 생성한다. 테이블 재작성이나 기존 마이그레이션 덮어쓰기는 하지 않는다.
2. Outbox 테이블에만 autovacuum/analyze 기준 1,000행 + 5%를 설정한다(전역 설정 유지).
3. 백엔드 system.outbox_sweep를 **2,000행씩, 최대 25회/하루**의 개별 트랜잭션으로 제한한다. 정렬·제한값 바인딩·7일 보관 정책·미배송 보존을 지킨다.
4. 스케줄러 실행 결과에 삭제 건수, 배치 횟수, 상한 도달 여부를 기록한다. 잘못된 DB 응답은 실패로 처리한다.
5. 주식 틱 정리·사용자 활동 로그·콘텐츠 보존 정책은 이번에 변경하지 않고 후속 검토 대상으로 남겼다.

## 검증

- RED 단계에서 신규 테스트 3개 실패 확인, 수정 후 스케줄러 10/10 통과.
- 백엔드·DB 타입 검사, 공유 계약 빌드, Nest 빌드 통과; DB 마이그레이션 패리티 7/7 통과.
- 백엔드 전체 테스트 1,165개 통과, **391개 DB 관련 테스트는 환경 정보 부재로 건너뜀**. 전체 무결성 합격으로 과장하지 않는다.
- 운영 데이터와 분리된 PostgreSQL 17.11 전용 합성 DB(26만 행)에서 SQL 마이그레이션 성공, 유효 인덱스 확인. 정렬 조회 25.606ms·1,701버퍼 → 0.400ms·13버퍼. 이는 인위적 데이터의 결과이지 운영 성능 개선률이 아니다.
- 2,000행 실제 DELETE는 BEGIN/ROLLBACK으로 효과만 검증하고 데이터 변경을 철회했다.

## 미완료 게이트

대표 데이터의 격리 Test 전체 스키마·DB 통합 테스트, Test 서버 정확한 SHA 및 백엔드 기능, 승인된 백업·복원 검증, 프로덕션 무중단 승격은 **미완료**. CONCURRENTLY 생성이 실패하면 invalid index가 남을 수 있으므로 indisvalid/indisready를 확인한 뒤 진행해야 한다. DB 마이그레이션이 코드보다 먼저 적용되어야 하며, 작업 중 main 변경을 다시 확인한다.
