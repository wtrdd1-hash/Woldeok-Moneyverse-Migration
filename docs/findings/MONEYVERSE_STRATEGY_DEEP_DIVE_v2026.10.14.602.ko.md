## 1. 핵심 결론 / 제품의 존재 이유
머니버스의 장기 경쟁 자산은 **원장 기반 가상 경제에서 자신의 경제적 선택이 실제로 작동하는 학습·놀이·사회적 시뮬레이션**이다. 공개 금융 계산기는 검색 이용자가 문제를 해결하는 **첫 관문**일 뿐 최종 서비스 정체성이 아니다.

- **선택 C(조건부 추천):** '현실 금융 이해를 돕는 무료 도구 → 원하면 실험하는 가상 경제 시나리오 → WLD 사회에서 성장·협업하는 장기 경험'.
- '가상 경제 플랫폼으로 바로 가입'만 강조하면 가입 전 복잡성이 커지고, '계산기와 광고'만 강조하면 기존 강자와 차별화/재방문이 어렵다. 두 층을 무리하게 결합하면 도구 사용자를 방해하므로 **계산 결과를 완전히 제공한 뒤 선택형 확장**만 허용한다.
- **North Star 후보:** '주간 의미 있는 경제적 선택을 완료하고 결과를 확인한 고유 이용자(WEDU)' + 검색 도구의 `useful_result_completed`를 별도 1차 전환 지표. 단순 DAU·가입·발행 URL·광고 클릭 수를 성공의 최상위 지표로 삼지 않는다.
- 실제 화폐/투자/수익과 WLD 비환전·비수익성·게임 데이터는 설명·UI·계약·API에서 구분한다.

## 3. 왜 SEO는 수천 URL보다 신뢰성부터인가
1. **검색량을 실제로 모른다.** 기존 키워드 후보 10,473개, Crossref 외부 논문·콘텐츠 식별자 111,313개는 수요 측정치가 아니라 탐색 재고다. 1,012개 사이트맵 URL도 Google 색인 1,012개를 의미하지 않는다.
2. **관리자 SEO 감사 API가 실제 성과를 과장할 수 있다.** `frontend/src/app/api/admin/seo-audit/route.ts`는 `totalIndexedUrls=allUrls.length`, 하드코딩된 색인율(99.4%, 99.8%, 100%), 크롤러 시각/지연, `VALID` 스키마 수를 반환한다. 대시보드가 이를 실제 결과로 보여주면 근본적 의사결정 오류.
3. **Google 인덱싱 제출 기능이 중복·혼재한다.** `frontend/src/app/api/admin/seo/indexing-submit/route.ts`는 구 `www.google.com/ping?sitemap=` 호출을 Google Indexing API 성공으로 표기한다. `gsc-sitemap-submit/route.ts`와 `backend/src/seo/gsc-client.ts`에는 **진짜 Search Console Sitemaps API 경로도 존재**한다. 그러므로 모든 GSC 통합이 없다는 주장이 아니라 잘못된 구식 경로·성공 판정·사용자 문구를 정리해야 한다. Submit != Googlebot crawl != indexed != ranking.
4. **기반 검색 신뢰 위험:** 일부 계산기 페이지에 4.9+ 고정 `AggregateRating`; FAQ/HowTo도 검색 노출 가능성 보장 아님. 실제 이용자 평가·표시 정보·지원 유형/문서 수정일이 검증되기 전에는 스키마를 자동 대량 적용하지 말 것.
5. **다국어/URL 구조적 불일치:** 운영 sitemap에는 9,108 alternate entries(1,012×9); `/en/en/`, `/ja/en/`처럼 locale 이중 접두를 가진 링크가 1,026개. 동일 sitemap의 `<loc>` 목록에 없는 alternate target은 5,766개(중복 언어 레이블 포함; 단독으로 오류 확정은 아님). 36개 공개 페이지 샘플은 모두 HTTP 200이나 일반 계산기의 EN/JA/ZH 제목이 KO이며 canonical이 KO로 합쳐지는 사례; glossary는 언어별 canonical/제목으로 작동. 지역별 페이지별 SEO 계약 불일치가 확인됐다.
6. **수정일/모든 페이지 일괄 제출:** sitemap `RELEASE_TIMESTAMP`는 페이지 고유의 실질 수정일이 아니다. 루트 계산기, 변화 없는 금융 사전·프리셋까지 같은 수정 시간을 주면 신뢰도 저하. Google은 올바른 `lastmod`만 참고하며 `priority`/`changefreq`는 무시한다.
7. **실제 품질에 대한 통찰:** 문서와 코드에 '430/580+ 프리셋', 수백 개 주식/세금/용어 변형이 있다. 각 URL이 수요·고유 답변·계산 범위·내부 링크·최신 법령·국가별 적용에 유의미하게 기여하는지 입증해야 한다. 임의 일괄 삭제/리디렉션은 현행 검색 트래픽을 훼손할 수 있으므로 GSC Page Indexing과 URL 검사 근거로만 결정.

**SEO 목표 변경:** '색인 버튼 성공/생성 URL 수' → '검증된 검색 노출 → 클릭 → 정확한 계산 결과 완료 → 가치 있는 두 번째 행동 → (선택) WLD 첫 경제활동 → D7'. 모든 단계는 데이터 출처, 기준 날짜, 자산/국가/매체별 분모가 있어야 한다.

## 6. 사용자·세그먼트 4개
**KO 검색 해결형:** 세금/급여/대출 계산 결과 즉시 필요. 목표 '60초 내 결과'; 민감값 로컬 처리, 결과 저장 선택.
**EN 학습·시뮬레이션형:** 복리/DCA/FIRE/저축 목표. 국가별 수치 단위와 법적 관할을 분리하고 영문 본문까지 검증.
**가상 경제 입문형:** 짧은 결정으로 자산 변화를 보고 싶은 사용자. 핵심 조작 1개와 피드백을 제공; 랭킹/매매/국고는 선택 심화.
**장기 사회경제형:** 사업·공공 예산·시장·클럽에 참여. 공급/수요와 공공재의 결과가 장기 프로젝트에 반영되도록 한다.
서로 다른 사용자에게 모든 기능을 똑같이 추천하지 않는다. 검색 결과에서 가상경제 참여를 요구하는 강제가입은 금지.

## 7. 통합 경제생활 시스템 제안
- **개인 레이어:** 직업·월급·필수 생활비·세금·예산·저축·신용·대출·보험(가상)·투자·창업·주거·장기 목표.
- **사회 레이어:** 기업 재고/생산/고용, 지역 수요, 클럽 협업, 공공 프로젝트의 실제 비용과 효과, 익명 경제 랭킹(사생활 보호).
- **거시 레이어:** 중앙은행 금리 제안·통화량 회계, 재정 국고 수입/지출, 국채와 공기업, 인플레/실업·시장 이벤트, 안전 비축.
- **AI 레이어:** 개인 재무 결과 설명/민감도 비교, 이상 거래 탐지 제안, 국가정책 시뮬레이션, 감사 가능 로그. **자금 이동·발행·소각·승인 불가**.
- **확률 및 돈:** 인게임 WLD는 외부 환전 없는 가상 점수, 실제/가상 주식 혼동 방지. 카지노·레버리지/카피트레이딩은 이용·법률·광고 정책 평가 전 성장 동선에서 뒤로 배치.
- **경제 안전:** 공급 불변식 `M(t+1)=M(t)+authorized_mint-authorized_burn`; 모든 세금·지출·거래는 원장 이체, 중앙은행 발행과 국고 고갈 대응 분리, 멱등성·잔액 음수·이중 입금·동시성 방지. 운영 DB 수치에 기반한 승인/시뮬레이션/롤백 필수.
- **정책 문서 특이사항:** v522 문서에 '4 Core Redistribution Functions'라고 쓰면서 40%+40%+30%+10%+20% **다섯 목적/총 140%**를 기록한다. 이들이 단일 국고 지출 예산 배분인지, 독립된 조건부 지출 및 소각률인지 기준/분모가 불명확하다. **오류 확정 아닌 P0 기획 정의 충돌**로 취급해 중복 사용·통화 소각 회계 위험을 차단. 30% 안전비축과 85% 현금유동성은 대상/시점/분모 다른 것으로 추정하되 실제 룰 대조 전 섣불리 합치지 않는다.

## 11. 돈을 벌려면 순서를 바꿔야 한다
현재 통합기획 v487의 **실제 화폐 수익화는 광고-only**가 우선 권위다. 과거 유료 멤버십/외부 API/가상 통화 유료 판매·도박 보상은 자동으로 재활성화하지 않는다.

수익 모델:
`월 광고 매출(가정) = 광고 적격 공개 PV/1,000 × 관측 순 Page RPM`
`공헌 = 광고 매출 - 운영 비용(컴퓨팅·콘텐츠 검수·지원·부정행위·규제/법률·기타)`.

아래는 **매출 민감도 산식 검산용 시나리오이며 실제 유입·RPM 측정값 또는 수익 보장이 아니다.**
| 월 적격 공개 PV | 가정 RPM 1,000원 | 가정 RPM 2,000원 | 가정 RPM 5,000원 |
|---:|---:|---:|---:|
| 10,000 | 10,000원 | 20,000원 | 50,000원 |
| 100,000 | 100,000원 | 200,000원 | 500,000원 |
| 1,000,000 | 1,000,000원 | 2,000,000원 | 5,000,000원 |

월 매출 1,000만 원은 RPM 2,000원 가정이면 적격 공개 PV 500만이 필요하다는 산술만 알려준다. 실현 가능성은 현시점 평가 불가. 참여에 필수인 경제 거래/계정/관리자/사적 메시지/사행성 화면 광고 금지. 클릭을 유도하는 레이아웃·게임 버튼 인근 광고 금지. 광고 수익을 올리기 위해 검색 페이지를 무가치하게 분할하거나 고객을 속이지 않는다.

## 12. 실측 KPI 계약 (측정 전 목표값 금지)
- **검색 퍼널:** GSC `impressions`, `clicks`, `CTR`, `position` by query/page/country/device/week; Naver 별도. `indexed`는 GSC Index coverage/inspection의 실제 결과만.
- **도구:** `tool_view`, `tool_result_completed`, `scenario_view`, `scenario_completed`, `second_useful_action`, `share`; 비민감 입력·관할·locale·tool 버전만 이벤트 속성.
- **첫 경제활동:** `sign_up`, `tutorial_begin`, `tutorial_complete`, `first_ledger_receipt_verified`, `economy_decision_completed`; 광고용 추적·소득·대출 원문 전송 금지.
- **재방문:** D1/D7/D30 가입 코호트와 검색 유입 cohort 별도; WAU/MAU/재방문 시나리오·행동 종료 비율. 유효 사용자는 봇·테스트·관리자를 제외.
- **품질:** p75 모바일 LCP≤2.5s, INP≤200ms, CLS≤0.1 및 영수증 중복 지급=0, 번역/접근성/관리자 UI 차단=0.
- **수익:** page RPM, fill, viewability, 정책 경고, 광고 적격 PV, 운영비·원가, D7 하락 여부. 단순 AdSense 태그 존재≠광고 승인/매출.

## 13. 12주 실행 제안 및 중단 기준
**1주차: Truth Reset.** 새 기능 잠시 보류, SEO mock·구식 ping/상태 문구·평점 schema·GSC Indexing eligibility/URL list 점검. 정확한 Production 소스 SHA와 Test 환경 식별, 관리자 UI 및 500 진단. 비정상 계측은 '사용 불가' 상태로 노출.
**2~3주차: URL Quality Gates.** 도구 상위 20~40개 품질/법령/언어/canonical/hreflang/스키마/수정일/링크/E2E 리뷰. 1,012개의 기초 URL 카탈로그를 상태별 분류하되 무작정 대량 noindex/삭제하지 않는다.
**4~6주차: 첫 가치.** 3개 계산기의 결과→1회 가상 경제 시뮬레이션→선택 가입→첫 경제 거래; 가입 완료만 목표로 삼지 않는다.
**7~9주차: 재방문.** 직업/경제 사건/국고 공공사업/클럽 예산 투표를 가드된 실험으로 도입·확대, D7/economy action 측정.
**10~12주차: 확장 판단.** 검색 품질과 재방문이 개선된 코호트/국가만 확대. 광고-only unit economics 검증. 최종 D1/D7/D30 지표와 순공헌 개선 없이 다국어 10만 페이지·신규 유료 상품·카지노 홍보 확대 금지.

**Kill/Pause:** 허위 SEO 지표 재발, 원장 불변식 위반, 예기치 못한 WLD 발행, 관리자 권한 우회, 법률/정책 위험, 개인정보 오송신, 서비스 성능/신뢰/재방문 악화.
**Proceed:** 정확한 측정, 실사용자 가치·보안·정책, exact source SHA Test/백엔드/DB/브라우저 검증 후만 무중단 운영 승격.
