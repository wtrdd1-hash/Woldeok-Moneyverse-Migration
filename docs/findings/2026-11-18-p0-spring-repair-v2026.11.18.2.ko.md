## 확인한 원인
1. 관리자 회원·주식·경제 API에서 쿠키/토큰 **존재**만으로 허용하던 권한 문제를 세션 유효성 및 DB 관리자 역할 확인으로 교체. 실제 요청자 UUID를 권한 범위 조회에 사용하고 모든 `/api/admin/**` 및 `/api/v1/admin/**` 앞단에 검증 게이트와 변경 요청 CSRF 검사를 추가. 가짜 자산 0 및 가짜 주식 정지 성공 응답 제거.
2. Java 상점 조회가 DB 함수의 필수 사용자 UUID 인자와 반환 컬럼 계약에 불일치. 실제 `shop_catalog_list_v2(NULL::uuid)`로 바꾸고 데이터 실패 시 가짜 상품 목록 대신 503. 개인 보관함은 검증된 세션의 사용자만 조회하고 임의 사용자 헤더 무시. 구매는 세션·CSRF·외부 멱등 키로 정본 함수 연결, 가짜 영수증/제작 성공 제거. **실제 금액 변경 성공 E2E는 미검증**.
3. Spring에 포함된 정적 관리자 HTML에 이미 데이터 로딩 오류 화면이 포함됨. 관리자 UI 실제 기능은 아직 복구되지 않음.
4. 공식 Test는 과거 Next 포트 미가동으로 다수 기능 502, health 200만으로 통과 불가. 내부 격리 검증 인스턴스는 공식 Test 승격과 구별.
5. OpenAPI GET 101개 읽기 전용 샘플: 200=68, 401=16, 503=16(의도된 보류 포함), 500=1. 개인 국민연금 계좌 경로의 익명 조회 500은 DB 테이블 권한 오류와 임의 사용자 헤더 사용으로 이어짐. 실제 원장 기반 조회·인가 계약은 아직 미해결.
6. 디스코드 Gateway 재연결 및 음성 오류는 확인됐지만 실제 음성방 입장 성공은 미인증.
