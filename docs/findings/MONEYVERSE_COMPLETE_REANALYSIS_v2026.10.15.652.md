## RA-652-01 — **P0 confirmed live: automated monetary policy approves actions on fabricated source figures**

This was independently cross-checked from **production source SHA, actual database objects, actual monetary event history, policy order status and backend journal**.

1. backend/src/economy/monetary/auto-monetary-regulation.service.ts onModuleInit (around lines 21–34) schedules every hour unconditionally; running prod-v600 file hash equals main. No explicit enable flag check exists in active code.
2. Its lines 145–156 SELECT from public.ledger_entries. On the DB actually used by production, to_regclass('public.ledger_entries') is **NULL**. The catch block fabricates **faucet_24h = 500,000 / sink_24h = 480,000 WLD**.
3. Production monetary_auto_regulation_configs has **is_enabled=true**; journal shows hourly evaluation. All **318 monetary_regulation_events** records use the single identical hardcoded pair **500000 / 480000**. Of those, **169 have policy_order_id values**, all matching **169 records with monetary_policy_orders.status=APPROVED**. Recent five events are TAPER_CONTRACTION, each proposed adjustment **25,000 WLD**. Most recent event **2026-10-15 01:47:57.606 UTC = 10:47:57 KST**.
4. **Approved policy orders based on false data are established. Actual balance/mint/burn effects are NOT established**, and must be reconciled with canonical ledger postings and policy executions before asserting money was lost or created. These results do not authorize executing any user transfer.
5. **Urgent operational containment requires a separate authorized change:** audit+disable this specific configured automation (e.g. monetary_auto_regulation_configs.is_enabled=false with before/after evidence, controlled rollback), or deploy an isolated-Test verified fail-closed patch. Merely setting MONEYVERSE_MONETARY_AUTOREGULATION_ENABLED=false has no effect on the *current* prod-v600 source (the flag check is in unmerged #844). **No live setting was changed in this audit.**
