# Spring 백엔드 기능·위험 감사 (중간 기록)

기준: main `9876c09888ec84034eec183cf1309c85df3d7447`. 이 문서는 소스 분석이며 실제 운영 버전이나 모든 기능의 실행 성공을 증명하지 않습니다.

## P0: 은행 API의 신원과 원장 처리

- `spring-backend/src/main/java/com/moneyverse/api/domain/bank/controller/BankController.java`의 은행 조회·입출금은 요청의 X-User-Id를 사용하며 기본 사용자 ID도 있습니다. `SecurityConfig.java`는 전체 요청을 허용하고 `SensitiveApiBoundaryFilter.java`의 보호 목록은 은행 전체 경로를 포함하지 않습니다. 각 외부 프록시나 추가 필터의 실제 적용 여부는 별도 검증이 필요합니다.
- `BankService.java`는 잔액 조회 실패 시 고정 숫자를 반환합니다. 입출금은 직접 테이블을 수정하려고 시도하고 예외를 무시한 뒤 임의 ID로 성공을 반환합니다. 이 코드는 정식 복식부기 영수증과 잔액 변경을 증명하지 못합니다.
- 조치: 해당 경로 운영 노출을 확인하고 안전하게 차단한 뒤, 세션에 바인딩된 사용자·CSRF·안정적인 멱등성 키·원장 함수·실제 영수증을 갖춘 경로로 교체해야 합니다. 운영 데이터 보정이나 배포는 별도 절차가 필요합니다.

## P0: 인증 경계

`SecurityConfig.java`는 CSRF를 전역 비활성화하고 `anyRequest().permitAll()`을 사용합니다. 개별 필터가 일부 보호하지만 새로운 API 또는 빠진 별칭에 대한 기본 차단이 없습니다. 공개 경로를 명시하는 기본 거부 정책과 실제 HTTP 권한 부정 테스트가 필요합니다.

`spring-backend/src/main/resources/application.yml`에는 비밀값 및 DB 접속정보의 기본값이 있습니다. 실제 운영에서 이 값이 사용되는지는 확인되지 않았습니다. 운영 비밀 주입 상태를 안전하게 확인하고 노출된 자격정보는 회전하며, 운영 설정 누락 시 기동을 중단하도록 해야 합니다.

## 기획 대비 구현 공백

- 부동산/공간: `space/service/SpaceService.java`의 주요 메서드는 정식 데이터 소스 미확보를 이유로 503을 발생시킵니다.
- 금융 조언: `advisor/service/AdvisorService.java`의 주요 메서드는 정식 소스 미확보로 503을 발생시킵니다.
- 은행: 위에서 확인한 조회와 입출금은 기획된 정확한 잔액 및 정식 원장 처리의 근거를 충족하지 않습니다.
- 지갑: `WalletService.java`의 레거시 송금은 안정적인 재시도 키 부재로 503 처리됩니다. 정식 송금 구현은 존재하지만 실제 DB 권한·동시성·테스트 서버 영수증 검증은 이번 감사에서 수행하지 않았습니다.
- 공간·성장·조언 일부 변경은 `SensitiveApiBoundaryFilter.java`에서 정식 영수증 미검증으로 차단됩니다. 이것은 안전장치이며 전체 기능 완료가 아닙니다.

그 외 도메인은 코드나 API 선언 존재만 확인했으며 기능 정상 또는 미구현으로 확정하지 않았습니다. 503 문자열 검색 수는 실제 장애 수가 아닙니다.

## 최적화 순서

1. 은행의 허위 성공과 신원 경계부터 해결하고 회귀 테스트를 추가합니다.
2. 모든 API에 인증·인가·CSRF 정책과 DB 함수·화면 호출자를 연결한 추적표를 만듭니다.
3. 기획 기능별 성공·빈 결과·권한 거부·실패·재시도와 모바일 계약을 격리 Test에서 검증합니다.
4. Test에서 SQL 호출 수, 실행 계획, 연결 풀 대기, p95/p99, 메모리/GC를 측정한 뒤 병목만 최적화합니다.
5. 금융 기능은 실제 PostgreSQL 앱 역할, 중복 요청·동시성, 복식부기 및 영수증 확인을 통과한 뒤 승격합니다.

## 범위와 한계

Spring Java 246개와 테스트 소스 110개, 매핑 어노테이션 452개를 정적으로 집계했습니다. 어노테이션 수는 실제 고유 API 수가 아닙니다. Gradle 결과 XML 104개에서 662개 테스트, 실패 0, 오류 0, 스킵 0이 관찰됐지만 실행 종료 코드와 완료 시점을 확인하지 못해 전체 테스트 통과로 판정하지 않습니다. 실 PostgreSQL 전용 테스트는 일반 Gradle test에서 제외됩니다.
