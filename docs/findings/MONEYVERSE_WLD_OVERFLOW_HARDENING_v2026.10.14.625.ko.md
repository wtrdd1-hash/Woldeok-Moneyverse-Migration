## 실제 증거와 원인

- PostgreSQL 17.11 개발 DB 읽기 전용 점검: 핵심 계좌 잔액과 원장 금액은 정밀도 제한 없는 numeric. 80자리 정수 보존 확인. 194번 마이그레이션에서 확장했음. 다만 다른 테이블 bigint, numeric(20,2), PL/pgSQL bigint 캐스팅은 별도 위험.
- PostgreSQL numeric 자체도 소수점 위 최대 131072자리 등 물리 한계가 있다. 임의 보유 한도를 새로 설정하지 않았으며 처리 불가 금액은 조용히 반올림하거나 원장을 훼손하지 않고 원자적으로 거절해야 한다.
- 실패 재현: 80자리 9 금액이 Number()로 다른 값으로 바뀜, 36자리 WLD 송금 알림의 뒷자리 0 변형, 국민연금 납입/환급/정기지급 부동소수점 계산.

## 수정한 범위 (배포 전 후보)

1. **지갑:** 문자열 잔액 및 BigInt 합산 유지, 100자리 잔액 회귀 시험, 송금 알림 Number 변환 제거. 정수 문자열 요청을 허용하고 레거시 JSON number는 안전한 범위만.
2. **통화 환산 UI:** KRW/USD/JPY/CNY의 정수 고정 환산율을 BigInt 소액 단위로 정확하게 계산/반올림. 0·Infinity 또는 틀린 금액을 표시하지 않도록 조치. 환산값은 참고 표시이며 실제 환율 거래가 아님.
3. **P2P 및 국고 기부:** 양의 정수 문자열 검사, 버튼·영수증·기부 순위 출력에서 Number 변환 제거.
4. **소각 드로우:** API 반환 WLD 금액을 문자열로 보존. 요청은 정수 문자열 또는 안전한 JSON 숫자만 허용; 안전 범위 초과 숫자 거절. 기존 10000 WLD 최소값과 누락 시 기본값 유지.
5. **국민연금:** 기여금·누적 원금·등급 판단·95% 환급/5% 복지기금·시간당 지급·총지급·국고 기장 파라미터를 BigInt/문자열 기반으로 전환. 공개/관리자 화면도 정확한 문자열로 통일. API 반환 WLD는 문자열이므로 소비자 계약 확인 필요.
