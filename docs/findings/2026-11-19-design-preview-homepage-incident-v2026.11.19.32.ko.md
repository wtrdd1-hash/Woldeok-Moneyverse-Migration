# 장애 분석: 디자인 비교 시안이 실제 홈페이지에 노출된 문제

**문서 버전:** v2026.11.19.32
**판정:** 운영 홈과 승인 디자인의 불일치 확인 / 실제 UI 수정은 미실시
**작성일:** 2026-11-19 KST
**범위:** 읽기 전용 증거 수집 및 문서화. UI·Spring·API·DB·Test·운영 배포를 변경하지 않음.
**영문 정본:** [English](2026-11-19-design-preview-homepage-incident-v2026.11.19.32.md)

## 1. 핵심 판정

사용자가 첨부한 `easy-scraping.com`의 모바일 화면에는 **'신규 사용자 유입을 위한 홈 화면 3안'**이 표시되어 있다. 이것은 기존에 승인된 게임형 홈페이지의 완성된 구현이라고 볼 수 없다. `frontend/src/app/design-preview/page.tsx`에서는 이 페이지를 3개 안을 **비교하기 위한 프로토타입**으로 규정하고, 실제 운영에는 선택된 **한 안만** 다듬어 적용한다고 명시하고 있다.

그러나 미니PC 로컬 QA 기록은 이 비교 페이지의 HTML을 Spring 정적 홈페이지의 `index.html`로 복사했다고 직접 기술한다. 실제 공개 사이트의 루트 HTML을 읽기 전용으로 조회해도 3안 비교 제목이 확인되었다. 따라서 단순한 색상 차이가 아니라 **'검토용 디자인 페이지 → 실제 홈페이지'라는 잘못된 승격 경계**가 발견된 것이다.

**제작자 확인 한계:** 화면만으로 ChatGPT/Gemini/사람 중 누가 특정 디자인을 제작했는지 단정할 수 없다. Git 커밋 작성자 정보도 디자인 원작자와 동일하다는 증거가 아니다. 조사한 통합 기획에서는 비교 페이지 전체를 홈페이지로 교체하라는 사용자 승인을 찾지 못했다. HTML 응답 확인만으로 화면의 모든 버튼·API·인증·금융 기능이 정상 작동한다고 주장하지 않는다.

## 4. 원인과 책임 범위

**직접 원인(문서로 확인):** 미니PC 로컬 QA 문서가 `design-preview/index.html`을 Spring 정적 루트 `index.html`로 복사했다고 기록한다. 이로 인해 사용자에게 보여 줄 완성된 단일 홈 대신 **3안 비교용 화면**이 운영 진입점에 노출되었다.

**프로세스상의 원인:** 비교용 시안과 승인을 받은 서비스 홈을 분리하는 배포 게이트가 작동했다는 근거가 없다. 원본 이미지 대조·시안 승인·라우트별 작업 목록·Spring 기능 검증이 생략되거나 서로 다른 의미의 '완료'로 혼용되었다.

**책임자:** 현재 증거만으로 특정 작업자 또는 AI를 원인 제공자로 단정할 수 없으며, 실행 명령·배포 이력·PR·작업 로그를 더 대조해야 한다.

## 5. 복구 및 실제 구현 요구사항 — 이번 작업에서 미실행

1. **원본 시안 추적:** 사용자에게 승인받은 실제 PC·모바일 이미지와 기획 경로를 연결한다. `home.png`는 인계용 개념도이며 이미지 원본과의 1:1 일치가 검증된 것으로 간주하지 않는다.
2. **비교 페이지 격리:** `/design-preview`는 필요한 경우 내부/Test 전용으로 유지하며 noindex 및 접근 통제를 설정한다. 전체 3안 비교 페이지를 `/`로 복사하는 행위를 금지한다.
3. **승인 디자인 재구현:** 네이비/보라/블루 게임형 경제 메인, 실제 첫 퀘스트, 출석·보상 근거, 자산/시세(인증된 사용자만), 커뮤니티, 빠른 기능 이동. 게스트/로그인/로딩/빈 데이터/권한 없음/API 오류/데이터 지연 상태를 분리한다.
4. **Spring 단일 런타임:** 현재 통합 지시에 맞는 Java Spring Boot 기반 화면·API만 사용하고, Node.js/Next.js를 다시 운영 프론트엔드 런타임으로 도입하지 않는다. 임의 잔액·퀘스트 달성률·성공 응답·실시간 연결 표시 금지.
5. **반응형/접근성:** 320/360/390/430/768/1024/1280/1440/1920px, 200% 확대, 가로 오버플로 0, 키보드 포커스, 터치 ≥44×44px, 하단 내비와 56px 문의 버튼 충돌 0, WCAG 2.2 AA.
6. **실제 기능 QA:** 회원·게스트·관리자별 로그인/권한·CSRF, 금융 복식부기 원장, 주식·은행·직업·퀘스트·커뮤니티·문의채팅·사이트 검색·SEO와 로케일, 성공·실패·UNKNOWN을 실제 Spring API로 검증한다.
7. **병렬 작업 충돌 방지:** Gemini 담당 파일과 소유권·브랜치를 확인하고 별도 작업 worktree를 사용한다. Test 서버에 정확한 빌드 SHA를 띄워 이미지 비교·브라우저 E2E·보안 검증 후 사용자 시각 승인에 따라 무중단 운영 승격과 즉시 롤백을 수행한다. **본 문서 PR 자체는 운영승격 승인이 아니다.**

- [ ] 영어 기본/한국어 2번째, 320~1920 반응형, 200% 확대, 키보드, 접근성, 이미지 회귀 테스트 증거 확보
- [ ] Spring 전용 Test 환경에서 인증된 회원/관리자 E2E, API 실패 처리, 금융 무결성, 정확한 릴리스 SHA 및 롤백 검증 통과
- [ ] 내부/깃허브 업데이트 내역, 작업 전·중·후 로그, QA 증빙, 배포 및 운영 확인을 서로 구별해 기록
