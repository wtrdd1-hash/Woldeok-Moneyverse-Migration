## 3. 실제 발견한 4개 결함과 처리

**R1001-01: 잘못된 리비전 재시도도 기존 ID가 반환되는 무결성 문제.** 기존 초안이 expected_revision=0일 때 기록됐어도 동일 작업키로 expected_revision=7을 보내면 기존 ID가 반환됐다. PostgreSQL 실패(RED) 테스트로 재현했다. 신규 SQL 279가 저장 리비전과 요청 예상 리비전을 대조하여 불일치 시 거부한다.

**R1001-02: 출처가 만료되면 이미 성공했던 초안의 정상 재시도마저 오류 처리되는 복구 문제.** 기존 SQL 278은 기확정 작업번호를 찾기 전에 출처 만료를 검사했다. 출처와 초안 모두 과거 기록의 정확한 작업키/내용은 만료 후에도 영수증으로 조회할 수 있도록 새로운 SQL 279의 검증 순서를 변경했다. 새 작업은 여전히 만료된 자료로 생성 불가다. 별도 PostgreSQL RED 재현 후 GREEN 검증을 통과했다. 기존 278 SQL 본문을 수정하지 않았고 279로만 전진한다.

**R1001-03: 출처 만료시각이 수집시각보다 먼저인 불가능한 조합 통과.** 01:03 수집, 01:02 만료, 01:00 현재인 시나리오를 별도 Vitest로 실패 재현한 뒤 validUntil > retrievedAt 검사를 추가했다.

**R1001-04: 타임존 없는 시간과 내부 IP 주소가 공식 출처 형식검사처럼 통과.** zone 없는 시간문구, 127.0.0.1, 내부 *.internal 주소를 형식 단계에서 차단했다. 이것은 **완전한 실제 출처 인증이나 네트워크 SSRF 방어가 아니다**. 실제 공인출처 수집에는 추후 DNS 재해석·허용 호스트·redirect·콘텐츠 검증이 필요하다.
