## 4. 확인된 결함·차단 사항

### P0, 우선 조치 필요
**TR676-01 / 실제 운영 SWF 합성 수입:** 운영 `backend/src/admin/treasury/auto-swf.service.ts`는 부팅 30초 뒤와 매시간 자동 실행. DB SWF 사용 설정도 true. 시간당 공기업 배당·법인세 **124,000 WLD 고정 추가**, 국부펀드 평가액을 회차마다 약 1.2% 증가시켜 그 성장분의 약 30%를 ‘현금화’ 명목으로 VAULT_MAIN에 바로 반영. 공식 복식거래가 아닌 `UPDATE system_treasury_vaults`+국고 보조원장 기록. 2026-10-15 13:47 실제 한 번에 835,791 증가 확인. 최신 main의 `MONEYVERSE_SWF_EXECUTION_ENABLED`, `MONEYVERSE_SWF_SCHEDULER_ENABLED` 차단 코드는 **운영 prod-v600에는 없다**. 이 기능을 정상 세수라고 표시하면 안 됨.

**TR676-02 / 국고 대사 결과 조작 수준의 고정 성공:** 실제 운영과 최신 main의 `backend/src/admin/treasury/treasury.repository.ts:getReconciliation`는 금고합계만 조회한 뒤 `status='RECONCILED'`, 차이 `0`, 원장 순유입=금고합계로 강제 설정한다. 독립 분개/원장/부채 대사 불가능. 관리자 ‘정상’ 표시는 검증 근거가 아님.

**TR676-03 / 지급·복지·그랜트의 복식전표 공백:** SQL 240·268의 배당/저자산 보조금/그랜트 함수는 수령자 `account_balances` 직접 증가, 국고 금고 잔액 직접 감소 및 국고 보조원장 기록. Economy Core 차변·대변 분개와 하나로 연결되지 않는다. 범용 그랜트는 지급받는 회원 ID가 null 가능, 신청서 ID/멱등 키가 없다. 기존 DB 지출 4건은 보조원장 등록이지 총통화량 보전 근거가 아니다. **main** 시민 claim/지원서 신청/관리자 심사는 503 차단. **prod-v600**에는 원장 없이 지급 성공을 응답하는 옛 claim 및 신청자 고정 문자열을 이용한 JSON 신청 코드가 남아 있다.

**TR676-04 / 과도한 DB 권한:** 앱 역할이 보호 테이블을 포함한 대부분 테이블에 직접 쓰기 가능. 보안 함수 11개에 DB PUBLIC EXECUTE 부여. 일부 함수 내부 관리자 역할검사는 있으므로 ‘누구나 웹에서 출금 가능’이라고 단정하는 것은 부정확하지만, 복합 취약면과 회귀 위험이 크다. 운영에서 일괄 REVOKE하지 말고 격리 DB와 권한 음성시험으로 전환해야 한다.

**TR676-05 / 공개 국고 안내·지급내역 예시를 실제처럼 표기:** `frontend/src/app/treasury/page.tsx`와 공개 조회 API는 관리자 권한이 필요한 `/api/v1/admin/treasury/overview`에 의존한다. 실패 시 **25,000,000 WLD**, 누적 지급·소각 고정액, 수혜자 **1,420명**, 5건 예시 지급기록, 임의 생성 날짜, 지갑 **3,200 WLD** 같은 고정값을 실제 현황처럼 제공한다. 일반 시민에게 인증된 공개 재정 조회 모델이 필요하다.

**TR676-09 / 실원장과 화면 합계 연결 실패:** 회계·지급 실적·복식분개 총량·소각 증서·예산 확보, SWF·연금·국채의 부채를 일관되게 증명하는 영수증 식별자/대사 연결이 부족하다. Economy Core 내부 분개 합계가 같다는 사실로 전체 지급을 인증하지 못한다.

## 6. 권장 해결 순서와 합격 증거
1. **즉시 사고 범위 진단·통제:** 자동 SWF/통화정책 이벤트·설정·계정·백업을 먼저 증거 보존. 운영 변경을 명시적으로 승인받으면 롤백 가능한 절차로 실제 효력이 있는 SWF `treasury_swf_configs.is_enabled=false` 등을 사용해 통제하고 다음 자동 실행시각 이후 새 수입 중지 여부 확인. 현재 보고서 작업에서는 변경하지 않음.
2. **기초 회계·DB 권한:** 운영 복제본 Test 복원, 초기 금고 시드·SWF 모의 세수·직접 지급·부채·채권 등 출처 분류. 표시금고와 경제 국고계정의 **연결식**을 설계하고 진짜 재원/가용잔액 계산. 실서비스 계정·원장에 차액 무단 복사 금지. 직접 DML 237개와 PUBLIC 함수 11개를 세부 테스트한 후 점진적 최소권한 전환.
3. **국고 모든 자금이동 정비:** 세금·기부·국채·연금·배당·그랜트·예산이동·매입소각·조폐/폐기를 개별 도메인 불변식과 공통 복식분개·멱등·감사·outbox·영수증으로 교체. 실패는 전부 롤백.
4. **서비스 진실성 복원:** 공개 조회 API와 관리자 API 분리, 허위 지급·통계·예시 날짜 제거. 주민투표·그랜트는 서버 UUID·DB 유니크 키·관리자 심사/실지급 분리.
5. **운영승격:** 새 브랜치→정확한 SHA CI→실제 복원 DB 권한·금액·중복/동시성/실패복구 테스트→Test 프론트·백엔드 건강도, 로그인/관리자 E2E·320–430px 모바일 5회 전체 UI→최신 main 재확인→PR 검토→백업/복구/세션 유지와 무중단 운영 승격→영수증 실검증. 합격 증거 없으면 운영 변경 금지.
