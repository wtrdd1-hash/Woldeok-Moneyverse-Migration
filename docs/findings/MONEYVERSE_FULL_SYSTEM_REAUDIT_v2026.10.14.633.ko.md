## 2. 최우선 P0: 운영 백엔드 DB 최소권한 붕괴 확인

**실제 연결 검증:** `moneyverse-backend`는 `NODE_ENV=production`에서 `moneyverse_app` 계정으로 `127.0.0.1:5433/woldeok_moneyverse_dev`에 접속한다. 비밀번호/토큰은 출력하지 않았다. 이 연결 DB를 읽기 전용 SQL로 별도 확인했다.

- `public` 테이블 **241개** 중 앱 계정의 SELECT 가능 **238개**, INSERT **237개**, UPDATE **237개**, DELETE **237개**.
- `account_balances`, `ledger_transactions`, `users`, `auth_sessions` 등에 앱 계정 직접 **전체 DML ACL** 존재. `audit_logs` DELETE도 가능. 앱 계정은 슈퍼유저가 아니고 migrator 역할을 상속하지 않으므로 명시 권한 문제다.
- DB `public` 함수 **549개** 중 **485개 SECURITY DEFINER**, 이 중 **11개는 PUBLIC EXECUTE** 가능. 함수 자체가 별도 인증을 할 수 있으므로 11개 모두 악용 가능하다고 단정하지 않는다.
- DB `schema_migrations` **266개 적용, 최고 268번, 최종 적용 기록 2026-10-11**. GitHub SQL 파일은 269번까지 있고 PR #834에 **270번 권한 보정 마이그레이션**이 제안됐지만 현재 main/DB에 적용됐다는 증거가 없다. 해당 270번도 열거된 특정 테이블의 권한만 철회하므로 **전체 237개 테이블의 ACL 문제를 해결했다고 볼 수 없다.**
- 이는 `AGENTS.md`의 원장/계정 직접 쓰기 금지, 최소권한·SECURITY DEFINER 정산 정책과 배치된다. **DB 계정 탈취나 SQL 취약점 때 피해 확대 위험**이지, 실제 자금 탈취 발생 증거는 아니다.

**수용 조건:** 운영과 별도 DB에서 실제 권한과 프로그램 종속성을 매핑하고 백업→권한 축소→정상/비정상 트랜잭션·원장 대사·ADMIN/일반회원 음성 테스트→복구 검증을 통과한 후 정확한 SHA 기반 무중단 승격. 즉각적인 무검증 `REVOKE` 실행은 금지한다.
