## 현행 안전 상태 (2026-10-16)
- 운영 v717 및 Test v721의 자동발행 API는 미검증 금융 글을 거부하지만 구식 v600·v635·v697·v712 프론트엔드 인스턴스에 발행 경로가 남아 있음. 이들은 공개 Nginx v717 :3234 프록시 대상이 아니며, **16:16:41 실제 작성 주체는 미확정**.
- 공유 저장소 `/srv/moneyverse-data/shared/blog-posts.json`은 `debian:debian`과 모드 `0444`. 제한 백업 `/srv/moneyverse-tasks/ai-blog-v721/blog-posts.before-readonly.json`. 기존/변경 후 SHA256 동일 `f146cd031e63054f72dc3289f6b7d270fcff29f81e2a20d4260e471d8b8dddd3`. 일반 서비스 사용자 쓰기만 차단하며 root 권한 및 디렉터리 파일 교체까지 차단하는 절대 보안 수단은 아님.
- v721 Test는 과거 AI 글의 직접 URL을 보관·`noindex,follow` 적용, 공개 목록/사이트맵에서는 제외. 실제 Google 검색 제외는 GSC 확인 전까지 미확정.

## 읽기 전용 운영 점검
1. `stat -c '%a %U %G %s %y' /srv/moneyverse-data/shared/blog-posts.json` 및 `sha256sum`으로 파일 모드·변경시각·내용 해시를 추적. v717 운영 중의 `/api/blog`는 전 목록을 반환하지만 v721에서는 교육용 6편만 반환하므로, v721 배포 후 해당 API 개수만으로 원본 파일 전체 개수를 판단하지 않음.
2. `systemctl list-units '*moneyverse*' --all`, 토큰 제거한 `nginx -T`로 활성 인스턴스/프록시 추적. 검증 목적으로 구식 `/api/blog/generate`에 POST하지 말 것(실제 발행될 위험).
3. 파일이 쓰기 가능으로 복귀하거나 파일 해시·수정시각이 예상 없이 바뀌면 조사. 로그에서 헤더·토큰·개인정보는 제거하고 특정 서비스 로그만 조회.
4. 운영/Test `/blog`, 국가별 교육 본문, 사이트맵 헬스 확인. HTTP 200은 검색 색인 성공 의미가 아님.

## 쓰기 재개 전 필수조건
- 기존 발행 가능한 구식 서비스의 실제 소유자와 롤백 경로를 확인한 후 적법하게 폐기·격리하고 중복 스케줄러를 끔. 원본 릴리스 파일은 보존.
- 글별 출처 URL·취득/기준 시각·법역/편집자 승인·유사도·콘텐츠 해시·이미지 권한 등을 저장하는 승인증빙, 발행 중복방지 락/멱등성 및 실제 저장 실패 처리 구현. 기본 비밀키 금지.
- 별도 PR/CI·정식 Test·세션·DB·백업 후 승인된 변경창에서만 적법한 쓰기 권한 복구. 복구 전에 담당자·예상 쓰기 프로세스·해시·차이·롤백 기록. **구식 프로세스가 남은 상태에서 단순히 `chmod 644`로 되돌리지 말 것.**
- 금융 DB·전 화면 수용 검사 등 앱 전체 운영 게이트는 별도로 통과해야 함.
