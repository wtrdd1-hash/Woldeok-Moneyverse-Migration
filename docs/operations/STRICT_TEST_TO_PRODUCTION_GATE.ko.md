# 테스트 서버 → 운영 서버 엄격 승격 규정

[English canonical](STRICT_TEST_TO_PRODUCTION_GATE.md) | **한국어**

> 정책 버전: v2026.11.23.1
> 상태: 제안/문서 작성 — GitHub 보호 설정·CI/CD·서버 권한에 실제 적용되기 전까지 자동 강제 아님
> 적용 범위: 웹 UI, Spring 백엔드, API, DB/마이그레이션, 인증, 금융/경제, 봇 연동, 인프라

## 대원칙: 확인되지 않으면 무조건 차단(Fail Closed)
**운영 서버에서 직접 소스·정적 파일·Nginx·systemd·DB·세션·설정·릴리스 포인터를 임의 수정하는 것을 금지한다.** Gemini, GPT, 관리자, 예약 작업 모두 동일하게 적용한다. 운영 릴리스 디렉터리에서 `git pull/reset/checkout`, 파일 직접 덮어쓰기, 즉흥 SQL, 확인 없는 서비스 재시작, 단독 프로세스 교체를 금지한다. 운영 변경은 검증된 불변 산출물을 승인된 승격 트랜잭션으로만 전환한다. **사용자의 운영 승격 지시는 작업 승인 의사이지 검증 면제권이 아니다.** 문서만 변경한 커밋으로 운영 재배포 금지.

작업 전/중간/승격 직전 [통합 마스터](../planning/INTEGRATED_PLANNING_MASTER.md), [프로젝트 기획](../planning/PROJECT_PLAN.md), [릴리스 지침](../RELEASING.ko.md), [운영 배포 지침](production-deployment.ko.md), [런타임 기준](../CURRENT_RUNTIME_BASELINE.ko.md)을 새로 확인한다. 실제 공개 경로가 Debian systemd/Nginx인지 확인하고, 역사상 Flux/Compose·Node 기록과 현재 Spring 전환 지시를 혼동하지 않는다. 문서가 충돌하면 승격 중단 후 권위 문서부터 정합화한다.

## G0~G9 필수 단계

| G1 코드 검토 | 별도 브랜치 PR, 변경 범위/위험/DB/API 영향, 영·한 문서, 내부/공개 업데이트, 민감 변경 시 소유자+독립 기술 검토 | 운영/main 직접 수정, 무심사, 비밀 노출, 자기 승인만 존재 |

| G6 최종 승인 | main과 통합문서 재확인, Gemini/GPT 병렬 PR 정리, **최종 병합 SHA 재검증**, 증거 제출 후 **이번 배포만을 위한 소유자 명시 승인** | 예전 일괄 승인만 존재, main 변경 미반영, 미검증 범위 |
| G7 무중단 카나리 | 기존 운영 계속 가동, 신규 불변 generation 별도 기동, health/버전/세션/롤백 검증 후 승인 트래픽 순차 전환 | 유일한 운영 프로세스 선중지, 롤백 불가, frontend/backend 버전 혼합 |
| G8 운영 수용 | 공개 URL 및 실제 origin 버전, 핵심 인증 API·DB·금융 차단선·UI·로그 확인, **최소 30분 관측**(금융/DB는 추가) | 오류 급증, 세션 손실, 잘못된 SHA, 권한/원장 이상, 보안경고 |
| G9 기록 종료 | 정확한 SHA/산출물 해시, Test 증거, 승인자, 전환·관측·롤백 대상, 영·한 작업·업데이트 내역 및 완료 상태 | 감사 기록 누락 시 운영 검증 완료 선언 불가 |

**테스트가 통과했다고 자동 운영승격하지 않는다.** GitHub protected Production Environment에서 릴리스별 승인 절차를 통과해야 한다. 이전의 포괄적 승인, CI 녹색만, 로컬 성공, 테스트 서버 장애는 예외 사유가 아니다. 모든 항목은 `PASS`·`FAIL`·`BLOCKED` 및 근거 링크로 기록하고, 미확인은 `BLOCKED`이다. 문서 변경만으로 `TEST_VERIFIED` 또는 `PRODUCTION_VERIFIED` 표시 금지.

## 실제로 강제해야 할 기술적 보호 설정
1. **GitHub main 보호:** 직접 push·force push 금지, PR 필수, CODEOWNERS, 필수 검사 성공, 신규 커밋 시 이전 승인 무효화, 최신 SHA 검사, 병합 큐로 작업 직렬화.
2. **Production Environment 보호:** 지정 승인자·자기 승인 차단(가능한 환경), 보호된 main/릴리스 태그만 배포, 배포 동시성 잠금, 버전별 승인 증빙.
3. **운영 호스트 권한 격리:** 진단 읽기 전용 계정과 배포 전용 최소권한 계정 분리. 운영 디렉터리 대화형 수정 차단, SHA가 포함된 신규 불변 디렉터리만 허용, sudo 허용 명령 제한, Nginx/systemd/pointer 수정 전체 감사.
4. **Test 격리:** 운영 DB 계정/비밀/데이터를 Test·CI에서 재사용 금지. Test에서 운영 DB 네트워크 접근도 가능한 범위에서 차단.
5. **정확한 산출물 검증:** 테스트한 source SHA 및 backend/frontend 빌드 해시를 운영 배포에 고정. main 변동 시 후보 재검증.
6. **승격 직렬화:** 동시에 한 건만 처리. 전환 이전 이전 버전과 즉시 복귀 절차 검증.
7. **인증·금융 변경 특별 게이트:** 실제 계정/권한·DB·원장·세션 별도 증거 필수. UI 성공만으로 데이터 기능 승인 금지.

## 중단 및 롤백
전환 전 실패는 운영 무변경 `BLOCKED`. 카나리 또는 관측 중 P0/P1, 5xx 급증, 세션 손실, SHA 불일치, 금융원장·보안 위험 발견 즉시 트래픽 증가 중지. **검증된 호환 이전 애플리케이션/설정 포인터로만 롤백**한다. DB·회원 세션·감사·금융원장 삭제 금지. DB 파괴적 마이그레이션을 무조건 역실행하거나 백업으로 무단 복원하지 않고 안전하게 쓰기 차단 후 검증된 복구 계획을 실행한다.

P0 긴급 복구는 새 기능 우회 배포가 아닌 **이전 검증 정상 버전 복귀**를 우선하며, 별도 긴급권한·담당자·사용자 승인·사건번호·백업·시간 기록 및 24시간 이내 사후검토를 필수로 한다.

## 릴리스 기록 필수 양식
- 버전 / 티켓 / 작업자 / 시작·중간·최종 main SHA:
- PR / 독립 검토자 / 이번 승격의 사용자 승인 일시:
- 정확한 소스 SHA / backend·frontend 해시 / 불변 배포 경로:
- 공식 Test URL / 공개 버전 / 실제 테스트 DB·API 입출력 증빙:
- 필수 CI 결과·skip 목록 / PC·모바일·5언어·UI / 로그인·세션·금융 QA:
- 백업 ID·체크섬 / 복원 연습 / 마이그레이션 / 롤백 호환:
- 카나리 전환 및 운영 공개 버전 / 최소 30분 지표와 로그:
- 롤백 대상 / 장애 참조 / 최종 상태(`BLOCKED`, `TEST_VERIFIED`, `PRODUCTION_VERIFIED`):

## 현 시점 적용 상태
이 문서는 **규정 제정 제안**이며 GitHub 브랜치 보호/CI/운영 계정에 실제 설정 완료라고 주장하지 않는다. 영·한 문서 PR 검토 및 병합 후, 보호 규칙·워크플로·호스트 권한 변경은 별도 PR과 실측 검증으로 이행한다. 그 전에는 검증되지 않은 후보의 운영 변경을 승인하지 않는다. 11월18일 UI 통일성 및 인증 포함 전체 기능 QA 미해결 항목을 임의 통과 처리하지 않는다.
