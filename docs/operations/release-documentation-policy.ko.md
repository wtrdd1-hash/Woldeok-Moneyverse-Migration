# 릴리스 및 변경 기록 정책

이 문서는 코드, 설정, 배포, 문서 등 저장소의 의미 있는 변경에 적용하는 저장소 전역 기록 규칙을 정의합니다.

## 언어 우선순위

GitHub에서 사용하는 공식 문서는 해외 기여자와 국제 개발자가 별도 번역 없이 프로젝트를 이해할 수 있도록 **영어를 기준 원문으로 사용합니다.**

필수 순서는 다음과 같습니다.

1. **영어 — 공식/기준 문서**
2. **한국어 — 유지되는 번역본**

다른 언어 번역은 선택 사항입니다. 영어와 한국어 문서가 함께 존재하는 경우 동작, 운영 상태, 릴리스 범위를 의미상 동일하게 유지해야 합니다.

## 버전 형식

의미 있는 변경 묶음마다 다음 형식의 버전을 부여합니다.

```text
vYYYY.MM.DD.N
```

예:

```text
v2026.09.08.1
v2026.09.08.2
```

같은 날짜에 추가 변경 묶음이 생기면 마지막 숫자를 증가시킵니다. 배포가 끝나기 전에도 버전을 부여할 수 있지만 문서에는 반드시 `검증 중`, `배포 대기`, `테스트 배포 완료`, `운영 배포 완료`, `main 병합 완료` 등 실제 상태를 명시합니다.

## 버전별 릴리스 문서

각 버전은 `docs/releases/` 아래에 최소 다음 두 파일을 유지합니다.

- `vYYYY.MM.DD.N.md` — 영어 공식 기준본
- `vYYYY.MM.DD.N.ko.md` — 한국어 번역본

문서의 구성과 상세 수준은 저장소의 GitHub Release 형식을 따르며, `v2026.09.07 — Gameplay, UX and Economy Stability`를 기준 예시로 사용합니다.

각 릴리스 문서는 해당되는 경우 다음 항목을 포함해야 합니다.

1. 버전 제목과 짧은 릴리스 요약
2. 주요 변경 사항
3. 기능/서브시스템별 세부 변경
4. 주요 수정 파일/컴포넌트
5. 검증 및 테스트 결과
6. 데이터베이스 migration
7. 운영 안전성 메모
8. 테스트 서버 배포 상태
9. 운영 서버 배포 상태
10. `main` 병합 상태
11. 남은 문제 또는 후속 작업

## CHANGELOG 동기화

버전 문서를 생성하거나 중요하게 수정할 때 같은 버전을 다음 파일에도 동기화합니다.

- `docs/changelog/CHANGELOG.md` — 영어 공식 CHANGELOG
- `docs/changelog/CHANGELOG.ko.md` — 한국어 번역본

CHANGELOG는 요약본이며 상세 기준 문서는 버전별 릴리스 문서입니다.

## GitHub Release 게시

변경 사항이 테스트 환경에서 검증되고 운영 배포까지 확인된 뒤 동일 버전/태그로 GitHub Release를 게시하거나 갱신합니다. GitHub Release 본문은 영어를 우선 작성하며 영어 공식 릴리스 문서와 내용이 일치해야 합니다. 한국어는 대응하는 `.ko.md` 문서로 제공합니다.

실제 운영 배포가 검증되기 전에 운영 완료로 표시한 Release를 게시해서는 안 됩니다.

## 배포 원칙

문서는 실제 배포 상태를 그대로 반영해야 합니다.

```text
feature/fix 브랜치
  -> CI / 로컬 검증
  -> 테스트 서버 배포
  -> 테스트 검증
  -> 운영 서버 배포
  -> 운영 smoke 검증
  -> 저장소 절차에 따라 main 통합
  -> 릴리스 문서 및 GitHub Release 최종화
```

테스트, 운영, `main` 통합을 실제 검증 전에 완료로 표시하지 않습니다.

## 추적성

모든 의미 있는 변경은 가능한 한 동일 버전으로 다음 항목 사이에서 추적 가능해야 합니다.

- 커밋
- Pull Request
- 릴리스 문서
- CHANGELOG
- 게시된 경우 GitHub Release/태그
- 해당되는 경우 배포 및 테스트 근거

새 버전을 게시할 때 이전 릴리스 기록을 삭제하지 않습니다. 릴리스 기록은 누적 보존합니다.
