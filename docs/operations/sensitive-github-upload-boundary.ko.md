# GitHub 민감정보 업로드 경계 (v2026.11.18.11)

[English canonical](sensitive-github-upload-boundary.md) | **한국어**

## 규칙
GitHub에는 소스와 **비식별화된 작업 증빙**만 저장한다. 비밀번호·토큰·OTP·세션 쿠키, 실제 회원 식별정보나 잔액, 운영 DB 덤프·암호화 백업 원본, MCP 호출 원본 매개변수, 운영 호스트 백업 설정, 원시 셸 이력, 가림 처리되지 않은 사고 이미지, 서명 키, 서버 로그, 민감한 내부 작업 기록을 올리지 않는다. 비공개 GitHub 저장소라도 이 규칙을 면제하지 않는다.

실제 민감 감사 자료는 권한·보존·암호화 정책이 적용된 미니PC 보호 경로에 보관한다. GitHub에는 작업 버전/날짜/소스 SHA/테스트 SHA/명령 종류(민감 명령 원본 제외)/결과/이슈·PR/차단 사항/배포 증빙/다음 작업을 EN·KO 비식별 요약으로 기록한다. PR·이슈 본문에도 실제 비밀값을 기재하지 않는다.

## 차단 범위와 한계
- 웹 `.gitignore`는 신규 민감 파일을 제외하며 기존 보안 스캐너를 확장해 추적 파일의 확실한 비밀값과 변경된 내부 기록 경로를 차단한다. 기존 `ci.yml` 정책 작업에 연결했다. Android도 별도 Python 검사기와 GitHub Actions 워크플로를 구성한다.
- `.gitignore`는 이미 추적된 파일이나 강제 추가/직접 업로드를 차단하지 못한다. GitHub 관리자 설정에서 **필수 CI 검사·브랜치 보호·비밀정보 push protection**을 활성화해야 강제 효과가 생긴다. 모든 종류의 비밀값·개인정보를 완벽히 인식하지는 못한다.
- 과거 GitHub에 올라간 자료는 신규 차단 정책만으로 숨겨지지 않는다. 실노출은 비공개 조사 후 키 폐기·재발급 및 승인된 기록 정리가 필요하다. 감지된 값은 이슈/PR/보고서에 재출력하지 않는다.
- 본 변경으로 서버 재시작, 운영 코드 승격, DB·원장 수정, 기존 기록 삭제 또는 인증정보 변경을 수행하지 않는다.

## 검증
2026-11-18 미니PC 격리 임시 디렉터리에서 웹·Android 스캐너 단위 테스트 각각 3/3 통과. GitHub PR 전체 CI와 필수 검사 설정은 별도 검증 전이다.
