## 반드시 같은 수준으로 유지할 항목
메인 README가 크게 변경되면 각 현지화 가이드는 다음 내용을 계속 포함해야 합니다.

1. 서비스 개요와 가상 데이터 고지
2. 실제 공개 Production 스크린샷과 반응형 동작
3. 기능 개요/표
4. 아키텍처와 신뢰 경계
5. 직업/작업 및 재시도/멱등성 동작
6. 퀘스트/이벤트의 실제 구현 여부
7. 카지노 확률, 제한, 서버 권한 결과
8. 은행/신용/채권 무결성 규칙
9. 주식/사업/상점 요약
10. 기준 WLD 정수 문자열 정밀도 규칙
11. 보안 모델과 내부 API 경계
12. 모바일/외부 앱 게이트웨이/BFF 지침
13. Test → Production 배포 흐름
14. 백업/복구 정책
15. 개발/런타임 기준
16. 상세 아키텍처/기능/운영/릴리스 문서 링크

## 반드시 동기화할 사실
기술적 의미가 달라지도록 번역해서는 안 됩니다.

- Job 2.0 현재 카탈로그: 8개 직업 × 활성 과제 3개 = 총 24개
- 공개된 핵심 카지노 기준: 문서화된 동전/주사위 핵심 게임 RTP 95%
- 카지노 노출 기준: 1회 10–200 WLD, 일일 베팅 2,000 WLD, 일일 실현 손실 1,000 WLD. 이후 정책 릴리스에서 명시적으로 변경한 경우 제외
- WLD는 API 경계에서 정확한 기준 정수 문자열
- `INTERNAL_API_TOKEN`은 서버 간 통신 전용이며 브라우저/네이티브 클라이언트에 포함하지 않음
- Production 배포는 명시적 절차를 따름
- Production DB/회원/원장 데이터와 볼륨은 일반 정리 대상이 아님

## 스크린샷 정책
현지화 README는 `docs/images/showcase/`의 동일한 언어 중립 Production 스크린샷을 재사용할 수 있습니다. 같은 PNG를 언어별로 중복 복사하지 않습니다. 공개/세션 안전 스크린샷만 커밋하며 번역을 위해 회원 비공개 또는 관리자 데이터를 커밋하지 않습니다.

## 업데이트 체크리스트
릴리스가 현지화 문서의 사실을 변경할 때:
- 루트 README 갱신
- 영향을 받는 모든 현지화 가이드 갱신
- 각 현지화 CHANGELOG 갱신
- 필요한 상세 기능/운영 문서 갱신
- 상대 링크 검사 실행
- 비밀정보/제어 바이트 검사 실행
- GitHub `main`에서 파일 확인

번역은 자연스러운 현지 용어를 사용할 수 있지만 보안/경제 동작은 모든 언어에서 의미상 동일해야 합니다.
