# Application Role Boundary — Read-Only Release Prerequisite

`node scripts/release/verify-app-role-boundary.mjs --env-file /absolute/operator.env --expected-db <database>` checks the current PostgreSQL catalog under one `REPEATABLE READ READ ONLY` transaction. The env file must be approved by an operator and contain `DATABASE_URL`; do not print its contents or commit it. The supplied database name must match `current_database()` exactly.

A result of `READY_FOR_OTHER_RELEASE_GATES` (exit 0) only establishes that `moneyverse_app` is a LOGIN, NOINHERIT, NOSUPERUSER, NOCREATEDB, NOCREATEROLE, NOREPLICATION, NOBYPASSRLS role without direct role memberships, without effective CREATE on the connected database or public schema, and with public schema USAGE. Effective CREATE includes inherited and PUBLIC grants. Any unknown evidence, unexpected role membership (including SET ROLE exposure), dangerous role attribute, database mismatch or unavailable catalog fails closed with exit 2. TEMPORARY database access is not rejected by this narrow prerequisite; audit `SECURITY DEFINER` search paths independently.

**This is not a privilege remediation.** It neither changes the role nor revokes grants, does not check table DML/TRUNCATE/TRIGGER/MAINTAIN, future default ACLs, function EXECUTE, object ownership, migrations, ledger integrity, runtime credentials or production provenance. Keep RELEASE HOLD until all separate required gates, official exact-SHA Test with authenticated E2E, independent restore and GitOps approval pass. The current DEV catalog passes this narrow gate; QA v1476 independently reports dangerous table privileges, so overall release remains BLOCKED.

For disposable PostgreSQL regression, create an isolated `moneyverse_app LOGIN NOINHERIT` role, verify exit 0, then independently grant public schema CREATE, database CREATE, membership in `pg_read_all_data`, and CREATEROLE: each must produce exit 2. Revoke each fixture grant and verify exit 0. Do not perform fixture grants on the shared DEV/Test/Production database.
