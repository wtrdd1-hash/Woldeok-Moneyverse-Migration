# v2026.09.16.145 — Casino Theme Action Contract Fix

## User benefit

Casino themed interfaces (Lucky 777 slots, High/Low, Color Wheel, Treasure and Gems) now submit the selected server-game choice through the same `choice` field consumed by the casino server actions. These views previously posted `number` or `parity`, so valid themed plays were rejected before reaching the backend settlement API.

## Integrity and performance review

The settlement model remains server-authoritative: the browser submits only a choice and integer WLD stake, while the backend/database owns RNG, policy checks, idempotency and ledger settlement. The casino page already loads independent read models concurrently, and no client-side RNG is used for settlement; slot `Math.random()` is animation-only while pending and the final reels derive from the server receipt.

## Validation

Shared contract build passed. Targeted casino frontend tests passed (40/40), frontend typecheck passed, and targeted ESLint passed. A broader first test attempt exposed only a workspace bootstrap issue where `@moneyverse/contract` had not yet been built; after building the contract, focused validation passed. Runtime promotion still requires the repository Test/Production gates.
