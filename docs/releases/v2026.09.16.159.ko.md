# v2026.09.16.159 — 직업 일간/주간 초기화 수렴

## 사용자 변경 사항

- 직업 페이지에서 서버 권위 기준의 일간·주간 WLD 사용량, 남은 한도, 정확한 다음 초기화 시각을 표시합니다.
- 회원 전체 일간/주간 보상 한도 또는 해당 업무의 일일 수행 횟수에 도달하면 사유를 표시하며 업무 실행 버튼을 비활성화합니다.
- 보상 미리보기도 실제 정산과 같은 업무별/일간/주간 한도를 반영하여 서버가 거절하거나 감액할 금액을 미리 지급 가능한 것처럼 표시하지 않습니다.

## 원인 및 수정

실제 직업 정산과 업무 보드 카운터는 이미 가속 머니버스 시간(`현실 600초 = 게임 1일`, `게임 7일 = 현실 70분의 1주`)을 사용하고 있었습니다. 그러나 기존 `work_my_dashboard` 읽기 모델은 실제 `Asia/Seoul` 날짜와 주간 키를 사용했습니다. Production 읽기 전용 점검에서 활성 회원 4명의 현재 게임시간 영수증 합계와 대시보드 값이 실제로 불일치함을 재현했습니다.

새 forward migration `203-work-reset-convergence.sql`은 `work_my_dashboard_v2`를 추가하고, 기존 5개 컬럼 함수는 호환 wrapper로 유지하며, 보상 미리보기도 quota-aware로 통일합니다. 이미 적용된 migration은 수정하거나 번호를 바꾸지 않습니다.

## 통합 전 검증

- Production은 읽기 전용으로만 점검했으며 미병합 migration은 적용하지 않았습니다.
- Test PostgreSQL의 격리 복제 DB에 migration 203을 성공적으로 적용했습니다.
- 실 PostgreSQL Work/clock 회귀: 3개 파일 / 15개 테스트 통과. 현실 10분 day rollover, 70분 week rollover, DB timezone 독립성, 업무/전역 한도, preview·실지급·dashboard 일치, 직업 전환, 멱등성/무결성을 포함합니다.
- DB 패키지 7개, 백엔드 871개, 프론트엔드 612개 테스트 통과. DB 조건부 스위트는 별도 격리 실DB 실행으로 보완했습니다.
- workspace lint 0 error(기존 이미지 최적화 warning 11개), 전체 typecheck, backend/frontend production build를 통과했습니다.

Production 적용 완료 표시는 GitHub CI, exact-SHA 격리 Test QA, main 통합, DB 백업/migration, Production smoke를 모두 통과한 뒤 갱신합니다.


- 모바일 API 계약 버전을 `v2026.09.16.159`로 올렸으며 Work 요약 계약에 권위 있는 게임 일/주간 키와 정확한 초기화 시각을 명시했습니다.
