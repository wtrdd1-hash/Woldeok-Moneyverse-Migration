# v2026.09.16.155 — Casino Browser Runtime Recovery

## User-facing changes

- Casino play no longer crashes the whole page after a bet because client initial state is no longer exported from a Next.js `use server` module.
- The casino route now has a dedicated recovery screen that tells members to verify the server-authoritative recent play history before submitting another bet.
- The casino loading state now mirrors the actual page structure instead of using a generic card skeleton.

## Root cause

Production journal evidence for reference `3286936712@E352` showed Next.js rejecting `frontend/src/app/casino/actions.ts`: a `use server` file exported the `CASINO_IDLE` object and a synchronous re-export. Next.js allows runtime exports from that module only when they are async server actions. The invalid boundary was reached when the browser loaded casino action references.

## Reliability and performance

The production frontend cache was also found owned by `root` while the systemd service runs as `debian`, producing repeated `EACCES` writes in `.next/cache/fetch-cache`. Cache ownership was repaired on the active Debian runtime. This operational repair is independent of the casino code fix and should remain part of release-host hygiene.
