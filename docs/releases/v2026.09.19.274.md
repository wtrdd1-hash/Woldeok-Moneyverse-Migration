# v2026.09.19.274 — Deployment continuity and cache-freshness standard

## Summary

This operational release makes zero-downtime frontend/backend handoff, member-session continuity, and forced application-shell freshness mandatory release gates for every runtime-affecting change.

## Changes

- Require replacement instances to become healthy before the previous Production instance is removed.
- Require member sessions issued before a backend restart to remain valid after restart using the same PostgreSQL `auth_sessions` store and cookie contract.
- Require version-sensitive HTML/bootstrap responses to revalidate so users receive the latest release without manually clearing browser cache.
- Preserve long-lived caching for content-hashed immutable Next.js assets.
- Explicitly forbid using session deletion/revocation as a cache-clearing mechanism.
- Require readiness, session-continuity, exact-SHA freshness, and smoke checks before a restart/rollout is considered complete.
