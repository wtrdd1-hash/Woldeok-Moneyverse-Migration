## 실제 운영 변경
미니PC에서 기존 Spring/Nest/Next 서비스를 중지하거나 재시작하지 않고 Nginx 설정 검사와 reload만 수행. 내부 4400의 관리자 콘솔 보안 및 본인 권한 검사, 공개 80의 동일 API를 실제 DB 세션/역할/관리자 콘솔을 확인하는 Nest로 연결. Spring 고정 역할·가짜 콘솔 `open` 응답을 기존 Next rewrite가 익명에 노출하던 경로도 차단. 기존 요청 쿠키와 인증 헤더를 조작하거나 가짜 권한을 생성하지 않음. DB·원장·거래·금액·Spring JAR·프론트 빌드 모두 변경 없음. 서버의 2단계 원본 설정 백업은 `/srv/moneyverse-data/tasks/incident-stock-20261117/`에 보존.

## 잔여 위험 및 복원
Spring의 익명 세션 성공 응답과 내부 토큰만으로 관리자 권한을 인정하는 구현은 런타임에 남아 있으므로 전체 Spring 인증 경로 별도 P0 감사 필요. Spring 거래정지 정산 SQL 경고도 별도 문제. 이번 운영 패치는 해당 주식 관리자 진입 및 공개 API 권한 우회만 안전하게 차단하였음. 원복 시 신규 include 두 줄만 제거하고 `nginx -t && systemctl reload nginx` 수행하되, 공개 관리 권한 정보가 재노출될 수 있으므로 보안 검토 우선.
