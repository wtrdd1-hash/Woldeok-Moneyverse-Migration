# v2026.10.16.739 — Prevent Unintended SEO Indexing from Test and Shadow Backends

**Status: code candidate; runtime promotion pending security and full UI/finance release gates.** [한국어](v2026.10.16.739.ko.md)

## Defect
During the independent v738 financial-guard Test shadow backend verification, an existing `SeoCronPingService` scheduled a live IndexNow/Google submission 30 seconds after boot without checking Test mode or a positive indexing opt-in. Its logs reported 39 URL submissions. The temporary shadow instance was stopped and its installed unit removed; official Test and Production remained unchanged.

## Fix
- `SeoCronPingService.onModuleInit` now refuses to schedule in `NODE_ENV=test` even if SEO indexing is enabled. Outside Test it schedules only if `SEO_INDEXING_ENABLED=true`, defaulting to off.
- Track both the initial 30-second timeout and repeating 6-hour interval, cleaning up both via `OnModuleDestroy`.
- No changes to curated blog editorial content, financial database or member money, sessions, release pointers, or SEO manual submissions.
- Focused Vitest: 4/4 PASS, testing Test opt-in rejection, Production default-off, explicit Production opt-in and destroy cancellation. CI and final build tracked by GitHub PR.

## Remaining restrictions
- Do not assume the earlier 39 submissions were indexed by Google; the evidence is only log-reported submission.
- Active public Production v717 and Test v735.2 are unaffected until a permitted exact-SHA release.
- Finance/ledger app grants, 19 uncertified balance projections and full authenticated 166-route × 5 UI Test acceptance remain separate P0 deployment blockers.
