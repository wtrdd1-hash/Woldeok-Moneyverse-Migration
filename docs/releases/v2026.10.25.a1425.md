## User-visible change in Draft PR #1284
The /tools Mega Jackpot card no longer invents personal tickets, purchases, historical draws, HMAC evidence, burned WLD or paid prizes. It now requests up to 12 actual public lottery round records from PostgreSQL through Nest GET /api/v1/lottery/rounds and Next GET /api/lottery/rounds. Android GET /app-api/v1/lottery/rounds is routed through the existing gateway. On a missing or malformed record the API returns 503; on a confirmed empty set the UI shows an empty state. Recorded jackpot pool is labelled as a DB record, not a payout. No purchase action is offered.

## Financial, security and privacy boundaries
No new migration, no account balance mutation, no ticket issuance, no burn, no settlement, no PII response. All WLD values are integer strings; DB writes remain denied for the app role in isolated PostgreSQL. Actual lottery purchase and settlement require the separately reviewed P0 issue #1283.
