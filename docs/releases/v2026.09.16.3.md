# v2026.09.16.3 — Watchlist discovery controls

## User-facing change
- The member-only stock watchlist can now be searched by stock symbol or name.
- Saved stocks can be ordered by recently saved, day change, current WLD price, or name.
- Search and sort are represented as `q` and `sort` URL parameters, so a filtered watchlist view survives navigation/reload and can be bookmarked.
- A distinct no-results state lets members clear filters without confusing it with an empty watchlist.

## Integrity
- Filtering is read-only and actor-scoped through the existing authenticated watchlist endpoint.
- Price and percentage ordering use `BigInt`; no integer-string price is converted to floating point.
- No database schema, migration, ledger, trade mutation, idempotency, authorization, or Production data path changed.

## Validation/promotion
- GitHub CI and exact-SHA candidate validation are required before staging.
- Staging must verify authenticated search/sort combinations, URL persistence, no-results/reset behavior, responsive/accessibility behavior, private noindex policy, and exact candidate SHA/image parity before merge or Production promotion.
