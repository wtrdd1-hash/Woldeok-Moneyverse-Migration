# v2026.10.21.1061 — Bond subscription refusal and mobile layout incident (candidate)

## Summary
A user reported an HTTP 500 `internal server error` while attempting a one-unit KTB-05Y subscription (100,000 WLD) on mobile. Four backend receipt logs and a read-only account query showed that the wallet cash available to this API was only 51,351 WLD. The existing repository treated an ordinary insufficient-balance refusal as an untyped Error, which the production ProblemFilter correctly sanitized to a generic 500; the user could not distinguish that refusal from infrastructure failure.

## Fix scope
- Convert the insufficient WLD balance refusal to a typed HTTP 409 conflict, preserving the transaction rollback and cash invariants.
- Validate units as a strictly positive safe integer before any database connection. Return HTTP 400 for invalid quantity and HTTP 404 for missing bonds; subscription-closed and exhausted-unit refusals are HTTP 409.
- In the web subscription form, reject a quantity above the displayed available units and keep all calculations integer-based.
- Make the mobile form title wrap without colliding with Cancel; arrange the three holdings/Repo/guide tabs in one column on narrow viewports rather than squeezing them into three clipped columns.
- Add database-transaction mock regressions covering rollback on insufficient funds, rejection before connecting, and preservation of true infrastructure faults.

## Data, migration and risk boundaries
- No schema migration, permission grants, balance change, coupon run, purchase, or production ledger mutation was made for this fix.
- **P0 NOT RESOLVED:** the existing bond service directly mutates `account_balances`, `system_treasury_vaults`, and bond inventory instead of using an auditable Economy Core journal transfer and an idempotent purchase receipt. A correct error code does not validate the rest of the settlement path. Full financial reconciliation, idempotency and isolated authenticated transaction testing remain mandatory before claiming bond settlement safety.
- The read-only wallet balance is a snapshot and may change; never assume the member has enough funds without rechecking on the authoritative transaction boundary.
