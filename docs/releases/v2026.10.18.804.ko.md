# v2026.10.18.804 — 불변 원장 테이블 직접 권한 축소

**상태:** 금융 보안 개선 후보. 실제 운영 애플리케이션 v717 유지, 기초잔액 19건 인증 미완료. [운영 기록](../worklog/2026-10-18-ledger-privilege-v804.md).

## 위험과 조치
실제 운영 DB의 `moneyverse_app`은 핵심 `ledger_transactions`, `ledger_postings`에 직접 `INSERT/UPDATE/DELETE/TRUNCATE/TRIGGER/REFERENCES/MAINTAIN`이 가능했다. 앱 계정 침해 시 검증된 정산 경로를 우회하거나 원장 기록을 훼손할 위험이 있다. 실제 운영 v717 컴파일 코드와 최신 소스는 두 테이블을 조회하지만 직접 수정 SQL은 발견되지 않았다.

신규 번호 `277-core-ledger-app-privilege-lockdown.sql`은 한 트랜잭션에서 두 원장 테이블의 앱 직접 권한을 모두 회수하고 **SELECT만 다시 허용**한다. 기존 `SECURITY DEFINER` 정산 함수·소유자 권한은 변경하지 않으며 WLD, 회원 잔액, 원장 행을 수정하지 않는다. 직접 잔액 쓰기 이관이 필요한 `accounts`, `account_balances`, `system_treasury_vaults` 권한은 이 단계에서 바꾸지 않는다.

## 검증
소스 TDD RED→GREEN, DB 패키지 9건 통과·3건 스킵. 기존 운영 백업 SHA256을 확인하고 **회원 데이터 없이 스키마·권한만** 격리 PostgreSQL 17 DB로 복원해 원래 과도한 권한을 확인했다. 마이그레이션 정상 적용·반복 적용 통과, 이후 두 테이블 SELECT 허용 및 INSERT/UPDATE/DELETE/TRUNCATE 차단 확인. 원장 범용 함수는 migrator 소유 SECURITY DEFINER로 유지되며 앱의 해당 범용 직접 EXECUTE는 기존에도 제한돼 있다.

## 남은 조건
운영 DB 권한 반영은 CI와 배포 후 실제 증거로 별도 기록한다. DB 권한 축소만으로 운영 앱 코드가 갱신되는 것은 아니다. 다른 핵심 금융 3개 테이블 직접 DML, 19계좌 +4,779,188 WLD의 기초잔액·전표 불일치, 전체 인증 UI·세션·실복원은 여전히 별도 승격 차단 항목이다.
