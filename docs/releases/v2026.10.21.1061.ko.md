# v2026.10.21.1061 — 국채 청약 오류 안내·모바일 겹침 수정 (개발 후보)

## 요약
모바일 KTB-05Y 1좌(100,000 WLD) 청약에서 HTTP 500 `internal server error`가 발생한 화면을 조사했다. 백엔드 요청 로그 4건과 읽기 전용 사용자 현금계좌 조회에서 청약 API의 사용 가능 잔액이 51,351 WLD로 확인되었다. 기존 코드는 잔액 부족 시 일반 `Error`를 던지고 운영 오류 필터는 이를 포괄적인 500으로 감춰 실제 실패 이유를 알려주지 않았다.

## 변경 범위
- 청약용 WLD 잔액 부족은 트랜잭션 ROLLBACK 유지 후 HTTP 409로 반환한다.
- 청약 좌수는 1 이상 안전한 정수만 허용(HTTP 400). 국채 없음은 404, 청약 마감·잔여 좌수 부족은 409 처리.
- UI에서 남은 발행 좌수 초과를 청약 요청 전에 차단하고 WLD 계산은 정수로 유지한다.
- 모바일 제목·취소 버튼 충돌을 제거하고 내 보유 채권/Repo/안내의 3개 탭을 모바일에서 한 열로 배치한다.
- 잔액 부족 ROLLBACK, 잘못된 좌수 사전 차단, 실제 DB 오류 보호를 단위 테스트로 추가한다.

## 검증
- RED 7개 중 6개 실패 확인 후 GREEN 국채 저장소/서비스 및 ProblemFilter 23개 통과.
- Nest 백엔드 빌드, Next 프론트 운영 빌드, 양측 타입 검사 통과.
- 변경 파일 ESLint 오류 0건, 기존 UI 경고 16건.
- 최종 diff 및 배포 검증 결과는 작업 종료 기록에 별도 반영한다.

## 데이터 및 미해결 P0 위험
- 사용자 잔액, 국채, DB 스키마, 운영 API는 본 변경 과정에서 수정하지 않았다.
- **금융 무결성 미해결:** 기존 국채 가입 구현은 `account_balances`와 국고 잔액을 복식부기 원장 경유 없이 직접 갱신하며, 중복 구매 방지 식별키도 없다. 오류 코드 개선과 원금 정산의 안전성은 별개의 문제다. 별도 원장 우선 교체 및 실제 Test 금융 원장 대사가 필요하다.
- 잔액 51,351 WLD는 검사 시점 스냅샷이며 이후 변동 가능하다.
