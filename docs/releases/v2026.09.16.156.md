# v2026.09.16.156 — Casino Play Contract and Dice UX Repair

## User-facing changes

- Coin and dice stakes are now submitted as JSON numbers, matching the authoritative casino API DTO instead of being rejected as numeric strings with HTTP 400.
- Dice parity and exact-number games now have a dedicated visual play stage, live server-result state, and an in-flight rolling cue consistent with the coin-flip experience.
- Casino animations remain presentation-only: outcome and settlement continue to come exclusively from the server receipt.

## Root cause

`AmountInput` intentionally posts a formatted text value. `wholeAmount()` normalized that value to a string, and the coin/dice server actions forwarded the string directly as `stake`. The backend casino DTO deliberately rejects numeric strings because implicit conversion is disabled. Therefore a valid UI stake such as `10` reached `/api/v1/casino/dice/plays` as `"10"` and failed validation with HTTP 400, which the generic action error mapper rendered as “입력한 내용을 다시 확인해 주세요.”

## Contract correction

Casino play actions now use `wholeNumber()` for their bounded play stake. It strips display separators, requires a positive safe integer, and sends a JSON number. The backend and database continue to enforce policy min/max, daily limits, outcome generation, idempotency, and settlement. No odds, payout, ledger, or database migration changed.
