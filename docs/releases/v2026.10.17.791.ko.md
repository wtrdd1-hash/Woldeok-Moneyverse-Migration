# v2026.10.17.791 — 호스트 릴리스의 프론트엔드 빌드 SHA 일치 강제

**상태:** 별도 소스 수정 후보. 새로운 Test/운영 앱 승격이 아님.

## 원인
v790 완료 후 읽기 전용 확인에서 공개 Test의 소스 SHA는 `4997cf2b1f84c15f3ed5817d75ed5d85b560776c`였지만, 실제 Next `.next/BUILD_ID`는 `1792212026459`. 실제 호스트 빌드 동일성 검사에서 `ok=false`, `frontend_artifact_sha_mismatch` 확인. `/status`와 `/api/version`이 HTTP 200이어도 정식 릴리스 수용 증거가 아님.

## 수정
`ops/release/stage-host-release.sh`가 Test/운영의 불변 릴리스 디렉터리를 생성·복사하기 **전에** Next `.next/BUILD_ID`가 승인 소스 40자리 SHA와 완전히 일치하는지 확인. `BUILD_ID`를 빌드 시 전달하지 않으면 Next가 시간값을 만들기 때문에 그 산출물의 승격을 차단한다. 현재 파일/릴리스 포인터/환경설정/서비스는 변경하지 않음.

Git은 소스만 추적하고 `backend/dist`, `frontend/.next`는 별도 빌드 산출물인 테스트 픽스처로 수정. 잘못된 빌드 ID를 통과시키던 기존 코드에서 RED 확인, 수정 후 GREEN. 릴리스 단위 테스트 **56개 통과, 실패/스킵 0**, Bash 구문·공백 검사 통과.

## 남은 조치
정확한 승인 소스로 `BUILD_ID=<40자리 SHA>` 등 배포 빌드 변수를 전달해 **새 불변 Test 릴리스**를 준비하고, 실제 frontend artifact/manifest/백엔드/세션/공개 버전·인가 부정 테스트 검증. 기존 `.next/BUILD_ID`를 수동으로 덮어 쓰거나 버전만 속이지 않음. 금융 P0와 v530 인증 전체 UI가 해결되기 전 운영 승격 금지.

GitHub PR/CI 최종 결과 별도 기록. 후보 Test·운영 승격 미실시. DB·원장·마이그레이션·기능스위치 변경 없음.
