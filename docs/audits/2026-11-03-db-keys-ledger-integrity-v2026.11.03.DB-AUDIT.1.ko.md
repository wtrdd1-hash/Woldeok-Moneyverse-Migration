## P1/P2: 관계 키·보존·성능·관측성
- `national_pension_accounts.user_id`, `pension_funded_positions.user_id` 등 일부 금융 `user_id`에는 `users(id)` FK 부재. 과거 연금 계좌는 현재 0건이라 실제 고아 데이터 존재가 입증된 것은 아님.
- 과거 연금 납입/지급 로그의 `account_id` FK는 **ON DELETE CASCADE**. 상위 계좌 삭제가 금융 감사기록을 지우지 않도록 보존 정책 설계 필요.
- 단일 열 FK **167개**가 해당 참조 열을 선두로 하는 유효 인덱스 없음(금융 관련 이름 22개). 성능 병목으로 단정하지 말고 실제 플랜·잠금/크기 확인 후 후보별 판단.

- 핵심 원장은 PostgreSQL 무제한 `NUMERIC`로 오버플로 우려가 상대적으로 적음. 다만 국고 금액 `TEXT`, 일부 부가 금융 `BIGINT`/`NUMERIC(20,0)`가 공존하므로 JS Number 사용·정수 문자열/BigInt 경계 시험 필요.

- `moneyverse_migrator`가 SUPERUSER임. 운영 자격증명과 실행 권한을 비밀 노출 없이 점검할 것.
