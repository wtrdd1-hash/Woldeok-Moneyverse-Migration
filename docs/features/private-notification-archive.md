# Private notification archive snapshot — candidate A0751 (RELEASE HOLD)

**Not available in Production.** This candidate adds an authenticated, owner-bound snapshot endpoint `GET /api/v1/notifications/archive-snapshot`, a private CSV route `/account/notifications/notifications.csv`, a conditional accessible download action and Android app-api parity at `GET /app-api/v1/notifications/archive-snapshot`.

The response is `{ "notifications": [...], "complete": true }` only if all retained rows fit in a single 101-row bounded read. A 101st record rejects with HTTP 409 instead of silently truncating the archive. This is neither a permanent audit history nor a WLD reward receipt. No client-supplied user ID is accepted; the backend derives the actor from its authenticated session and existing consent guard. The CSV route checks the current viewer, validates each field and date, neutralizes spreadsheet formulas and control bytes, and returns private/no-store/noindex/nosniff headers. Android preserves the session cookie and receives private/no-store/noindex JSON.

**Blocking source-of-truth finding:** The isolated PostgreSQL 17.11 `wdmv_v761_test_acl` database has 281 migrations but lacks `public.in_app_notifications` and all `notification_%` functions. The existing main notification service already references this absent table. No additive migration was created because main ends at migration 279 and the isolated database contains unmerged 280/281. A separate reviewed migration stack and complete official Test verification are prerequisites. The UI hides the download action when the authoritative snapshot is unavailable. Do not merge or promote this candidate while the source is absent.
