# 퀘스트

[English](quests.md) | **한국어** | [문서 색인](../INDEX.ko.md)

퀘스트는 반복 작업 위에 구성된 활동 계층으로 일일 이벤트, 초반 진행 단계, 성장 목표를 포함합니다.

## 설계 목표
퀘스트는 시스템이 실제로 수행할 수 있는 효과만 설명해야 합니다. 아직 구현되지 않은 미래 기능을 현재 제공되는 보상처럼 UI에서 약속해서는 안 됩니다.

## 일일 이벤트
일일 이벤트 청구는 데이터베이스 기반이며 멱등성을 가져야 합니다. 이벤트 청구는 WLD, EXP, 아이템 또는 구현된 임시 효과를 지급할 수 있습니다. 9월 게임플레이 감사에서는 실제 기능이 없던 `pending_effect` 설명을 제거하고 실제 WLD/EXP/아이템 보상은 유지했습니다. 내구도나 실제 계약이 없는 보너스 같은 기능은 구현 전에 제공되는 것처럼 표시하지 않습니다.

## 마켓 세일 이벤트
완전한 효과 계약의 예시는 다음과 같습니다.
1. 회원이 이벤트를 청구합니다.
2. 현재 서울 날짜 기준으로 청구를 기록합니다.
3. 대상 초보 도구 카탈로그 가격을 10% 할인합니다.
4. 상점 읽기 모델과 구매 함수가 같은 실효 가격 규칙을 사용합니다.
5. 날짜 경계에서 효과가 종료됩니다.

이렇게 하면 상점이 표시한 가격과 실제 결제 가격이 다른 문제를 막을 수 있습니다.

## 초반 성장
초반 단계는 별도의 보상 체계를 임의로 만드는 것이 아니라 제품의 주요 루프를 학습하도록 설계합니다. 진행 상태는 지갑, 프로필, 상점, 작업, 수집 활동과 연결될 수 있습니다.

## UX 규칙
- 청구 완료, 사용 가능, 사용 불가 상태를 구분합니다.
- 성공적으로 청구하면 즉시 갱신합니다.
- 효과 종료 시점을 설명합니다.
- 원장에는 청구됐는데 스피너가 계속 돌아가 미청구처럼 보이게 하지 않습니다.
- 실제 구현된 혜택처럼 읽히는 임시 문구를 사용하지 않습니다.
