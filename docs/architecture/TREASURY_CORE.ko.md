# 국고 코어 — 단일 정식 복식원장 금전 처리 경계 (v2026.11.01.1618.2)

## 원칙
정책상 자금과 실제 집행 가능한 WLD를 구분합니다. 국고 코어 `public.treasury_core_post(행위자,멱등키,명령,정확한 WLD 정수)`는 신규 국민연금 적립·환급을 정식 거래 `economy_post_transaction`으로 연결해 단일 DB 트랜잭션에서 잔액·양쪽 분개·Outbox·불변 감사 영수증을 만듭니다.

## 돈의 소유권과 보관
- 회원 `USER_CASH`: 실제 회원 지갑, 잔액 음수 금지.
- `ESCROW:national_pension_fund`: 신규로 정식 납입한 연금 재원만 보관. 최초 0, 초과 지급 금지.
- `ESCROW:national_pension_welfare`: 조기 환급 때 실제 원금 5%를 별도 보관. 가짜 국고·발행 또는 소각으로 처리하지 않음.
- `TREASURY:treasury`: 현재 정식 국고 0 WLD. 옛 국고 552/배당 744 기록은 자동 인증 금지.
- `MINT`: 별도 공식 발권 권한·통화량 증빙 전에는 국고 코어에서 추가 발권 불가.

## 권한·증빙
Nest가 로그인 세션에서 행위자 UUID를 확보하며 회원이 직접 행위자를 지정할 수 없습니다. 일회용 CSRF 필수. DB는 SECURITY DEFINER·고정 검색 경로, 앱은 명령 EXECUTE만 가능하고 보관액/영수증 직접 수정 금지. 같은 요청 멱등키 반복 시 같은 거래·영수증을 돌려주고 다른 금액으로 재사용하면 거절. 회원·통화정책·최소 적립 1000 WLD·충분한 실제 지갑과 에스크로 금액을 DB에서 검사합니다.

새로운 연금 적립액은 기존 미검증 `national_pension_accounts`와 분리합니다. 238건의 옛 연금 지급을 소급 생성하지 않으며, 과거 재원도 신규 에스크로로 임의 편입하지 않습니다.

## 기능별 적용 상태
- 국고: 기존 회계기 독립 대사 유지. 신규 연금 에스크로와 현재 국고 보관금 혼동 금지.
- 국민연금 신규 납입/신규 적립금 95% 환급+5% 실제 복지 에스크로: SQL·백엔드·BFF·UI 구현, 실제 운영 미승격.
- 과거 연금 정기지급, 공기업 배당, SWF, 채권 집행, 조폐국·중앙은행 신규 발권: **정식 재원/발행증서/별도 승인 없어 차단 유지.**

## 운영 승격 조건
기존 운영 초기화 SQL314/회원 잔액/백업 보존. 실제 격리 PostgreSQL에서 결제·재시도·동시 실행·부족잔액·대사·영수증 변조·롤백·큰 정수 검증, 공식 Test 정확한 SHA/회원 세션/CSRF, 그 뒤 무중단 운영 승격과 최종 공개 실행 검증 필요. **SQL 적용이나 단위 테스트만으로 실제 금융 증명 완료를 선언하지 않음.**
