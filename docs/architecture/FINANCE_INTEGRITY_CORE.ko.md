# 금융 무결성 코어 v2026.11.03.1701

## 단일 원장과 계층
모든 WLD 원본은 PostgreSQL 복식부기 원장 하나다. 국고·유저·은행·주식 코어가 따로 돈을 보관하지 않는다. 인증된 도메인 함수가 공통 economy_post_transaction을 호출하고, 새 finance_integrity_assert_and_record가 요청/저장 분개 완전 일치, 차변/대변 0 합계, 계정별 이전 잔액 + 변동액 = 이후 잔액을 검증한다. 분개·잔액·이벤트·JSON 증빙은 단일 DB 트랜잭션으로 모두 성공하거나 모두 롤백한다. JSON에는 요청 해시, 거래 ID, 계정별 전후 잔액, 정확한 정수 문자열과 SHA256 해시를 저장한다.

## 외부 접근 금지
새로운 공개 HTTP 금융 코어 API·포트는 만들지 않았다. moneyverse_app과 PUBLIC은 원장 원시 함수·증빙 기록·대사 함수·증빙 테이블 직접 접근이 거부된다. moneyverse_reconciler만 내부 집계 검사를 할 수 있다. 원장/증빙 UPDATE·DELETE·TRUNCATE 금지. DB 네트워크 방화벽·인증·내부 서비스 인증도 별도 확인해야 실제 외부 침입 차단이 완성된다.

## 적용 범위
SQL329 이후 공통 원장 함수를 거친 신규 거래에만 적용된다. 과거 증빙을 가짜로 만들지 않고, 기존 차이는 조사 경고만 띄우며 임의 보정하지 않는다. 원장 함수를 우회하여 잔액/국고 보조장부/주식 포지션/대출 등을 변경하는 레거시 함수는 별도 통합 필요하다. DB 내부 SHA256은 독립 서명 증명이 아니다. 신뢰 분리된 서명 백업이 필요하다.

## 확인 및 승격
격리 PostgreSQL 17.11에서 가상 거래 5건·도메인 4종, 큰 금액 정밀도, 재요청·실패 롤백, 수정/삭제 금지, 강제 불일치 탐지, 외부 역할 접근 거부 통과. 운영 DB 스키마·공식 Test 백엔드·독립 복원·CI·운영 승격은 별도로 검증하기 전까지 완료로 보고하지 않는다.

**네트워크 확인:** 실행 중인 개발 DB가 호스트 0.0.0.0:5433에서 수신 중이었다. compose.yml은 127.0.0.1 전용으로 수정했으나 타 개발 작업 보호를 위해 실행 중 컨테이너를 재생성하지 않았으므로 실제 네트워크 바인딩 조치는 후속 배포 검증이 필요하다.
