## 180개 PNG 색상 전수 분석

**방법:** 미니PC에서 README의 180개 파일 목록을 파싱하고 실제 PNG를 Pillow로 열어 각 332×198로 축소, HSV 색조·채도·명도 기반으로 고채도 강조 픽셀의 청록/파랑 계열과 보라 계열을 구분. 기준: 채도 > 0.26, 명도 > 0.30, 최대/최소 채널 차이 > 55, 청록/시안 hue 0.38–0.57, 보라 hue 0.68–0.84. **색상 경향을 분류한 것으로 WCAG 인증이나 모든 청록색 사용 금지 판정은 아님.**

|---|---:|---|
| 관리자 | 40 | 시안 40개 모두 청록/시안·블루 |
| 금융 | 27 | 시안 27개 모두 민트/청록 |
| 금융 도구·계산기 | 37 | 시안 37개 모두 밝은 시안·블루 |

금융에서 실제로 검증된 이익·정상 상태를 녹색으로 표시하는 것은 허용되나, 지갑·은행 로고/히어로 윤곽선/범용 차트까지 상태와 무관하게 청록 브랜드로 바꾸는 것은 공식 지침과 충돌한다.

## 디자인 자체의 더 큰 결함: 템플릿 복제

Pillow로 PNG들을 **동일한 415×248 해상도로 축소한 후 RGB 픽셀 완전 일치율** 계산:

- `wallet.png` ↔ `bank.png` **99.51%** 일치.
- `bank.png` ↔ `bank-savings-pot.png` **99.31%** 일치.
- `wallet.png` ↔ `wallet-activity.png` **99.33%** 일치.
- `wallet.png` ↔ `stocks.png` **99.52%** 일치.

이는 **이미지 반복도**이며 애플리케이션 코드나 실제 이용 가능 기능의 중복률이 아니다. 주요 패널은 공통 잔액/예시 증감/진행 상태/가짜 차트/최근 기록/빠른 작업으로 사실상 똑같다. **은행 상품 선택, 예금·출금 입력/확인/완료, 포켓별 목표·입금·인출, 잔액 부족·실패 영수증 등 화면별 전용 디자인이 충분히 보이지 않는다.**

- `12,580 WLD`, `+2.41%` 등의 반복 값은 예시일 뿐 실잔액·실수익률이 아니다.
- `admin-bank.png` 등 40개 일반 관리자 시안은 청록 계열인데, 별도 11월18일 관리자 PC/모바일 참고 이미지 두 개는 네이비·보라 중심으로 **같은 날짜 내부에서 충돌**한다.
- 1660×990 합본에 PC·휴대폰 모형이 나란히 그려진 사실은 실제 320px 반응형, 200% 확대, 5개 언어, 키보드 접근성 통과 증거가 아니다.
- 기존 인계서에도 11월18일 원본이 사용자 대화에서 처음 승인받은 고화질 이미지와 **픽셀 단위 동일함은 확인되지 않았다**고 기록됨. 이를 최종 원본으로 단정 금지.

## 현재 코드·운영 화면과의 구분

- Spring 공통 `mv-theme-nov18.css`의 브랜드 보라 토큰은 올바른 기준이지만 은행 Spring 정적 HTML에는 오래된 파랑·녹색 장식도 남음. 스타일 파일의 존재만으로 전체 180개 실제 웹 화면이 디자인과 일치한다고 볼 수 없음.
- 2026-11-23 익명 운영 `GET /bank` HTTP 200 확인. 로그인 후 실제 운영 입출금 동작 및 전 화면 시각 QA를 통과한 것은 아님.
- 관련 은행 인증·입출금 원장 결함은 기존 문서 감사 초안 PR #3368에 따로 기록되어 있다.
