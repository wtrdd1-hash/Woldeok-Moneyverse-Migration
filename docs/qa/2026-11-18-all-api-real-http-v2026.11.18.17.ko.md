## 실제 실행 증거
- 격리 Spring QA 서버 4611 OpenAPI: **경로 903개, HTTP 작업 정의 982개** — GET 578 / POST 340 / PUT 28 / DELETE 22 / PATCH 10 / OPTIONS 2 / HEAD 2. 목록에 존재하는 API는 기능 합격과 다르다.
- **실제 GET 요청 520회:** HTTP **200 270건 / 401 210건 / 503 38건 / 500 1건 / 406 1건**. 인증 미제공 401은 정상 방어일 수 있다. 금융 근거 부족 503은 의도된 안전 차단일 수 있다. 406은 JSON Accept와 text-only 정적 경로의 미스매치다.
- 격리 서버에서 비정상 인증 값의 추가 읽기 검증 **130회: 401 110건 / 200 20건**. URL 문자열로 추정한 민감 경로에는 원래 공개된 API도 포함될 수 있어 20건 전부를 취약점으로 단정하지 않는다. 운영 Spring의 일부 관리자 조회에서는 별도 권한 검증 결함을 확인했으나 악용 재현 방법과 응답 내용은 공개하지 않는다.
- **공식 Test 경로 18개 중 16개 HTTP 502**, `/health`, `/api/version`만 200. 이 둘은 운영 Spring 포트 4550으로 전달하므로 독립 Test 가동의 증거가 아니다. Test 공통 업스트림 포트 3101은 해당 시각 리스너가 없었다.
- **운영 경로 18개:** HTTP 200 13 / 404 4 / 406 1. 200만으로 DB·원장·인증 정상 여부는 확정할 수 없다.
- **Android 앱 API 게이트웨이:** 운영 `/app-api/v1/` 대표 GET 네 경로는 응답 코드 200이지만 필수 JSON이 아닌 **HTML**, 공식 Test는 502였다. Android Retrofit 정적 정의 **158개 중 Spring 경로 직접 일치 0, 가정한 접두어 변환 후 method+path 일치 59, 불일치 99**. 단순 경로 비교이므로 별도의 BFF 구현 여부와 앱 런타임 동작까지 부정하는 근거는 아니다.

**안전 점검 사실:** 연금 GET이 계좌를 생성할 수 있다는 사실은 운영 비교 GET 요청을 1회 이미 보낸 뒤 소스에서 발견했다. POST/PUT/PATCH/DELETE 및 금융 명령은 의도적으로 실행하지 않았으나 이 GET으로 **DB 변경이 발생했는지 확인되지 않았다**. 발견 즉시 해당 운영 GET의 추가 요청을 중단했다. 따라서 이번 시험의 모든 GET을 무조건 무변경 시험이라고 표현하지 않는다.
