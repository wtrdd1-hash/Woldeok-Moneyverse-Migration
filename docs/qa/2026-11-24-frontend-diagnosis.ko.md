### D01 · P1 · 실행 JAR과 표시 SHA가 다름

### D02 · P1 · 메뉴·허용 목록과 실제 화면 핸들러가 불일치

Test의 `/shop`, `/board`, `/quests`, `/account`는 ingress와 프론트엔드 직접 요청에서 모두403이다. 실제 백엔드는 같은 경로에200 HTML을 반환한다. 즉 이 사례의 차단은 외부 방화벽 전체 장애가 아니다.

현재 통합 소스의 `UnifiedFrontendApplication`은 이 경로들을 GET 허용 목록에 넣었으나, DB 없는 프론트엔드의 `MemberPresentationPageController`는 wallet/bank/stocks/support/chat만 매핑한다. 누락된 화면의 오류 처리도 `anyRequest().denyAll()` 경계에 걸려 빈403으로 나타난다. `/community`, 청년도약 계산기 상세 경로 등은 별도 연결이 없다. 사이드바·빠른 실행에 노출된 기능과 서버 화면 계약이 다르다.

지갑·은행·일부 관리자 화면의 **302 로그인 이동은 비로그인 상태에서 정상 보호 동작**이다. 이를 누락 화면403과 구분한다. 로그인 후 실제 역할별 동작은 별도 검증해야 한다. [세 경계 비교](2026-11-24-frontend-diagnosis-boundaries.json).
