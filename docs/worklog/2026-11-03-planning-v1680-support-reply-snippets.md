### Existing source and purpose (verified vs proposed)
- **Verified existing:** `frontend/src/app/admin/support/admin-support-view.tsx` has three hardcoded `CANNED_RESPONSES` (lines 59–74) and inserts their literal text into the **unsent** `replyText` composer (around line 596). `backend/src/support/support.controller.ts` provides administrator inbox/messages/reply/status endpoints. Migration `196-user-admin-support-chat.sql` stores `support_threads`/`support_messages` and does not create an administrator-owned snippet catalog. No durable per-admin snippet CRUD was identified. This is an enhancement to an existing composer, **not** a claim that no canned responses exist.
- **Purpose / target:** authenticated support administrators repeatedly type specialized safe replies; permit up to **20 personal, editable snippets per administrator**, without replacing the three built-in presets. Operator productivity and consistent wording are the objective, not automated decisions, priority, moderation or financial changes.
- **Non-goals:** no shared/global snippet library, no auto-generated AI content, no variable interpolation, no member-authored snippets, no automatic sending, no automatic case-status changes, no member notifications, no attachments, no WLD/stock/ledger writes. Feature flag `admin_support_personal_snippets` defaults **OFF**.

### Roles, entry points, screen states and actions
- Only a current administrator with a valid session, consent and recent administrator step-up can GET or mutate **their own** snippets. Nest `SessionGuard`, `AuthenticatedGuard`, `ConsentGuard`, `AdminGuard`, `AdminSessionGuard`; CSRF on writes. Server derives actor from verified session, never client-supplied UUID. DB function independently checks current administrator role and owner; coordinate role-revocation locking so a revoked operator cannot complete a concurrent write. Superuser is not a bypass for cross-owner access.
- Entry: `/admin/support` reply composer → **Saved replies** → **Manage my replies**. Built-in three presets stay available when the flag is OFF. Saved list: own title, last-updated time, Insert, Edit, Delete; create with title (1–60 Unicode code points, trim and NFC-normalize) and body (1–2,000 Unicode code points, trim and NFC-normalize). Reject control characters other than line breaks and tabs in body; reject HTML/script markup execution, do not interpolate `{{name}}`, account data or tokens. Max 20 active, casefolded unique title per operator. No auto-save of a drafted case reply into snippets.
- **Insert** copies plain text into the **unsent** composer at caret or appends with a separator; never calls `adminSupportReply`, never changes thread status, and never overwrites nonempty draft without an explicit choice. The administrator reviews/edits and separately clicks the existing Send CTA. Create/Edit/Delete require explicit confirmation and expose loading, success, 401/403, 409 duplicate/quota, 412 stale revision, 428 missing precondition, 503 unavailable and offline/retry states. On stale 412, refresh and show current value; never silently overwrite. Distinguish built-in read-only presets from personal editable snippets; feature-OFF hides personal management without affecting existing presets.
- Mobile: responsive 320px, keyboard and screen-reader support (WCAG 2.2 AA), focus return after dialog, descriptive buttons and live-region errors, 44px targets, reduced-motion support, localized date/time and content labels. Android/member endpoints must never list personal administrator snippets, including through generic app-api proxy or cached account switch.

### Exact proposed API and transport (NOT IMPLEMENTED)
- `GET /api/v1/admin/support/snippets` → 200 `{scope:'CURRENT_OPERATOR',items:[{id,title,body,revision,updatedAt}],limit:20}`, ordered `updated_at DESC,id DESC`. Built-in presets remain frontend constants, not DB records. Empty array means verified empty only after authorized successful read.
- `POST /api/v1/admin/support/snippets` → 201 `{id,title,body,revision:1,updatedAt,replayed:false}`; body strictly `{title,body}`; required UUID `Idempotency-Key` and CSRF. `PATCH /api/v1/admin/support/snippets/:id` → 200 with strict `{title,body}`, UUID key and strong `If-Match: "<revision>"`; `DELETE /api/v1/admin/support/snippets/:id` → 200 `{id,deleted:true,revision,replayed:false}`, UUID key and strong If-Match. No request-supplied owner or revision field; reject unknown fields. Delete is soft until policy-approved retention/erasure.
- Required error semantics: 401 no session, 403 no current administrator/step-up, 404 missing or other owner's snippet (indistinguishable), 409 duplicate title/quota or same-key changed payload, 412 stale strong revision, 428 missing precondition, 400 invalid content, 503 dependency/DB unavailable. Fail closed on DB permission failures. All responses including errors: `Cache-Control: private, no-store`, `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: no-referrer`; no public SEO, sitemap, canonical, OpenGraph or snippets in server logs. Next BFF must preserve CSRF, If-Match, Idempotency-Key and private cache policy; do not leak `INTERNAL_API_TOKEN`.
- Idempotency receipt binds authenticated actor, method, target ID or CREATE, API version, normalized title/body and expected revision via keyed HMAC; same-key/same-payload returns immutable original outcome with `replayed:true` and **no current-resource ETag**; same-key/changed payload returns 409 even after deletion. No second audit or quota consumption on replay. HMAC key ID, rotation and retention/tombstone policy require security approval; do not promise replay protection after lawful erasure.

### Forward-only PostgreSQL, transactions, authorization and deletion
- Proposed `support_admin_reply_snippets`: `id uuid PK`, `owner_id uuid NOT NULL REFERENCES users(id)`, `title text NOT NULL`, `body text NOT NULL`, `revision bigint NOT NULL CHECK(revision>=1)`, `created_at/updated_at timestamptz NOT NULL`, `deleted_at timestamptz NULL`. Validate normalized title/body bounds in DB; partial unique index `(owner_id,lower(title)) WHERE deleted_at IS NULL` with documented Unicode casefold limitations; owner+updated_at DESC,id DESC index filtered to active. Immutable receipt table with `UNIQUE(owner_id,idempotency_key)`, method/resource/version/fingerprint/original outcome, key_id, created_at, expiry and tombstone policy. Audit event stores actor, snippet ID, operation, revision, timestamp, not raw body or title.
- Use a **new unique migration number** after checking concurrent developers (never edit migration 196 or checksum history). Revoke ALL table grants from PUBLIC/`moneyverse_app`; expose only bounded `SECURITY DEFINER` functions with `SET search_path=pg_catalog,pg_temp`, schema-qualified relations, PUBLIC EXECUTE revoked, explicitly granted app EXECUTE. SQL role check is not a substitute for HTTP session actor binding. Count quota and create under a serialized owner lock; PATCH/DELETE lock target row and compare strong revision; audit+receipt+mutation commit atomically. Role-revoke/owner-erasure must coordinate lock order and cascade/anonymize only per approved retention policy. Do not add direct app-role table grants.
- Admin audit: actor-only own snippet changes and aggregate operational counts; no member PII in snippets, logs, analytics or audit. Enforce content privacy, retention policy, lawful deletion and backup retention review before rollout. No automated policy change or moderation action.
