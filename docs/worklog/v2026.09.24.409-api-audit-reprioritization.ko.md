## 작업 시작 기록

현재 API 문서에 서로 다른 인벤토리 수치가 존재해 감사를 시작했다. 기계 판독 모바일 계약은 179개 endpoint를 포함하고, 모바일 전체 명세는 backend 57 controller / 335 endpoint / mobile 179 endpoint를 적고 있으며, 구형 endpoint catalog는 아직 mobile 139개를 표기한다. v402 소스 탐색 기록에는 별도로 58 controller file / HTTP decorator 361개가 존재한다. 이 수치들은 동일한 계산 방식이라고 간주하지 않는다.

최신 main CI 증거도 확인했다. 직전 runtime-check는 API contract 검증 완료 전에 ESLint 오류로 실패했으므로, 현재 main exact SHA에서 API 계약 검증이 끝까지 통과했다는 수용 가능한 증거는 아직 없다.

## 기획 결정

구현 우선순위를 generated contract 권위와 위험도 중심으로 재지정한다.
1. 필수 CI 게이트 복구
2. exact candidate SHA에서 API 계약 생성 및 검증
3. method+path 기준 권위 인벤토리 확정 및 전체 API 문서 정합화
4. 인증·인가, CSRF, 최근 재인증, 멱등성, 동시성, 오류 계약 감사
5. 돈/상태를 변경하는 고위험 mutation API 우선 검증
6. 실시간/채팅 및 모바일·웹 BFF 정합 검증
7. exact-SHA Test E2E
8. 모든 blocker 종료 후에만 Production 승격 허용
