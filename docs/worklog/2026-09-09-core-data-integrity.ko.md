# 2026-09-09 — 핵심 데이터 무결성 강화

## 상태

`hardening/data-integrity-20260909` 브랜치 / PR #138에서 진행 중입니다. 운영 배포와 `main` 병합은 CI 및 테스트 서버 검증이 끝날 때까지 보류합니다.

## 작업 범위

이번 변경은 서비스 경제 및 영속 계정 데이터의 데이터베이스 무결성 경계를 강화합니다.

### 구현 내용

- 계정/잔액 완전성을 보장하기 위한 지연 PostgreSQL 제약 트리거 추가
- 원장 트랜잭션의 차변/대변 균형 검증 추가
- 원장/잔액 불일치, 음수 잔액 정책, 유효하지 않은 제약조건·인덱스, 보호 테이블 권한 회귀를 점검하는 읽기 전용 데이터 무결성 검증 게이트 추가
- 마이그레이션 직후 CI에서 무결성 게이트 실행
- 데이터베이스 무결성 계약 및 운영 검증 절차 문서화

## 데이터 무결성 영향

마이그레이션은 추가형이며 정상적인 다중 SQL 문 트랜잭션이 완료된 뒤 불변조건을 검사할 수 있도록 지연 검증을 사용합니다. 이 변경 후보 자체에는 운영 데이터 직접 변경이 포함되지 않습니다.

## 이 작업의 문서화 규칙

이 작업에도 프로젝트 공통 문서화 규칙을 적용합니다. 구현 내용, 검증 결과, 테스트 서버 배포, 운영 배포, 최종 완료 상태를 작업내역서와 Release/CHANGELOG 문서에 기록해야 작업 완료로 간주합니다. 개발자용 공식 문서는 영어를 기준으로 하고 한국어 번역본을 함께 유지합니다.

## 검증 기록

- CI: 완료 전 현재 실행 결과를 이 문서에 기록
- 데이터베이스 마이그레이션 검증: 완료 전 결과 기록
- 데이터 무결성 게이트: 완료 전 결과 기록
- 테스트 서버 검증: 운영 배포 전 필수
- 운영 검증: 운영 배포 후 최종 완료 처리 전 필수

## 배포 게이트

1. 검증 중에는 `main`을 직접 변경하지 않습니다.
2. 작업 중 `main`이 변경되면 최종 검증 전에 최신 변경을 동기화하고 충돌/차이를 조정합니다.
3. CI, 마이그레이션, 무결성 검사를 통과합니다.
4. 테스트 서버에서 실제 동작을 검증합니다.
5. 검증된 리비전을 운영에 배포합니다.
6. 운영 환경의 데이터 무결성과 서비스 상태를 다시 확인합니다.
7. 최종 결과를 이 작업내역서와 Release/CHANGELOG에 반영합니다.
8. 검증된 작업을 `main`에 통합하고 작업 브랜치를 정리합니다.

## 완료 상태

아직 완료 전입니다. 최종 커밋 SHA, 테스트 서버 결과, 운영 배포 결과, Release/CHANGELOG 참조를 이 문서에 추가한 뒤 작업을 종료합니다.
