# v2026.09.16.136 — 브랜치 자동 충돌 해소 및 정리

## 목표
통합 파이프라인의 최종 목적을 브랜치 정리로 고정한다. 검증 완료, 병합 충돌, 병합 완료 뒤에 개발 브랜치가 계속 쌓이지 않도록 자동으로 처리한다.

## 변경사항
- 성공한 `Build Test Candidate` 뒤 이벤트 기반 실행은 유지하고, 예약 통합의 보조 주기를 1시간에서 15분으로 단축했다.
- 이미 `main`에 완전히 포함된 관리 대상 브랜치는 자동 삭제하며, 해당 브랜치의 열린 PR도 함께 닫는다.
- 충돌 상태의 관리 대상 PR은 현재 `main`을 기준으로 자동 재조정한다. 충돌 부분은 최신 `main`을 우선하는 `git merge -X theirs origin/main` 전략을 사용한다.
- 재조정으로 브랜치 HEAD가 바뀌면 즉시 병합하지 않고, 새 exact HEAD SHA에 대해 `Build Test Candidate`를 다시 통과해야만 다음 자동 통합에서 병합된다.
- 재조정 결과 트리가 `main`과 동일해지면 PR을 닫고 브랜치를 즉시 삭제한다.
- 충돌이 없고 exact-SHA 검증을 통과한 PR은 기존처럼 squash 병합 후 원본 브랜치를 삭제한다.
- 별도 브랜치 정리 워크플로는 main push / PR close 이벤트 외에도 30분마다 실행하며, main에 포함된 브랜치의 오래된 열린 PR을 닫고 브랜치를 삭제한다.
- `planning/*`, `release/*`, `staging`, `production`, `develop`, `main`은 자동 충돌 해소 및 자동 삭제 대상에서 제외한다.

## 안전 및 배포 게이트
자동 충돌 처리는 검증을 우회하지 않는다. 재조정으로 HEAD가 바뀐 브랜치는 반드시 그 exact SHA로 다시 빌드·테스트한다. 운영 승격은 최종 통합된 `main` 후보가 기존 isolated Test / exact-SHA 백엔드 게이트를 통과해야 한다.

## 현재 적체 브랜치 처리
이전 `branch-auto-promotion` 구현은 v2026.09.16.134~136에 의해 대체되었으므로 재병합하지 않고 닫고 삭제한다. 나머지 기능/보안 브랜치는 자동 재조정 → exact-SHA 검증 → 병합 → 원본 브랜치 삭제 흐름으로 처리한다.
