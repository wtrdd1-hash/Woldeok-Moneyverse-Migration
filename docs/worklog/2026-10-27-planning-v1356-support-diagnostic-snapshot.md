### F675-146 purpose and actual gap
A member troubleshooting an issue cannot attach a safe, bounded, structured environment snapshot to an existing support thread: current `frontend/src/app/support/page.tsx` has subject/body/reply only; `backend/src/support/support.controller.ts` has thread/message endpoints; migration `196-user-admin-support-chat.sql` contains only support_threads/support_messages and no diagnostic receipt. Do **not** silently capture browser data or call this an existing feature. Goal: reduce avoidable clarification rounds without exposing secrets. Audience: authenticated consenting member, and a currently authorized operator viewing the same support case. This is distinct from F675-141 private image evidence, F675-142 triage, F675-143 internal notes, F675-144 templates, F675-145 help center, and #1522 engineering.

### Member journey, explicit consent, states
Entry `/support?thread=<uuid>` → existing thread → **Optional diagnostic snapshot** card. CTA **Preview safe details**, **Review exactly what will be sent**, **Attach to this case**, **Cancel**, **Remove snapshot**. No collection on page load, chat submission, login, or help article click. Preview is client-only and editable: browser family from an enum (Chromium/Firefox/WebKit/Other), platform class (desktop/mobile/tablet/other), viewport bucket (small/medium/large, not exact pixels), web app release identifier from a server-approved release manifest, and self-selected issue area (login/wallet/shop/community/other). Explicit opt-in checkbox is unchecked and tied to each snapshot and a visible policy version. No IP, GPS, exact URL/query/hash, cookies, Authorization headers, access/refresh tokens, session IDs, raw User-Agent, localStorage, account/wallet balance, personal messages, screenshots, stack traces, device fingerprint, arbitrary text fields or request headers. Never send automatic error logs. Browser compatibility uncertainty displays UNKNOWN instead of invented values.
States: CLOSED, PREVIEW_LOCAL, CONSENT_REQUIRED, REVIEW_READY, SUBMITTING, VERIFYING_RECEIPT, ATTACHED, UNKNOWN_COMMIT, EXPIRED, REMOVED, FORBIDDEN, OFFLINE, ERROR. Only verified server receipt permits ATTACHED. On thread switch, logout, account switch, consent withdrawal or role loss, clear preview and fence stale requests. Keyboard-only, screen reader, 320px and 400% zoom, WCAG 2.2 AA; focus/error summary and no diagnostic payload in live-region announcements. Android native client must use its own allowlist and explicit consent; never forward OS identifiers.

### API, schema and transaction contract (engineering proposal, NOT deployed)
Member `POST /api/v1/support/threads/:id/diagnostics` (CSRF + session + consent + owner), `GET /api/v1/support/threads/:id/diagnostics?cursor=`, `DELETE /api/v1/support/threads/:id/diagnostics/:snapshotId` (withdraw/remove); operator `GET /api/v1/admin/support/threads/:id/diagnostics` with live operator role + admin session; approver-only/server_operator-only must deny. App API parity must preserve identity and response semantics, not expose admin route. Requests: `{idempotencyKey:uuid, policyVersion:known_enum, acknowledged:true, snapshot:{browserFamily,platformClass,viewportBucket,appRelease,issueArea}}`; reject unknown keys, nested values, free-form strings, malformed enums, unsupported policy, >4096 UTF-8 bytes with 422. Response `{snapshotId,threadId,createdAt,expiresAt,state,receiptId,contentDigest}`; digest is a server-side canonical allowlist SHA-256, never a fingerprint of device. GET is owner scoped, bounded <=50 with HMAC cursor bound to member/thread/filter/snapshot and short TTL; errors never masquerade as empty.
Add additive `support_diagnostic_snapshots` (id uuid PK, thread_id FK ON DELETE CASCADE, owner_user_id FK, policy_version, allowlisted jsonb, payload_sha256, idempotency_key uuid, state ACTIVE/REMOVED/EXPIRED, version bigint, created_at, expires_at, removed_at) and append-only `support_diagnostic_events` (id, snapshot_id, actor_id, event_kind, event_at, receipt_digest), with UNIQUE(owner_user_id,idempotency_key), CHECK JSON object+exact keys+strict enum constraints and immutable payload; partial index `(thread_id,created_at DESC,id DESC) WHERE state='ACTIVE'`, expiration index `(expires_at,id) WHERE state='ACTIVE'`. Retention target 30 days **provisional pending privacy/legal approval**; scheduled expiry with auditable tombstone and independent backup-retention review. No new arbitrary device identifiers.
Use narrowly granted SECURITY DEFINER functions with pinned search_path, REVOKE EXECUTE FROM PUBLIC, no direct `moneyverse_app` table DML, verify real session-bound actor and current thread ownership or current operator capability at DB boundary; do not trust caller-supplied UUID/GUC. Lock order thread → snapshot → receipt; validate actor after lock; same key+same canonical digest returns same receipt, same key+different digest =>409, concurrent duplicate must recover unique-conflict by reread, not 500. Insert snapshot+immutable event+receipt in one PostgreSQL transaction; audit failure rolls back all. DELETE is idempotent tombstone; no accidental support message, WLD, ledger or feature-switch mutation. Never infer commit success from lost HTTP response: UNKNOWN_COMMIT → receipt lookup. 401 expired session, 403 role, 404 non-owner, 409 key conflict, 422 validation, 429 rate limit, 503 audit/DB unavailable. `Cache-Control: private, no-store`, `Vary: Cookie`, no CDN or indexing.

### Security, administration, SEO, metrics and release
Operator sees **Diagnostic snapshot (member-consented)** in `/admin/support` with exact allowlisted fields, consent timestamp, expiry, removal state; no export, bulk download, cross-case search or copy to public reply by default. Treat snapshot as untrusted plain data; escape output, CSP, rate-limit <=10 snapshots/member/thread/day and <=3/minute, cap payload and total storage, log only action/status/receipt ID, never raw snapshot. Legal review of access/deletion/export and privacy notice required before enable; no automatic disclosure of internal support notes. Admin aggregated counters only (opt-in preview→submit, verified attach, expiration, failures), k-anonymity threshold >=20, no per-device telemetry. SEO noindex/nofollow on support and diagnostics; robots and sitemap must exclude. Mobile reduced motion, localization parity, offline safe retry, screen reader announcements.
Test with isolated PostgreSQL: 10,001 synthetic snapshots for pagination/expiry, 100 same-key concurrent submits, 100 forged owner/operator/expired-session attempts, consent OFF, malformed payload, unsupported release, 409 reuse, audit failure rollback, DB/HTTP response loss, deletion vs read, restore with expired rows, retention job and Android parity. Verify no leakage to public help/chat/SEO/logs, no ledger/WLD deltas, no PII. Stage: feature `support_diagnostic_snapshot_v1` OFF → isolated migration/ACL review → authenticated exact-commit-SHA official Test, security/a11y/perf, independent encrypted backup restore → approved GitOps canary → gradual enable. Rollback disable flag and stop writes; preserve auditable tombstones and avoid destructive down-migration. Any audit, ACL, consent or privacy failure keeps OFF.
