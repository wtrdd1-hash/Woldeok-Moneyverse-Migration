## Root cause / middle evidence — 01:04–01:14 KST
1. `/admin/market` rendered **HTTP 200 without cookies** at the actual public edge (`Host: easy-scraping.com`, forwarded HTTPS). The page's `requireMember()` trusts a status-200 session response; `Spring AuthController.session()` returns HTTP 200 and a random CSRF-looking field even with *no resolved session*.
2. `Spring AdminSecurityController` answers `consoleSession.state=open` and fixed `admin/superadmin` roles whenever `AdminAuthService` sees the server-to-server transport token; that token is not proof of a caller's identity, role or open admin session. Thus Next's `requireAdminConsole` falsely passes.
3. Nginx 4400 already routes `/api/v1/admin/stocks` and `/api/v1/admin/stocks/*` to authoritative Nest port 4500. Nest correctly requires a real session, role and console; contemporaneous market requests returned HTTP 401, and the evidence-parsing UI showed unavailable data. Spring does not implement `stocks/dynamics` or `stocks/market-events` (404 on Spring direct). The Spring stock halt settlement receipts also log a distinct SQL warning, not established as this page's cause.
4. Official Test backend on `:3100` was stopped (public Test auth API 502). Restarted only the existing `test-main-backend.service`; it now reports `/health` 200, `/api/version` 200, unauthenticated `/api/v1/auth/session` 401, and privileged `/api/v1/admin/security` 401; test market ticker/schedulers report disabled. Test frontend remains live at :3101. No real administrator session credentials were acquired or fabricated.

## Narrow remedy — isolated branch
`fix/stock-admin-auth-v2026.11.17.1` from refreshed `origin/main` adds `ops/nginx/stock-admin-auth-bridge-v2026.11.17.1.conf`, for inclusion inside **localhost-only 4400 server**. Three precise authenticated boundaries (`/api/v1/admin/security`, its child paths, `/api/v1/admin/me`) now use Nest's existing token + DB session + roles + console checks. No global authentication routing, no arbitrary user impersonation, no DB migration, no stock creation, no ledger access, and no Spring runtime replacement. This explicitly preserves legacy read safety and other concurrent Spring conversion work.
