### 소스 확인 및 신규 설계 위험
- 마이그레이션 196에는 비연쇄 사용자 외래키를 가진 support_threads/support_messages가 있으나 개인 재확인 알림 테이블은 없다. AdminSupportController는 목록·메시지·답변·상태 변경만 제공하고 Session/Authenticated/Consent/Admin/AdminSession 가드 아래 requireUserId(req)에서 행위자를 얻는다. SQL의 관리자 역할 검사는 전달된 UUID를 HTTP 세션에 독립적으로 결속하지 않는다. 임의 행위자 호출과 역할 회수 직렬화는 해결된 사항이 아니라 P0 선행 조건이다. v1676의 관리자·문의별 비공개 알림 1개, 활성 최대 20개, 회원 비노출, 기본 OFF는 유지한다.
- **과거 재실행 결과는 현재 리소스 상태가 아니다.** 동일 키 재시도는 나중에 알림이 해제·변경됐더라도 최초 PUT/DELETE 결과를 돌려준다. 과거 리비전을 현재 상태의 ETag처럼 반환하거나 과거 기한을 현재 화면에 반영하면 잘못된 정보를 표시한다. 재실행 응답은 replayed:true, originalRevision, 최초 결과와 상태 코드를 보존하되 현재 상태를 보증하는 ETag는 **제공하지 않는다**. currentStateVerified:false, Replay-Status: replayed, Cache-Control: private,no-store를 사용하고 UI는 권한 검증된 GET을 새로 호출한 후에만 알림 카드를 갱신한다. 새 쓰기·감사 이벤트 중복·새 기한 검증은 하지 않는다. 신규 정상 변경만 강한 현재 ETag를 반환하며 Next BFF도 이 구분을 보존한다.
- **요청 정규화·HMAC 키 교체 계약이 부족하다.** 불변 영수증에는 인증된 관리자 UUID, 대상 문의 UUID, HTTP 메서드, API 계약 버전, 강한 선행 리비전, UTC 초 단위 기한(DELETE는 null)을 결속한다. 알 수 없는 필드와 소수 초를 먼저 거부한다. 서로 다른 RFC3339 오프셋이라도 동일한 절대 시각이면 같은 의미의 요청으로 처리하고, 동일 actor/key에서 작업·대상·실제 시각이 다르면 409를 반환한다. HMAC 키 식별자와 이전·신규 키 검증 기간을 명세하며 키 교체를 이유로 기존 영수증을 임의 재해시하지 않는다. 비밀키·문의 본문을 로그에 남기지 않는다. 승인된 보존기간 밖의 영구 재실행 보장은 불가하며 최소 키 재사용 방지 tombstone, KEY_EXPIRED/409 처리 및 보존·법적 보류 정책 승인을 선행한다. 합법적으로 삭제된 영수증 이후 영구 차단을 약속하지 않는다.
- **시각·DST 검증 기준을 명확히 한다.** 변경당 하나의 DB 기준 시각을 캡처해 15분~30일(양끝 포함) 검증과 asOf에 공통 사용하고, 초 단위로 정규화한 UTC 입력과 명시적으로 초 단위 절삭한 DB 시각을 비교한다. DB 마이크로초 때문에 정확히 15분인 요청이 간헐적으로 실패하면 안 된다. RFC3339 오프셋은 절대 시각을 식별하지만 IANA 시간대는 알 수 없으므로 서버가 DST의 존재하지 않는 지역 시각을 판별했다고 주장하지 않는다. UI는 선택한 IANA 시간대의 DST 공백·중복을 확인하고 중복 시각을 명시적으로 구분한 뒤 오프셋 포함 시각을 만든다. 기한 도래·예정 목록은 DB 단일 SQL 스냅샷으로 판정하고 브라우저 시계로 저장 상태를 결정하지 않는다.
- **측정하지 않은 확인 행위를 KPI로 주장하지 않는다.** 기한 도래 목록을 열었다는 사실은 관리자가 문의를 검토했다는 증거가 아니다. 기존 '기한 확인 완료' KPI를 '기한 도래 목록 조회'로 수정하고, 인증된 1차 서비스 이벤트가 별도로 기록될 때만 '기한 목록에서 문의 열기'를 집계한다. SLA 준수·해결 시간 개선은 추정하지 않는다. 20명 이상 집계만 제공하고 행위자·문의 ID·제목은 외부 분석에 보내지 않는다.
