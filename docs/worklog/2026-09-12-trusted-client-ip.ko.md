# 2026-09-12 — 신뢰 클라이언트 IP 보안 수정

업데이트 버전: `2026.09.12-10`

## 발견 사항

`requestClientKey`는 `CF-Connecting-IP`를 우선했지만 해당 헤더가 없으면 같은 배포 스위치 아래에서 `X-Forwarded-For` 첫 항목을 신뢰했습니다. 프론트엔드도 `X-Forwarded-For`를 내부 API로 전달하고 있었습니다. 이는 저장되는 원본 IP가 신뢰 프록시 체인에서 확정되어야 한다는 기획 요구사항과 맞지 않았습니다.

## 작업 순서

1. 최신 V2 기획서와 구현 계획을 다시 확인했습니다.
2. `origin/main`에서 별도 worktree와 `fix/trusted-client-ip-v2026.09.12.10` 브랜치로 작업을 격리했습니다.
3. 백엔드 IP 식별에서 `X-Forwarded-For` 사용을 제거했습니다.
4. 신뢰 엣지 IP와 소켓 IP를 Node `net.isIP`로 검증하도록 했습니다.
5. 프론트엔드의 두 내부 API 경로 모두 `X-Forwarded-For` 전달을 중단했습니다.
6. 보안 테스트를 갱신하고 집중 검증을 수행합니다.
7. 후보를 푸시하고 CI/테스트 후보 빌드 후 정확한 SHA를 테스트 서버에 배포해 백엔드를 검증한 다음에만 운영으로 승격합니다.

## 롤백

해당 애플리케이션 커밋을 되돌리고 기존에 검증된 불변 이미지 SHA를 정상 GitOps 절차로 다시 승격합니다. 스키마나 저장 데이터는 변경하지 않으므로 데이터베이스 롤백은 필요하지 않습니다.
