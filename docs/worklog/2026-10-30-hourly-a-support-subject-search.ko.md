## 결함과 수정

회원 문의 화면에는 상태 선택만 있고 제목 검색이 없었다. 기존 실패 테스트를 재현한 후 `q`(1~80자)와 선택적 `status`를 결합하는 검색을 구현했다. SQL은 바인딩 변수를 사용하고 `support_my_threads(회원,100)`에서 최근 100건만 대상으로 검색하여 최대 50건을 반환한다. `%`·`_`는 와일드카드가 아닌 일반 문자다. 잘못된 상태, 중복 배열, 제어문자, 초과 길이는 DB 조회 전에 거부한다. 검색 결과에 없는 대화 ID로 추가 메시지 조회를 수행하지 않는다.

웹은 접근 가능한 GET 검색 입력과 검색 범위 안내를 제공하고 필터를 링크에 보존한다. Backend 및 Android app-api는 `private, no-store`·`noindex`를 강제한다. 기존 본인 전용 PostgreSQL 함수만 사용하며 신규 마이그레이션, 금융 원장 변경, 권한 확대, WLD 변동은 없다. 롤백은 코드 되돌리기로 가능하다.

## 검증과 배포 제한

Backend·Frontend RED 테스트를 재현하고 대상 Backend 7건, 웹·Android 6건을 통과했다. 외부 포트를 열지 않은 격리 PostgreSQL 17.11에서 304/304 SQL 적용, 합성 108건, 회원별 격리, 일반 문자 검색, 최근 100건 상한 및 테이블 직접 조회 차단을 확인했다. 전체 CI·공식 Test 정확 SHA 인증 E2E·금융/백업 검증이 통과하지 않으면 병합과 운영 승격을 금지한다. 기존 국고·Frontend SHA P0 문제 및 다른 개발자의 PR은 그대로 보존한다.
