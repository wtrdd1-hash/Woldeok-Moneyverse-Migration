# 디스코드 OAuth 세션 충돌 수정 — v2026.11.17.5 (작업 기록)

## 작업 전
- 2026-11-17, 운영 로그인 화면의 `oauth_state` 오류 신고. 통합 기획, AGENTS, GEMINI, 릴리스 절차 및 실제 Node/Spring/Next/Nginx 구성을 확인.
- 변경 시작 시 GitHub `main` `cd822aa098d16a6f8bbfa5e41cf721eb1594e767`. 별도 브랜치·워크트리 사용. 재검토 중 동일 `main` 유지 확인.
- 자금·DB·계정 정보·인증 비밀값은 변경하지 않음.

## 원인 재현 / 중간 기록
- Spring 사전 로그인은 `mv_session`을 발급하지만 Nest는 `__Host-mv_session`을 우선 읽음. 두 쿠키가 공존하면 OAuth 요청 생성 및 반환 시 세션이 달라짐.
- 운영 HTTPS의 익명·가상 인증 취소로 재현: 정상 단일 쿠키에서는 `oauth_cancelled`, 유효한 과거 호스트 쿠키와 새 Spring 쿠키가 공존하면 `oauth_state`. 실제 인증 코드·상태·토큰·개인정보는 로그에 기록하지 않음.
- 수정 범위는 OAuth 시작/완료 시점에 한정. 시작 시 새 Spring 세션 발급 사실이 확인되면 오래된 호스트 쿠키만 제거하고, 정상 로그인 성공 시 Nest가 새 호스트 쿠키를 발급했을 때 이전 Spring 쿠키만 제거함. 계정 연결·추가 인증·오류는 무조건 초기화하지 않음.
- 테스트 우선 작성: 초기 모듈 누락으로 RED, 구현 뒤 4개 Node 보안 회귀 + 4개 실제 Next 라우트 통합 테스트 PASS. TypeScript 검사 및 전체 프론트엔드 빌드 PASS.

## 운영 전 검증
- GitHub CI, 독립 Test 실행/쿠키 회귀, 실제 HTTP 동작, 기존 사용자 세션 영향 및 무중단 롤백 가용성 확인 전까지 운영 승격 미완료.
- 운영 실제 디스코드 사용자 동의 및 계정 로그인까지 완료했다는 증거는 아직 없음.

## 2차 중간 검증
- 별도 Next 테스트 포트에서 로그인 화면 200 및 익명 OAuth 취소 콜백 확인. `/health` 직접 경로는 Next 소유가 아니므로 404; Nginx/API 헬스와 구분.
- 실제 HTTP 응답에서 `Max-Age=0`이 정규화 과정에 누락되어 빈 쿠키가 남을 수 있는 문제 발견. 운영 변경 없이 보완.
- 삭제 헤더에 `Expires=Thu, 01 Jan 1970 00:00:00 GMT` 추가. 테스트에 만료일 조건을 넣어 RED 2건 → GREEN 8건 통과.
- 새 빌드의 실제 HTTP에서 과거 쿠키 제거가 입증되기 전 운영 승격 보류.
