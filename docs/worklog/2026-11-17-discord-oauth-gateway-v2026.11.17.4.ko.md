# 디스코드 OAuth 게이트웨이 장애 수정 — v2026.11.17.4

**기준일:** 2026-11-17 KST

## 시작 및 원인
- 운영 `/auth/discord/authorize` 요청이 Discord가 아닌 `/login?error=oauth_login`으로 돌아오는 현상을 재현함.
- 프론트엔드는 모든 인증 요청을 내부 게이트웨이 4400으로 전달하지만, 인증 시작·콜백 경로가 Nginx에 명시되지 않아 기본 Spring 4550(404)으로 전달됨.
- 기존 Node 4500에는 해당 인증 경로가 존재하며 비인증 접근에 401을 반환함. 별도 운영 Node와 Spring 서비스는 활성 상태임.

## 변경 범위
- 내부 Nginx 4400 서버에서 Discord·Google의 authorize/callback 네 경로만 Node로 프록시함.
- 쿠키와 PKCE/state 처리는 기존 애플리케이션이 담당하며 새 인증 우회나 DB 변경 없음.
- Spring 기본 라우트, 사전 로그인, 로컬 계정, 금융 API는 변경하지 않음.
- OAuth code/state가 로그에 기록되지 않도록 해당 내부 경로 access_log를 비활성화함.
