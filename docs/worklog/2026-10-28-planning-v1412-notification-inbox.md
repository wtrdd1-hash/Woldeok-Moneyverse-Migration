**Purpose, target, entry and observed gap.** For signed-in, consented members, /account/notifications must display only server-authoritative messages and truthful unread state. Both are example strings, not proven ledger entries. Local React state handles click/read-all, so it can report success without any DB write. The page already includes a real engagement notification preference form; preserve it, do not confuse the setting with the actual inbox. This is verified source behavior, NOT proof that real members saw a financial incident. The development DB currently has zero in_app_notifications rows, so a truthful empty state is required.

**Existing integration and nonduplication.** NestJS notification.controller.ts already exposes GET /api/v1/notifications, GET /unread-count, POST /:id/read, POST /read-all-receipt, and disabled POST /claim-all (409). Next.js app/api/notifications/route.ts already exposes authenticated GET/POST BFF with no-store. Reuse these paths; do not invent a second inbox, a second unread counter or a reward claim. The current BFF GET forwards limit and unreadOnly but not offset or category. Current repository query is owner-filtered direct SELECT with ORDER BY created_at DESC only. Separate event producers and plans F675-152 security, F675-153 balance threshold, F675-157 support replies remain independent; only display genuinely persisted records. Never imply an in-app notification is a ledger settlement.

**User flow, CTA and states.** Entry /account/notifications → tab All/Business/Bank/Season/Space/Security/System → live list with validated category, title, plain-text body, created time and read state. CTA: Open linked destination (only validated internal relative paths), Mark read, Mark all read, Load older, Retry, Reset filter; preserve existing Receive/Stop goal alerts form. Explicit loading, empty (no fake sample), offline, unauthenticated, consent-required, invalid category, expired cursor, rate-limited, stale session, DB unavailable and action-failure states. Mark-read confirmation only after server receipt; optimistic UI must roll back on error. Badge is server unread count, never count of local mock items. Do not silently mark items read merely by viewing the list. Mark-all receipt must distinguish affectedCount from remainingUnreadCount and acknowledge concurrency.

**API contract and permissions.** Backward-compatible GET /api/v1/notifications?category=BUSINESS|BANK|SEASON|SPACE|SECURITY|SYSTEM&unreadOnly=true|false&limit=1..50&cursor=opaque; legacy offset support remains until callers migrate. Response {items:[{id,category,title,body,link,isRead,readAt,createdAt}],nextCursor,hasMore,unreadCount,observedAt} with stable field casing defined in DTOs. Unknown category 400; absent/expired auth 401, missing consent 403, inaccessible item 404, stale cursor 409 or expired 410, throttle 429, dependency failure 503. GET is safe/no CSRF; POST read/read-all retains CSRF and session guards. BFF must forward allowlisted category/cursor/limit without exposing actor IDs, preserve no-store on success and errors, and never convert 503 into a zero-notification success. Android App API must mirror auth, DTOs, error semantics, caching and deep-link safety; implement only after checking its existing adapter rather than assuming a route exists. Bind owner from verified server session, not caller-supplied UUID.

**Database, ACL, transaction and performance.** Development DB read-only catalog: public.in_app_notifications exists with 0 rows; notification_unread_count(uuid) and notification_mark_read(uuid,uuid) exist; moneyverse_app has direct SELECT and UPDATE on the table. No in_app_notifications DDL was found under tracked packages/database in main; establish schema/function provenance and migration checksum parity before adding any forward-only migration. Do not rely on undocumented dev-only schema as a portable baseline. Target least-privilege SECURITY DEFINER owner-scoped read/write functions with fixed search_path, explicit PUBLIC revoke and narrow EXECUTE; DB actor spoofing cannot be solved by accepting an arbitrary p_actor alone, so verify the session-to-DB authorization boundary with negative tests and fail closed. Preserve unique notification id, owner FK, category CHECK/allowlist, dedupe_key scoped uniqueness if present, read_at/is_read consistency, link safety, and explicit retention. Stable keyset ORDER BY created_at DESC,id DESC; apply owner/category/unread filter before LIMIT+1; tie handling and concurrent insert must not imply a durable cross-request snapshot. Validate EXPLAIN (ANALYZE, BUFFERS) with 10,001 synthetic records before creating an index such as (user_id,category,is_read,created_at DESC,id DESC). Existing markAllReadWithReceipt executes separate UPDATE and count statements; require one atomic receipt function or explicitly label remaining count as post-update observation, never promise one snapshot. Do not change ledger/WLD, and keep claim-all disabled.

**Security, abuse prevention and administration.** Escape title/body; reject external/javascript/data URLs and malformed internal paths; disallow sensitive body/actor UUID/cursor in logs, analytics, referrers or cache. Require owner-specific query, authorization, per-account/IP rate limit, strict cursor TTL and session binding, replay/CSRF protection on POST, and logout/account-switch response fencing. Administrator may see aggregate delivery/read/failed counts with small-cohort suppression (k<20), not arbitrary private message bodies or silent mark-read actions.
