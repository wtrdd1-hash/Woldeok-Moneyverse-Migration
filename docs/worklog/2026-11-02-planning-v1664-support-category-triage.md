## API contracts and failure modes

4. Versioned member POST /api/v1/support/threads/categorized with {subject,body,categoryCode,idempotencyKey:uuid}. Return {thread:{threadId,status,categoryCode,categorySource,categoryRevision,createdAt},receiptVersion:1}. Validate JSON content type, exactly one category enum, trimmed NFC subject/body, bounded UTF-8 bytes and UUID; reject unknown fields and duplicate parameters. Same key+same payload returns same receipt; same key+different category/subject/body/actor rejects 409; unique-key race returns one result. Existing POST /support/threads remains untouched until explicitly migrated.
5. Admin GET /api/v1/admin/support/triage?category=&status=&cursor= returns {items:[{threadId,subject,status,categoryCode,categorySource,categoryRevision,lastMessageAt}],nextCursor,hasNext,queueRevision,scope:"RETAINED_CASES",countIsComplete:false}. Fixed page 50+1, DB-owner keyset (last_message_at DESC, uuid DESC), no offset or unbounded COUNT. One MVCC snapshot for queue revision and rows; changed revision → 409 with no partial results. Opaque AES-256-GCM cursor (96-bit random nonce, key-id rotation, admin session+filter binding, five-minute expiry), exact DB microsecond boundary string; tamper 400, expiry 410, malformed upstream HTTP 200 → 503, never an empty success.
6. Admin PUT /api/v1/admin/support/threads/:id/category with {categoryCode,expectedCategoryRevision:decimal-string,idempotencyKey:uuid,reasonCode:taxonomy_error|member_clarification|routing_fix}; result {threadId,categoryCode,categoryRevision,categorySource:"admin_reclassified"}. Require recent admin session and CSRF, compare-and-swap category revision under row lock. Same key/same payload returns original receipt, different payload rejects 409; simultaneous admins: exactly one wins, other 409 with refresh CTA. A same-category no-op does not increment revision or forge an audit event.
