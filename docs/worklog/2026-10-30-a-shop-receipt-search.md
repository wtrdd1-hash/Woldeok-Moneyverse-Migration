# Development A — owner-private shop receipt search (2026-10-30 05:25 KST)

Status: **P1 targeted verified; full release HOLD**. Baseline `62c6cd038951d65c94b709302bdaec6e75b080b6`.

The existing `/shop` member receipt widget showed only the latest 30 receipts, with no search. This change adds an accessible, debounced item-name search across the **latest 100 owner-scoped purchase receipts**, using the existing `shop_list_my_purchases(actor, 100)` SECURITY DEFINER read model. No new table grant, migration, write command, payment mutation, or whole-history claim. The default unfiltered read remains the latest 30. The 80-codepoint query rejects arrays, control bytes, and overlong input; matching is case-insensitive. Exact amount strings are never coerced to JavaScript numbers.

NestJS `GET /api/v1/shop/purchases?q=` enforces session and consent guards, validates input before the database call, and maps invalid input to HTTP 400. Next.js `GET /api/shop/purchases?q=` rejects duplicates, returns 503 instead of fabricating an empty history when the backend is unavailable, and sets private/no-store/noindex. Android `/app-api/v1/shop/purchases?q=` forwards the session and query, overrides upstream cache headers, and adds noindex. The UI differentiates a transport failure from a genuine empty result and prevents stale responses from replacing newer search results.
