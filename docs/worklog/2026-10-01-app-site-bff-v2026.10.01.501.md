## Security ruling: Play Integrity
- Repository audit found no backend Play Integrity verifier/requestHash validator.
- A new RED test proved that a raw attacker-controlled token would otherwise pass an enabled presence-only gate.
- v501 therefore does **not** treat raw `x-play-integrity-token` as a verified verdict. When `APP_API_INTEGRITY_ENFORCEMENT=true`, an integrity-marked route fails 403 if evidence is missing and fails 503 `app_integrity_verifier_unavailable` even when raw token text is present, until a real server verifier exists.
- With enforcement disabled, the token may still be forwarded as untrusted evidence for future server verification; it is not authorization.
