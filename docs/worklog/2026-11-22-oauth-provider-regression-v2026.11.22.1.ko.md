## 작업 전 — 최초 증거 및 보호
- 사용자는 Google 로그인을 삭제하라고 지시하지 않았으며, 현재 Google 로그인 버튼 누락 및 Discord 로그인 실패를 보고했다. 검토한 통합 정책에서 삭제 승인 근거가 발견되지 않았다. 확인하지 못한 과거의 모든 대화를 부정하는 뜻은 아니다.
- 공유 원본 `main`은 `768d932b202fbd506e5b0692bf4a38d1f5af1ef6`; 다른 작업자의 Spring UI 파일이 이미 스테이징되어 있으므로 리셋·수정·커밋하지 않는다.
- 기존 Next UI의 `login-providers-view.tsx`는 Google/Discord를 모두 지원한다. Spring `mv43/auth.html`은 Discord 링크와 Google 이용 불가 안내를 표시한다.
- 최초 Spring 인증 템플릿 작성 커밋 `ac12a17328` (11월 20일 14:32 KST, Git 작성자 `wtrdd1-hash`)에서 이미 Google 이용 불가가 나타난다. `2ac581b24f` (15:15)로 통합됐고, `88b70b90d7` (17:04, Git 작성자 `Hong Jong-hwan`)의 파일 전체 변경에서도 유지됐다. 현재 `git blame`만 보고 최초 도입자를 잘못 특정해서는 안 된다.
- Spring 공급자 목록 API는 Google을 `enabled=true`로 표시하지만 실제 `OAuthController`는 Google 인가·콜백이 완성되지 않았다. 기능 상태 불일치.
- Spring 4550은 실행 중이고 로컬 `/login`은 200이나 Google 로그인 링크가 없다. 로컬 Nginx에서 Discord OAuth 인가 경로의 403을 확인했으나 현재 운영 브라우저의 실패 원인으로 확정하지 않는다.
- 11월 17일 기록에는 이전 게이트웨이 경로 및 세션 쿠키 충돌 문제가 남아 있다. 과거에 경로 테스트가 통과했다는 사실은 현재 Discord 실제 계정 로그인 성공을 입증하지 못한다.
- MCP 감사 로그 백업 및 소규모 조회는 `Invalid string length`로 실패했다. 실패한 백업·감사를 성공으로 표시하지 않는다.
- OAuth 설정·외부 응답 로그에서 별도의 보안 민감 위험 발견. 실제 비밀값과 민감한 본문은 공개 보고서에 절대 기록하지 않는다.
