# v2026.09.14.70 — 이메일 인증 전달 안정화

## 범위
운영 회원가입 인증메일이 잘못 입력된 수신 도메인 때문에 반송된 사례를 기준으로 자체 이메일 회원가입 흐름을 보강했습니다.

## 변경 사항
- 확실성이 높은 대표 메일 서비스 도메인 오타만 회원가입 생성 전에 차단하고 교정 주소를 안내합니다.
- 정상 주소와 알 수 없는 사용자 정의 도메인은 임의로 교정하지 않습니다.
- 표시용 `From`과 반송용 envelope sender를 분리할 수 있도록 `SMTP_RETURN_PATH`를 지원합니다.
- SMTP 실패 시 수신자 도메인과 SMTP 원인만 기록하고 인증 토큰, 자격증명, 전체 이메일 주소는 로그에 남기지 않습니다.
- 운영 SMTP가 동작하지 않으면 기존처럼 503으로 실패해 인증메일이 발송됐다고 잘못 안내하지 않습니다.

## 검증
- 백엔드 테스트: 849개 통과, 테스트 DB URL이 없어 DB 의존 테스트 353개 건너뜀.
- 백엔드 TypeScript 검사: 통과.
- 격리 Test 및 Production 승격은 저장소의 GitHub Actions/GitOps 배포 체인을 그대로 통과해야 합니다.

## 운영 참고
DKIM은 애플리케이션 코드만으로 완료할 수 없습니다. 현재 relay에 OpenDKIM 키 마운트는 있으나 활성 키가 확인되지 않았으므로 mail relay selector/키와 DNS 공개키 설정이 필요합니다. 반송 메일 수신을 위해서는 공개 MX 호스트가 외부 TCP 25번 포트를 수신해야 합니다.
