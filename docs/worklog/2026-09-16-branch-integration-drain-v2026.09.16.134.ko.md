# 브랜치 자동 통합 드레인 안정화 — v2026.09.16.134

## 범위

자동 브랜치 통합 워크플로 자체는 예약 실행되고 있었지만, 한 번 실행할 때 최대 1개 브랜치만 병합할 수 있었습니다. GitHub 예약 작업은 지연 실행될 수도 있어 후보 테스트가 통과한 브랜치와 PR이 계속 쌓이는 현상이 발생했습니다.

## 변경 전 확인 내용

- `Auto Integrate and Promote` 예약 실행 기록이 존재했고 2026-09-15T22:00:05Z 실행도 성공 상태였습니다.
- 해당 실행은 충돌 중인 PR #341을 건너뛴 뒤 PR #349 하나를 병합하고 main 후보 테스트를 실행한 다음, 나머지 검증 완료 브랜치를 처리하지 않았습니다.
- 실행 후에도 #344, #346, #350, #351 등 검증 완료 PR이 남아 있었습니다.
- 기존 셸 루프가 파이프 서브셸에서 실행되며 첫 병합 뒤 `exit 0`으로 루프가 끝나 전체 대기열을 비우지 못했습니다.

## 변경 내용

1. 개발 브랜치의 `Build Test Candidate` 성공 직후 통합을 시작할 수 있도록 `workflow_run` 트리거를 추가했습니다. 시간당 cron은 보조 안전망으로 유지합니다.
2. 파이프 기반 `while`을 `mapfile` + `for` 방식으로 바꿔 한 번의 직렬 실행에서 모든 대상 브랜치를 확인합니다.
3. 정확한 브랜치 HEAD SHA에 대한 후보 테스트 성공을 병합 필수 조건으로 유지합니다.
4. 충돌 PR은 경고 후 건너뛰어 뒤쪽 정상 브랜치가 막히지 않도록 했습니다.
5. 한 번의 드레인에서 가능한 병합을 모두 끝낸 뒤 최종 main SHA에 대해 후보 테스트를 딱 한 번 실행합니다.
6. 실제 저장소에서 사용 중인 `security/*` 개발 브랜치도 자동 통합 대상 접두사에 포함했습니다.

## 배포 안전성

운영 승격 조건은 변경하지 않습니다. 최종 `main` 빌드 성공, 격리 테스트 서버의 정확한 SHA 일치, 백엔드 공개 카탈로그/DB 경로 확인, 테스트 서버 `noindex` 확인이 모두 통과한 뒤에만 운영 이미지가 준비 상태가 됩니다. 충돌 브랜치는 자동 해결하거나 강제 병합하지 않습니다.
