## 주요 발견
- P1: 주식 틱 함수가 틱마다 0.1% 확률로 `recorded_at` 기준 전체 삭제 실행 → 약 2.5분마다 약 110만 행 전체 스캔(틱 트랜잭션 내부). 해당 컬럼 선두 인덱스 없음. 분봉도 동일. 후속 마이그레이션(인덱스 또는 별도 배치 정리)으로 Test에서 EXPLAIN 전후 검증.
- P2: 보존 기간 경로 불일치(레거시 24시간 vs DB 함수 2일).
- P3: 쿼리 단위 관측 불가(pg_stat_statements 미설치, 느린 쿼리 로그 꺼짐).
- P4: statement/유휴 트랜잭션 타임아웃 없음, 교착 3회 기록.
- P5: 운영 Spring JVM 힙 상한·systemd 메모리 상한 없음, 로컬 추론 서비스 최대 7GiB 허용.
- P6: shared_buffers 128MB 등 기본값, 임시 파일 405MB 누적.
- P7: 활동 로그·상태 스냅샷 테이블 증가, 미사용 대형 인덱스.
- P8: max_connections 100, JVM당 풀 10 — 런타임별 연결 예산 필요.
