## 과거 문서 해석

작업로그·릴리스·QA·결함·업데이트·날짜별 기획의 원문 증거를 보존한다. 과거 신규 UI 기술 지시를 현재 목표로 재사용하지 않는다. 채택된 기획의 업무·보안 요구사항은 계속 적용한다. 실패를 통과로 고치거나 원본 이미지를 지워 문서를 맞추지 않는다.

캡처한 브랜치 tip 전체의 고유 Markdown/텍스트 blob 내용을 검색했다. 자동 지시어/링크 탐지 결과는 검토 후보이며 모든 문장의 수동 의미 검토 완료를 뜻하지 않는다. 현재 진입 문서는 이 기준으로 안내하고 과거 영수증은 당시 범위로 읽는다. 미해결 기능과 통합 차단 사유는 계속 표시한다.

## 완료 판정

소스에 연결된 검사와 브랜치 변경 보존 후 통합한다. 삭제 전 새 fetch, 예상 head 일치, main 포함 여부, 추가 파일 보존을 확인한다. PR 닫힘·squash 표기·브랜치명만으로 삭제하지 않는다. 다른 작업자의 수정 중인 작업 디렉터리를 초기화하거나 제거하지 않는다.

운영 전환에는 실제 애플리케이션 소스·JAR/이미지·제공 자산 해시, 실제 인증 계약, 독립 Test·보안/DB 검사·복원 가능성이 필요하다. 문서 전용 변경은 서버 배포나 모든 기능 정상 인증을 승인하지 않는다.
