## Verified corpus scale

The redesign requirement is not “look at a few moodboards.” It uses public libraries whose verified inventory already exceeds 1,000 human-authored or shipped-product examples before implementation decisions are accepted.

- Mobbin: 1,428 apps, 621,500+ screens and 323,900 flows; real-world app/web patterns.
- SiteInspire: multiple large curated categories, including Agencies & Consultancies 2,393; Typographic 2,103; Design & Art Direction 1,939; Portfolio 1,430.
- SaaSFrame: 170 curated SaaS dashboard examples in its dashboard category, used only as one focused subset rather than the sole corpus.
- Gummble: 1,500+ apps/sites, 300,000+ real app screens and 21,000+ flows.

## What we adopt

- clear reading order before decoration;
- asymmetric composition when content warrants it;
- dense tables/ledgers for financial and operational work;
- editorial rhythm for community/content surfaces;
- explicit labels, units, timestamps and states;
- mobile recomposition instead of desktop shrink;
- visible empty, loading, error, permission and reauthentication states;
- restrained motion and surface effects.

## What blocks review

A route fails review if it still reads as a generic AI-template UI. Blocking patterns include:
- the same bento grid on unrelated pages;
- neon/purple glow or glass cards used everywhere;
- generic four-KPI rows with no task need;
- identical radii and spacing across all product families;
- decorative icon tiles with no information value;
- fake “AI insight” or placeholder analytics panels;
- excessive pills/badges;
- perfect symmetry that ignores reading order;
- copied visual language that suggests real banking or investment products.

## Moneyverse product families

1. Finance terminal — wallet, bank, stocks, portfolio, alerts, history, businesses, marketplace.
2. Member workspace — dashboard, account, profile, search, notifications, security.
3. Community/editorial — board, announcements, gallery, lobby, support, public home.
4. Gameplay — work, quests, progression, seasons, inventory, shop, casino, calendar.
5. Operations console — every admin route; dense, auditable, permission-aware.
6. Utility/auth/legal — login, verification, reset, privacy, terms, deletion.

Shared primitives are allowed. Shared page composition is not the default.
