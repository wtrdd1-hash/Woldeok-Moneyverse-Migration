# C v1130 — Verified IndexNow notification evidence (English canonical)

## Scope and reproduction
On authoritative `origin/main` the administrator SEO page's manual submission accepted `success: true` without validating three provider statuses or a timestamp. The same-origin Next gateway forwarded arbitrary JSON as HTTP 200. This could falsely report a URL-change notification as received, even though no IndexNow provider accepted it. This is not proof of search indexing.

## Implementation
The existing authenticated NestJS API and CSRF-protected mutation remain authoritative. A shared pure parser validates the actual backend receipt: three unique known provider endpoints, 200/202 acceptance consistency, bounded status/message, fresh timestamp, same-origin canonical submitted URLs and retired Google sitemap ping 410. Next BFF rejects malformed evidence (503) and no provider acceptance (502). Browser shows confirmed acceptance counts only after validation; invalid or unknown outcomes show an actionable warning. No financial, database, external crawler or production changes.
