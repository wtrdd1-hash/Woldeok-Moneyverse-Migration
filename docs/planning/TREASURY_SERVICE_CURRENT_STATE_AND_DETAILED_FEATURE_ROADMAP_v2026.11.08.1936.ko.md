### P0 실제 소스/DB 위험 3건

**P0-1 연금 직접 잔액쓰기:** DB 등록된 admin_pension_distribute_hourly_payouts(uuid) 본문에 직접 INSERT INTO public.account_balances 로직이 있고 economy_post_transaction 호출은 없다. 소스 SQL341도 국고 목적금고를 차감한 뒤 수급자 지갑 잔액을 직접 늘리므로 원장 거래와 충돌할 수 있다. 현재 수급자는 0명이지만 미래 지급 전에 반드시 중지·정방향 SQL 교체가 필요하다. **이 함수는 실운영에서 시험 실행하지 않았다.**

**P0-2 공기업 배당 통화발행 위험:** 소스 SQL340은 시간당 계산된 예상 기업이익을 MINT → TREASURY 복식부기로 기록하며 실행마다 새 UUID를 사용한다. 정식 원장의 차대평형 여부와 별개로 공기업이 실제 벌어들인 현금의 배당이 아니라 신규 WLD 발행이 될 수 있고 중복 실행 가능성이 있으므로 **실제 SOE 현금계좌·회계기간·중복방지**로 교체해야 한다.

**P0-3 운영 적용·승인과 지급 차이:** 데이터베이스 적용이 339에 멈춘 사실과 소스 340/341 존재가 충돌한다. 실제 등록 함수 본문도 함께 검증해야 한다. 한편 지원금 500,000 WLD 건은 APPROVED지만 돈을 받은 거래증빙은 없다. 이는 승인만 된 상태일 수 있으므로 **APPROVED_UNFUNDED와 PAID를 분리**해야 한다.

## 2. 기관 분리·원장 통합 원칙

- **국고:** 실제 WLD 징수, 예산배정, 재원예약, 지급, 결산. WLD 임의 발행 권한 없음.
- **중앙은행:** 기준금리, 은행 지급준비, 통화정책, 화폐 공급명령. 국고세금을 직접 사용하지 않음.
- **조폐국:** 유효한 중앙은행 명령에 한해 조폐·소각, 불변 증명서 발급. 지원금 심사/지급 결정 금지.
- **정산 코어:** 경제의 유일한 금전 원장 economy_post_transaction, immutable 영수증, DB권한, 대사.
- **국부펀드/공기업:** 실제 사업자산/현금/주식·채권 보유, 실현수익과 평가이익 구분.
- **국채:** 국고에 실지급된 투자대금에 대한 채무·이자·만기 반환을 추적.
- **연금/건강보험/KDIC:** 보험료·적립금 자산과 미래지급의무를 별도 관리.

**필수 금융 불변식:** 실제 정산거래마다 차변=대변; 계좌 잔액은 전후 금액과 posting 합계 일치; 발행과 소각이 아닌 모든 돈 이동은 총 WLD 공급량 변화가 0. 금전은 정수 문자열로 받고 모든 데이터 접근은 인증된 서버·허가된 DB 프로시저에서 한다. 기존 과거 이력을 초기화하거나 가짜 인증하지 않는다.

## 3. 기능별 상세 설계 색인

아래 세부항목은 모두 **구현 요구사항 후보**다. PARTIAL은 현재 DB/소스 일부 구조가 있다는 뜻일 뿐 실제 운영 완료가 아니다. GAP은 추가 도입할 기능이다. P0는 먼저 안정화할 금융·보안, P1은 관련 서비스 완성, P2는 게임경제 고도화다.

### TR-01 — 국고 단일계정·5개 금고 [PARTIAL / P0]

- **TR-01.01** 하나의 TREASURY 정식 계좌를 화폐 잔액의 권위로 지정하고 나머지 금고는 용도별 분류·장부로 유지한다.
- **TR-01.02** MAIN·WELFARE·EMERGENCY·INFRA·RESERVE 금고의 합계가 정식 국고 계좌와 정확히 일치하는지 검사한다.
- **TR-01.03** 프로그램별 예산·예약금·지출·잔액·미지급채무를 구분한다.
- **TR-01.04** 가용재원은 실제 국고잔액에서 정책예비금과 기존 유효 예약액을 차감해 산정한다.
- **TR-01.05** 예비금은 실제 다른 돈이 아니라 지출을 제한하는 정책 상한으로 관리한다.
- **TR-01.06** 7일·30일·90일 자금 유입 및 의무지출을 구간예측으로 표시한다.
- **TR-01.07** 금고 내부 재배분은 통화량을 바꾸지 않고 단일 트랜잭션 안에서 처리한다.
- **TR-01.08** 거래별 전후 잔액, 상대계좌, 금융정책 버전, 영수증을 조회한다.
- **TR-01.09** 회계기간별 스냅샷과 최신 데이터 수집 시각을 저장한다.
- **TR-01.10** 현재 합계가 일치하더라도 과거 회계기간 증빙미확인은 별도 상태로 표시한다.

### TR-02 — 국가예산·기금·재정계획 [GAP / P1]

- **TR-02.01** 정책 회계연도 생성, 종료, 재개를 버전별로 관리한다.
- **TR-02.02** 교육·복지·산업·기업지원·인프라·재난·금융안정 등 사업분류 코드를 부여한다.
- **TR-02.03** 연간 정부예산안과 중기 3개년 재정계획을 구성한다.
- **TR-02.04** 분야별 신규사업 신청·심의·최종 예산배정과 집행을 분리한다.
- **TR-02.05** 사업 예산액·계약액·예약액·집행액·미지급액의 흐름을 표시한다.
- **TR-02.06** 정책변경에 따른 증액·감액·이월·불용 사유를 증명한다.
- **TR-02.07** 예상 세수와 실제 세수의 차이에 따라 사업별 우선순위를 재계산한다.
- **TR-02.08** 긴급 예비비 사용 조건과 일회 한도·재검토 기한을 둔다.
- **TR-02.09** 시민 예산투표는 의견수렴으로 제한하고 즉시 지급 권한을 부여하지 않는다.

### TR-03 — 조세·세외수입·환급 [PARTIAL / P1]

- **TR-03.01** 노동소득세·부유세·거래수수료·기업이익세·기부금 등 재원 출처를 세분화한다.
- **TR-03.02** 원거래 UUID와 세율 정책버전·시행시각을 묶어 중복 세금징수를 차단한다.
- **TR-03.03** 과세액 평가와 실제 세금 수납을 별도 상태와 영수증으로 관리한다.
- **TR-03.04** 체납·부분납부·정정·이의신청 및 환급금을 분리한다.
- **TR-03.05** 환급은 국고 현금에서 납세자 현금으로 복식부기 지급한다.
- **TR-03.06** 소액 세율의 반올림/내림과 정수 WLD 단위 규칙을 보존한다.
- **TR-03.07** 세수 저조·과대 징수·중복 징수 이상을 진단한다.
- **TR-03.08** 회원 납세 내역은 소유자에게만 제공하고 공개자료는 합계로 제한한다.
- **TR-03.09** 실제 국가 주민번호·민감 금융신원 수집을 요구하지 않는다.

### TR-04 — 국고 지출·결산·감사 [PARTIAL / P0→P1]

- **TR-04.01** 예산 확정·지출약정·지급예약·수급확인·정산·회계마감의 단계를 분리한다.
- **TR-04.02** 지급 대상 계정·예산한도·가용 WLD·정책버전을 같은 DB 트랜잭션에서 검증한다.
- **TR-04.03** 지급 전 취소는 예약만 해제하고 지급 후 환수는 새로운 반대방향 거래로 처리한다.
- **TR-04.04** 실제 원장 영수증 없는 지급에는 PAID 상태를 부여하지 않는다.
- **TR-04.05** 일간·월간·연간 회계보고서를 불변 회계기간 기준으로 확정한다.
- **TR-04.06** 과거 재정 초기화 epoch의 오래된 이력은 별도 보존하고 새 금융증빙을 위조하지 않는다.
- **TR-04.07** 세입·세출·재정수지·국가부채·현금흐름을 구분해 공개한다.
- **TR-04.08** 결산 보고서 CSV·JSON의 행수·생성시각·SHA256을 기록한다.
- **TR-04.09** 사업별 예산집행 성과와 실제 WLD 이동을 연결한다.

### GR-01 — 창업지원금 신청·승인·지급·환수 [PARTIAL / P0→P1]

- **GR-01.01** 실제 공개 경로 /treasury의 신청 모달을 접근 가능한 네비게이션에서 찾도록 한다.
- **GR-01.02** 별도 /treasury/portal 경로는 구현된 경우에만 안내하고 그렇지 않으면 공식 경로로 정정한다.
- **GR-01.03** 지원 사업·업종·Tier별 한도와 사업계획서 유효성 검사 규칙을 정의한다.
- **GR-01.04** 회원 로그인·신청서 임시저장·제출·보완요청·심사·취소 기록을 제공한다.
- **GR-01.05** 동일 회원/지원사업/회계기간 중복 신청을 차단한다.
- **GR-01.06** AI는 심사의 참고점수·검토근거를 제공하지만 실제 승인권한은 관리자에게 둔다.
- **GR-01.07** 기존 사용자 정책에 따라 슈퍼관리자 1인 단독 승인, 2인 승인 재도입 금지.
- **GR-01.08** 승인금액과 실제 자금예약 금액과 정산된 지급금액을 세 상태로 분리한다.
- **GR-01.09** APPROVED_UNFUNDED·RESERVED·DISBURSING·PAID·RECOVERY_REQUIRED 전이를 명시한다.
- **GR-01.10** 지급확정 시 국고에서 신청자 계좌로 WLD를 원자적 이동하고 거래ID·영수증을 발급한다.
- **GR-01.11** 사업개설 기한 14일과 사업개설 증빙을 추적하되 재검증 유예·면제·이의제기 절차를 둔다.

## 4. 거래 상태모델 및 핵심 업무 흐름

### 국고 지급 공통

1. 사용자 인증·프로그램 적격성·수급자 계좌 확인.
2. 예산 허용량과 실제 국고 계좌 잔액, 준비금, 이미 예약된 돈을 같은 트랜잭션에서 조회·잠금.
3. 금액과 수급자를 업무 ID·회계기간에 묶어 한 번의 지급 ID로 고정.
4. 국고 잔액 -X / 사용자 지갑 +X 를 하나의 정식 복식부기 거래로 커밋.
5. 사업별 지급 상태·영수증·금고 투영값·이벤트 outbox를 동일 트랜잭션에 기록.
6. 실패하면 전부 취소. 이미 지급된 요청이면 동일 영수증 반환. 텔레그램 전송 실패로 돈을 다시 주지 않음.

**지원금 상태:** DRAFT → SUBMITTED → ELIGIBILITY_REVIEW → UNDER_REVIEW → APPROVED_UNFUNDED 또는 APPROVED_FUNDED → RESERVED → DISBURSING → PAID → MONITORING → CLOSED. REJECTED, CANCELLED, HOLD, FAILED_RETRYABLE, APPEALED, RECOVERY_REQUIRED, PARTIALLY_RECOVERED, RECOVERED는 독립 예외 상태. 실제 ledger ID와 지급시각이 없으면 PAID 금지.

**조폐 상태:** DRAFT_ORDER → POLICY_ACCEPTED → ENVELOPE_RESERVED → QUEUED → MINTED_AND_CERTIFIED → LEDGER_FINALIZED. FROZEN, REJECTED, EXPIRED, HOLD는 발행 0. 정책명령 해시/한도 검증 실패는 실제 공급량을 절대 변경하지 않는다.

**공기업 배당:** 실제 사업수입 입금 → 비용 지급 → 회계기간 결산 → 배당가능 이익 및 현금 확인 → 주주배당 승인 → SOE 실제 현금 -X / 국고 +X → 회계기 유일 영수증. 예상 시간당 이익만 있으면 배당 0이다.

**국민연금:** 가입자 납입 → 실기금 ESCROW → 적립권리 확정 → 수급자와 지급회차 결정 → 실제 지급재원 잠금 → 회원별 한 번 정산 → 영수증. 회차별 지급 중단 후 재실행해도 과거 수급자를 다시 지급하지 않는다.

**국채·레포:** 입찰금 실제 예약 → 낙찰 → 현금이 국고로 이동하는 동시에 소유권 확정(DvP) → 보유자별 지급회차 쿠폰 지급 → 만기 국고 현금으로 원리금 지급. 레포는 이미 소유한 담보 국채를 잠근 뒤 실행한다.

| POST /api/v1/admin/enterprises/:id/close-and-distribute | 실제 공기업 배당가능 현금 정산 |
| POST /api/v1/admin/mint/execute/:orderId | 유효한 조폐명령 실행과 증명서 |
| POST /api/v1/admin/bonds/:issueId/close-auction | 국채 낙찰 현금/소유권 동시결제 |

공통 금전 POST는 requestId, businessId, periodId, amountWld 문자열, policyVersion, reason을 사용하되 **실제 실행자(actor)는 서버 인증정보로만 얻는다**. 서버가 금액을 재계산하고 응답에 status, transactionId, receiptId, asOf, sourceVersion을 포함한다. 금융코어 원시 함수는 공개 HTTP API로 만들지 않는다. Next BFF와 Nest의 실제 URL 변환을 확인해야 하며 새 엔드포인트가 현재 운영에서 제공 중인 것처럼 적지 않는다.

## 7. 인수테스트 및 실패 처리

- **0원/자금부족:** 돈 지급 0건, 어떤 현금계좌도 변경 없음.
- **100개 동시 요청:** 중복연금·지원금·공기업배당·국채이자 같은 회차 1건만 정산.
- **중간 실패:** 원장만 기록되거나 사업상태만 PAID가 되는 절반 커밋 0건.
- **공기업 실제 현금 0:** 추정 이익이 있어도 실제 배당 불가, 조폐국 상대계정 금지.
- **금전공급:** 총 WLD 발행량 변화는 유효 조폐/소각명령 합계와 동일.
- **권한:** 공개 사용자는 DB 금융 테이블에 직접 INSERT/UPDATE/DELETE 불가, 원시 금융코어 외부 실행 불가.
- **개인정보:** 로그인 없이 본인 연금/보험/지급내역 노출 0, Android 계정 변경 시 이전 캐시 제거.
- **자료없음:** 정상 0건은 VERIFIED_EMPTY, API 실패는 UNKNOWN, 정책중지는 HOLD.
- **실제 DB 복구:** 미니PC 2번 디스크와 독립 백업의 sha/복원/금전 정합성 기록.
- **배포:** 공식 Test의 정확한 코드 SHA·SQL 번호·마이그레이션 checksum·실제 회원 E2E 검증, 무중단 롤백 능력과 운영승격 관찰.

## 8. 개발 순서와 버전·브랜치 계획

**P0-A 현재상태/버전 고정:** 미니PC와 GitHub main 재조회, 실제 배포 SHA와 Test SHA, DB 등록 함수/SQL 체크섬/권한, 모든 금융용 직접 잔액쓰기 경로 조사. GitHub 브랜치 충돌 방지. 기획 완료와 개발 완료 구분.

**P0-B 금융코어 교체:** 현재 국민연금 직접 잔액쓰기 및 공기업 MINT 배당 경로를 위험 실행으로 간주하고, 운영에는 아직 적용하지 않은 **정방향 신규 번호 SQL**로 공기업 실제 현금→국고, 연금기금/국고→회원의 정식 원장 이전을 구성. 동일 회차 1회, 실패 롤백, 기존 데이터 보존.

**P0-C 지원금·복지 실제 지급:** 회원 신청→승인→실제예약→1회 지급→영수증→검증/환수의 전 구간을 구축. 현재 승인 500,000 WLD 건은 무근거로 지급완료 변경하지 않는다.

**P0-D 경로·화면·경고:** /treasury/portal 404의 실제 원인에 맞춰 링크 정정 또는 신규 페이지 작성. 관리자 인증 401과 서비스 장애를 분리하고 정상 0원·0건에 잘못된 경고가 없도록 한다.

**P0-E Test와 무중단 운영승격:** PostgreSQL17 독립복원, 기능별 실제 원장 단위/통합/부정/E2E, CI, exact SHA 테스트, 백업·복구 리허설, 새 릴리스 건강 검증, Nginx 원자 전환, 롤백 확인. 통화 무결성 위험이 남으면 배포한 것으로 보고하지 않는다.

**P1-A 국가예산/조세/결산:** 프로그램 회계, 예산·예약, 자금 예측, 세수 체계, 공개재정 보고서.

**P1-B 국채/국부펀드/기업:** 국채 경매·쿠폰·만기·레포, 국부펀드 실제 유동화, 기업 진짜 현금배당, 운영 위험 관리.

**P1-C 복지/보험:** 국민연금 실적립과 실지급, 건강보험 청구, 예금보험 실제 보상과 채무.

**P2-A 중앙은행/조폐국 고도화:** 금리·통화량·정책자동 제안과 발행·소각증명서 공개. 오프라인 CBDC 연구는 실제 지급 기능과 완전 분리.

**P2-B 국민참여/AI/Android:** 예산참여, 기업 경영공개, 정책 시뮬레이션, 모바일 접근성·다국어.

각 단계는 BEFORE→MID→FINISH 기록, 영어 기준/한국어 쌍문서, 내부 및 GitHub 업데이트 문서, 별도 새 개발 브랜치, 실제 QA와 Test를 거쳐 운영에 승격한다. Gemini가 작업하는 파일이나 SQL 번호와 충돌하지 않도록 메인과 기존 브랜치를 다시 확인한다.

## 9. 국제 공식 레퍼런스 적용과 기획 권위

[39개 공식자료 조사표](../research/2026-11-08-sovereign-treasury-feature-reference-matrix-v1936.ko.md)는 한국재정정보원 dBrain+, 한국은행 통화정책/BOK-Wire+, 한국조폐공사, IMF 국고단일계정/GFSM/재정투명성/PIMA, BIS PFMI 및 CBDC, PEFA, OECD, World Bank BOOST/DeMPA, 미국 TreasuryDirect·FDIC·Do Not Pay, 노르웨이 NBIM, 한국 국민연금 기금운용, ISO20022, 공개조달 OCDS와 각 기능 ID를 연결한다. **실제 법률 준수나 금융기관 인증을 주장하는 자료가 아니라 게임의 금융·재정 설계 비교 근거**다.

이 문서는 이전 [v1912 국고·중앙은행·조폐국 설계 초안 PR #2882](https://github.com/wtrdd1-hash/Woldeok-Moneyverse-Migration/pull/2882)을 확장한 후속 **기획**이다. 상위 PROJECT_PLAN 및 INTEGRATED_PLANNING_MASTER에 자동 편입하지 않았다. 향후 승인된 개발팀이 현재 main을 다시 가져와 계획 통합·새 SQL 번호 배정·분리 브랜치·정식 Test·무중단 운영승격을 실행해야 한다.

**실제로 수행하지 않은 작업:** DB 쓰기 및 초기화, WLD 발행·보조·배당·연금 지급, SQL340/341 적용, 백엔드 기능구현, 정식 Test 금전 E2E, 운영승격. 위 결과는 읽기 전용 현황 조사와 기능별 매우 상세한 제안이다.
