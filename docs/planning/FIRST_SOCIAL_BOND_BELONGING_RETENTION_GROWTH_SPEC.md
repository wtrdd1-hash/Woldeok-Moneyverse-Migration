## 1. Gap selected for this iteration

Moneyverse already has detailed plans for clubs, clubhouse UX, community moderation, creator acquisition, notifications, user priorities, collections, seasons and World Pulse. The remaining consumer-growth gap is narrower: **a solo user can activate successfully, but there is no single growth contract for turning that solo success into one safe, durable social bond that creates a reason to return.**

The current production home describes Moneyverse as a community virtual economy, but the visible community lobby is primarily a transient greeting surface: messages are not persisted, the user sees whoever is currently online, and an empty lobby can offer little continuity. The current getting-started guide is still predominantly wallet/job/finance oriented. A user can therefore understand systems without yet feeling that anyone or any group expects, recognizes or remembers their participation.

This version defines the consumer loop:

`solo first value → choose a social context → low-risk first contribution → acknowledgment/response → one relationship or group thread saved → D1 recognition → D3 reciprocal progress → D7 shared outcome → D14 belonging signal → D30 durable shared history`

Consumer promise:

**“I can find one relevant group or person, contribute without pressure, and come back because something we started together is still moving.”**

This is not a friend-graph schema, chat protocol, invite API, moderation state machine or club backend specification.

## 2. Why social activation comes after individual value

Do not make “find friends” or “join a club” the first mandatory task for every visitor. A new member should first understand at least one useful Moneyverse action on their own. Social connection is then offered as a multiplier of meaning, not as a prerequisite for basic comprehension.

Recommended sequence:
1. understand one individual thread (build, collect, explore, learn, profession or season);
2. complete or preview one meaningful action;
3. show one relevant social continuation tied to that exact interest;
4. let the user observe before participating;
5. allow one bounded contribution;
6. invite them to save/follow/join only after the context is understood.

Avoid dropping a newcomer into a busy feed, giant member list or unfamiliar club dashboard with no explanation.

## 3. First 30 seconds, first 3 minutes and first social session

### First 30 seconds
A newcomer should be able to answer:
- What is Moneyverse?
- What can I do alone right now?
- Is there a relevant community context around this interest?
- Can I observe safely before joining or posting?

Do not lead with member count, wealth rank, donation totals, casino outcomes or “everyone is already here” pressure.

### First 3 minutes
After one solo value proof, offer one social bridge:
- collection thread → view one curated club exhibit or shared collection project;
- season/world thread → view one newcomer-friendly club/project following that theme;
- profession/build thread → inspect one cooperative project role that needs a non-financial action;
- educational market thread → read one moderated discussion/replay without exposing private positions;
- creator/community acquisition → continue into the same bounded topic rather than a generic lobby.

The user should be able to leave without social penalty.

### First social session
The healthiest first contribution is usually non-financial and low-risk:
- react to a bounded prompt;
- vote in a non-financial preference poll;
- choose a project role or interest;
- add a preset/limited contribution note;
- complete a cooperative learning or collection step;
- welcome or acknowledge another newcomer where moderation permits.

WLD donation, WDX trading, referral recruitment and open-ended personal disclosure must not be required for first belonging.

## 4. Social lifecycle contract

### D0 — recognition, not obligation
The user completes one individual value moment and sees one social context that matches it. Success is not “joined a club”; success is “understood why this group/thread is relevant and took or saved one voluntary next step.”

### D1 — someone/something remembers
Return to the exact shared thread. Show whether the user's bounded contribution was acknowledged, incorporated, answered or simply remains visible. Do not fabricate replies or social activity.

### D3 — reciprocal progress
Offer one real change involving the same group/thread: a project moved, someone responded, a related contribution became available, or the user can deepen the same topic. If nothing changed, say so and provide an evergreen continuation.

### D7 — shared outcome
The user should be able to point to one result that was not purely individual: a club exhibit advanced, a learning objective completed, a project milestone moved, a small group challenge concluded, or a shared archive gained a meaningful chapter.

### D14 — belonging without lock-in
Offer identity expression such as a club/project badge, curated contribution history, optional profile display or recurring cooperative role. These must be reversible and must not imply economic superiority.

### D30 — durable shared history
Preserve one artifact of participation: project chapter, club archive entry, seasonal collaboration, learning replay, exhibit contribution or reflection. The record should remain useful even if the user later leaves the club or reduces participation, subject to safety/privacy policy.

### Comeback
Use “what your group/thread did while you were away” only when a material change exists. Do not shame users for absence, threaten loss of membership/value, or make them repay missed activity.

## 5. Belonging ladder

Use an aspiration ladder that does not require money or popularity:

1. **Observe** — understand a group safely.
2. **Choose** — select an interest/project/thread.
3. **Contribute** — perform one bounded useful action.
4. **Recognize** — see that the action mattered or was acknowledged.
5. **Collaborate** — participate in a shared objective.
6. **Curate** — help shape an exhibit, guide, archive or project outcome.
7. **Represent** — optionally display affiliation or contribution.
8. **Remember** — retain a durable shared history across seasons.

Do not equate belonging with member count, WLD donated, post volume or leaderboard rank.

## 6. Newcomer-friendly social discovery

Social discovery should prioritize fit and safety over scale.

Useful discovery attributes:
- language;
- interests/themes;
- newcomer-friendly status;
- activity recency expressed coarsely;
- current cooperative project;
- communication style or participation mode where appropriate;
- public preview availability;
- moderation/rules clarity.

Avoid default ranking by member wealth, aggregate WLD, raw message volume or WDX performance.

A user should be able to preview rules, purpose and one recent safe artifact before joining when the community is public.

## 7. Viral and referral boundary

The strongest social acquisition artifact is a **shared outcome with context**, not a raw invite code.

Good candidates:
- before/after club project result;
- curated season collaboration;
- collection exhibit;
- educational replay or challenge result;
- “we built this together” archive card;
- newcomer-friendly public project page with one safe sample action.

Recipient path:
`shared outcome → understand context without login → preview/sample → choose interest → contextual signup → first individual value → optional social continuation`.

Do not pay meaningful WLD/WDX for raw invites, joins, messages, reactions or shares. Referral rewards, if used, should be bounded, delayed until verified retained participation, and favor cosmetics/recognition/convenience over economic power.

## 8. Habit/session design

### 1–3 minute quick social check
- one response/project delta;
- one useful next action or “nothing important changed” state;
- easy exit.

### 5–15 minute meaningful social session
- contribute to one project;
- review one discussion/replay;
- curate one shared artifact;
- complete one cooperative learning/collection objective.

### 30+ minute deep social session
- build or curate a project/exhibit;
- participate in a substantial club event;
- review history and plan next steps;
- collaborate on a season/city/community objective.

Long sessions must not justify proportional ad-load growth or stronger pressure to donate WLD.

## 9. Monetization boundary

Belonging must not become pay-to-belong.

Allowed candidates after repeated value:
- club/space cosmetic themes;
- archive/gallery presentation styles;
- non-P2W profile/affiliation expression;
- ad removal;
- clearly disclosed sponsor-supported community content where sponsorship does not control moderation or rankings.

Do not sell:
- moderation priority;
- preferential club discovery placement disguised as organic quality;
- WDX execution/returns or loan benefits;
- enhanced project voting power;
- guaranteed leadership/status;
- access to basic community safety tools;
- secret pricing based on attachment to a club or social graph.

## 10. SEO and public-content boundary

Index only pages with independent public value:
- substantial public club/project overview;
- editorial project retrospective;
- season collaboration archive;
- original learning/community guide;
- carefully moderated public exhibit with sufficient context.

Default noindex/unlisted:
- join/invite/referral-code pages;
- private member lists and social graphs;
- thin activity feeds;
- private club pages;
- personal contribution histories without explicit public choice;
- moderation/report/security/recovery state;
- balances, holdings, debt or casino history.

Do not create mass `club × interest × city × season` doorway pages.

## 11. Experiment backlog

### A — relevant social bridge vs generic lobby CTA
Hypothesis: a social continuation tied to the user's first interest improves D7 retention more than sending everyone to a generic lobby.
Target: newly activated users.
Control: generic “visit community” CTA.
Treatment: one context-matched club/project/thread preview.
Primary: social-preview→meaningful-action, D7 retention.
Guardrails: report/block rate, confusion, unwanted contact, privacy complaint.
Minimum observation: D7-mature cohort; D30 before broad rollout.
Next: expand only if retained quality improves without safety deterioration.

### B — observe-before-join vs join-first
Hypothesis: safe public preview reduces low-quality joins and improves first-contribution quality.
Primary: first useful contribution per join, D7 club/thread continuation.
Guardrails: public-data exposure, abuse scraping, bounce.

### C — non-financial first contribution vs WLD contribution prompt
Hypothesis: a bounded social action creates belonging with less pressure and abuse than asking for WLD first.
Primary: D3 reciprocal progress, D7 shared outcome.
Guardrails: economic abuse, regret/support contacts, newcomer drop-off.

### D — shared-outcome card vs raw referral invite
Hypothesis: showing what a group created attracts higher-quality recipients than generic referral messaging.
Primary: recipient sample→activation→D7.
Guardrails: fake signup, referral fraud, spam/report rate, privacy leakage.

### E — weekly shared-progress recap vs generic daily community reminder
Primary: message→meaningful social action and D30 retention.
Guardrails: unsubscribe/mute, spam report, phishing confusion.

## 12. KPI framework

Acquisition/activation:
- qualified social/public visit;
- social-context comprehension;
- preview-before-join rate;
- preview→authored social choice;
- contextual signup;
- time-to-first-individual-value;
- first useful social contribution;
- time-to-first-safe-social-value.

Retention/belonging:
- D1 exact-thread recognition;
- D3 reciprocal-progress rate;
- D7 shared-outcome rate;
- D14 voluntary affiliation-expression rate;
- D30 durable shared-history rate;
- social continuation among users with/without a first bond;
- returning-user share, WAU/MAU and sessions/user;
- meaningful social actions/session;
- comeback after a material shared change.

Viral/economics:
- outcome-card→recipient sample→activation→D7;
- referral fraud-adjusted CAC;
- D7/D30 retained CAC by social source;
- cohort LTV and retained-user contribution;
- ad-induced churn and subscription conversion only after repeated value.

Trust/safety:
- block/mute/report rate;
- harassment/doxxing/impersonation/phishing rate;
- spam/bot rate;
- fake-signup/referral-fraud rate;
- suspicious reward duplication;
- account-takeover signal rate;
- privacy complaint rate;
- moderation appeal/reversal signal where available.

## 13. Security, abuse and privacy review

### HIGH — harassment, grooming, doxxing or unwanted contact
Impact: direct user safety harm, with heightened risk for minors.
Scenario: a newcomer is pushed into open contact, asked for personal details, or targeted across public/community surfaces.
Minimum protection: observation before participation where possible; clear block/report; bounded newcomer interactions initially; no requirement to reveal real identity/contact details; preserve existing moderation policy; do not create new private-message growth flows without separate safety review.
Separate dev/QA: **yes** before expanding open-ended or private communication.

### HIGH — social invite/referral phishing and account takeover
Impact: credential/session theft.
Scenario: fake club/project invite or “you were mentioned/rewarded” message leads to a lookalike login page.
Minimum protection: canonical domain/brand consistency; growth messages never request password/OAuth/recovery codes; safe landing before auth; preserve current OAuth/session boundaries including recent mobile prelogin isolation; no asset-loss urgency.
Separate dev/QA: **yes** before external/deep-link social invites.

### HIGH — multi-account/referral/reward farming
Impact: distorted acquisition, economic inflation and fake community activity.
Scenario: linked accounts join clubs, react, post or invite each other to farm rewards or qualify projects.
Minimum protection: no meaningful WLD/WDX for raw join/message/reaction/share; delayed/capped milestone rewards; fraud-adjusted measurement; suspicious networks do not become social proof.
Separate dev/QA: **yes** before any economically meaningful social/referral reward.

### HIGH — private social/economic state leakage
Impact: exposes balances, holdings, debt, casino behavior, private club membership, hidden social graph, moderation/security state or recovery data.
Minimum protection: public-safe allowlist; private by default; explicit reversible public sharing; no secrets/session/recovery data in URL/metadata/analytics.
Separate dev/QA: **yes** before personalized public profiles, public contribution history or external share surfaces.

### HIGH — coordinated market/community manipulation
Impact: fake social proof and distorted WDX behavior.
Scenario: a club coordinates posts, reactions and trades to manufacture interest in a fictional issuer.
Minimum protection: preserve `COMMUNITY_MARKET_INTEGRITY_SPEC.md`; community popularity must not drive WDX prices/rewards; reports are signals, not votes; no official buy/sell recommendations; clear game-only framing.
Separate dev/QA: **yes** for any stock-tagged club campaign or public ranking.

### MEDIUM — impersonation and fake social proof
Minimum protection: distinguish official/operator/creator/member content; no unverified “trending” or participant counts as primary trust signal; no purchased/bot engagement in KPIs.

### MEDIUM — analytics overcollection
Minimum protection: minimize social attribution data; do not export private graph/economy/security state to ad vendors; avoid inferring sensitive attributes for social matching.

## 14. Minors and community safety

Treat age-sensitive community design as a launch gate, not an afterthought. Roblox's January 7, 2026 global chat changes are directional evidence that large youth-facing platforms are adding age-based communication boundaries and stronger verification around chat. Moneyverse should not copy that implementation automatically, but should require a separate age/safety/legal review before open private messaging, adult-minor contact expansion or other high-risk communication surfaces.

The FTC's February 2026 COPPA policy statement confirms that operators covered by COPPA still have notice, parental-consent and children's-data obligations, while providing limited enforcement relief for certain age-verification-only processing. PIPC's April 1, 2026 international-trends note on COPPA 2.0 is a policy signal, not current Korean law; it should trigger re-review before youth-targeted personalization, social discovery or advertising.

## 15. External research note — 2026-09-14

### Directly adopted
- **Discord Community Onboarding, updated June 25, 2026.** New members can choose relevant roles/channels through simple questions and can later change those choices. Discord explicitly frames overload/confusion as a reason newcomers leave. Adopted: small user-chosen social starting surface; reversible interests; do not expose every community surface at once.
- **Discord Community Onboarding Examples, updated May 15, 2026.** Recommends limiting options to avoid overwhelming newcomers. Adopted: one bounded social bridge, not a giant discovery grid.
- **Discord GDC 2026 / Social Layer, March 9, 2026; update August 20, 2026.** Discord reports causal retention/session benefits across partner integrations when social connection is closer to gameplay. Adopted directionally: measure social connection by downstream meaningful action and D7/D30, not friends/join counts alone. Discord's internal percentages are not Moneyverse forecasts.
- **Roblox, January 7, 2026 — age verification required for chat.** Adopted as a safety signal: communication features need age-appropriate boundaries, privacy, proactive filtering and easy reporting; no automatic implementation copy.
- **KISA spam guidance, March 4, 2026, plus May/August 2026 impersonation warnings.** Adopted: social invites/return messages must not disguise advertising consent or train users to enter credentials from links.

### Legal/reference only
- **FTC COPPA age-verification policy statement, February 2026.** Recheck applicability before minors-facing social features.
- **PIPC, April 1, 2026 COPPA 2.0 international-trends note.** Policy signal only; not treated as current Korean law.

## 16. Runtime Product Reality Audit — 2026-09-14

Verification status: **available**.

Observed public production behavior:
- home clearly states WLD/rewards are game-only virtual data;
- home positions Moneyverse as a Discord-connected community virtual economy;
- community lobby says messages are not stored and are visible to currently connected users, with a warning not to post passwords, auth codes, financial information, addresses or contact information;
- the lobby can show an empty state and offers a generic “say hello” interaction;
- the getting-started guide remains centered on login, wallet, quests/jobs, bank, virtual stocks/business and casino rather than a durable first social bond.

Consumer conclusion: the runtime has a safe basic community entry and strong virtual-currency disclosure, but **a persistent interest-matched `first social bond → D1/D7 shared continuity` path is not visibly established on the public surfaces reviewed.** This spec remains a growth hypothesis; no runtime change is made in this pass.

## 17. Decision for the next growth cycle

Validate one narrow social-retention loop before expanding feeds, DMs, referral economics or public rankings:

`first individual value → one relevant social preview → one bounded non-financial contribution → D1 recognition → D3 reciprocal progress → D7 shared outcome → D30 shared history`

Do not expand open DMs, economic invite rewards, public wealth/status leaderboards, finance-linked club campaigns, mass community SEO pages or higher notification frequency until this loop improves retained quality without worsening safety, privacy, fraud or moderation guardrails.
