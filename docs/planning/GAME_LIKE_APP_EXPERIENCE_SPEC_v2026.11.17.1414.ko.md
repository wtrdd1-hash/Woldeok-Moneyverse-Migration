# 월덕 머니버스 — 전체 앱 게임형 사용자 경험 통합 기획서

**버전:** v2026.11.17.1414
**상태:** 기획 초안 / 문서만 변경 / 구현·운영 승격 보류
**원문:** [영어 기준 명세](GAME_LIKE_APP_EXPERIENCE_SPEC_v2026.11.17.1414.md)
**적용 대상:** 월덕 머니버스 웹·PWA·Android 앱 전반. Spring Boot 서버 및 PostgreSQL 경제 원장을 사용하되 구현 여부는 실제 소스 확인이 우선한다.

> **제품 최상위 원칙: 앱은 앱이지만, 사용자에게는 하나의 게임을 플레이하는 듯한 세계관과 상호작용으로 구현한다.** 일반 서비스의 안정성, 빠른 조작, 정확한 금융 기록과 계정 보안은 그대로 유지한다.

기존 통합 기획서, 기능별 상세 기획, 보안·금융·접근성 정책과 함께 적용한다. **통합 기획서가 우선**하며, 이 문서는 새로운 전체 UX 기준을 명확히 정의한다. 기존 퀘스트·시즌·인벤토리·도파민 설계를 덮어쓰지 않고 일관된 게임형 사용성으로 연결한다.

## 1. 반드시 구현할 사용자 경험

- **게임 로비 같은 홈:** 접속하면 내 캐릭터/계정 상태, 검증된 WLD 잔액, 오늘의 목표, 진행 중인 미션, 세계 활동 현황이 보인다. 사용자는 무엇을 할지 즉시 이해한다.
- **직접 플레이하는 진행 구조:** 기능마다 행동 → 처리 상태 → 서버 검증 → 성공·실패 결과 → 다음 행동의 흐름을 통일한다. 단순 페이지 이동·표 읽기에서 벗어나되 불필요한 클릭을 강요하지 않는다.
- **세계관 일관성:** 지갑/은행은 금고·금융 지구, 상점은 상점가, 직업은 직업 구역, 주식은 시장, 커뮤니티는 광장·소식 게시판, 인벤토리는 장비 가방과 같은 화면 인상을 준다. 실제 기능명은 항상 함께 표시해 금융·보안 의미를 흐리지 않는다.
- **성장과 수집:** 프로필/아바타, 레벨·경험치·업적·퀘스트·희귀도·아이템 장착·시즌 진행을 연결하되 **원천 데이터와 지급 영수증이 확인되는 것만 획득으로 표시**한다.
- **완료감:** 보상을 실제로 받은 뒤 선택형 짧은 애니메이션, 명확한 완료 메시지, 다음 행동을 제시한다. 앱에서 계산한 가짜 XP·잔액·아이템은 절대 반영하지 않는다.
- **즐거움과 신뢰 병행:** 도박형 압박, 유료 확률형 보상 강요, 무분별한 스트릭 페널티, 허위 수익 보장, 공격적인 광고와 자동 재생 음향을 금지한다.

## 2. 화면별 게임형 UI 배치 기획

| 화면 | 사용자에게 보이는 UI 위치·구성 | 사용자 동작 및 주의점 |
|---|---|---|
| 홈/세계 로비 | 맨 위 아바타·알림·계정. 첫 화면 중앙에 실제 잔액과 마지막 확인 시각, 현재 목표 1개, 주요 진입 버튼. 아래 세계 구역 카드 3~5개와 소식 | 임무 계속하기 → 해당 기능. 소스 실패를 “잔액 0”으로 표시하지 않는다 |
| 프로필/캐릭터 | 상단 캐릭터 카드·닉네임, 중단 장착 슬롯과 꾸미기, 하단 업적·레벨·기록·개인 설정 | 서버에 존재하는 캐릭터·진행률만 표시. 미구현 XP는 검증 전 상태로 구분 |
| 퀘스트/활동 | 오늘·주간·스토리 탭, 목표 카드마다 조건·진행률(실제 분자/분모)·기한·보상·원천 기록 | 활동 열기, 조건 검토, 완료 후 서버 확인 및 중복지급 방지 |
| 지갑/국고 | 금고 테마 상단에 **정확한 WLD 잔액**과 확인 시각, 하단 거래 목록·영수증·전송 확인 | 숫자 가독성과 경고를 우선. 원장을 게임 그래픽으로 대체하지 않음 |
| 은행/주식 | 금융 구역 지도 및 카드, 보유량·가격·손익·위험 고지·갱신 시간, 작업별 확인 모달 | 수익 보장이나 추정 수익을 확정 보상처럼 나타내지 않음 |
| 상점/인벤토리 | 상점가 상품 카드·검색·희귀도 필터. 보관함에 아이템 슬롯·장착 상태·수량·만료·유지비·정지 상태 | 실제 소유권/영수증 기반. 기존 장착 기능 및 조회 정책 유지 |
| 직업/업무/회사 | 일자리 구역 카드, 요구 조건, 작업 게시판, 진행 단계, 완료 근거 | 수락·제출·검증·정산이 다른 상태임을 명확히 표시 |
| 커뮤니티/블로그/소식 | 광장·신문·게시판 인상, 글 작성/상태, 공지 및 시각 표시 | 공개·검수·광고 여부는 기존 실제 정책 사용 |
| 시즌/업적/도감 | 시즌 진행판, 획득 증표, 수집 현황, 과거 기록 보관함 | 일시적으로 검증 불가한 증표를 이미 획득한 것처럼 표시하지 않음 |
| 알림/설정/고객센터 | 일반 앱과 동일하게 찾기 쉬운 구조에 약한 세계관 스타일만 입힘 | 계정 보안·약관·데이터 접근·문제 신고는 게임 연출보다 명료함 우선 |
| 관리자 | 운영 관제실 콘셉트만 최소한 적용하고 실제 로그·원장·장애·권한·승인·복구 중심 | 금전/보안 상태에 장식용 성공 배지나 가짜 실시간 그래프 금지 |

위 화면 구조는 **지향하는 설계**이며, 해당 라우트나 API가 모두 구현되었다는 뜻은 아니다. 실제 코딩 전 최신 Spring SPA/Android 파일·API 및 기능 스위치를 대조한다.

## 3. 네비게이션과 최초 접속 흐름

**웹·PC:** 왼쪽 고정 세계 메뉴, 현재 구역 강조, 상단 상태와 탐색 경로, 메인 게임 카드. **모바일:** 하단 최대 5개 주요 탭 **홈 / 퀘스트 / 세계 / 인벤토리 / 프로필**. 세계 탭 안에서 지갑·은행·주식·상점·직업·커뮤니티 진입. Android 뒤로가기는 이전 화면으로 자연스럽게 돌아가며, 열린 모달은 우선 닫는다.

**첫 방문:** 선택 가능한 3단계 튜토리얼(표시 이름/캐릭터 이해 → 검증된 세계 상태 확인 → 안전한 비금전성 활동 경험). 언제든 건너뛸 수 있어야 하고, 데모를 실제 지급 내역처럼 보여주지 않는다. 로그인이 필요한 위치의 딥링크는 인증 및 동의 절차 후 원래 화면으로 복귀한다.

**정보 구조:** 카드에 멋진 이름만 넣지 않는다. 예: “금융 지구 · 주식”처럼 게임 속 장소와 기능명을 함께 표기한다. 잔액·금융·약관·인증·로그아웃은 직관적인 실제 앱 문구를 우선한다.

## 4. 공통 인터랙션 상세 기준

1. **행동 즉시 반응:** 누른 버튼의 시각적 반응은 즉각적이어야 한다(인지 목표 100ms 이내). 서버 처리는 별도 진행 중 표시. 중복 클릭 방지. 결과는 서버 검증 후 확정한다.
2. **명확한 상태:** 대기, 요청 전송, 처리 중, 완료, 실패, 확인 불가를 구분한다. 서버 타임아웃은 성공도 실패도 아닌 “확인 불가/재조회”이며 잔액이나 XP를 추정 증가시키지 않는다.
3. **퀘스트 카드 표준:** 이름, 완료 조건, 실제 근거, 2/5 같은 진행, 갱신 시각, 마감, 보상 유형, 유효 상태, CTA. 원천값 미확인은 0%가 아니라 “진행 정보 확인 불가”.
4. **레벨/경험치:** 기획 확정된 산식, 지급 한도, 리셋 기준, 서버 원천, 기록 저장, 중복방지 키가 마련되지 않은 항목은 실제 기능으로 출시하지 않는다.
5. **아이템/보상 연출:** 서버에서 획득이 확인된 시점에만 150~500ms 정도의 선택형 짧은 효과. 희귀도는 색뿐 아니라 글자와 아이콘으로도 표현.
6. **실시간 요소:** WebSocket 이벤트는 재조회 요청의 계기일 뿐 금융 거래 확정 증명이 아니다. 연결 단절 시 예전 데이터를 “현재”로 둔갑시키지 않는다.
7. **음향/진동:** 기본 끔, 사용자가 켜도록 하고 언제든 음소거 가능. 로그인·보안·금융 경고에는 예고 없는 소리나 자동 재생 금지.
8. **스트릭과 알림:** 참여 강요, 과도한 FOMO, 허위 마감 압박 금지. 복귀는 친절하게 안내하되 과거 미접속을 처벌하는 UI를 기본화하지 않는다.

## 5. 디자인·반응형·접근성

**스타일:** 고품질 경제 시뮬레이션·전략 게임의 몰입감 + 일상 앱의 빠른 조작. 공통 배경, 아바타·지도형 아이콘, 정돈된 카드, 프레임/희귀도, 작은 전환 애니메이션. 과도한 3D·상시 파티클·무거운 비디오 배경을 기본값으로 사용하지 않는다.

**제안 토큰(기존 구현값이 아닌 설계 기준):** 간격 4/8/12/16/24/32px, 모서리 12/16/20px, 모바일 본문 16px 이상, 터치 영역 최소 44×44px, 명확한 2px 이상 포커스 테두리, 데스크톱 콘텐츠 최대 폭 약 1200px. 컴포넌트: GameShell, WorldNav, PlayerIdentityCard, VerifiedBalanceCard, QuestCard, ObjectiveProgress, RewardReceiptToast, LocationTile, InventorySlotCard, RarityLabel, StatusBanner, PendingActionDialog, SourceFreshnessLabel.

**반응형:** 320px·200% 확대에서 가로 스크롤/금액 잘림/버튼 겹침/탭 누락이 없어야 한다. 360~767 휴대폰, 768~1023 태블릿, 1024 이상 PC 각각 확인한다. WCAG 2.2 AA 기준 키보드/스크린리더/명암 대비/포커스 이동/상태 알림/색에 의존하지 않는 경고 및 동작 줄이기를 반영한다.

**성능:** 저사양 모바일에서도 장면 이동과 스크롤이 부드러워야 한다. 효과는 정적 이미지·CSS 수준의 가벼운 대안 제공. 제안 목표: p75 모바일 LCP 2.5초 이내, INP 200ms 이내, 애니메이션으로 인한 메모리 5% 초과 회귀 없음(실측 전 목표치, 합격 사실 아님).

## 6. 서버와 실제 경제 기능 분리 정책

- **WLD는 실제 경제 원장 기준:** PostgreSQL의 검증된 이중기입 원장과 서버 권한을 우선하며, 잔액은 정수 문자열로 정확하게 표시한다. 프론트엔드 소수 실수 계산이나 서버 확인 없는 동적 숫자 증가는 금지한다.
- **아이템 소유·장착·유지비:** 캐릭터 슬롯 UI는 실제 유효한 보관함 정보만 사용. 만료/효과 만료/체납/정지 상태를 실제 값과 함께 표시한다. 기록 없음·정보 없음은 “정상 납부”, “영구”가 아니다.
- **퀘스트·레벨·업적:** 서버에서 계산하고 확인한 기록/지급 영수증만 인정한다. 특정 기능의 원천 API가 없으면 신규 API나 DB 함수 설계 검토가 선행되어야 하며, 기획서만으로 가짜 값을 연결하지 않는다.
- **보안:** 정상 인증 세션·동의·CSRF·소유자 확인·기능 스위치·재인증·관리자 권한을 우회하지 않는다. 민감 응답은 캐시 금지·검색 차단, 로그에는 개인정보와 원장 원문을 남기지 않는다.
- **장애 처리:** 401 인증 필요, 403 권한/동의, 409 충돌, 429 요청 제한, 503 데이터 소스 장애, 잘못된 응답/진짜 데이터 없음의 구분을 유지. 재로그인·계정 변경·오프라인 시 이전 사용자의 캐릭터/잔액/인벤토리가 노출되지 않는다.
- **현재 아키텍처:** 문서에는 과거 Nest/Next 구조와 최신 Spring 단일 런타임 설명이 공존한다. 코딩 전 실제 최신 실행/소스·API 경계를 확인한다. 이 문서는 특정 미검증 엔드포인트를 새로 약속하지 않는다.

## 7. AI 바이브 코딩용 단계별 개발 지시

| 단계 | 구현 작업 | 확인 조건 |
|---|---|---|
| GX-01 최신 기준 | 최신 GitHub main/통합문서/실제 Spring 및 Android 구성 분석, 기존 메뉴·API·기능 스위치 연결표 | 겹치는 기능 없음, 미구현 명시, 다른 AI 작업과 충돌 방지 |

**기능 스위치 제안:** game_like_app_shell (기본 OFF, **이번에는 추가하지 않음**). 개발은 소유자별 작업 브랜치로 분리하고 다른 개발자/Gemini의 변경을 덮어쓰지 않는다.

## 8. 테스트 시나리오·완료 판정

- 손님/회원/관리자 각각 잘못된 데이터·메뉴·권한 노출이 없는가?
- 지급 서버가 503이나 타임아웃일 때도 퀘스트 “완료!” 또는 WLD 증가 애니메이션을 재생하지 않는가?
- 동일 보상을 2회 누르거나 앱을 재시작해도 단 1건만 검증·지급되는가?
- 계정 A에서 B로 바꿨을 때 이전 지갑/아이템/레벨/통지가 섞이지 않는가?
- 320px/200%/다크 모드/키보드/스크린리더/동작 줄이기/영어·한국어에서 UI가 무너지지 않는가?
- 모든 주요 버튼이 실제 화면과 API에 연결되어 있으며 로딩·실패·재시도·확인 불가 상태가 정확한가?
- 테스트 서버와 운영 버전이 일치하며 이전 버전 복구 및 금융 원장 무변경이 확인되었는가?

모든 항목은 **향후 구현 시 검증해야 할 기준**이다. 현재 이 문서 작업에서 테스트·구현·실제 운영 배포가 완료되었다고 주장하지 않는다.
