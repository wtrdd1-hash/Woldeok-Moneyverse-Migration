## 0. 공통 개발 수용 계약
- 기능 요구는 실제 배포 경로 **호스트+HTTP 메서드+경로+보안 주체+DB 함수+기록자**를 먼저 매핑해 동등성을 검증한다. 과거 Nest 경로는 계약 참고이며 신규 구현은 Spring MVC/Security에서 소유권을 확인한다. Next.js/React BFF/SSR 및 Android 앱은 자바로 무조건 바꾸지 않는다. 경로당 활성 쓰기/스케줄 소유자는 한 명만 유지한다.
- 작업 분할: A=Next/웹 UX, B=Spring/DB/금융, C=Android/통합, QA=독립 검증. 공통 DTO와 오류코드 표를 PR 전 동결, 소유 모듈 중복 수정 및 운영 DB 직접 수정 금지.
- 회원 API는 실제 로그인 세션·동의·계정 식별에서 actor를 서버가 확정. 클라이언트 actor UUID/헤더 직접 신뢰 금지. 관리자는 별도 DB 검증 superadmin + MFA/CSRF + 최소 권한. 잘못된 인증/권한은 401/403, 재시도 제한 429, 원천 다운은 503이며 어떤 장애도 성공·빈 목록·0원으로 바꾸지 않는다.
- 읽기 API는 인증 경계, 고정 search_path, 최소 SELECT/EXECUTE 권한, `private,no-store`/`noindex,nofollow`/`no-referrer`를 **성공 및 오류 최종 HTTP**에서 검증. 공개 블로그만 캐시·색인 가능. 개인 UUID, 세션, 검색어, 서명 커서, 원장 개인 전표, 토큰, 전체 응답을 로그에 쓰지 않는다.
- WLD는 0 이상의 정규화된 10진 정수 문자열, DB NUMERIC/BIGINT 검증, 브라우저 BigInt 사용; JS Number/부동소수점·암묵적 소수 반올림 금지. UNKNOWN, VERIFIED_ZERO, VERIFIED_NONZERO, UNAVAILABLE, STALE 구분. 검증되지 않은 정산·납부·수익/보상·공개 품질을 VERIFIED로 표시 금지.
- DB 변경은 전방 마이그레이션만 사용; 기존 번호·체크섬 수정 금지. SECURITY DEFINER 고정 search_path·PUBLIC EXECUTE 회수·호출역할 제한·타인 접근 음성시험. GET·진단이 금융 쓰기/스케줄을 발생시키지 않도록 함.
- 모든 기능은 EN 정본/KO 대조, 320px·200% 확대·WCAG 2.2 AA·키보드/스크린리더·44px 터치·명시적 로딩/오류·계정 전환 중 오래된 응답 폐기. UI 기본 기능 플래그 OFF, 스테이징 합성 데이터 사용.
- 공통 완료 게이트: 변경 전후 main 재확인, 정확 SHA의 테스트, 정상/거부 권한·계정 전환·극한값·실패 주입·동시성·Android 동등성·실제 HTTP, DB 복제본·독립 백업복원, 회귀 CI, 공식 Test, 모니터링, 롤백. 실패 시 해당 기능 OFF 또는 이전 검증 아티팩트 복구; 금융 불일치·권한 우회는 모든 운영 승격 중단.

## 3. F675 주간 퀘스트 근거 조회
**목적:** /quests '근거 보기'에서 진행률의 **검증된 원천 집계**를 회원에게 설명. P1, v1508→v1510 기준; V1 보상 지급/소급 정정·금융 쓰기 불가.
**UI/API:** 현행 목표 코드+KST 주 시작으로 GET `/api/v1/engagement/early-game/weekly-evidence`(Spring 실제 라우트 충돌 확인 후 확정), Next/Android 동등. `{goalCode,weekStartKst,windowKind,weekEndExclusiveUtc,metric,target,progress,selfReported,sourceStatus,evidenceStatus,asOfUtcMicros,rows,nextCursor}`; 목록은 최대 50+1 키셋 페이지, 집계 총계를 페이지 합으로 만들지 않는다. NPC는 전체기간 MAX 관계값 자기신고 집계로 개인 영수증/목록이 없는 `AGGREGATE_ONLY/SELF_REPORTED` 상태.
**정합성:** 기존 SQL 101 `early_game_weekly_goals`과 **동일 읽기 트랜잭션·동일 KST 주·동일 기준시각**에서 목표별 네 원천의 집계·직업선정·WLD 타입을 대조한다. 기존 SQL은 주 하한만 포함하는 부분이 있어 임의로 주 상한을 '개선'하면 원본과 결과가 달라질 수 있다. 원본과 상세가 불일치하면 `503 PARITY_UNVERIFIED`, 주 경계 변경은 409, 원천/직업/소급변경은 409, 서명 커서 만료는 410. 기존 SQL을 수정하려면 원본·상세 동시 전방 마이그레이션과 기준 테스트 필수.
**세부 집계:** 직업은 현재 최고 레벨 우선·직업 타입 정렬; 작업은 DISTINCT task_id, 직업 영수증은 실제 행 수, 소비는 4가지 승인 거래유형, 예금은 지정된 입출금 USER_BANK 순액과 양수 클램프, NPC는 평생 MAX 친밀도(주간 영수증 아님). 원본의 통화/주 상한 누락을 상세에만 변경 금지. 모든 금액 10진 문자열.
**상태/인수시험:** 인증/동의/실제 빈 근거/자기신고/401/403/409/410/429/503/오프라인/계정 전환 분리; 위변조 커서·10,001 원천·경계 전후·직업 순위 변경·소급 전표·다른 회원·NPC 근거 없음·앱 캐시 음성시험. 플래그 `quest_weekly_evidence` 기본 OFF.

## 4. 블로그 미검증 글 공개 및 광고 정책
**목적:** 사용자 v1946.2 지시에 따라 사람 사전승인 없이 미검증 AI 생성 글도 **명시적인 공개 설정**인 경우 표시. 검증 상태를 위조하지 않는다. P1; 금융·계정·정부기금 데이터의 진실성 요구를 완화하지 않음.
**게시 상태 머신:** 작성중 DRAFT → 게시 의도 확인 → PUBLISHED 또는 철회 WITHDRAWN. 공개/철회와 검증 PASS/UNVERIFIED는 **독립 필드**. 검증 PASS는 기존 검증 DB+영수증 유지; 미검증은 블로그 전용 멱등 저장으로 근거·검증 결과·버전·원본 해시·공개 시각 기록. 변경/재시도 시 단일 article id/version으로 중복 발행 금지. 검증 실패를 PASS로 덮어쓰기 금지. 게시 전 필수 메타데이터·권한·슬러그 충돌·XSS·HTML sanitizer 검증.
**웹:** 공개 글만 SSR·피드·사이트맵·canonical·광고 대상으로 검토; DRAFT/WITHDRAWN은 공개 API·색인·피드에서 제외. 미검증 글에 눈에 보이는 'AI 생성·미검증' 라벨과 검증 관련 설명. 출처와 생성 콘텐츠를 구별하며 사용자 개인정보/비밀/원장·허위 수익 보장 표현을 걸러낸다. 철회 시 캐시 무효화·사이트맵 제거·404/410 정책 일관.
**광고:** 광고는 사용자의 정책상 허용이나 외부 네트워크(예: AdSense) 정책 준수 검증을 대체하지 않는다. 검토 없는 대량 자동생성 글은 광고 제한 위험; 광고 송출은 **별도 policyEligible 판정 플래그 기본 OFF**, 광고 없는 공개 경로 가능, 광고가 없더라도 글 공개 성공 처리와 독립. 광고 코드/개인정보 동의·법적 표시 및 CLS/LCP·robots 검증.
**보안/QA:** 비인증 게시/삭제 금지, HTML/MD 스크립트·이벤트 핸들러·악성 URL·프롬프트 인젝션/외부 이미지, 중복 재시도/동시 발행, 공개→철회, SSR·sitemap·robots·cache, 광고 차단/계정 위험, 관리자 감사 이벤트 확인. 플래그 `blog_unverified_publication` 기본 OFF; 활성화 정책은 명시 승인·Test 실측 후 판단. 금융 스케줄러 재활성화 금지.

## 5. 국고·원장 금융 정합성 및 안전한 관리자 진단
**목적:** 공개/관리자 지표가 실제 정식 원장에 합치되는지 확인하고 출처가 없는 거래·발권·지급을 금지. P0. 이는 단순 새 대시보드가 아니라 모든 금융 쓰기의 출시 게이트.
**정본:** `TREASURY:treasury`의 실제 정식 WLD 보관액과 정책/모형 AUM은 완전히 별개. 과거 국고 552 이벤트/공기업 배당 744, 이전 연금 238건, SWF 모델평가를 소급 원장으로 채우거나 출처 확인 없이 '집행 가능'으로 표시 금지. 조폐국 MINT 권한 없는 발권 금지. 새로운 연금의 정식 `ESCROW:national_pension_fund`와 welfare는 기존 미검증 예산과 분리한다.
**쓰기 경계:** 이미 승인된 `public.treasury_core_post(actor,idempotencyKey,command,integerWld)` → `economy_post_transaction`의 하나의 DB 트랜잭션에서 차변·대변 분개, 잔액, Outbox, 불변 영수증 생성. 클라이언트 actor/header 무시, 세션·MFA(관리자)·CSRF, DB 역할, 충분 잔액·상한·명령 허용목록, 인가된 단일 금융 기록자/fence 확인. 같은 키·같은 요청은 같은 영수증, 다른 금액 재사용은 충돌; 응답 타임아웃 재시도 중복 결제 금지.
**읽기/대사:** 정식 금융 계정잔액 vs 분개합계, 거래-분개 1:1 대응/복식합 0, 회원·국고·에스크로 음수/고아 계정, 승인된 외부 재원 출처와 회계기 분리, 이전 자료 격리, 집계 asOf 일치, 금액 정밀도·시각/타임존 일치. 결과 `VERIFIED`, `VERIFIED_ZERO`, `UNAVAILABLE`, `MISMATCH`, `HISTORICAL_UNVERIFIED`를 구분. 불일치/원천 다운이면 현황 '정상' 표시 및 금융 POST 자동 복구 금지.
**관리자 기능:** 출처 상태·마지막 원장 대사시각·일치/불일치 건수·상세한 비식별화 증빙 링크·차단 이유·읽기 전용 재검사 버튼. 임의 잔액 조정, 조폐, 수익 지급·리셋 기능은 기존 승인된 권한/정식 출처와 별도 구현·승인 없이는 비활성. 개인정보와 원장 raw row 외부 노출 금지. 관리자 조회도 실제 DB superadmin 세션·MFA·CSRF를 확인; fail-closed.
**QA/출시:** 격리 PostgreSQL에 합성 입금/출금/잔액부족/동일키 중복/다른 금액 키 재사용/동시 100건/타임아웃 후 재시도/교차 계정/큰 정수·overflow/구 회계기/원장 고아/전표 불균형/스케줄 두 기록자/백업복원·권한 차단 주입. 전체 금전 변동은 대조된 정식 영수증으로 입증. 공식 Test 정확 SHA + 권한 있는 실제 테스트 세션 + 독립 복원 + 배포 롤백 증거가 없으면 Production HOLD. 실제 회원 잔액으로 테스트하지 않는다.
