# 월덕 머니버스 — 서버 게임 시계 명세

> 버전: v2026.09.15.114
> 상태: 구현 지향형 런타임 계약
> 기준일: 2026-09-15
> 영문 기준 문서: [SERVER_GAME_CLOCK_SPEC.md](SERVER_GAME_CLOCK_SPEC.md)

## 1. 목적

머니버스는 반복 플레이 제한과 로테이션을 위해 현실 달력과 분리된 가속형 게임 달력을 사용합니다. 게임 시계는 서버가 권위를 가집니다.

기본값:
- 현실 10분 = 서버 1일;
- 서버 7일 = 서버 1주;
- 따라서 현실 70분 = 서버 1주;
- 기준 epoch: 2026-09-15 00:00:00 KST;
- 정책 버전: `v2026.09.15.114`.

목표는 실제 하루를 기다리지 않아도 일일/주간 루프에 다시 참여할 수 있게 하면서, 서버 전체가 `오늘`과 `이번 주`를 하나의 기준으로 계산하도록 만드는 것입니다.

## 2. 권위 데이터 모델

`server_game_clock_policy`가 epoch, 서버 1일의 현실 초, 주당 서버 일수, 정책 버전을 소유합니다. 앱 역할은 SECURITY DEFINER 함수를 통해 시계를 읽을 수 있지만 정책 테이블을 직접 수정할 수 없습니다.

권위 함수:
- `server_game_clock(at)` — 서버 일/주 인덱스와 경계 시각;
- `server_game_day_key(at)` — 일 단위 레코드용 안정적 synthetic date key;
- `server_game_week_key(at)` — 주 단위 레코드용 안정적 synthetic date key;
- `server_game_day_start(at)` — 현재 서버 하루가 시작된 현실 시각;
- `server_game_week_start(at)` — 현재 서버 한 주가 시작된 현실 시각.

## 3. v2026.09.15.114 적용 범위

가속 서버 시계 적용 대상:
- 작업별 일일 완료 제한과 작업 보상 일/주 윈도우;
- 상점 카탈로그 `daily_N`, `weekly_N` 구매 제한;
- 인증된 카지노 화면에서 표시하는 게임 세계 시간 정보.

가속 서버 시계 미적용 대상:
- 카지노 보호용 일일 베팅/손실 한도;
- 카지노 자가제외·cooling-off 잠금;
- 인증/세션 만료, 비밀번호·이메일 검증, 보안 cooldown;
- 감사 보존, 백업 일정, 법률·규제 보존기간;
- 현실 연령·지역·스토어 배포 요건.

카지노 보호 한도는 현실 날짜 기준 안전장치로 유지합니다. 이를 10분마다 초기화하면 현실 하루 노출량이 크게 증가해 카지노 안전 명세와 충돌합니다.

## 4. UX 계약

현실 시간과 혼동될 수 있는 화면은 `서버 하루`, `서버 주`라고 명시합니다. 다음 경계의 고정 시각은 보여줄 수 있지만 카지노 화면에서는 베팅 압박을 만드는 실시간 카운트다운을 사용하지 않습니다.

카지노 시각 개선은 게임 구분, 결과 가독성, 즐거운 표현을 강화할 수 있지만 손실 만회 문구, near-miss 조작, 연승 압박, 긴급성 유도, 더 좋은 확률을 암시하는 CTA는 사용하지 않습니다.

## 5. 마이그레이션·롤백

`190-server-game-clock.sql`은 forward-only입니다. 정책 테이블을 버전 관리하고 Test/Production에서 동일한 epoch를 사용합니다. 운영 롤백 시 이미 적용된 마이그레이션 기록을 수정하지 않으며, 필요하면 후속 마이그레이션으로 주기나 정책 버전을 변경합니다.

Production 승격 전 Test 수용조건:
1. epoch + 00:10은 서버 day index 1이어야 함;
2. epoch + 01:10은 week index 1 / day 1이어야 함;
3. 작업 보드와 작업 완료가 같은 서버 하루 경계를 사용해야 함;
4. 상점 일/주 제한이 같은 서버 day/week 시작점을 사용해야 함;
5. 카지노 보호 한도는 현실 날짜 기준을 유지해야 함;
6. 보안·자가제외 등 현실시간 제어에는 가속 시계를 사용하지 않아야 함.
