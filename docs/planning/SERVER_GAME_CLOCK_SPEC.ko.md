# 월덕 머니버스 — 서버 게임 시계 명세

> 버전: v2026.09.15.114
> 상태: 구현 지향형 런타임 계약
> 기준일: 2026-09-15
> 영문 기준 문서: [SERVER_GAME_CLOCK_SPEC.md](SERVER_GAME_CLOCK_SPEC.md)

## 1. 목적

머니버스는 반복 플레이 제한과 로테이션을 위해 현실 달력과 분리된 가속형 게임 달력을 사용합니다. 게임 시계는 서버가 권위를 가집니다.

기본값:
- 현실 10분 = 서버 1일;
- 서버 7일 = 서버 1주;
- 따라서 현실 70분 = 서버 1주;
- 기준 epoch: 2026-09-15 00:00:00 KST;
- 정책 버전: `v2026.09.15.114`.

목표는 실제 하루를 기다리지 않아도 일일/주간 루프에 다시 참여할 수 있게 하면서, 서버 전체가 `오늘`과 `이번 주`를 하나의 기준으로 계산하도록 만드는 것입니다.

## 2. 권위 데이터 모델

`server_game_clock_policy`가 epoch, 서버 1일의 현실 초, 주당 서버 일수, 정책 버전을 소유합니다. 앱 역할은 SECURITY DEFINER 함수를 통해 시계를 읽을 수 있지만 정책 테이블을 직접 수정할 수 없습니다.

권위 함수:
- `server_game_clock(at)` — 서버 일/주 인덱스와 경계 시각;
- `server_game_day_key(at)` — 일 단위 레코드용 안정적 synthetic date key;
- `server_game_week_key(at)` — 주 단위 레코드용 안정적 synthetic date key;
- `server_game_day_start(at)` — 현재 서버 하루가 시작된 현실 시각;
- `server_game_week_start(at)` — 현재 서버 한 주가 시작된 현실 시각.

## 3. v2026.09.15.114 적용 범위

가속 서버 시계 적용 대상:
- 작업별 일일 완료 제한과 작업 보상 일/주 윈도우;
- 상점 카탈로그 `daily_N`, `weekly_N` 구매 제한;
- 인증된 카지노 화면에서 표시하는 게임 세계 시간 정보.

가속 서버 시계 미적용 대상:
- 카지노 보호용 일일 베팅/손실 한도;
- 카지노 자가제외·cooling-off 잠금;
- 인증/세션 만료, 비밀번호·이메일 검증, 보안 cooldown;
- 감사 보존, 백업 일정, 법률·규제 보존기간;
- 현실 연령·지역·스토어 배포 요건.

카지노 보호 한도는 현실 날짜 기준 안전장치로 유지합니다. 이를 10분마다 초기화하면 현실 하루 노출량이 크게 증가해 카지노 안전 명세와 충돌합니다.

## 4. UX 계약

현실 시간과 혼동될 수 있는 화면은 `서버 하루`, `서버 주`라고 명시합니다. 다음 경계의 고정 시각은 보여줄 수 있지만 카지노 화면에서는 베팅 압박을 만드는 실시간 카운트다운을 사용하지 않습니다.

카지노 시각 개선은 게임 구분, 결과 가독성, 즐거운 표현을 강화할 수 있지만 손실 만회 문구, near-miss 조작, 연승 압박, 긴급성 유도, 더 좋은 확률을 암시하는 CTA는 사용하지 않습니다.

## 5. 마이그레이션·롤백

`190-server-game-clock.sql`은 forward-only입니다. 정책 테이블을 버전 관리하고 Test/Production에서 동일한 epoch를 사용합니다. 운영 롤백 시 이미 적용된 마이그레이션 기록을 수정하지 않으며, 필요하면 후속 마이그레이션으로 주기나 정책 버전을 변경합니다.

Production 승격 전 Test 수용조건:
1. epoch + 00:10은 서버 day index 1이어야 함;
2. epoch + 01:10은 week index 1 / day 1이어야 함;
3. 작업 보드와 작업 완료가 같은 서버 하루 경계를 사용해야 함;
4. 상점 일/주 제한이 같은 서버 day/week 시작점을 사용해야 함;
5. 카지노 보호 한도는 현실 날짜 기준을 유지해야 함;
6. 보안·자가제외 등 현실시간 제어에는 가속 시계를 사용하지 않아야 함.

## 6. 머니버스 연도 확장 — v2026.11.26.GAMEYEAR.1 (기획 후보)

사용자 요청: 서버 고유 연도 추가. 구현 전 검토할 고정 365일 달력 제안이며, 기존 epoch(2026-09-15 00:00 KST), 현실 600초/일, 연속 7일 주차와 기존 일/주 키를 보존한다. 현실 그레고리력이 아닌 논리 달력이며 윤일·0년·월 정의는 이번 범위에 없다. epoch가 서버 1년 시작점이며 기존 세계는 원래 epoch에서 연도를 산출한다. 배포·재시작·시즌 전환 시 초기화 금지.

- 서버 권위 0기반 dayIndex d >= 0일 때 yearIndex = floor(d / 365), gameYear = yearIndex + 1, dayOfYear = (d mod 365) + 1. epoch 이전은 공개 연도 없음. 1년은 현실 219000초(60시간 50분). 시작 = epoch + yearIndex * 219000초, 종료 = 시작 + 219000초, 시작 포함/종료 제외 구간. 주는 연도에 걸칠 수 있으며 전역 일/주 인덱스는 초기화하지 않는다. SQL synthetic date key는 표시 연도가 아니다.
- 기존 game-clock API에 calendarVersion, gameYear, dayOfYear, gameDaysPerYear, realSecondsPerGameYear, yearStartedAt, yearEndsAt, observedAt 추가 제안(경계와 관측 시각은 현실 ISO-8601). 기존 일/주 필드 유지. 웹 BFF, 앱, Discord는 동일 Spring/DB 권위 사용. 클라이언트 날짜로 연도 임의 계산·가짜 fallback·오래된 성공 표시 금지. 실패 시 조회 불가 또는 마지막 검증값과 지연 표시, 경계/재접속/포커스 시 재조회. 영어 기본("Moneyverse Year 28 · Day 1"), 한국어 두 번째("머니버스 28년 · 1일차"), 나머지 지원 언어 보존. 공통 헤더, 모바일 내비게이션, 대시보드, 관련 게임 통계에 연도·일차·기존 주차를 표시하고 현실 시각과 구분한다. 카지노 베팅 긴급성 유도 금지.
- epoch + 218999초: 1년 365일차; +219000초: 2년 1일차; +219001초: 2년 1일차. dayIndex=365*27이면 28년 1일차. 단일 DB 관측값 및 버전별 불변 과거 매핑 사용. 정책 변경에는 적용 경계·시간 연속성·마이그레이션 승인 필요, 과거 영수증 재해석 금지.
- 최초에는 조회/표시 전용. 연도별 통계는 검증된 경계로 기존 이벤트를 집계할 수 있다. 연간 자동 지급·세금·배당·채권이자·계정/시즌 초기화·만기·이율 변경 없음. E542-04는 상품별 금리 기준·복리·반올림·재원·별도 승인 전까지 BLOCKED 유지. 인증·보안·카지노 보호·법률/동의·백업·감사 시각은 현실시간 유지.
- 소스 결함: Spring GameClockService.current()의 DB 오류 catch가 ok=true, dayIndex=42, realSecondsPerDay=14400 가짜 값을 반환하고 null 경계도 대체한다. 연도 출시 전 제거하고 오류 시 성공으로 표시하지 않는 테스트 필요. 소스 확인이며 실제 운영 장애 확인은 아님.
- 구현 순서: GAMEYEAR.2 forward-only DB 연도 읽기 함수 및 경계 회귀(190 수정 금지); GAMEYEAR.3 Spring DTO/service/controller, 실패 및 호환성 테스트; GAMEYEAR.4 웹/앱/Discord 계약·다국어 공통 헤더·반응형·재접속 QA; GAMEYEAR.5 실제 DB 독립 Test에서 동일 아티팩트, 재시작·시간 오차·중복 경계·일/주·금융·보호 회귀 검증. 별도 운영 승인 후 무중단 승격/롤백 증거 필요. 별도 승인 없는 데이터 변환 금지. 이번 기획만으로 런타임·금융 변경을 승인하지 않는다.
