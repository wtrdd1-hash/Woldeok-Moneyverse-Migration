# 런타임 로그 보관·압축·관리자 조회 정책 — v2026.11.17.3

**상태:** PLANNING / DRAFT — 미구현, 테스트/운영 미검증.
**근거:** 2026-11-17 KST 사용자 지시. 이 작업 브랜치의 프로젝트 통합기획서에 명시적으로 반영하는 상세 후보.
**언어:** [영문 정본](RUNTIME_LOG_RETENTION_ADMIN_CONSOLE_v2026.11.17.3.md) / 한국어 대응본.
**범위:** Nginx, Spring Boot API/백엔드, Next.js 프론트엔드(서버 로그), 전환 완료 전의 NestJS 구 백엔드. 운영 로그는 PostgreSQL 데이터베이스 백업이나 불변 경제 원장이 아니다.

## 1. 분류와 보관 기간

기준 시각은 **파일 생성일이 아닌 각 로그 이벤트의 UTC 발생 시각**이다. 수집 때 서비스·이벤트 유형별 허용 목록으로 분류하며 중요도로의 승격을 기록하고, 로테이션으로 보관 기간을 초기화하지 않는다.

| 로그 출처 | 일반 로그 — **7일(7×24시간)** | 중요 로그 — **30일(30×24시간)** |
| --- | --- | --- |
| Nginx | 개인정보 최소화한 접근/요청 성능, 정상 상태, 통상 경고 | ERROR/CRITICAL/PANIC, 서비스 중단, 보안 공격·비정상 5xx 폭증 등 사고 |
| Spring Boot 백엔드/API | 앱 INFO/WARN, 상태·지연·일반 요청 메타데이터 | 처리되지 않은 예외, 중요 API/DB 장애, 인증·OTP 실패, 권한 상승 시도, 관리자 중요 명령, 금융·보안 사고 |
| Next.js 프론트엔드 서버 | SSR/BFF INFO/WARN, 일반 렌더링·라우팅 이벤트 | SSR/BFF 중대 오류, 보호 경로 장애, 개인정보 유출 가능성, 서비스 가용성 사고 |
| NestJS 기존 백엔드(전환 중) | 동일한 일반 백엔드 기준 | 동일한 중요/보안 기준, 서비스 간 추적 ID 유지 |

브라우저 개발자 콘솔 출력은 서버가 자동 저장하는 로그가 아니다. 클라이언트 오류 수집은 별도 도입·개인정보 검토·동의/최소화·샘플링 후 동일 정책을 적용한다.

단순히 메시지에 `ERROR` 문자열이 있다는 이유만으로 분류하지 않고 **심각도와 보안·업무 영향**으로 판정한다. 일반 7일, 중요 30일을 고정 기본값으로 하며 **기한 전 임의 삭제·무단 연장 금지**. 법적 보존 및 사고 증거 격리는 별도 승인·사건번호·보관 책임자·암호화·접근 감사·만료 재검토가 있는 격리 사본으로 관리하며 기본 보관 기간을 무제한 연장하는 것이 아니다.

**예외:** PostgreSQL 금융원장·불변 감사기록·규제상 의무 기록·DB 백업은 별도의 정합성 및 백업 정책 대상이다. 여기서 이 데이터 삭제나 백업 주기를 변경하도록 승인하지 않는다.

## 2. 수집·로테이션·압축·만료 처리

1. Nginx 접근/오류, Spring, Next.js, 전환 중 NestJS를 고정된 출처 ID로 수집·조회한다. UTC 시각·심각도·서버 환경(Test/Production)·인스턴스·상관관계 ID·이벤트 유형·마스킹한 메시지로 구조화한다. 비밀값 원문은 저장 전에 제외한다.
2. Nginx 파일은 **매일 또는 용량 임계값 도달 시** 순환한다(초기 제안: 파일당 20 MiB, 실측 후 확정). Nginx의 재열기 신호를 사용하여 쓰는 중인 파일을 임의 truncate하지 않는다. Spring/Next/기존 백엔드가 journald를 사용하는 경우 수집 체크포인트와 저장소를 분리한다. **journalctl/journald만으로 심각도별 7/30일 검색 보관을 보장할 수 없다.** journald 자체 상한도 별도 정한다.
3. 닫힌 로그 파일은 **24시간 이내 zstd 압축**(호환성 필요 시 gzip), 체크섬 검증·원자적 치환·복구 가능한 색인을 적용한다. 현재 기록 중인 파일은 압축하지 않는다. 색인에 시간 범위·분류·커서를 보존하며 관리자 검색 시 자원 제한 내에서 압축 해제한다.
4. 일반 이벤트 `발생 시각+7일`, 중요 이벤트 `발생 시각+30일`에 만료된다. 삭제 작업을 최소 매일 실행하여 물리적 정리 지연을 최대 한 번의 작업 주기로 제한한다. 같은 파일에 두 분류가 섞였으면 **분리/재패킹**하고 보존 기한이 남은 중요 기록을 통째로 삭제하지 않는다. 만료 정리 수량·경계·검증 결과·실행자는 중요 감사 로그에 남긴다.
5. 시각 오류, 압축/체크섬 오류, 누락, 수집기 중단, 권한·디스크 부족은 `DEGRADED`/`UNAVAILABLE`로 표시한다. 데이터가 없다는 뜻인 `EMPTY`로 위장하거나 중요 기록을 조기 삭제하지 않는다. 모호한 이벤트는 제한 구역에서 확인한다.

**용량 정책:** 실제 로그 발생량·압축률·디스크 가용량·DB 백업 여유·검색 압축 해제 부하를 G0 단계에서 먼저 측정한다. 잠정 방침은 로그 전용 저장소를 할당 볼륨의 10% 이내로 설정하고 60/75/85% 경고, 90% 긴급 대응이다. 중요 로그 30일을 우선 보장하고 일반 소음 로그의 수집량을 제한한다. 용량이 부족해 30일을 지킬 수 없으면 무단 삭제가 아니라 **배포 차단(BLOCKED)** 및 저장공간/구조 조정을 요구한다. 압축률은 실측치로 관리하며 임의 보장 수치를 제시하지 않는다. Test와 Production은 접근 권한·저장 경로·쿼터를 분리한다.

## 3. 관리자 로그 이력 조회 및 실시간 보기

- 위치: 기존 `/admin/logs/system`. Nginx/백엔드/프론트엔드 출처 선택, Test/Production 구분, 일반/중요, 심각도, 시각 구간(저장 UTC·화면 KST), 키워드/요청 ID 검색, 수집 최신 시각·압축 상태·오류 상태를 표시한다.
- 이력 조회: 서버 측 안정적 커서 페이지네이션, **요청당 최대 500건**, 허용된 기간만 탐색한다. 일반은 최근 7일, 중요는 최근 30일이며 만료 기록을 되살리지 않는다. 검색·압축 해제 시간/메모리/IO를 제한한다.
- 실시간: 인증된 **SSE 우선**, 불가 시 **5초 폴링 대체**. 정상 Test 조건에서 표시 지연 **5초 이내 목표**(실제 테스트 필요). 복구 가능한 불투명 커서·재연결·중복 제거·유실 구간 알림·버퍼/동시 연결 제한. `LIVE`, `RECONNECTING`, `DEGRADED`, `SOURCE_UNAVAILABLE`, `NO_MATCH`를 구분하며 장애를 가짜 정상 로그로 대체하지 않는다. 로그아웃/권한 만료/화면 이동 시 연결을 끊는다.
- 접근 보안: 검증된 `SUPER_ADMIN` 또는 공식 승인된 동등 권한. 중요/보안 로그 열람과 내보내기는 **최근 발급한 추가 OTP 인증**(디스코드/텔레그램 기존 기획 활용)을 요구한다. 실제 로그인 세션·관리자 권한·CSRF 정책을 프론트 페이지, 서버 액션, Spring API에서 **각각 검증**한다. `x-internal-token` 헤더만으로 관리자 인증 불가. 외부 입력으로 임의 파일경로나 셸 명령을 받지 않고 읽기 전용 최소 권한 수집자와 허용 목록만 사용한다.
- 개인정보 보호: 토큰·쿠키·OAuth·OTP·비밀번호·요청 본문·재무 계정번호·불필요한 IP/회원식별자 등은 **수집 전과 표시/내보내기 전 이중 마스킹**하고 가급적 상관관계용 비식별 ID를 사용한다. 검색엔진/CDN/브라우저 영속 캐시 금지(`no-store`, `noindex`). 평문 내보내기는 기본 OFF, 승인할 경우 OTP 재확인·크기 제한·목적 감사·짧은 다운로드 만료를 적용한다.
- 관리자 로그 열람/검색/추출, 인증 실패, 분류/보관 정책 변경, 압축·삭제·수집 실패를 **중요 감사 로그 30일**로 별도 기록한다. 관리자는 조회화면에서 임의 수정/삭제할 수 없다. 속도 제한·SSE 연결 제한·검색 정규식/ANSI/HTML 인젝션·로그 기반 XSS 대응을 필수화한다.

- **Spring:** 고정된 출처 등록표, 최소 권한 API, 7/30일 이력 검색, SSE/폴링, 마스킹, 커서, 상태 코드 구분을 구현하고 직접 API 인증·보안 음성 테스트를 실시한다. 기존 `SystemLogService`가 `tail`/`journalctl`을 읽는 기능만으로는 30일 이력·압축·실시간 연결·보관 정책을 달성했다고 간주하지 않는다.
- **Next.js:** 키보드/스크린리더 접근성, 320px/200% 확대, 한국어/영어, 안전한 검색·필터·실시간 상태·연결 종료, `no-store`/`noindex`, 오염 데이터 표시 방어를 검증한다.
- **마이그레이션:** Nginx → Next → Spring/Nest 상관관계 ID 유지. 금융 단일 실행자나 데이터베이스 기록 보존 정책 변경은 범위 밖이다.
