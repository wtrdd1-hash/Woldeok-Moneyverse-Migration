## SEO + SEO backend concrete contract
Public profile/community/gallery/catalog/help/durable-search pages: stable lowercase slug URL; unique title/meta/H1; self-canonical; index/follow only when public and substantive; sitemap entry with authoritative `lastModified`; breadcrumb/internal real `href` links; OG/Twitter; only Google-supported JSON-LD matching visible content; descriptive image alt and dimension metadata; hreflang for actual translated equivalents; permanent moves use redirect-map-backed 301/308; deleted durable content uses 410 when intentionally gone; filters/query variants canonicalize or noindex according to unique-value policy. Private account/admin/security/transaction/private-upload pages require authorization and `noindex` and are excluded from sitemap.

Backend components: `SeoPageReadModel`, `CanonicalUrlService`, `StructuredDataSerializer`, `SitemapShardService`, `RobotsPolicyService`, `RedirectMap`, `SearchEvidenceStore`. `SeoPageReadModel` returns locale, canonical, title, description, headings, indexability reason, updatedAt, images and schema payload source IDs. Sitemap generation must emit only 200-indexable canonical URLs and shard before protocol limits; cache keys include locale+content version+policy version. Release tests compare server HTML and hydrated DOM, canonical consistency, sitemap membership, private URL exclusion, redirects, hreflang reciprocity, schema-visible-content parity and crawler resource access. KPI funnel: impressions -> organic visit -> signup -> activation -> D7/D30 -> net revenue; SEO scale only when incremental acquisition improves without thin-content, crawl-error or conversion-quality regression.
