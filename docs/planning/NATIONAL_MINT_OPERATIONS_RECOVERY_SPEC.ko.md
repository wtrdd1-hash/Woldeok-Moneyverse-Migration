## 1. 장애 접수, 검증 사실, 사용자 영향

사용자가 국가조폐국 관련 기능이 작동하지 않는다고 신고했다. 첨부된 모바일 화면에는 ‘정책 DB 조회 완료’, ‘승인된 정책 명령 1건’, ‘즉시 주조 가능’, ‘20초 자동 동기화’, 신규 통화 주조·화폐 영구 소각·긴급 발행 동결 버튼이 표시된다. **정책 조회 성공과 승인 명령 존재는 실제 WLD 주조 성공의 증빙이 아니다.** 화면은 사용자 신고 증거일 뿐, 인증된 운영 POST 응답이나 원장 증빙까지 직접 확인한 것은 아니다.

2026-11-07 소스 확인: 구형 /api/v1/mint/batches 및 /burn POST는 LEGACY_MONETARY_AUTHORITY_UNVERIFIED 상태로 실행을 차단한다. 구형 MintService에는 메모리 기반 예시 발행/소각이 있으며 실제 운영 금액으로 사용하면 안 된다. 별도 통화정책 경로에는 정책 승인, 발행 한도 예약, 조폐·소각 증명서 DB 기록과 발행 동결이 있다. 그러나 mint-bureau.service.ts의 해당 SQL에는 **공식 복식부기 원장, 수취 사용자 WLD 잔액 변화, 원장 증명서까지 단일 트랜잭션으로 보장하는 절차가 확인되지 않았다.** 인증서 존재 자체를 화폐 집행으로 표현해서는 안 된다. 공동 작업 폴더에는 미커밋 화면/BFF 코드가 있으며 실제 Test/Production 배포 여부는 미확인이다. 증명서 BFF는 조회 실패를 빈 배열로 바꾸는 코드가 있어 장애가 0건으로 오인될 위험이 있다.

유저 영향: 운영자가 미집행을 집행 성공으로 오해할 수 있고, 유저에게 실제 WLD 잔액이 반영되지 않을 수 있다. 기존 금융기록을 재실행하거나 데이터 초기화로 숫자만 맞추면 안 된다. 서버가 active라고 해서 금전거래가 정상이라는 증거는 아니다.

## 2. 시스템 권한 분리·불변 조건

기존 [중앙은행·조폐국·국고·경제코어 기획](CENTRAL_BANK_MINT_TREASURY_ECONOMY_CORE_SPEC.ko.md)을 준수한다. 중앙은행은 정책 승인, 조폐국은 승인된 명령 집행, 국고는 기존 자산 집행, 경제 무결성 코어는 복식부기 및 수치 대사 담당이다. **정책 사용량 예약 + 적합한 원장 차변·대변 분개 + 수취/지급 계좌 잔액 + 불변 거래 영수증 + 주조/소각 증명서 + 알림 발송 예약**을 하나의 DB 커밋으로 결속한다. 단계 중 하나라도 실패하면 모두 롤백한다. 인증서만 생성된 기록은 검증되지 않은 것으로 분류한다.

화폐 공급량 변화 = 정식으로 증명된 신규 발행 - 정식으로 증명된 영구 소각. 세금·국고 지출·사용자 간 이체·연금·국부펀드 이동은 통화 총공급을 변경하지 않아야 한다. 모든 통화별 원장 차변·대변 합은 거래별로 일치하고, 계좌 잔액은 원장에서 재계산한 결과와 일치해야 한다. 지급 전후 금액 보전, 음수 가용잔액 방지, 재시도 중복 발행 방지, 근거 없는 화폐 생성 금지. 금액은 1 WLD 최소 정수, DB numeric과 BigInt 또는 정수 문자열을 사용하고 JS Number 부동소수 계산 금지. 국고 잔액이 0이라고 임의로 주조해서는 안 되며 신규 공급은 독립적으로 승인된 정책·계정·원장 근거가 필요하다.

기존 적용 SQL 변경 금지. 신규 마이그레이션 번호는 동시 작업자와 조정한다. 금융코어는 내부 DB 소유 SECURITY DEFINER, 고정 search_path, 인증 세션에 연결된 행위자, 행 잠금, 일관된 잠금 순서와 실행 제한으로 구현한다. 외부에서 원장 쓰기 함수 또는 테이블 DML 직접 호출 금지. 애플리케이션 역할은 최소 EXECUTE 권한만 부여하며, 실제 DB 권한을 부정 테스트한다.

## 4. 화면 흐름·상태머신·에러 처리

상태 증거의 순서: UNKNOWN → POLICY_READ_VERIFIED → ORDER_APPROVED → PREFLIGHT_VERIFIED → SETTLEMENT_COMMITTED → PROJECTION_RECONCILED → CERTIFICATE_VERIFIED. **이 순서는 증빙 상태이지 무조건 자동 승인 절차가 아니다.** 장애 상태는 FROZEN / STALE / BLOCKED / UNVERIFIED로 표시하고 확인할 수 없는 원장은 VERIFIED_EMPTY(확인된 0건)로 표현하지 않는다.

- 관리자 탭: 종합현황 / 정책 명령 / 신규 주조 / 영구 소각 / 인증서 / 원장 대사 / 장애 이력.
- 신규 주조: 유효한 승인명령 선택 → 수취인·출처·정수 금액 확인 → 사전검증 해시·요약 출력 → 독립 승인자 검토 → 최종 문구 입력 확인 → 인증된 단일 POST → 원장 거래·인증서 원본 확인. 브라우저 시간초과 후 POST를 자동 반복하지 않고 멱등키로 진행 상태를 조회한다.
- 영구 소각: 출처별 실제 사용 가능 자금 확인 → 승인 및 소각 한도 → M0/공급량 영향 미리보기 → 별도 승인 → 단일 정산 후 증명서. 국고 총계만 보고 임의 source_type 선택하지 않는다.
- 긴급 동결: 서버 확인 상태, 변경자, 이유, 시각, 정책 버전, 실제 적용 범위와 진행 중 요청 처리 방식을 표시. 해제는 새로운 독립 승인 및 사전검증을 요구한다.
- 인증서 상태: PROVEN_CANONICAL / CERTIFICATE_ONLY / LEGACY_UNVERIFIED / SOURCE_UNAVAILABLE, 원장 ID·정책 ID·SHA256·검증 시각 포함. 모든 관련 조회가 성공해야 VERIFIED_EMPTY를 표시한다.
- 20초 갱신은 읽기 모델에만 적용. 최근 성공 시각, 신선도, 부분 장애를 분리. 503을 빈 배열이나 0으로 바꾸지 않는다. 로그아웃·계정 전환 시 이전 요청 취소/결과 폐기, 개인 데이터 캐시 금지, no-store/noindex.
- 회원 영향 화면: 실제 입금액/잔액과 원장 영수증이 정합할 때만 ‘지급 완료’ 표시, 그 이전은 ‘검증 대기’ 또는 ‘오류’ 안내.

## 5. 세부 API 및 데이터 계약 초안

아래 경로는 **신설 제안**이며 실제 서비스에 구현되었다는 의미가 아니다.

| 기능 | 제안 HTTP 경로 | 데이터 계약 |
| --- | --- | --- |
| 관제 | GET /api/v1/admin/mint-v2/readiness | sourceStatus, asOfUtc, policyRevision, ledgerVerified, certVerified, freeze, blockers[] |
| 명령 | GET /api/v1/admin/mint-v2/orders | 커서 기반 한도 있는 목록, 상태, 잔여금액 문자열, 승인 증적 |
| 실행 예비검증 | POST /api/v1/admin/mint-v2/operations/preflight | 검증 전용 nonce, 요청 해시, 만료시각, 차단 원인, DB 변경 없음 |
| 원장 집행 | POST /api/v1/admin/mint-v2/operations | MINT/RETIRE, orderId, 출처, 수취인, 정수문자열 amount, UUID 멱등키, 사전검증 해시 |
| 집행 증빙 | GET /api/v1/admin/mint-v2/operations/:id | ledgerTxId, 차변·대변 검증 해시, 계좌 증감, certId, 실제 커밋 상태 |
| 2인 결재 | POST /api/v1/admin/mint-v2/orders/:id/approve | 독립 최종 승인자 및 정책 버전 확인 |
| 긴급 정지 | POST /api/v1/admin/mint-v2/freeze | freezeType, reason, ticket, expiry, 2인 해제 |
| 증명서 | GET /api/v1/admin/mint-v2/certificates | 검증 상태·기간·커서·가린 감사 출력 |
| 대사 | GET /api/v1/admin/mint-v2/reconciliation | 동일 스냅샷 공급량·분개·불일치 분류 |

기존 구형 차단(503)은 실제 안전 대체 경로가 완료될 때까지 유지한다. 공통 응답에는 status, code, evidence, requestId, asOfUtc; 금액은 정수 10진 문자열. 400 입력 오류, 401 세션 만료, 403 관리자·CSRF·동의 거부, 409 멱등키 본문 충돌/정책 버전 변경, 410 승인/사전검증 만료, 422 무자금·불일치·정책 초과, 423 동결, 429 과다호출, 503 원천 DB/원장 장애로 명확히 분리한다. 인증되지 않은 사용자에게 내부 계정·원장 기밀을 노출하지 않는다.

DB 연계 설계: monetary_policy_orders → monetary_policy_approvals(서로 다른 두 승인자) → monetary_execution_attempts(멱등키·요청 해시·상태) → 원장 거래 및 최소 2개 분개 → 불변 발행·소각 증명서(고유 거래·원장 연결, 해시) → outbox 이벤트 → 감사 로그. 멱등키 고유 제약, amount>0, 유효 정책 상태·버전·기한, 원장 참조와 중복 분개 금지. 구형 이력은 수정 없이 분리, 필요한 이관은 승인된 별도 감사 작업으로 처리한다.
