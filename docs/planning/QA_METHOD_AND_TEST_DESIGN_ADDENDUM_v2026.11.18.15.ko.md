## 2. QA 필수 절차 12단계

|---|---|---|
| 01 요구 분석 | 최신 통합기획·기능·라우트/API·Spring 이관 소유권·보안/금융 불변조건·관리자·Android·Discord 계약 확인. 메인 변경 비교. | 요구사항 ID와 TC 추적표, 불확실성 명시 |
| 02 테스트 계획 | 정확한 후보 SHA, 범위, 위험, 담당자, 역할, Test 환경, 독립 롤백, 시작/종료 조건과 자원 한계 확정. | P0 차단 항목을 포함한 테스트 계획 |
| 03 시나리오 | 성공·거부·빈 값·로딩·부분 데이터·지연·타임아웃·동시 처리·오프라인·계정 전환·복구 경로 설계. | 정상/비정상/회복 시나리오 목록 |
| 04 TC 설계 | 동등 분할·경계값·결정 테이블·상태 전이·페어와이즈, API 응답과 실제 DB 부작용을 함께 검증. | TC ID, 준비, 입력, 실행, 예상 UI/API/DB 결과, 정리 |
| 05 환경 준비 | Test 엔드포인트·프론트+Spring+Nginx 실제 SHA·DB 계약·운영 쓰기 차단·전용 픽스처 확인. | 신원·설정 증빙; 환경 접근 불가 시 BLOCKED |
| 06 데이터 준비 | 게스트/회원/타인/관리자 합성 계정, 분리된 금융 데이터, 비식별 로그, 초기화 절차 마련. | 픽스처 ID·초기화 근거; 실제 개인정보 복제 금지 |
| 07 실행 | 단위/통합/API/브라우저/Android/Discord/보안/금융/부하/시각 테스트를 위험별 실행. 전체 라우트 5회 QA 준수. | 시간·실측 결과가 있는 TC 증빙 |
| 08 결함 등록 | 재현 절차, 심각도 P0~P3, 예상/실제 결과, SHA, 경로, 역할, 추적 ID, 비식별 스크린샷/로그 수집. | 담당자·영향 범위가 있는 결함 이슈 |
| 09 재테스트 | 원본 오류 재현, 수정본 정확 SHA에서 단위·API·재현 테스트 재실행, 원인 차단 확인. | RED/GREEN 또는 동등한 수정 전후 증빙 |
| 10 회귀 | 공유 컴포넌트 소비 페이지·API 호출자·실제 Test 로그인·금융/보안 경로 재검증. 기존 전체 라우트 5회 규칙 유지. | 영향도 추적표 및 회귀 근거 |
| 11 보고 | 라우트/API/역할/기기/시나리오별 PASS, FAIL, BLOCKED, NOT_RUN을 분리하고 미해결 위험 기록. | 산술적으로 검증되는 보고서; 임의 합격률 금지 |
| 12 종료 판정 | P0/P1 미해결, 관리자/라우트 누락, 실제 Test 오류, 원장 불일치, 보안 실패, 독립 복구 부재, SHA 불일치가 있으면 중단. | 근거 있는 GO/NO-GO. 실제 배포는 별도 검증·승격 절차 |

각 단계는 산출물과 직접 연결해야 한다. 기획서 또는 main SHA가 변하면 해당 TC를 다시 검토한다. 작업 전·중간·종료 기록과 파일 소유자 분리를 강제한다.

## 4. 머니버스 자체 QA 12개 검증 분류 (영상 원문 목록 아님)

1. 단위·속성 테스트: 입력 검증, 상태 변환, 금액 정수 안전성.
2. API 계약: HTTP 상태, DTO, 인증 쿠키/헤더, 오류·버전 호환.
3. 통합: Spring–DB 저장 함수–Nginx–세션 권위–이벤트 흐름.
4. E2E: 실제 브라우저 회원/관리자 및 Android 사용 여정.
5. 기능·탐색: 정상/비정상 흐름, 숨긴 메뉴, 저장/적용, 도중 중단.
6. 회귀: 변경 라우트, 공유 UI, 교차 리포지토리 호환, 과거 장애.
7. 보안·개인정보: IDOR, 소유자 격리, CSRF, MFA, 권한 상승, 캐시/noindex, 비밀 보호.
8. 금융·데이터 무결성: 정식 복식부기, WLD, 롤백, 멱등성, 진짜 영수증.
9. 신뢰성·복구: 타임아웃, 5xx, 원천 장애, 무중단 전환/롤백, 백업 복원.
10. 성능·동시성: 부하/급증/속도 제한/잠금 경쟁과 실측 기준 비교. 목표 수치 지어내지 않음.
11. 기기 호환·접근성: 320px~데스크톱, Android, 브라우저 엔진, 키보드, 초점, 동작 축소, WCAG 2.2 AA.
12. 운영·외부 연동: Discord 음성·로그인, 콜백, 스케줄, 관리자 실시간 로그, 경보·관측성.

각 항목은 상호 배타적 테스트 수준이 아니라 위험·대상별 검증 묶음이다. P0 기능은 여러 묶음에 동시에 속한다.

운영에서 실제 돈을 이동하거나 승인되지 않은 파괴적 테스트를 실행하지 않는다. HTTP 200, 단순 스모크, 소스 컴파일만으로 사용자·금융 기능 합격 선언 금지.

### Spring 전환 시 실제 라우트 인벤토리
프론트엔드가 Next.js/App Router에서 Spring MVC 템플릿·정적 번들로 이동한 후보라면 **실제 후보가 제공하는 화면**과 코드 소유권을 기준으로 라우트 목록을 재생성한다. 과거 Next.js page.tsx 파일 수만으로 전체 범위를 판단하지 않는다. Spring 관리자/인증 화면, 에러/권한 상태, 탐색·직접 진입 경로, Android 연계 진입점을 포함하고 각 행에 실제 렌더링 주체·런타임을 기록한다. Nginx+Spring 실제 응답과 대조한다. 과거 라우트 개수는 현재 커버리지 증거가 아니다.

## 6. 테스트 증빙 스키마와 운영 승격 게이트

각 TC에 다음을 기록한다.
- 신원: candidate_sha, frontend_sha, backend_sha, migration_checksums, test_case_id, requirement_id, route_or_api, environment, timestamp.
- 상태: role, session/MFA/CSRF 상태, fixture_id, viewport/device, browser/app version, 기능 스위치, locale, 원천 상태, 동시 조건.
- 실행: 단계·입력(비식별)·예상·실제 결과·HTTP 코드·확인 가능한 DB/원장 영수증 참조.
- 판정: PASS/FAIL/BLOCKED/NOT_RUN, defect_id, 보안 저장된 증빙 URI, 추적 ID, 담당자, 재실행 시각.
