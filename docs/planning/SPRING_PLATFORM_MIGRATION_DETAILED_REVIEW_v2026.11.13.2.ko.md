## 1. 전환 범위 및 언어 경계 — 기존 1장 주의사항

**목표 구조:** Java 21과 검토된 안정 버전 Spring Boot가 API·관리자·배치의 최종 소유자가 된다. React/Next.js 화면과 Android는 유지하며 PostgreSQL이 금융 원장을 계속 통제한다. Next.js BFF/SSR이 살아있는 한 일부 Node·TypeScript 실행은 정상적으로 남는다. “전체 스프링 전환”을 “브라우저 JavaScript까지 Java로 교체”로 오해하지 않는다.

**세부 작업:**
1. Next SSR/BFF, NestJS, Spring, DB 저장 함수, Discord/Telegram, Socket.IO, AI/스케줄, Android, Nginx, 백업/모니터링의 **실행 프로세스 단위** 의존성도를 만든다.
2. 기존 기능을 SPRING 이관 / 웹·모바일 클라이언트 유지 / 프로토콜 게이트웨이 별도 대체 / 기한 있는 승인 예외 / 증거 기반 종료로 각각 분류한다.
3. 공개 API, 내부 API, 관리자 API, 서명된 웹훅, 타이머, 큐 소비자, 봇 명령, 모바일 호출을 각각 전수 조사한다. 단순 컨트롤러 개수를 전체 기능 수라고 간주하지 않는다.
4. 프론트 SEO, SSR, 접근성, 한국어·영어, 반응형, 기존 공개 블로그 URL의 품질과 호환성은 별도 회귀 항목으로 유지한다.

**주의/중단:** 명령이나 금융 쓰기 기능에 두 명의 실행 소유자가 있거나, 소유자가 없는 경우 전환 금지. **완료 기준:** 전 프로세스 책임표와 예외 승인 목록 확정.

## 2. 문서 권위·현황·증거 관리 — 기존 2장 주의사항

1. 작업 시작, 중간, PR 통합 직전에 origin/main을 다시 가져와 최신 기획과 소스 차이를 분석한다. 실행 상태는 실제 도메인/DNS/TLS → Nginx location → 업스트림 → systemd PID·실행 경로 → 불변 배포 매니페스트/SHA → DB·역할 순으로 확인한다.
2. 프로젝트·통합 마스터와 현재 채택된 기능 명세가 우선이다. 과거 사고 기록·출시 노트·옛 버전 문자열은 **당시 증거**이지 오늘 기능이 정상이라는 의미가 아니다.
3. Nest 컨트롤러/모듈·Next 라우트·Socket.IO·Discord/Telegram 핸들러·systemd timer·cron·DB 함수·Android Retrofit·외부 웹훅에서 라우트 및 명령 목록을 자동 추출한다. 동적 라우트·숨겨진 소비자·누락 항목을 사람이 재검토한다.
4. 운영과 Test를 각각 별도 경로로 표준화하고 정확한 현재 SHA/서명/데이터베이스 역할을 기록한다. 이미 실행 중인 유닛 이름만 보고 실제 공개 트래픽 소유자로 판정하지 않는다.
5. 메모리·CPU·스왑·디스크 I/O·PostgreSQL 연결 수·기존 요청 지연의 시간대별 기준선을 만든다. 8GiB라는 이유로 무조건 불가능하다거나, Java가 설치돼 있으니 충분하다고 가정하지 않는다.

**주의/중단:** 운영 소스 SHA·실제 DB가 불명확하거나 격리 Test 환경이 동작하지 않으면 승격 불가. **완료 기준:** 비밀값을 제거한 G0 인프라·자금·복구 기준선 보고서.

## 3. 목표 Spring 구조·라우팅·모듈 — 기존 3장 주의사항

**권장 아키텍처:** 처음에는 스프링 모듈러 모놀리스 1개 실행체, MVC/Servlet 기반, Spring Security, 승인된 PostgreSQL 함수 호출용 JDBC, Actuator/Micrometer/추적을 사용한다. 작은 미니PC에 마이크로서비스 수십 개를 한번에 만들지 않는다.

**프레임워크 주의:** 2026-11-13 공식 문서 기준 Spring Boot 최신 안정판은 4.1.2로 표시된다. Boot 4.x는 Spring Framework 7 및 Jakarta EE 11/Servlet 6.1 호환 검토가 필요하다. 실제 G1 착수 때 보안 패치·지원 버전·의존 라이브러리·빌드 도구 재검증 후 선택하며, Java21과 버전을 고정한다. 실험 없이 “성능이 반드시 빠르다”라고 주장하지 않는다.

**Socket.IO 주의:** Spring의 일반 HTTP/WebSocket 지원만으로 Socket.IO 프로토콜 호환이 자동 성립하지 않는다. 브라우저와 Android에서 핸드셰이크·네임스페이스·ACK·방·재접속을 재현해야 한다. 불가능하면 승인된 최소 Node 게이트웨이를 예외로 유지하되 전체 전환 완료라고 거짓 보고하지 않는다.

**중단 조건:** 라우팅 중복, 인증 차단 우회, 섀도 개인정보 누출, 예상외 자원 소비.

## 4. 자금·DB 코어·멱등성 — 기존 4장 주의사항

**절대 금지:** Spring JPA save로 잔액/원장 직접 수정, Hibernate 자동 DDL, 금융 테이블에 광범위 INSERT/UPDATE/DELETE 권한 부여, SQL 이력 변경, 이중기입 불일치, 두 서버가 같은 자금을 별도 처리, 계좌 초기화, 사용자 자금 삭제. DB 트랜잭션 저장 함수가 최종 결제 권위를 유지한다.

**거래 순서 상세:**
1. 로그인 주체·CSRF·관리자 재인증·입력 형식·자격/잔액·정책·속도 제한을 확인한다.
2. 돈은 계약에서 정의한 십진 정수 문자열로 안전하게 왕복한다. Java BigInteger 또는 범위가 검증된 정수형을 사용하고 float/double·자동 반올림을 금지한다. PG 마이크로초·UTC·한국시간 정책도 유지한다.
3. NestJS와 Spring이 **같은 멱등키와 동일한 요청 소유권**을 사용한다. 이전 서버가 뒤늦게 수행한 재시도도 DB fence/epoch나 동등한 저장소 검증으로 거부해야 한다. JVM 내 synchronized만으로 프로세스 간 중복을 막을 수 없다.
4. 별도 최소 권한 DB 역할에서 기존 승인 저장 함수를 호출하고, 그 함수가 원장·파생잔액·감사·outbox·영수증을 원자적으로 확정한다.
5. SQLSTATE별 400/401/403/404/409/410/429/503 및 정상/재시도 결과를 기존 Next·Android에 똑같이 전달한다. 42501 진짜 권한거부와 설정 누락을 구분한다.
6. 응답 전 연결 단절, 커밋 후 ACK 손실, 재시도 100회, 동시 명령, 중복 멱등키·다른 사용자 키 충돌, 잠금 순서, 관리자/자동투자 경합, 시간대 경계 등 실제 PostgreSQL 시험을 수행한다.

**필수 증거:** 총 차변=대변, 중복/고아 영수증 0, 허가 없는 잔액 변화 0, 한 명령당 한 기록자, DB 역할 권한 최소, migration checksum 100% 일치, 독립 백업 복원 성공. 증거는 **DB 스냅샷·소스 SHA·환경**에 연결되어야 한다.

**중단·복구:** 원장 불일치·권한 확대·중복 거래 발견 즉시 해당 쓰기 도메인을 fence하고 운영 승격 차단. 실데이터 초기화로 복구를 대신하지 말고 검토된 정정 거래/전방 마이그레이션을 사용한다.

## 5. 세션·관리자·봇·API·모바일 — 기존 5장 주의사항

| 영역 | 검증 항목 | 위험·중단 기준 |
| --- | --- | --- |
| 웹 인증 | 쿠키 이름/도메인/Path/SameSite/Secure/HttpOnly, DB 세션, 갱신·로그아웃, 기존 세션 유지 | 전환 중 전원 로그아웃, 세션 고정, 권한 없는 재발급 |
| BFF/CSRF | 동일 출처 쿠키 전달, 토큰·origin 검사, 403, 브라우저 비밀 미노출 | 위조 origin/토큰으로 쓰기 성공 |
| 소셜 OAuth | state, nonce, callback, 계정 연결, 만료·중복 탭 | 타인 계정 잘못 연결 |
| 관리자 | 중대 페이지/명령에 최신 재인증; Discord·Telegram OTP 1회성·만료·시도 제한·감사 | 중간 서버 경유로 인증 우회. **이미 제거된 2인 승인 재도입 금지** |

| 서명 웹훅 | 수신 원본 바이트, 시각·nonce·중복, 키 교체 | body 변환 후 서명 검증 |
| 채팅·봇 | Socket.IO 연결·방·ACK·재접속, Telegram·Discord 명령 멱등 | 메시지/돈 중복 또는 손실 |
| 공개 웹/SEO | SSR, 캐시, hreflang, sitemap, robots, 한국어/영어, 관리자 noindex | 개인정보 색인, 발행 URL 단절 |

**계약 작성:** 기존 TS 공용 타입·route-map을 증거로 보존하고, OpenAPI/스키마·골든 HTTP 픽스처로 Java와 Android/Kotlin을 검증한다. 코드 생성 성공만으로 실제 동작 동등성이 입증되지는 않는다. 헤더·쿠키·오류·순서·decimal/날짜 직렬화까지 검증한다.

**통과 기준:** 기존 브라우저와 실제 Android 커밋으로 로그인 만료, 재인증 OTP 재사용, 세션 위조, 권한 우회, 봇 서명 실패, 재연결 시험 통과.

## 6. G0~G6 단계별 구현 계획 — 기존 6장 주의사항

각 단계는 **작업 순서**이지 완료 날짜 약속이 아니다. 모든 기능별 PR은 코드 대상·책임자·회귀·실서버 Test·결과·승격·복귀를 별도로 기록한다.

| 단계 | 구현·문서 산출물 | 검증 및 중단 조건 |
| --- | --- | --- |
| **G0 사전 조사** | 운영/Test 네트워크·소스·DB 권한도, API/봇/타이머/모바일 전수 목록, 원장 증거, 사용량 p50/p95/p99, 독립 백업 복원, 복귀 후보 다이제스트 | 실제 라우트/DB·복원·테스트 가능 여부 확인; 아직 운영 JVM 금지 |
| **G1 Java 기반** | Java21/Boot 검증, 빌드·의존성 잠금, 모듈 구조, 제한 DB 역할, 인증·오류 어댑터, SBOM/서명·CI, 내부 health, 격리 Test 전용 서비스 | 단위+실PG 권한 음성시험, 계약 검사, 정확한 Test SHA, 메모리 예산; 운영 쓰기 금지 |
| **G2 공개 읽기** | 안전한 공개 GET·도움말·상태 API, BFF 라우트 플래그, 기존 UI·Android 비교 | GET 부작용 0, 401/404/503·캐시/SEO 동등, 부하 중 원클릭 복귀 |
| **G3 로그인·커뮤니티** | 기존 세션/OAuth/CSRF, 블로그·상담/지원·개인정보 쓰기, 관리자 조회 | 이전 로그인 세션 유지, OTP/CSRF 공격 차단, 발행·outbox 중복 방지 |
| **G4 게임·실시간·배치** | 시장·게임 비금융 부분, Socket.IO, Discord/Telegram/Minecraft, 알림, 스케줄 리더 이전 | 서명·ACK·재접속·봇 멱등, 한 작업당 활성 리더 1개; 돈 관련 동작은 G5 통제 |

## 7. QA·성능·오류 발생 시 복귀 — 기존 7장 주의사항

**7단계 다층 시험:** (1) 전수 route-map·OpenAPI·정적/의존성 검사 → (2) HTTP/헤더/날짜/오류 골든 테스트 → (3) 실제 DB 최소권한·CSRF/OTP/위조 음성 시험 → (4) 양쪽 백엔드 재시도·원장/장애 주입 → (5) Next SSR/Android/봇/Socket.IO 사용자 시험 → (6) 격리 Test 업스트림·동일 SHA·부하/스왑/DB 풀·롤백 → (7) 명시 승인 후 운영 카나리 및 로그인·관리자·금융 확인.

**성능 잠정 기준:** 동일 하드웨어·동일 부하에서 Spring 후보 p95 지연 ≤ 기존 실측 p95의 110% **이면서** 기존 제품 SLO 충족. 절대 지연·오류율·p99·GC·메모리·스왑·DB 커넥션 기준은 G0 관측값으로 고정한다. 자원 추가 확보 또는 서버 분리가 승인되지 않으면 운영 상시 JVM 가동을 강행하지 않는다.

| 장애 유형 | 즉시 조치 | 복귀 검증 |
| --- | --- | --- |
| 읽기 오류·성능 악화 | Spring 읽기 비율 0으로 되돌림 | 이전 검증 이미지 digest, 동일 응답/세션/공개 SHA |
| 자금·관리자 우회 | 신규 명령 fence, 해당 도메인 중단·사고 기록 | 원장·권한·소유권 정합, 실제 DB 검증 |
| JVM OOM·DB 풀 고갈 | 신규 후보 중단, 기존 정상 업스트림 유지 | 호스트·DB·로그·자원 재검사 |
| DB 계약 차이 | 트래픽 차단, 승인된 전방 호환 정정만 사용 | checksum·복원·세션 호환 |
| 이미지/서명 분실 | 태그가 보여도 운영 승격 차단 | OCI digest pull, 증명서·매니페스트 검증 |
| 봇·소켓·스케줄 중복 | 하나의 리더로 fence 또는 이전 게이트웨이로 복귀 | 1회 경제 효과·ACK·재접속 실제 시험 |

**주의:** actuator 200 또는 홈페이지 정상만으로 QA 합격이 아니다. **확인되지 않은 롤백은 즉시 승격 중단**이다.

## 8. 동시 작업·문서·운영 기록 — 기존 8장 주의사항

- 통합 기획과 명시 채택된 세부 기능 규칙을 우선하고, 제미나이와 GPT는 별도 브랜치/작업 트리에서 작업한다. SQL 번호·라우트 소유권·공유 파일은 담당권과 인수인계 기록을 명시한다.
- 작업 전/중/종료 로그, 독립 브랜치, 원격 중간 체크포인트, 내부용/깃허브용 변경 내역, 영문 우선·한국어 2차, 버전을 모두 유지한다.
- origin/main은 시작·중간·통합 직전에 fetch. 이번 후속 PR은 미병합 v1을 기반으로 스택 PR로 제출한다. v1이 먼저 합쳐지면 새 main에 충돌 없는지 다시 검토한다.
- **문서 PR ≠ Java 빌드 ≠ Test 승격 ≠ 운영 승격.** 저장소 커밋 SHA와 실제 애플리케이션 소스 SHA, OCI digest, DB epoch, Test/Prod 증거를 구분한다.
- 실제 QA 증거·테스트 로그·작업 담당자·실패 사유를 남기고, 실패를 숨기거나 운영 우회로 처리하지 않는다.

## 9. 검토·승인·최종 완료 판정 — 기존 9장 주의사항

**권장안(아직 승인 아님):** Next.js/Android 유지 + 모듈형 Spring 단일 백엔드 + 단계별 strangler + PostgreSQL DB 금융 권위 + 금융 명령자 1개 + 실제 Test/복원·무중단 복귀. Java21은 초기 호환성 기준이고 Spring 패치·빌드 도구는 G1에서 다시 선정한다.

**결정 미완료:** 실제 공개 트래픽이 어느 v1546/v1550 세대를 가리키는지, Socket.IO를 Java로 완전 이전할지 승인된 임시 게이트웨이를 둘지, 8GiB 기기에 Java를 병행할지 별도 서버가 필요한지, GHCR 유지 또는 JFrog Artifactory 도입 여부, 전체 타이머/봇 소유자, 금융 미해결 증거·Test 독립성.

**승인 순서:** ① 전체 설계·상세 위험 승인 → ② G0 실제 목록·DB·자원·백업 확인 → ③ G1 개별 코드 PR과 Test → ④ 금융/인증 도메인 별도 승인 → ⑤ 공식 Test·무중단 운영 카나리·복귀 증거 → ⑥ NestJS 종료 승인. 한 단계의 동의가 다음 단계까지 자동 승인하는 것은 아니다.

### 기능별 추적·증거 양식

| 항목 | 필수 기록 |
| --- | --- |
| 기능 ID·상태 | 예: SPR-G2-READ-001 / PLANNING, BLOCKED, TEST_VERIFIED 등 |
| 소스 | 저장소, PR·브랜치, 40자리 소스 SHA, 병합 SHA |
| 아티팩트 | bootJar SHA256, OCI repo@sha256 다이제스트, SBOM/서명 |
| DB | 대상 환경·역할·checksum 집합·호환 epoch·독립 복원 증거 |
| API | 메서드/경로/소비자/TS·Java·Android 계약 픽스처 |
| 보안 | 권한·CSRF·OTP·서명·취약점 예외 |
| 검증 | CI 실행 링크, 실제 Test 주소, 사용자·관리자·실패 시험 |

### 후속 상세 산출물

1. G0 자동 목록 수집 스크립트와 경로·명령·봇·타이머·Android 전수 책임표.
2. G0 실제 배포 경로, 금융 권한/원장, 원본 백업의 독립 복원, 되돌릴 이미지/서비스 확인.
3. 별도 승인 후 G1 Java·CI·의존성·인증/DB 접근·아티팩트 구현 명세.
4. 각 기능 도메인에 관한 별도의 버전별 개발/시험/복귀 계획과 증거.
5. [아티팩트 및 Artifactory 세부 정책](SPRING_PLATFORM_MIGRATION_ARTIFACT_POLICY_v2026.11.13.2.ko.md): JAR·OCI 이미지, 공급망 증명, 버전·보관·서명·승격·롤백.
