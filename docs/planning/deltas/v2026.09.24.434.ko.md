## 결정
모든 신규/변경 프론트 화면은 완료 또는 Production 승격 대상으로 처리하기 전에 반응형 QA를 최소 5회 이상 수행한다.

## 필수 5회 QA
1. 기본 화면/텍스트 잘림, overflow, viewport 경계 검사.
2. navigation/grid/table/chart/action의 breakpoint 및 UI 위치 검사.
3. loading/empty/error/offline/validation/reauth/dialog/keyboard 등 상태·상호작용 검사.
4. 긴 KO/EN 문구, 적용 가능한 200% zoom/reflow, >=44px 제품 touch target, keyboard/focus, safe-area 접근성 스트레스 검사.
5. 모든 수정 후 최종 exact candidate SHA에서 회귀 재검증.

반응형/레이아웃을 다시 수정하면 영향을 받은 route/component는 5회 증거를 다시 시작한다.

## 최소 viewport 증거
적용 가능한 280/320/360/390/768/1024/1280/1440 CSS px와 관련 가로모드/회전, zoom/reflow를 확인한다. 중요 흐름은 실제 기기 검사도 유지한다.

## 릴리스 차단 결함
화면 잘림, 요소 겹침, control 접근 불가, 잘못된 UI 위치, safe-area 파손, 레이아웃 결함에 의한 가로 스크롤, keyboard/focus 회귀, 미해결 반응형 결함은 Test 수용 및 Production 승격을 차단한다.

## 증거 스키마
exact candidate SHA, route/screen, viewport, browser/device, QA 회차, 발견 결과, 수정, 재검증, 가능한 시각 증거, 미해결 제약을 기록한다.

## 범위
기획/문서 변경만 수행한다. 기존 route 전체가 이미 5회 QA를 완료했다거나 Test/Production 배포가 완료됐다고 주장하지 않는다.
