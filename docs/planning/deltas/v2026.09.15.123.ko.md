## 가상주식 검색 상세계약 — STOCK-123-01 — P1 — PARTIAL/런타임 미검증

목적은 로그인 사용자가 전체 시장을 훑지 않고 fictional instrument를 찾도록 하되 거래·보유 권위를 바꾸지 않는 것이다. actor는 signed-in member이며 진입은 `/stocks`, 공유 가능한 회원전용 `/stocks?q=<query>`다.

UX는 native GET search form, 연결된 label, 검색/초기화, 한·영 결과수, 검색 전용 empty state, 기존 market card로 구성한다. 입력은 trim/normalize 후 UI 상태 최대 80자다. 모바일은 full-width input과 터치 가능한 control, tablet/desktop은 scan 가능한 card를 유지한다. keyboard submit, visible focus, screen-reader label/result feedback, EN/KO parity를 요구한다. 서버/API 장애를 정상적인 `0 results`로 표시하지 않고 timeout/error와 empty를 분리한다.

현재 구현은 이미 권한검증된 market read model을 server-rendered page에서 필터링하며 새 mutation API나 DB migration을 만들지 않는다. 검색 결과에 private holdings/order/watchlist ownership/alert/account ID/ledger를 합치지 않는다. 향후 backend search가 필요하면 bounded `GET /api/v1/stocks?q=&cursor=&limit=`로 분리하고 query length/limit/stable ordering을 강제한다. invalid syntax=400, unauthenticated=401, resource budget=429, server failure=5xx이며 순수 read에는 idempotency key가 필요 없다.

보안·개인정보: query는 untrusted text다. SQL/regex injection, catastrophic matching, unbounded fan-out을 금지한다. raw free-text 검색어를 기본 analytics에 저장하지 않고 로그는 최소화/길이제한한다. backend/DB 검색으로 확장할 때 request/query complexity budget과 rate limit을 적용한다. 다른 사용자의 holdings를 검색으로 열거할 수 없어야 하며 설명 텍스트는 output encoding한다.

SEO: `/stocks?q=`는 회원전용 `noindex`, sitemap/structured data 제외다. ticker×query×date doorway page를 만들지 않는다. 별도로 설계된 public fictional-company/교육 페이지가 독창적이고 충분한 내용이 있을 때만 index한다. private portfolio/holdings/orders/alerts/search history는 anonymous HTML/JSON-LD/shared cache에 절대 포함하지 않는다. Breadcrumb는 실제 visible hierarchy와 일치하는 공개페이지에서만 사용한다.

성능·캐시: 현재 필터 비용은 이미 반환된 market catalog 크기로 제한되어야 하며 SSR p95와 catalog cardinality를 측정한다. catalog가 커지면 private data를 client로 내려받는 대신 index된 server search와 query-plan budget으로 이동한다. member HTML은 public shared cache에 들어가지 않는다.

분석·사업성: `stock_search_submitted`, `stock_search_zero_result`, result-count bucket, 이후 public-safe instrument selection을 pseudonymous event로 기록할 수 있으나 raw query는 기본 수집하지 않는다. KPI 가설은 search→detail, search→watchlist/trade exploration, zero-result, p95 latency, D7/D30 market return이다. 직접매출 기능이 아니며 WLD/WDX 거래는 실매출이 아니다. discovery 개선과 guardrail 유지 시 SCALE, zero-result/전환이 나쁘면 ITERATE, private leak/query cost/실투자 오인 증가 시 HOLD/KILL한다.

QA: symbol/name/description, case, whitespace, 0/1/80/>80, 한·영, 특수문자 unit; auth/market failure integration; keyboard/search/reset/shareable query/empty/error/mobile E2E; XSS/injection/resource abuse/private leak security; trading/watchlist/portfolio/ledger 불변 regression. exact-main-SHA Test, DB/ledger diff 없음, noindex/private 검증, REL-123-01 release evidence를 수용조건으로 한다. rollback은 DB 변경 없이 이전 immutable frontend로 한다.
