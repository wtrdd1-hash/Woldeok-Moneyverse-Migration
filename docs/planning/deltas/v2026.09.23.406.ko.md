## 2. 6대 도메인 기획 결함 분석 및 보완 명세

---

### 🏛️ [Domain 1] 주식 거래소 & 실시간 호가창 결함 보완

#### 1) 결함 식별: 웹소켓 단절 시 호가 뎁스 불일치 및 틱 유실 (Flaw G406-01 / P0)
- **현상**: 네트워크 깜빡임 또는 모바일 슬립 복귀 시 수신되지 못한 틱이 누락되어 클라이언트 호가창의 5D/10D 매수/매도 잔량과 서버 실제 체결 데이터가 영구적으로 불일치(Desync)할 수 있음.
- **보완 계약 (Monotonic Sequence Gap Recovery)**:
  1. 서버는 모든 호가/체결 브로드캐스트 이벤트에 단조 증가 정수 `sequence_id`를 부여한다.
  2. 클라이언트는 웹소켓 연결 시 먼저 REST `/api/stocks/:symbol/orderbook`으로 정적 Full Snapshot (`snapshot_seq`)을 가져오며, 그 동안 인입된 웹소켓 델타를 큐에 버퍼링한다.
  3. `delta_seq <= snapshot_seq`인 델타는 폐기하고, `delta_seq == last_seq + 1` 순서대로 멱등 적용한다.
  4. 만약 `incoming_seq > last_seq + 1` (시퀀스 갭 발생)이 감지되면 즉시 로컬 호가창을 무효화하고 즉시 스냅샷을 재요청(Auto Re-sync)한다.

#### 2) 결함 식별: 1원~1,000만 원 극단 가격대 틱 사이즈 규칙 부재 (Flaw G406-02 / P1)
- **현상**: 53원짜리 종목(CHIPS)과 8,991,585원짜리 종목(SPACE)에 동일한 가격 변동폭 및 주문 단위를 적용할 경우 스프레드 왜곡과 주문 입력 에러 발생.
- **보완 계약 (KRX 표준 준용 7단계 Tick Size Tier)**:
  - 1,000원 미만: 1원 단위 (최소 주문 1주)
  - 1,000원 ~ 5,000원: 5원 단위
  - 5,000원 ~ 10,000원: 10원 단위
  - 10,000원 ~ 50,000원: 50원 단위
  - 50,000원 ~ 100,000원: 100원 단위
  - 100,000원 ~ 500,000원: 500원 단위
  - 500,000원 이상: 1,000원 단위

#### 3) 결함 식별: 감성 지수의 AI 뉴스 단순 합산 편향 (Flaw G406-03 / P1)
- **보완 계약**: 다요소 가중 알고리즘을 도입하여 뉴스 부재 시에도 24시간 가격 변동성과 거래량 모멘텀을 결합한 0~100점 지수를 항시 유효하게 산출한다.

### 💰 [Domain 2] 가상 경제 거버넌스 & 통화 통제 결함 보완

#### 1) 결함 식별: Faucet 편향으로 인한 장기 인플레이션 및 아이템 가치 붕괴 (Flaw G406-04 / P0)
- **현상**: 직업 보상 및 일일 퀘스트로 공급되는 WLD 통화량 대비 완제품/희귀 아이템의 누적으로 인해 화폐 가치와 장비 시세가 동반 하락하는 MMORPG 전형적 경제 붕괴 위험.
- **보완 계약 (OSRS Grand Exchange Tax & Automated Item Sink)**:
  1. **2% 마켓 거래세**: 거래소 및 유저 마켓플레이스 체결 시 판매자 수령액에서 2% 거래세를 원천 징수(1회 거래당 상한 50만 WLD).
  2. **국고 연동 시스템 자동 매입 소각 (Automated Item Sink)**: 징수된 거래세의 50%는 즉시 영구 소각(Coin Sink)하고, 50%는 국고(Treasury)에 적립하여 시장 내 최저가로 등록된 잉여 장비/아이템을 시스템이 자동 매수 후 영구 파괴(Item Sink) 처리.
  3. **인플레이션 연동 역동적 이자율**: 경제 전역 인플레이션 지수 15% 초과 시 예금 이자율을 일시 인상하여 시중 통화를 은행으로 흡수.

### 💬 [Domain 3] 1:1 개인 채팅 (P0) 결함 보완

#### 1) 결함 식별: 모바일 네트워크 단절 시 메시지 중복 전송 & 페이지네이션 왜곡 (Flaw G406-05 / P0)
- **보완 계약 (Idempotency Key & Cursor Pagination)**:
  1. **클라이언트 UUID 멱등키**: 메시지 전송 시 클라이언트가 UUID `client_message_id`를 생성하여 전송. 백엔드는 `(conversation_id, client_message_id)` 복합 유니크 제약 및 Redis 캐시를 통해 중복 전송 시 추가 DB 삽입 없이 기존 `message_id`를 즉시 응답(Idempotent 200 OK).
  2. **커서 기반 페이지네이션 강제**: 오프셋 기반 대신 `WHERE conversation_id = ? AND id < ? ORDER BY id DESC LIMIT 50`를 사용하여 대화 중 신규 메시지가 와도 과거 기록 조회 시 중복이나 누락이 일체 발생하지 않도록 차단.
  3. **클라이언트 수신 ACK & 오프라인 복구**: 소켓 수신 시 클라이언트는 `ack(msg_id)`를 송신하며, 재연결 시 `last_delivered_id` 이후의 미수신 메시지를 REST `/api/chat/conversations/:id/sync`로 일괄 복원.

### 🏦 [Domain 4] 금융 / 은행 / 준비금 & 대출 리스크 결함 보완

#### 1) 결함 식별: 뱅크런(Bank Run) 방어선 및 대출 회수 알고리즘 부재 (Flaw G406-06 / P0)
- **보완 계약 (Aave Kinked Interest Rate Model & 바젤 III LCR)**:
  1. **점프 이자율 곡선 (Kinked Curve)**:
     - 유동성 이용률 $U = \frac{\text{Total Borrows}}{\text{Total Deposits}}$
     - $U \le 80\%$: $\text{Borrow Rate} = 3\% + (U / 0.8) \times 5\%$ (완만한 3~8% 금리)
     - $U > 80\%$: $\text{Borrow Rate} = 8\% + ((U - 0.8) / 0.2) \times 40\%$ (최대 48% 페널티 금리 폭등으로 자발적 대출 상환 및 예금 유입 강제)
  2. **바젤 III 지급준비율 (Reserve Ratio)**: 은행 총 예금의 최소 20%는 대출 불가 법정 준비금(Reserve Buffer)으로 동결하여 유저 인출 요구(Withdrawal) 100% 즉시 보장.
