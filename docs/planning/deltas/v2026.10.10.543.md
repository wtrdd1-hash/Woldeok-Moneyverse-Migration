## 2. Runtime containment contract

- `MONEYVERSE_SWF_EXECUTION_ENABLED` must be exactly `true` before `evaluateAndRebalance()` can mutate state.
- `MONEYVERSE_SWF_SCHEDULER_ENABLED` must separately be exactly `true` before an interval is scheduled.
- Backend startup must never trigger an immediate or delayed SWF economic cycle.
- The first explicitly enabled scheduled cycle is eligible only after one full hour.

- The locked `treasury_swf_configs` row plus `last_executed_at` / `rebalance_interval_hours` enforce a durable minimum interval.
- Lock contention or an unelapsed interval is a no-op, not an economic mutation.

Test/Production environment files MUST leave both SWF flags unset/false until v544 conservation-correct settlement, database-boundary remediation and reconciliation acceptance are complete.

## 3. Immutable Debian host release contract

A host release is an immutable exact-SHA artifact, not a Git working directory.

- Never run `git pull`, `git fetch`, `git reset`, `git checkout` or otherwise mutate a directory already serving under `/srv/moneyverse-data/releases/*`.
- Stage only from a clean worktree whose `HEAD` equals the approved 40-character application source SHA.
- Use a new SHA-qualified destination; never reuse or overwrite an existing release path.
- Require built backend/frontend artifacts before staging; strip Git metadata from the staged release.
- `.moneyverse-release.json` records channel, version, application source SHA and creation time.
- Move Test/Production pointers only after the exact candidate passes the required gate.
- A live `/api/version` or frontend identity mismatch against the approved release manifest blocks promotion and completion claims.

Tracked helper: `bash ops/release/stage-host-release.sh <test|prod> <version> <sha> <clean-source-dir> [release-root]`.
