**상태:** PLANNING

## 1. 확인된 API 기획 결함

### G409-01 / P0 — exact-SHA API 수용 증거 미확정
최신 main 기준 API contract gate가 통과했다고 주장할 수 없다. 직전 required runtime-check가 API 계약 검증 완료 전에 ESLint 오류로 실패했다.

**수용조건:** exact candidate에서 모든 required CI가 녹색이어야 하며 `pnpm api:contract:check`와 generated/committed artifact 일치가 포함되어야 한다.

### G409-02 / P0 — 상충하는 API 인벤토리 수치
현재 자료에는 다음 수치가 함께 존재한다.
- 기계 판독 모바일 계약: 179 endpoint
- 모바일 전체 명세: backend 57 controller / 335 endpoint / mobile 179 endpoint
- endpoint catalog: mobile 139 endpoint
- v402 소스 탐색: 58 controller file / 361 HTTP decorator

서로 범위/기준이 다르거나 오래된 값이므로 하나의 권위 숫자로 합치지 않는다.

**수용조건:** 각 route를 `scope, method, path, operationId, controller, authClass, exposureClass` 튜플로 정규화해 생성하고 그 결과에서 수치를 계산한다.

### G409-03 / P1 — API 문서 드리프트
complete spec, endpoint catalog, machine contract, schema reference, runtime contract가 하나의 강제된 버전/수치 소스를 사용하지 않는다.

**수용조건:** 생성/검사 파이프라인이 모든 유지 API 문서를 같은 작업에서 갱신 또는 검증하고, 오래된 endpoint 수/버전 문자열이 남으면 CI를 실패시킨다.

### G409-04 / P0 — 고위험 mutation 검증 순서 재지정
금융·경제 상태 변경이 가장 높은 정합성/악용 위험을 가진다.

**1군 mutation:** 지갑 송금, 은행 입출금/대출/채권, 주식 주문, 직업/보상 claim, 마켓 구매/세금/item-sink, 카지노 play/self-limit, 국고/관리자 경제 변경.

**각 mutation 수용조건:** 인증/인가, object-level access, 브라우저 CSRF, 필요한 recent reauth, DTO 범위, 멱등성, 동시성, 원장/상태 원자성, 안정적 오류 모델, negative test, 감사 증거.

### G409-05 / P0 — 클라이언트/API 정합
웹/모바일의 모든 서버 기반 액션은 실제 살아있는 API method/path에 연결되어야 한다.

**수용조건:** 죽은 버튼, 클라이언트 가짜 성공, 장애 시 silent mock fallback, 404 target, 네이티브 앱의 private backend 직접 호출을 금지한다.
