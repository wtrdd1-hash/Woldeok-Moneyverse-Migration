## 1. 권위 결정

v523 중앙은행·조폐국·중앙국고·Economy Core의 다음 불변식을 계속 최상위 경제 구현 계약으로 유지한다.

`총 WLD 통화량 변화 = 승인 조폐량 - 승인 폐기/소각량`

세금, 국고 이전, 연금, 국채, Repo 대출, 재정 투자는 암묵적으로 WLD를 생성하면 안 된다. 최신 소스의 기존 자율 SWF 구현은 백엔드 재시작/시간주기 실행으로 경제를 변경할 수 있고 원천 없는 국고 증가, 합성 자산 성장/수익실현, 유저 잔액 직접 증가 경로를 포함하므로 이 권위와 드리프트했다.

따라서 v543은 기존 자율 SWF 변동 엔진을 v544 구조수정 완료 전까지 **기본 차단 / AUTHORITY_DRIFT**로 분류한다. v543은 위험 격리 회차이지 해당 수식의 승인 회차가 아니다.

## 2. 런타임 격리 계약

- `MONEYVERSE_SWF_EXECUTION_ENABLED`가 정확히 `true`일 때만 `evaluateAndRebalance()`가 상태를 변경할 수 있다.
- `MONEYVERSE_SWF_SCHEDULER_ENABLED`도 별도로 정확히 `true`여야 주기 실행을 예약한다.
- 백엔드 시작 자체는 SWF 경제 사이클을 실행하지 않는다.
- 명시적으로 켠 스케줄러의 첫 실행도 한 시간 전체가 지난 뒤에만 가능하다.
- 모든 사이클은 경제 쓰기 전에 transaction-scoped PostgreSQL advisory lock을 획득해야 한다.
- 잠근 `treasury_swf_configs` 행과 `last_executed_at` / `rebalance_interval_hours`로 최소 실행간격을 영속적으로 강제한다.
- lock 충돌 또는 최소간격 미경과는 정상 no-op이다.

v544 자금보존 정산·DB 경계수정·대사 검증이 완료되기 전 Test/Production 환경에서는 두 SWF 플래그를 미설정/false로 유지해야 한다.

## 3. Debian 호스트 불변 릴리스 계약

호스트 릴리스는 Git working directory가 아니라 exact-SHA 불변 산출물이다.

- `/srv/moneyverse-data/releases/*` 아래 서비스 릴리스에서 `git pull`, `git fetch`, `git reset`, `git checkout` 등으로 내용을 변경하지 않는다.
- 승인된 40자리 application source SHA와 `HEAD`가 같은 clean worktree에서만 후보를 staging한다.
- SHA가 포함된 새 목적지를 사용하고 기존 release path를 재사용/덮어쓰지 않는다.
- staging 전에 backend/frontend 빌드 산출물을 요구하며 staged release에서 Git metadata를 제거한다.
- `.moneyverse-release.json`에 channel, version, application source SHA, 생성시각을 기록한다.
- exact candidate가 필수 Test gate를 통과한 뒤에만 Test/Production pointer를 이동한다.
- live `/api/version` 또는 frontend identity가 승인 release manifest와 다르면 승격/완료 주장을 차단한다.

저장소 도구: `bash ops/release/stage-host-release.sh <test|prod> <version> <sha> <clean-source-dir> [release-root]`.
