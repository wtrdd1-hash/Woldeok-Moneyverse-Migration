## 신규 P0

### REL-122-01 — P0 — OPEN — exact-SHA CI 증거 어댑터 오판 가능
릴리스 증거는 SHA를 키로 하는 단일 `ReleaseEvidence` 집계 모델로 통합한다. 필수 workflow/check의 ID·attempt·conclusion·시작/완료시각·artifact/provenance·SHA·신뢰 source를 기록하고 `missing/skipped/neutral/cancelled/stale-SHA/success`를 분리한다. legacy commit status는 보조 증거일 뿐이다. 테스트는 status 0+Actions 성공, 필수 check 실패, 취소 후 rerun, 다른 SHA 성공, 비신뢰 source, 중복 attempt, stale artifact, 필수 gate 누락, API timeout/rate limit을 포함한다. Production은 해당 SHA의 모든 적용 가능 필수 gate가 완전하고 성공일 때만 승격한다.

### ECON-122-01 — P0 — OPEN — arbitrary-precision WLD의 자원고갈·정책우회·호환성 표면
v121은 핵심 ledger/bank money를 PostgreSQL 임의정밀 `numeric`으로 확장하고 공개 요청 금액을 canonical decimal string으로 바꿨다. 저장 표현능력과 게임 정책 한도를 분리해야 한다. endpoint별 정책 최대값과 합법적 최대 게임경제 값+마이그레이션 여유를 근거로 transport digit-length 상한을 둔다. leading zero, 부호, 소수, 지수표기, 공백, Unicode 숫자, 초과 길이는 DB 접근 전에 거절한다. 서버가 가격/대출/위험 한도를 권위적으로 검증하고 원장 idempotency·잠금·비음수·double-entry reconciliation을 유지한다.

보안/회귀 QA는 1자리, 정책 max-1/max/max+1, transport max/max+1, 10k/1M자리 body, `+1`, `1.0`, `1e9`, safe integer 초과 JSON number, 동일 idempotency key+다른 금액, 동시 송금/상환, BOLA, rate/resource exhaustion을 포함한다. oversized 입력은 제한된 시간 내 4xx이고 DB query가 없어야 한다. web/mobile/Discord/App API/OpenAPI SDK/관리자 감사/analytics에서 precision loss가 없어야 한다. 관측 지표는 reason별 입력거절, bounded digit histogram, DB numeric latency, reconciliation failure, idempotency conflict, legacy numeric-request 비율이다. 거대한 원문 금액은 로그에 저장하지 않는다.

롤백 시 저장 데이터를 bigint/numeric(38,0)으로 강제 downcast하지 않는다. feature flag/정책 상한으로 입력 수용을 축소하면서 numeric 저장을 보존하고, 스키마 수정은 새 migration으로 forward-fix한다. 사업효과는 직접매출 0이며 fraud/DB비용/CS/정밀도 분쟁 회피다. P95/P99와 fraud loss 악화가 없는 것을 guardrail로 둔다.
