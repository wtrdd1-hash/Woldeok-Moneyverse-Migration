- **C497-01 / P0:** split the client-facing API boundary into App Core (`/app-api/v2`) and Site Core (`/site-api/v1`) while retaining one authoritative Economy Core.
- **C497-02 / P0:** App/Site BFFs do not own WLD, tax, banking, treasury, market or monetary-policy business rules and receive no protected-table write authority.
- **C497-03 / P0:** Economy Core commands require independently validated workload identity and end-user/admin/automation actor context; caller-authored actor IDs are never authority.
- **C497-04 / P0:** replace the shared static internal bearer boundary as the final multi-core identity design with short-lived, audience/scoped, environment-separated workload credentials; prefer proof-of-possession/mTLS for physically separated high-value paths.
- **C497-05 / P0:** preserve PostgreSQL `SECURITY DEFINER` + append-only ledger as the final financial integrity boundary; safe `search_path`, revoked PUBLIC EXECUTE and selective grants remain mandatory.
- **C497-06 / P0:** AI/model runtime owns no ledger-write, DB-owner, policy-executor or admin-session credential; model output is untrusted proposal data.
- **C497-07 / P0:** all adaptive economy tuning is consolidated under one Economy Policy Registry and one policy executor; independent work/stock/economy mutation paths are superseded.
- **C497-08 / P0:** AI automatic numeric mutation is limited by per-step, 7-day, 30-day, hard-range, cooldown, reconciliation and risk budgets; AI cannot widen its own envelope.
- **C497-09 / P0:** tax/rate/credit-buffer/monetary-issuance changes remain human-approved; direct member balance, absolute stock-price and historical-ledger AI writes remain zero.
- **C497-10 / P0:** mobile high-value actions may require Play Integrity request binding using canonical request digest; integrity is an additional risk signal, not identity.
- **C497-11 / P0:** generated method/path/scope inventory becomes routing/security authority for public APIs; generic compatibility transports cannot silently gain privileged economic write access.
- **C497-12 / P1:** migration is zero-downtime expand→shadow→switch→reconcile→contract, preserving App API v1 compatibility until measured retirement criteria are met.
