## 1. 근거 및 중복 제거 계약

기존 v400 경제 corpus의 31,289건 고유 후보를 광범위 탐색 기반으로 유지한다. v433에서는 미러, 번역본, 추적 파라미터만 다른 URL, 이미 채택한 표준을 다시 세어 숫자를 부풀리지 않는다.

신규/재검증 레퍼런스 식별 우선순위:
1. DOI 또는 안정적인 출판 식별자.
2. 추적 파라미터를 제거한 발행기관 canonical URL.
3. 정규화 제목 + 발행기관 + 버전/발행일.
4. 같은 요구사항의 다국어판은 근거 1건으로 유지하고 언어 URL은 alias로 기록.
5. 대체된 구판은 변경 요구사항 자체가 중요할 때를 제외하고 현재 권위 신규 건수로 세지 않고 역사 근거로 보존.

근거 우선순위: 규범 표준/규제기관/중앙은행 > 1차 운영 원자료 > 동료평가 또는 추적 가능한 연구 > 공급자 구현가이드 > 2차 해설.

## 3. 채택 요구사항

### G433-01 / P0 — 유상 직업은 즉시 정산할 수 없다
일반 작업 참여 기본 무제한 원칙은 유지할 수 있지만 보상이 발생하는 모든 작업은 서버 권위 실제 시간 또는 독립 검증 가능한 완료 경계를 가져야 한다. 클라이언트 클릭 즉시 사용 가능한 WLD를 생성하면 안 된다.

필수 필드: `started_at`, `eligible_at`, `settled_at`, `job_policy_version`, `reward_formula_version`, 불변 ledger reference. 서버 시계만 권위이며 클라이언트 시계는 표시용이다.

수용: 설정 최소시간보다 빠른 반복 start/complete가 추가 WLD를 만들지 않고, 재접속/재시도로 시간 경계를 우회할 수 없어야 한다.

### G433-02 / P0 — 원자적 정산과 중복 불가능 원장
직업보상·송금·세금·매수/매도·국고지급·환불 등 모든 잔액 변경 mutation은 고유 business idempotency key를 가진 하나의 영속 transaction으로 처리한다. 동시성 제어는 Serializable 재시도, row lock 또는 동등하게 강한 invariant 보존 설계를 사용한다.

수용: 동시 중복요청은 정확히 한 번의 경제효과만 만들고 모든 부분실패는 rollback한다. serialization/deadlock 실패는 제한된 retry 정책 아래 transaction 전체를 처음부터 재시도한다.

### G433-03 / P1 — faucet/sink 하나가 아닌 지표 묶음으로 경제 제어
최소 gross issuance, gross sink, net issuance, active money supply, dormant balance, velocity, 품목군 가격지수, 신규/중간 유저 구매력, 자산집중, 거래량, 정산실패, 주요 발행원/소각원을 관측한다.

자동조절은 rate-of-change 제한을 두며 단일 telemetry spike로 무제한 보상/세율 변경을 하면 안 된다. 파라미터 변경은 버전관리·가역·감사가 가능해야 한다.

### G433-04 / P1 — sink는 인과·분배효과 검증 필수
OSRS 연구에서 item sink가 거래량을 줄이지 않으면서 luxury item 가격을 올릴 수 있었으므로 sink를 자동으로 안정화 정책이라고 간주하지 않는다.

정책 전후로 품목군 가격·거래량·희소성·대체수요·신규유저 구매력·고자산 보유·불법/어뷰징 지표를 함께 본다. 영구 정책에는 관찰기간과 rollback threshold가 필요하다.

### G433-05 / P1 — 정산 속도는 위험·유동성 파라미터
빠른 정산이 항상 안전한 것은 아니다. 국고/은행/시장 정산주기는 거래상대방 노출, 유동성 수요, netting 효과, 운영위험, 복구동작을 함께 고려해야 하며 정산 latency만 독립 최적화하지 않는다.

### G433-06 / P1 — 경제 상태 관측 계약
trace·metric·log를 안정적인 semantic naming으로 연결한다. 최소 `money.issued`, `money.sunk`, `money.supply.active`, `money.velocity`, `work.payout`, `market.tax`, `treasury.inflow`, `treasury.outflow`, `settlement.retry`, `settlement.duplicate_blocked`, `settlement.rollback`을 관측한다.

모든 경제정책 버전 변경은 telemetry와 audit log에서 추적 가능해야 한다.

### G433-07 / P1 — WCAG 규범 최소와 Moneyverse 터치 목표 분리
44px를 WCAG 2.2 AA 규범 최소치로 표현한 기존 문구를 supersede한다. WCAG 2.2 SC 2.5.8은 정의된 예외가 있는 24x24 CSS pixel 최소를 사용한다. Moneyverse는 주요 터치 컨트롤의 더 강한 제품 기본값으로 44x44 CSS pixel 이상을 유지하며 예외는 문서화한다.

### G433-08 / P1 — 배포 직렬화 및 보호 환경
Test와 Production은 별도 deployment environment를 사용한다. Production 승격은 deployment concurrency로 직렬화하고 승인된 ref로 제한하며 저장소 기능이 허용하는 범위에서 필수 check/approval gate를 적용한다. 문서 전용 기획 커밋은 runtime 승격을 시작하지 않는다.

### G433-09 / P1 — Debian 기준 최신성
v404에서 관측한 호스트 기준은 Debian 13.6이다. Debian 13.7은 2026-09-12 보안/중요 버그 수정 중심으로 공개됐다. 운영은 실제 패키지 상태와 호환성을 확인한 뒤 업데이트하며, 호스트 증거 없이 관측 runtime을 13.7로 문서상 바꾸면 안 된다.

### G433-10 / P1 — 모바일 가상화폐 정책 경계
실제 결제 IAP로 Moneyverse credit/currency를 판매하게 되면 스토어 정책이 release contract 일부가 된다. Apple 배포에서는 IAP 구매 게임 화폐를 만료시키면 안 되고, 구매형 무작위 가상아이템은 구매 전 확률 공개가 필요하다. 제품/경제기획이 스토어 정책과 묵시적으로 충돌하면 안 된다.

## 4. 구현/승격 게이트

이번 기획 회차는 G433-01..10 구현 완료를 주장하지 않는다. 관련 런타임 변경은:
- 구현 직전/작업 중간 current main 재확인;
- API·영속화·인가·실패 계약 정합;
- deterministic economy replay 또는 격리 Test DB 검증;
- 중복/동시성 negative test;
- exact candidate SHA Test;
- 배포 관련 세션 연속성/무중단 검증;
- Production 전 rollback 증거를 요구한다.

외부 연구는 설계 가설 근거가 될 수 있지만 Moneyverse telemetry·Test 증거·rollback 기준 없이 운영 경제 파라미터를 승인하지 않는다.
