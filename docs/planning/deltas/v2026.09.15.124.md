## SEO backend contract refinement — SEO-124-01 — P1 — PLANNED

Purpose: prevent SEO metadata drift and obsolete structured-data promises while keeping private Moneyverse state non-indexable.

- Public-only `SeoDocument` read model: `{url, locale, title, description, canonical, robots, updatedAt, hreflang[], breadcrumbs[], structuredDataTypes[], image}`. Account, auth, portfolio, holdings, orders, alerts, wallet, loans, admin, moderation, recovery and transaction state cannot instantiate an indexable document.
- Canonical generator normalizes host/scheme/trailing-slash and strips tracking/search/filter parameters unless a reviewed public landing page explicitly owns them. Redirect map and sitemap canonical must agree.
- Structured-data serializer uses a versioned allowlist tied to currently supported Google Search features. Deprecated/unsupported rich-result types are disabled without deleting underlying content.
- Sitemap emits canonical public URLs and truthful `lastmod` from meaningful content changes, not request time. Split by configured URL/byte thresholds and expose generation freshness.
- Rendering: indexable metadata and primary content must be available in server-rendered HTML. Required JS/CSS must remain crawlable. Private/member responses use noindex and private/no-store or appropriately partitioned caching.
- QA: canonical conflicts, wrong-language hreflang, noindex+sitemap contradiction, authenticated content leak, stale lastmod, structured-data critical errors, 404/410/redirect loops, crawler render failure, cache contamination.
- KPI: impressions/CTR → organic visit → signup → activation → D7/D30 → attributable net revenue; crawler error rate and organic CAC are guardrails. Kill low-quality auto-generated landing pages; iterate if impressions rise without activation/retention.
