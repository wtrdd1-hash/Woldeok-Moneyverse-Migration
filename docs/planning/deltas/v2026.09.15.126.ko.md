## P0 SEC-126-01 — 관리자 2FA 폐기에 대한 보상통제

**심각도/우선순위:** CRITICAL/P0. **상태:** REDESIGN_REQUIRED / release guardrail. **최초 확인:** 2026-09-15. **근거:** PR #342, main `f55010bd...`.

**위험:** 관리자 기본 자격증명 또는 인증 브라우저 세션이 탈취/재사용되면 독립 2차 인증 없이 지원데이터와 특권 기능에 접근할 수 있다. IP allowlist는 공격면을 줄이지만 신원 인증요소가 아니며 광범위 CIDR, VPN/proxy·신뢰망 침해, 설정오류에 취약하다.

**필수 설계:** 관리자 세션 짧은 TTL+회전+서버폐기; 파괴/경제/보안정책 mutation은 bounded `reauthenticatedAt` 기반 fresh OAuth reauth; 세션발급과 특권 mutation에서 서버 IP/CIDR 정책 평가; IPv4/IPv6 최종 권위는 PostgreSQL `inet/cidr`; controller claim과 독립된 DB actor/role 검사; cookie mutation CSRF와 strict Origin/Host; account+network+device-risk rate limit; secret을 제외한 불변 감사 `{actor,target,action,requestId,idempotencyKey,networkDecision,beforeHash,afterHash,createdAt}`; allowlist 변경/반복차단/권한변경/파괴작업 경보; self/last-superadmin lockout 방지; 관리자 blast radius 확대 전 phishing-resistant MFA 복구 경로/feature flag 유지.

**QA/승격조건:** 실DB BFLA, 일반사용자·탈취 admin-session negative, expired reauth, 세션폐기 전파, CSRF/origin negative, IPv4/IPv6/CIDR canonicalization/overlap, allowlist race/idempotency, last-admin/self-lockout, audit immutability/log-redaction. exact candidate SHA에서 통과 전 특권면 확대 Production 승격 금지. 잔여위험은 phishing-resistant MFA가 있을 때보다 높으므로 관리자 takeover 확인 시 MFA 복구를 즉시 scale-stop 조건으로 둔다.

## P1 SUPPORT-126-01 — 영속 지원대화 계약

**상태:** main 구현 PARTIAL/IMPLEMENTED, release gate 이후 실제 Production 동작은 UNVERIFIED.

`/support`는 case 목록, unread, `open|waiting_user|waiting_admin|resolved|closed`, timeline, composer, retry를 제공한다. empty는 문의 생성 방법을 안내하고 offline/timeout에서는 미전송 draft만 로컬 보존하며 전송 성공을 위조하지 않는다. duplicate submit은 idempotency key로 차단한다. `/admin/support`는 queue filter, age/SLA, case detail, 회원에게 보이지 않는 운영 metadata, reply/status CTA를 제공한다. 모바일은 composer가 최신 메시지를 가리지 않아야 하고 데스크톱은 queue/detail split을 사용한다. 키보드 focus, semantic label, send/error live-region, 대비를 필수로 한다.

**데이터/API:** `support_cases(id,user_id,status,created_at,updated_at,last_message_at,closed_at)`와 append-only `support_messages(id,case_id,sender_user_id,sender_role,body,created_at,idempotency_key)`. `(sender_user_id,idempotency_key)` unique, FK ownership, `(user_id,updated_at desc)`, `(status,last_message_at)` index. 회원은 자기 case만 읽고 관리자는 service+DB privileged path 모두에서 권한검사한다. message 생성과 case timestamp/unread 변경은 한 transaction이다. body byte/character 제한, Unicode 정규화, HTML 실행 금지, server timestamp. 400 validation/401/403/비열거형 404/409 closed·idempotency/429/5xx 계약을 구분한다.

**보안/개인정보:** text safe rendering으로 stored XSS 차단, arbitrary HTML 금지, URL/file 첨부는 별도 threat model 전까지 비활성화. 사용자/case send rate limit, spam 통제, oversized payload DB 이전 차단, analytics/log에 message body 저장 금지, 보존·삭제정책, support-access audit, 계정 privacy export/delete와 일관성 유지. admin search를 무제한 PII 탐색기로 만들지 않는다.

**운영/KPI:** content가 아닌 ID/status/timing 이벤트만 `support_case_opened`, `support_reply_sent`, `support_first_admin_reply`, `support_resolved`, `support_reopened`으로 기록한다. first-response p50/p95, resolution p50/p95, reopen, messages/case, abuse, cases/1k active, support cost/user, 해결 후 retention을 본다. 문의량/메시지 수를 늘릴 유인은 금지한다. 사업효과는 support 비용 절감·신뢰·retention의 간접효과이며 실측 전 금액은 HYPOTHESIS다.

**QA:** ownership/BOLA, admin BFLA, idempotent retry, 동시 member/admin reply, close-vs-send race, Unicode/emoji/large payload, XSS string, 429, DB rollback, pagination order, 접근성, 모바일 viewport, offline draft, audit/retention. Production 수용은 exact-SHA Test E2E+실DB와 배포 후 create→admin reply→member read→resolve smoke 및 타 사용자 case 비노출을 요구한다.

## SEO·사업성 교차정책

support/admin/account/transaction URL은 인증, `noindex`, sitemap 제외, 공개 structured data 없음, query-derived canonical 없음. 공개 marketing/help만 실제 visible content와 markup이 일치하고 검증을 통과할 때 canonical/Breadcrumb/SoftwareApplication을 사용한다. Organic KPI는 impression→visit→signup→activation→D7/D30→revenue cohort다.

지원대화는 support cost/case, cases/MAU, resolution, repeat-contact, 해결 후 D7/D30, prevented refund/churn으로 평가한다. spam/moderation burden만 증가하고 repeat contact/churn을 낮추지 못하면 iterate/kill, 만족·보안 guardrail을 유지하며 support cost/user가 낮아질 때 scale한다.
