## Decision
Every new or changed frontend surface requires a minimum five-pass responsive QA sequence before completion or Production eligibility.

## Required five passes
1. Baseline clipping/overflow and viewport-boundary audit.
2. Breakpoint/layout-position audit across navigation, grids, tables, charts and actions.
3. State/interaction audit across loading/empty/error/offline/validation/reauth/dialog/keyboard states.
4. Long-content/accessibility stress including KO/EN labels, 200% zoom/reflow where applicable, >=44px product touch targets, keyboard/focus and safe area.
5. Post-fix regression on the final exact candidate SHA.

If responsive/layout code changes again after a pass, affected routes/components restart the five-pass evidence sequence.

## Minimum viewport evidence
Use 280/320/360/390/768/1024/1280/1440 CSS px where applicable, plus relevant landscape/orientation and zoom/reflow. Critical flows retain real-device checks.

## Release blocking defects
Clipping, overlap, unreachable controls, materially wrong positioning, broken safe-area behavior, layout-caused horizontal scroll, keyboard/focus regression or unresolved responsive regressions block Test acceptance and Production promotion.

## Evidence schema
Record exact candidate SHA, route/screen, viewport, browser/device, pass number, defect/result, fix, rerun, visual evidence when available, and unresolved limitations.

## Scope
Documentation/planning only. This delta does not assert that existing routes have already completed five passes and does not assert Test or Production deployment.
