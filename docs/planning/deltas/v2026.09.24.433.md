## 1. Evidence and deduplication contract

The existing v400 economy corpus remains the broad discovery base at 31,289 unique candidates. v433 does **not** inflate that count by re-counting mirrors, translations, tracking-parameter URL variants, or already-adopted standards.

New or refreshed references use this identity order:
1. DOI or stable publication identifier.
2. Canonical issuer URL with tracking parameters stripped.
3. Normalized title + issuing organization + version/publication date.
4. If the same requirement is published in multiple languages, keep one evidence identity and record language variants as aliases.
5. A superseded edition is historical evidence, not a new current-authority item unless its changed requirement is material.

Evidence priority: normative standard/regulator/central bank > first-party operational dataset > peer-reviewed or traceable research > vendor implementation guide > secondary commentary.

## 3. Adopted requirements

### G433-01 / P0 — Paid work cannot settle instantly
Ordinary work participation may remain unlimited by default, but paid work MUST have a server-authoritative duration or independently verifiable completion boundary. A client click cannot immediately create spendable WLD.

Required fields: `started_at`, `eligible_at`, `settled_at`, `job_policy_version`, `reward_formula_version`, and immutable ledger reference. The server clock is authoritative. Client clocks are display-only.

Acceptance: repeated start/complete attempts faster than the configured minimum duration create no additional WLD; reconnect/retry cannot bypass the duration boundary.

### G433-02 / P0 — Atomic settlement and duplicate-proof ledger
Every balance-changing mutation (job payout, transfer, tax, buy/sell, treasury payment, refund) MUST execute as one durable transaction with a unique business idempotency key. Concurrency control must use a proven database strategy: Serializable retry, row locks, or an equivalently strong invariant-preserving design.

Acceptance: concurrent duplicate requests yield exactly one economic effect; all partial failures roll back; serialization/deadlock failures are retried as a whole transaction under bounded retry policy.

### G433-03 / P1 — Economy control uses a metric bundle, not one faucet/sink ratio
At minimum monitor gross issuance, gross sinks, net issuance, active money supply, dormant balances, velocity, category price indices, median/new-user purchasing power, wealth concentration, trade volume, failed settlements, and top issuance/sink sources.

Automatic control must use bounded rate-of-change. No single telemetry spike may trigger an unbounded reward/tax jump. Parameter changes are versioned, reversible, and auditable.

### G433-04 / P1 — Sink interventions require causal and distributional checks
The OSRS evidence shows an item sink can raise luxury-good prices even without reducing trade volume. Therefore a sink is not automatically stabilizing.

Before/after evaluation must include item-category price, volume, scarcity, substitution, new-user affordability, high-wealth holdings, and illicit-abuse indicators. Permanent policy requires a defined observation window and rollback threshold.

### G433-05 / P1 — Settlement speed is a risk/liquidity parameter
Faster settlement is not universally safer. Treasury/banking/market settlement cadence must consider counterparty exposure, liquidity demand, netting benefit, operational risk, and recovery behavior. Moneyverse must not optimize settlement latency independently of liquidity safety.

### G433-06 / P1 — Observability contract for economic state
Use stable semantic naming and correlate traces, metrics and logs. Required economic metrics include `money.issued`, `money.sunk`, `money.supply.active`, `money.velocity`, `work.payout`, `market.tax`, `treasury.inflow`, `treasury.outflow`, `settlement.retry`, `settlement.duplicate_blocked`, and `settlement.rollback`.

Every economic-policy version change must be discoverable from telemetry and audit logs.

### G433-07 / P1 — WCAG floor and Moneyverse touch-target goal are separate
Supersedes wording that treated 44px as the WCAG 2.2 AA normative minimum. WCAG 2.2 SC 2.5.8 uses a 24x24 CSS pixel minimum subject to defined exceptions. Moneyverse retains a stronger default product target of at least 44x44 CSS pixels for primary touch controls unless a documented exception applies.

### G433-08 / P1 — Deployment serialization and protected environments
Test and Production deployments use distinct environments. Production promotion must be serialized with deployment concurrency, restricted to approved refs, and gated by required checks/approvals where repository capabilities permit. Documentation-only planning commits do not trigger runtime promotion.

### G433-09 / P1 — Debian baseline freshness
The observed host baseline in v404 was Debian 13.6. Debian 13.7 was released on 2026-09-12 with security and serious-bug corrections. Operations must verify actual package state and compatibility before updating; planning MUST NOT rewrite observed runtime as 13.7 until host evidence proves it.

### G433-10 / P1 — Mobile virtual-currency compliance boundary
If real-money IAP ever purchases Moneyverse credits/currency, platform policy is part of the release contract. For Apple distribution, purchased in-game currency must not expire and randomized purchased virtual items require pre-purchase odds disclosure. Product/economy design must not silently conflict with store policy.

## 4. Release and implementation gates

This planning cycle does not assert that G433-01..10 are implemented. Any affected runtime change requires:
- current-main re-read before implementation and again during work;
- API + persistence + authorization + failure-contract parity;
- deterministic economy replay or isolated Test DB coverage;
- duplicate/concurrency negative tests;
- exact candidate SHA on Test;
- session continuity and zero-downtime checks when deployment is involved;
- rollback evidence before Production promotion.

External research may justify a design hypothesis, but cannot authorize a Production economic parameter without Moneyverse telemetry, Test evidence, and rollback criteria.
