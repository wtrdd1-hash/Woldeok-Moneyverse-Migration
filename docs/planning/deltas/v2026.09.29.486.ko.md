## 채택 요구사항
- **DB486-01 / P0:** concurrent index/reindex 후 예상하지 않은 invalid index를 거부하고 장시간 빌드는 PostgreSQL progress view로 관측.
- **DB486-02 / P0:** nullable 비즈니스 키 고유성마다 NULL distinct 의미를 명시하고 테스트.
- **DB486-03 / P1:** 상관 컬럼 추정 오류가 측정된 경우에만 extended statistics를 만들고 계획 개선을 검증.
- **DB486-04 / P0(활성화 시):** 복제/CDC 슬롯별 소유자·소비자·지연/보존 WAL 관측·용량 예산·보존 상한 또는 문서화된 예외 필수.
- **DB486-05 / P0:** 물리/base backup은 `pg_verifybackup`과 실제 격리 복구 리허설을 모두 통과해야 하며 서로 대체 불가.
- **DB486-06 / P0:** 대형 테이블 제약 변경은 지원되는 경우 저영향 단계 검증을 사용하고 락/스캔 분류 유지.
- **DB486-07 / P1:** RLS 도입 시 owner/BYPASSRLS/FORCE-RLS를 명시적으로 테스트하며 현재 제한 역할 기반 변경 경계를 대체하지 않음.
