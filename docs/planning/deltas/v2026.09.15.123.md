## Virtual-stock search detailed contract — STOCK-123-01 — P1 — PARTIAL/UNVERIFIED RUNTIME

Purpose: let authenticated members find fictional market instruments without scanning the full market while keeping trading/holdings authority unchanged. Actor is signed-in member; anonymous users must follow existing auth behavior. Entry is `/stocks` and shareable member-only `/stocks?q=<query>`.

UX: native GET search form, associated label, submit and clear/reset actions, localized result count, empty-search result, existing market cards and existing loading/error behavior. Query normalization trims/limits accepted UI state to 80 characters. Mobile uses full-width input and reachable controls; tablet/desktop preserve scan-friendly market cards. Keyboard submit, visible focus, screen-reader label/result feedback and EN/KO parity are mandatory. Offline/server failure must not be rendered as “0 results”; timeout/error is distinct from legitimate empty results.

Data/API: current implementation filters the already-authorized market read model in the server-rendered page; it does not introduce a mutation endpoint or DB migration. Search must never join private holdings, orders, watchlist ownership, alerts, account IDs or ledger data into public/cacheable output. If a future backend search endpoint is introduced, use bounded `GET /api/v1/stocks?q=&cursor=&limit=` with normalized query length, bounded limit, stable ordering, generic 400 for invalid syntax, 401 for unauthenticated member-only access, 429 for resource budget and 5xx for server failure. No idempotency key is needed for a pure read.

Security/privacy/abuse: treat query as untrusted text; no SQL/regex injection, catastrophic matching or unbounded fan-out. Query logs are truncated/minimized and must not become a PII search-history profile. Apply request/query complexity budgets if backend search is added. Other-user holdings must remain impossible to enumerate. Search result descriptions are output-encoded. Rate limits become mandatory if search moves from in-memory authorized list filtering to DB/API execution.

SEO: `/stocks?q=` is authenticated/private and `noindex`, excluded from sitemap and structured data. Do not generate ticker×query/date doorway pages. Only separately designed public fictional-company/educational pages with substantial unique content may index; private portfolio, holdings, orders, alerts and search history never appear in anonymous HTML/JSON-LD/cache. Breadcrumb structured data is only for public hierarchical pages whose visible navigation matches markup.

Performance/cache: current filtering cost must be bounded by the already-returned market catalog; measure server render p95 and catalog cardinality. If catalog growth makes full-list filtering expensive, move to indexed server search with explicit query plan budget rather than client-side downloading private data. Member HTML must not enter public shared cache.

Analytics/business: events may record pseudonymous `stock_search_submitted`, `stock_search_zero_result`, result-count bucket and subsequent public-safe instrument selection, but not raw free-text by default. KPI hypothesis: search-to-detail rate, search-to-watchlist/trade exploration, zero-result rate, p95 latency, D7/D30 market return. This is an indirect retention/discovery feature, not direct revenue; WLD/WDX trading is not real revenue. SCALE if discovery improves without latency/support/manipulation guardrail regressions; ITERATE on high zero-result or poor search-to-detail; HOLD/KILL if it leaks private data, materially increases abuse/query cost, or encourages real-investment framing.

QA/release: unit tests for symbol/name/description, case, whitespace, 0/1/80/>80, Korean/English, special characters; integration for auth and market-data failure; E2E keyboard/search/reset/shareable query/empty/error/mobile; security for XSS/injection/resource abuse/private-data leakage; regression for trading/watchlist/portfolio/ledger unchanged.
