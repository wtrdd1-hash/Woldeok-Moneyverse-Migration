## P0 SEC-126-01 — administrator 2FA retirement requires compensating assurance

**Severity/Priority:** CRITICAL / P0. **State:** REDESIGN_REQUIRED / release guardrail. **First observed:** 2026-09-15. **Latest evidence:** PR #342 / main `f55010bd...`.

**Risk scenario:** theft/replay of an administrator primary credential or authenticated browser session can reach support data, user controls and other privileged operations without an independent second factor. IP allowlisting reduces exposure but is not an identity factor and can fail under broad CIDRs, proxy/VPN compromise, trusted-network compromise or misconfiguration.

**Required design:** (1) maintain short admin session TTL plus rotation and server-side revocation; (2) require fresh OAuth reauthentication for destructive/economy/security-policy operations, with a bounded `reauthenticatedAt` age; (3) evaluate IP/CIDR policy server-side before session issuance and on privileged mutation, canonicalizing IPv4/IPv6 with PostgreSQL `inet/cidr`, never regex as final authority; (4) preserve DB-side actor/role checks independent of controller claims; (5) CSRF for cookie mutations, strict Origin/Host checks and secure cookie attributes; (6) rate-limit login/reauth by account+network+device-risk dimensions; (7) immutable audit `{actor,target,action,requestId,idempotencyKey,networkDecision,beforeHash,afterHash,createdAt}` without raw secrets; (8) alert on allowlist changes, repeated blocked logins, privilege changes and destructive actions; (9) self-lockout/last-superadmin protections; (10) keep a feature flag/path to restore phishing-resistant MFA before expanding administrator blast radius.

**Tests / acceptance:** real-DB BFLA tests; stolen normal-user/admin-session negative cases; expired-reauth rejection; session-revocation propagation; CSRF/origin negatives; IPv4/IPv6/CIDR canonicalization and overlapping-network cases; allowlist race/idempotency tests; last-admin/self-lockout tests; audit immutability and log-redaction tests. Production promotion is blocked for privileged surface expansion until these pass on exact candidate SHA. Residual risk after controls: primary-provider/session compromise remains materially higher than with phishing-resistant MFA; therefore scale criterion is no privileged compromise and bounded suspicious-login rate during observation, while any confirmed takeover triggers MFA restoration.

## P1 SUPPORT-126-01 — durable support conversation contract

**Status:** PARTIAL/IMPLEMENTED in main, runtime behavior beyond release gate UNVERIFIED. **Users:** authenticated member owns one or more support cases; administrators may list/reply/change status only through privileged authorization.

**UX:** `/support` shows case list, unread state, status (`open|waiting_user|waiting_admin|resolved|closed`), message timeline, composer and retry state. Empty state explains how to open a case. Loading uses stable skeleton; timeout/offline preserves unsent draft locally but never fabricates a sent message. Duplicate submit is prevented by idempotency key. `/admin/support` provides queue filters, age/SLA indicator, case detail, internal operational metadata separated from member-visible messages, reply and status CTA. Mobile keeps composer reachable without obscuring latest message; desktop uses queue/detail split view. Keyboard focus, semantic labels, live-region send/error feedback and contrast are mandatory.

**Data/API contract:** server-authoritative `support_cases(id,user_id,status,created_at,updated_at,last_message_at,closed_at)` and append-only `support_messages(id,case_id,sender_user_id,sender_role,body,created_at,idempotency_key)`; unique `(sender_user_id,idempotency_key)`, FK ownership, indexes `(user_id,updated_at desc)` and admin queue `(status,last_message_at)`. Member reads only own cases/messages; admin authorization is checked in service and DB privileged path. Message create is transactional with case timestamp/unread update. Body has byte/character bounds, normalized Unicode, no HTML execution, and server-generated timestamps. API errors distinguish 400 validation, 401 unauthenticated, 403 ownership/role, 404 non-enumerating missing case, 409 closed/idempotency conflict, 429 abuse limit, 5xx retryable server failure.

**Security/privacy/abuse:** stored XSS defense by rendering text safely; no arbitrary HTML; URL/file support remains disabled until separately threat-modeled. Per-user/case send limits, spam heuristics, block on oversized payload before DB, no raw message bodies in analytics/logs, explicit retention/deletion policy, support-access audit and export/delete behavior consistent with account privacy policy. Admin search must not become unrestricted PII enumeration.

**Operations/analytics:** events use IDs/status/timing, not message content: `support_case_opened`, `support_reply_sent`, `support_first_admin_reply`, `support_resolved`, `support_reopened`. KPIs: first-response p50/p95, resolution p50/p95, reopen rate, messages/case, abuse rate, support cases/1k active users, CS burden/user and retention after resolved case. Guardrail: no incentive to delay resolution or inflate message count. Business value is indirect support-cost reduction and trust/retention; monetary values remain HYPOTHESIS until measured.

**QA gate:** ownership/BOLA, admin BFLA, idempotent retries, concurrent member/admin replies, close-vs-send race, Unicode/emoji/large payload, XSS strings, 429, DB rollback, pagination ordering, accessibility keyboard/screen-reader, mobile viewport, offline draft, audit and retention tests. Production acceptance requires exact-SHA Test E2E plus real-DB tests and post-deploy smoke of create→admin reply→member read→resolve without exposing another user's case.
