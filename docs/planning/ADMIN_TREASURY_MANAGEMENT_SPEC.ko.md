## 1. 목적

관리자 제어 센터에 전용 **국고 관리(Treasury Management)** 화면을 추가한다. 국고는 플랫폼이 통제하는 수입·지출을 회계 처리하는 서버 권위의 공공/경제 준비금이며, 일반 회원 지갑이 아니다. 따라서 제한 없는 “잔액 수정” 입력창으로 구현해서는 안 된다.

기존 원장, BigInt-safe 금액 처리, DB 권한 검증, 불변 감사로그, 정확한 SHA의 Test 검증, 무중단 Production 승격 원칙을 그대로 유지한다.

## 2. 기능 범위

국고 관리에는 다음을 포함한다.
- 현재 국고 잔액, 사용 가능액, 예약/확정 예정액;
- 수입·지출 분류 및 기간별 집계;
- 정책상 국고를 거치도록 설정된 세금, 수수료, 소각처 연계, 보조금, 지원금, 보상 재원, 시스템 조정;
- 명시적인 보정 거래를 통한 관리자 수동 입금/출금;
- 예산 배정 및 예약된 지출;
- 전체 거래 이력, 대사 상태, 차이 증거;
- 준비금 임계치와 경고;
- 권한을 우회하지 않는 회계 조회/내보내기.

다음은 금지한다.
- 관리자 UI에서 보호 테이블 직접 수정;
- 과거 원장 항목 수정/삭제;
- 국고 기능으로 회원 잔액을 몰래 재작성;
- 기존 보상·세금·상점·주식·은행·사업 계약 우회;
- 부동소수점 금액 연산;
- 감사 기록 없는 “잔액 직접 설정”.

## 3. 관리자 정보구조

**관리자 → 경제 → 국고 관리**를 추가하고 다음 영역으로 구성한다.

1. **요약**
   - 총 잔액;
   - 사용 가능 잔액;
   - 예약/확정 예정 금액;
   - 오늘/7일/30일 수입과 지출;
   - 순유입/순유출;
   - 준비금 비율과 임계치 상태;
   - 마지막 정상 대사 시각;
   - 미해결 대사 차이 건수.

2. **거래 내역**
   - 수정 불가능한 시간순 원장;
   - 기간, 입출금 방향, 분류, 발생 시스템, 참조 유형, 행위자, 상태 필터;
   - 커서 기반 페이지네이션;
   - 고정 transaction/reference ID;
   - 안전한 경우 거래 전/후 국고 잔액;
   - 세금·수수료·보상·지원금·보정 등 원인 레코드 연결.

3. **수입**
   - 세금/수수료/시스템 수입 요약;
   - 출처별 분해;
   - 총액과 환불/역거래 구분;
   - 원장 진실을 변경하지 않는 기간 비교.

4. **지출**
   - 보상, 보조금, 지원금, 운영성 경제 이전 등 국고 재원 지출;
   - 최소권한 범위의 수취인/참조 정보;
   - 예약 기능이 있을 경우 확정 예정액과 실제 정산액 구분.

5. **예산/배정**
   - 목적별 예산 묶음 생성;
   - 적용 기간, 목적, 한도, 잔여 금액;
   - 예산 배정 자체가 화폐 생성이 되어서는 안 됨;
   - 실제 지출은 국고 원장 거래로만 정산.

6. **보정**
   - 권한이 필요한 수동 입금/출금;
   - 사유, 금액, 분류, 증거/참조, 멱등성 키 필수;
   - 반영 후 잔액과 준비금 영향 미리보기;
   - 확정 직전 재인증;
   - 잔액 직접 덮어쓰기 금지.

7. **대사**
   - 국고 원장 잔액과 설정된 원천 집계 비교;
   - 정확한 차이 금액 및 기간/출처 표시;
   - 대사 결과는 증거이며 자동 파괴적 수정 수단이 아님;
   - 수정은 별도 감사 가능한 보정 거래로만 수행.

8. **정책/경고**
   - 준비금 부족 경고선;
   - 선택적 위험 준비금 하한;
   - 비정상 대규모 입출금 기준;
   - 대사 지연 기준;
   - 다른 정책 엔진이 권위인 값은 읽기 전용으로 표시.

## 4. 국고 회계 모델

로그인할 수 없고 일반 회원 계정으로 취급되지 않는 전용 국고 계정 식별자를 사용한다.

모든 금전 변경은 최소한 다음을 포함하는 append-only 원장 항목을 만든다.
- 국고 거래 ID;
- 입금/출금 방향;
- 정수 문자열 금액;
- 자산/통화 식별자;
- 분류;
- 발생 원천/참조 유형과 참조 ID;
- 시스템 또는 관리자 행위자;
- 사유 코드와 선택적 설명;
- 변경 명령의 멱등성 키;
- 생성/정산 시각;
- 역거래/보정 연결 정보.

화면의 국고 잔액은 권위 원장/회계 상태에서 읽는다. 현재 페이지에 보이는 일부 거래만 합산해 기준 잔액을 계산하면 안 된다.

## 5. 기본 분류

초기 정규화 분류:
- TAX_REVENUE
- PLATFORM_FEE
- SHOP_OR_MARKET_FEE
- ECONOMY_SINK_TRANSFER
- REWARD_FUNDING
- SUBSIDY
- GRANT
- EVENT_BUDGET
- SYSTEM_TRANSFER
- ADMIN_CORRECTION_IN
- ADMIN_CORRECTION_OUT
- REVERSAL

새 분류를 추가할 때는 자유 텍스트만 늘리지 말고 DB/API/문서 계약을 함께 맞춘다.

## 6. 수동 보정 안전장치

수동 보정은 고위험 작업이다.

필수 조건:
- 현재 관리자 권한 모델에 따른 operator/superadmin 권한;
- 최근 재인증/step-up 인증;
- 브라우저 변경 요청의 CSRF 보호;
- 양의 정수 문자열 금액과 서버측 한도;
- 입금/출금 방향 명시;
- 구조화된 사유와 사람이 읽는 설명;
- 금액 기준에 따른 증거 참조;
- preview 또는 서버에서 결정적으로 계산되는 사전 결과;
- 멱등성 키;
- DB 함수의 실제 행위자 재검증;
- 트랜잭션 원자성;
- 불변 감사로그;
- 저장 직후 실제 커밋된 거래 재조회.

고액 작업은 추가 확인 challenge를 요구할 수 있다. 현재 제품이 단일 최고관리자 모델이면 이를 억지로 2인 승인 모델로 바꾸지는 않는다.

## 7. 예산과 예약금

예산 배정은 회계상 사용 목적을 예약하는 것이며 화폐 발행이 아니다.

예산 묶음은 최소 다음을 가진다.
- 고정 budget ID;
- 이름/목적;
- 기간;
- 배정액;
- 확정 예정액;
- 실제 집행액;
- 잔여액;
- 상태;
- 생성/수정 행위자;
- 시각 정보.

예약된 금액은 자유롭게 사용할 수 있는 잔액에 포함하지 않는다. 만료/취소 시 예약만 해제하고 과거 지출 기록은 변경하지 않는다.

## 8. API 방향

구현 시 다음과 동등한 actor-scoped 관리자 API를 제공한다.
- 국고 요약;
- 거래 목록/상세;
- 수입/지출 집계;
- 예산 목록/생성/수정/상태 변경;
- 보정 preview/commit;
- 대사 상태/실행;
- 정책/경고 조회 및 안전한 범위의 변경.

모든 변경 API는 서버 권위, 입력 검증, 재시도 가능한 명령의 멱등성, 관리자 권한, DB 행위자 검증을 적용한다.

## 9. 보안/권한

- 기본 거부;
- 애플리케이션 역할의 보호 테이블 직접 쓰기 금지;
- UI 역할 표시를 최종 권한으로 신뢰하지 않음;
- 국고 거래/예산/증거의 IDOR/BOLA 차단;
- 비밀값, 세션 쿠키, CSRF 토큰, 불필요한 회원 개인정보 로그 금지;
- 회원/수취인 참조는 최소 출력 DTO 사용;
- 고위험 변경 rate limit;
- 정책 변경 시 행위자, request correlation ID, 이전값, 새값 기록;
- 수동 보정, 예산 변경, 대사 실행, 정책 변경 모두 감사로그 기록.

## 10. UI/UX

- 데스크톱은 회계형 고밀도 표를 사용할 수 있지만 모바일은 가로 잘림 없는 거래 카드 형태로 전환한다.
- 표시 포맷은 locale-aware하게 하되 전송 값은 정확한 정수 문자열을 유지한다.
- 입금/출금을 색상 하나만으로 구분하지 않는다.
- 중요 변경 확인창에는 방향, 금액, 출처/대상, 사유, 반영 후 잔액을 명시한다.
- loading/empty/부분 데이터/권한 없음/대사 stale/error 상태를 모두 정의한다.
- 실패한 변경을 성공으로 먼저 표시하지 않는다.
- CSV/내보내기도 현재 필터와 권한 범위를 그대로 적용하고 비밀값을 포함하지 않는다.

## 11. 관측성과 경고

다음을 추적한다.
- 국고 총액/사용 가능액;
- 입출금 속도;
- 보정 실패 건수;
- 중복 멱등성 거부 건수;
- 대사 수행시간/결과/차이;
- 준비금 부족/위험 상태;
- 대사 지연;
- 변경 API 지연시간과 오류율.

경고 시스템이 자체적으로 화폐를 만들거나 차이를 자동 보정해서는 안 된다.

## 12. QA 승인 기준

Production 승격 전 최소 검증:
- 비관리자/권한 없는 관리자 접근 거부;
- 위조/오래된 관리자 identity;
- CSRF 및 재인증 누락;
- 음수/0/소수/overflow/비정상 금액;
- 동일 멱등성 키 재전송;
- 동시 보정 요청;
- 중간 실패 시 전체 rollback;
- 입금/출금/역거래 후 정확한 잔액;
- 예산 available/committed 계산;
- 페이지네이션/필터 무결성;
- 정상/불일치 대사;
- 감사로그 생성;
- 320/360/390px 반응형;
- 키보드/스크린리더;
- BigInt-safe 표시;
- 로그/내보내기 개인정보·비밀값 미노출;
- exact-SHA Test에서 backend/API/DB 실제 동작 확인.

## 14. 현재 구현 상태

이번 변경은 **기획/문서 전용**이다. 현재 저장소에 관리자 경제 제어 기능은 존재하지만, 이 문서는 전용 국고 원장/UI/API가 이미 구현됐다고 주장하지 않는다. 실제 구현은 최신 Living Project Plan을 다시 읽은 뒤 새 구현 브랜치에서 시작한다.
