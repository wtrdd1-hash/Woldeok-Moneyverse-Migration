## 필수 추가 시정 지시 및 완료 기준
1. **180개 전체 경로와 통합 기획의 세부 기능을 1:1로 재대조**할 것. 각 기능별 `요구사항 ID/정본 문단/경로/PC 화면 요소/모바일 화면 요소/진입 메뉴/입력·CTA/대기·확인·성공·영수증·실패·빈 화면/권한/5개 언어/실데이터 출처/증거/상태` 표를 작성한다. 근거 있는 요소별 검증만 `VERIFIED`, 나머지 `PARTIAL`, `NOT_DESIGNED`, `NOT_REVIEWED`로 기록한다. 경로·파일 존재만으로 합격 금지.
2. 우선순위 8개 `/`, `/dashboard`, `/work`, `/admin/work`, `/bank`, `/wallet`, `/quests`, `/shop`에 대해 PC·390px 모바일 수정 시안 전/후 이미지 및 번호 있는 UI 요소를 제공하고, 그 뒤 나머지 172개 시안을 순차 전수 점검한다. 범용 카드 복사로 완료 금지.
3. 모든 주요 업무를 홈·공통 메뉴·상황별 링크·모바일 전체 메뉴에서 발견할 수 있어야 한다. 권한 차단, 대기, 403/503, 빈 데이터, 최종 확인, 성공 영수증, 로그아웃·계정 전환을 화면으로 정의한다.
4. 네이비 `#0C1020`, 카드 `#151D32`, 브랜드 보라 `#9C83FF`, 보조 파랑 `#64B7FF`, 글자 `#E9F1FF` 유지. 청록/녹색을 페이지별 브랜드 색으로 쓰지 말고 상태 의미에서만 사용한다. 승인된 실제 출처 데이터 또는 명시적 디자인 샘플만 허용한다.
5. 기본 EN, 두 번째 KO, JA/ZH/VI 자동 감지·상시 수동 선택을 제공한다. 모든 페이지에 문의·채팅 런처 하나만 두고 관리자/회원 권한·본인 신원을 서버에서 확인한다.
6. 디자인 승인 뒤 실제 웹은 Java Spring MVC + Thymeleaf로 구현한다. Gemini와 파일 담당 충돌 방지, 별도 브랜치, main 중간 재조회, 정확 SHA Test의 브라우저·API·권한/보안/접근성 검증, 독립 롤백 및 무중단 운영 승격 게이트 준수.
7. 기능·시안·코드·운영 각 상태를 구분하고 수정 이미지·요소별 합격 근거·미해결 목록을 남길 것. 증거 없이 완성·배포로 기록 금지.
