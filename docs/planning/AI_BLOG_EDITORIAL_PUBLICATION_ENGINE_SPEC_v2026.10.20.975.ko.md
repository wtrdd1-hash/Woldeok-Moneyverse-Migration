## 2. 이용자 관점의 핵심 경험

**일반 독자:** 검색에서 실제 질문에 답하는 페이지 방문 → 본문 상단에서 국가/자료 기준일/작성·수정 시점/AI 보조 작성 여부 확인 → 복잡한 지표는 모바일 표로 읽고 출처 링크 열기 → 관련 계산기로 실제 숫자 입력·산출 확인 → 회원가입 요구 없이 핵심 계산 사용 → 관심 있으면 자발적으로 다른 글·즐겨찾기 이동. 금융 수익 보장, 가짜 WLD 보상 문구 금지.

**관리자 편집자:** 오늘 추천 주제, 출처 수집 실패, 검증 실패, 중복 후보가 큐에 숫자로 표시 → 초안을 열어 문단별 수치와 근거를 비교 → 수정 후 자동검증을 다시 실행 → 동일 리비전의 해시와 검토 사유를 제출 → 다른 권한의 최종 발행 또는 예약을 기다림. 검증·승인 전 공개 링크에 새로운 글이 보이면 P0 장애.

**최종 발행자:** 검수 상태/유효기간/법역/SEO 미리보기/이미지 저작권 확인 후 공개 시각 승인. 2중 권한이 필요한 기사에는 편집자와 발행자 구분. 이미 승인된 본문을 바꾸면 승인 무효. 게시 실패시 ‘확인되지 않음’으로 표시하고 서버 영수증 재조회, 무조건 중복 발행 재시도 금지.

**운영 담당자:** ‘최종 공개글 10/15’, ‘수집 실패 3건’, ‘검토 중 4건’, ‘공개 실패 0건’은 서로 다른 값. 기사 수가 늘었어도 GSC 유입·색인은 실측 데이터가 들어오기 전까지 미확인으로 표시한다.

## 3. 전체 데이터 처리 흐름

### 3.1 주제선정 — 검색수요를 측정한 것과 추정한 것을 분리

기존 /admin/seo 및 GSC 연계를 재사용한다. Google Search Console 검색어·페이지·국가·기기·노출·클릭·CTR·평균순위는 데이터 지연/표본 구간·타임존(PT)과 출처 상태를 보존한다. 네이버 도구나 외부 키워드 광고 API가 없으면 ‘월간 검색량’은 표시하지 않는다.

주제 분류: **MEASURED**, **GSC_IMPRESSION_ONLY**, **RELATIVE_TREND_ONLY**, **INFERRED_DEMAND**, **NO_DATA**. 검색량 근거가 없더라도 실제 유익하고 신뢰할 수 있는 편집 주제는 제안 가능하다. 단, 발행 효과를 수치로 보장하지 않는다.

우선주제군 예시: 복리/72법칙, 예적금 원리, 연봉 실수령액과 공제, 대출 상환/DSR, ISA·배당세, 연금·퇴직금, ETF 총비용, 환율의 읽는 법, 주식 평단가/수익률. **사이트에 있는 계산기는 중복 개발하지 않고 문서 품질부터 보강.** 1주 3~5개 후보 검토가 출발점이며 실제 발행 수는 자료·편집 검증 역량에 맞춘다.

### 3.2 출처 수집·인증

공식 권고 목록: 금융위원회, 금융감독원, 한국은행 ECOS, 국가통계포털 KOSIS, 한국거래소 KRX, 국세청, 국민연금/관련 정책 공식 고시; 미국 Fed/FRED/IRS, 일본 금융청·국세당국·일본은행, 중국 관할 공식 원문. 기사 유형에 따라 공급자 자료를 보조로 사용할 수 있지만 공인 자료와 같은 등급으로 표기하지 않는다.

출처 레코드는 URL, 발행기관, 원문 제목, 해당 법역, 관측/공포/시행/수집 시각, 수집 결과, 저장 해시, 참고 인용 범위, 이용권한·라이선스, 만료시각을 갖는다. HTTPS·도메인 allowlist·IP 사설/메타데이터 접근 차단·리다이렉트 제한·본문 크기 제한·요청 시간 제한·캐시 정책을 적용한다. 외부 문서 안의 ‘관리자 명령’이나 모델을 움직이려는 문장은 일반 데이터 취급.

출처가 차단/삭제됐거나 시행일 충돌이 있으면 SOURCE_UNAVAILABLE 또는 REVIEW_REQUIRED로 보류하고, 모델이 기억으로 공인 수치를 채우지 않는다.

### 3.3 내부 AI 기능 역할의 분리

- **Demand Analyst:** 증거 있는 검색어를 주제 의도로 묶고 신규 계산기보다 기존 페이지 개선 제안.
- **Research Assistant:** 출처 목록·자료 기준일·핵심 요약 및 상충된 근거 보고.
- **Writer:** JSON 스키마에 맞는 제목·요약·본문·질문/답변·수치별 citation ID가 포함된 초안.
- **Claim Examiner:** 법령/숫자/현재시각·시장 수치의 근거 부족/만료·충돌 표시. 모델 결과는 참고 증거일 뿐 최종 판정 아님.
- **Duplicate Reviewer:** 기존 전체 데이터에 대한 제목 정규화·내용 유사성 의심 여부 제안.
- **Refresh Planner:** 출처 변경/기한 도래를 탐지해 정정 요청 생성.

동일 AI 단계가 초안을 만들고 자체 생성한 ‘승인’을 부여할 수 없다. 서버의 역할·권한·DB 제약으로 차단한다. 내부 모델이 응답하지 않아도 기존 공개글은 정상 조회되도록 분리한다.

### 3.4 금융 수치 검증

본문에 숫자가 등장하는 문장마다 다음 유형을 분류한다: 정적인 수학 공식, 연도별 제도/세금, 실제 시장 관측값, 통계 추정, 시뮬레이션, 가상 WLD 데이터. 같은 숫자가 제목·표·그림·본문에 쓰이면 **동일한 구조화 소스 레코드 하나**에서 렌더링하도록 한다.

표시 기준:
- 기준금리/환율/주가 등 실제 수치: 단위, 출처, 정확한 관측일시 및 시차 표시. 공급자 장애·TTL 초과 시 ‘최신’ 표현 차단.
- 세금/연금/지원제도: 대상 국가, 법규, 시행일, 적용연도, 계산식 및 예외조건 표시.
- 금융 수학: 계산식 버전, 입력 예시, 오차/반올림, 공식 검산값 필요.
- 백테스트/Monte Carlo: 재현 가능한 데이터집합·모델 가정·실행 코드/결과 없으면 성과·승률 숫자 사용 금지.
- 가상거래·WLD: 반드시 가상경제/모의 결과로 표시하고 실제 시장 투자 추천이나 수익보장처럼 쓰지 않는다.
- 조회수/이용자 수/순위: 서버에 실제 검증된 측정 데이터가 없으면 표시하지 않는다.

### 3.5 중복 통제

검사 1: 동일 locale/country/title 정규화 해시. 검사 2: 동일 canonical/slug, 콘텐츠 해시. 검사 3: 문단/문장 유사도 MinHash/SimHash. 검사 4: 임베딩 코사인 유사도 및 이미 있는 계산기·기존 글과 의도 중복. 초안 검수 제안 임계값은 유사도 0.85 이상 ‘검토’, 0.92 이상 ‘높은 중복 위험’ **가설**로 시작하고, 171개 구 데이터와 합성·신규 정답셋에 맞춰 조정. 자동 삭제 금지. 서로 다른 제도·국가가 실제로 유의미하게 다르면 담당자가 차이를 증명하여 예외 승인할 수 있다.

### 3.6 글의 최소 품질·구성

글 하나는 질문/대상 독자, 한 문장 결론, H2/H3, 핵심 계산 예시, 신뢰 가능한 참고자료, 적용국가·기준일, 관련 계산기, 자주 묻는 질문(실제 수요가 있을 때), 마지막 검토시각, 업데이트·정정 이력으로 구성. 단어 수를 맞추기 위해 반복 문장을 붙이거나 키워드만 바꾸는 템플릿 글을 양산하지 않는다.

내부 평가 100점: 사용자 질문 해결 20, 독창성 15, 공식출처 20, 수치 검증 20, 계산기/공식 정확성 15, 현지화·접근성 10. 85점 이상은 **검토 후보**, 발행 승인 자동 조건이 아니다. 필수 수치 근거 하나라도 누락하면 게시 차단.

## 4. 검증 가능한 콘텐츠 상태 머신

TOPIC_PROPOSED → SOURCE_GATHERING → SOURCE_READY → DRAFTING → DRAFT_READY → QA_PENDING → EDITOR_REVIEW → APPROVED → SCHEDULED → PUBLISHING → PUBLISHED.

보조 상태: SOURCE_UNAVAILABLE / DRAFT_FAILED / QA_FAILED / CHANGES_REQUESTED / PUBLISH_FAILED / CANCELLED / REVISION_PENDING / CORRECTION_REQUIRED / WITHDRAWN.

| 상태 | 독자 공개 | 다음 허용 행동 |
|---|---|---|
| 주제 제안~초안 완료 | 비공개 | 자료 확보·AI 작성·수정 |
| QA 실패/출처 만료 | 비공개 | 근거 추가 또는 거절 |
| 관리자 검토 | 비공개 | 승인/수정 요청/거절 |
| 승인 완료 | 비공개 | 권한 있는 발행자가 예약/즉시발행 |
| 발행 대기/발행 중 | 비공개 | 잠금·재시도·영수증 확인 |
| PUBLISHED | 공개 | SEO 노출 가능; 실제 색인 여부는 미확인 |
| 정정필요 | 오류의 심각도에 따라 표시·검색 제외 | 새로운 리비전 재검수 |
| 철회 | 승인된 HTTP 410 또는 noindex 등 | 기존 이력 보존, 원인 기록 |

강제 불변식: **공개 본문 해시 = 승인한 리비전 해시 = 발행 영수증 해시.** 승인 이후 한 글자라도 수정되면 기존 승인 재사용 금지. 생성/검증 성공 상태만으로 공개되면 안 된다.

## 5. 권한 체계 및 안전 대책

권한은 관리자 boolean 하나로 완료하지 않는다. 예: blog_editor (초안/검수), blog_publisher (공개/철회), content_ops (장애/재시도·모니터링), blog_reader (공개 조회). 실제 제품 역할 등록부에 통합하고 새 권한 이름을 무조건 바로 추가하지 않는다.

- 요청은 기존 Next 서버 전용 API 클라이언트 경계 사용. 브라우저에서 비공개 Nest API를 직접 호출하지 않는다.
- 관리자 작업은 현재 로그인 사용자, 구체 권한, CSRF, 요청 출처, 동시 수정 버전, 감사 로그를 통과해야 한다.
- 중요한 승인·철회·전체 지역 동시발행에는 기존 step-up 요구 적용 여부를 작업 전에 권한 설계와 일치시킨다.
- 내부 AI/스케줄러는 편집 승인 함수 권한을 갖지 않는다. 문서만으로 모델의 행동을 제한했다고 주장하지 않고 DB/RBAC가 실행을 거부해야 한다.
- PostgreSQL SECURITY DEFINER와 허용된 EXECUTE 함수로 한정하며, 앱 계정에 전체 테이블 쓰기/읽기 권한을 새로 부여하지 않는다. PUBLIC EXECUTE 반드시 회수. 금융 테이블 기존 권한·잔액·원장에는 손대지 않는다.
- 외부 AI/공식문서의 악성 프롬프트 삽입, XSS/Markdown/이미지 URL, 외부 원격 리소스, 비밀키 로그 유출을 차단한다.
- 본문 이력·검수자·발행사유는 불변 감사 이력으로 남기되 회원 개인정보와 원본 입력 금액은 기록하지 않는다.

## 6. DB 구조 (제안, 마이그레이션 아님)

실제 구현 직전 최신 마이그레이션을 확인해 다음 미사용 번호를 할당한다. 이미 적용된 001~277 SQL 체크섬은 변경하지 않는다.

## 7. API 계약과 실패 처리

인증된 사용자 브라우저 → Next /app-api/v1/admin/blog/editorial → 내부 Nest /api/v1/admin/blog → 역할 검사 → 권한한정 DB 함수. 현재 레거시 /api/blog/generate는 계속 403/503.

| 관리자 API 후보 | 접근 권한 | 성공/실패 처리 |
|---|---|---|
| GET editorial/queue | 편집자 | 상태별 필터, 페이지네이션, 실제 마지막 변경시각 |
| POST editorial/topics | 편집자 | 주제 ID 생성; 중복키 409 |

| POST topics/:id/draft | 편집자 | AI 초안 생성 202, 모델 장애시 신규 글 없음 |

## 8. 다국어 발행 기준: 한국·미국·일본·중국

**KO:** 한국 관할, ECOS/KRX/KOSIS/국세청/공식 정부 고시 근거.
**EN:** 미국 독자 대상일 경우 미국 규정·단위·세율을 새 자료로 다시 검토. 한국 청년도약계좌 글을 직역해 미국 제도로 오인시키지 않는다.
**JA:** 일본 NISA·세금·연금·은행 제도는 금융청/일본은행 등 공식 자료별 검토 필요.
**ZH:** 중국 독자의 관할·지역을 명시, 원문 규제기관 근거 없으면 한국 자료임을 표시. 동일 언어권의 서로 다른 국가 법령 혼동 금지.

한 국가판이 작성되어도 모든 지역이 자동 공개되지 않는다. 각각 local_editor_id, jurisdiction, source_valid_until, content_hash, approval_status가 필요하다. /blog, /en/blog, /ja/blog, /zh/blog의 기존 주소를 재사용한다.

다국어 SEO: 각 언어 자체 canonical, 실제 번역 공개된 국가끼리만 상호 hreflang, 게시 승인일 기준 datePublished, **실제 본문 중요 수정일**에만 dateModified 변경, 해당 공개 URL만 sitemap; 임의 빌드시간을 lastmod로 표시 금지. 검수 안 된 글에는 Article JSON-LD/색인 대상 자격 미부여.

**Google 일반 블로그 글에는 Indexing API를 쓰지 않는다.** Google 정책상 해당 API는 지원되는 채용 공고·실시간 방송 이벤트로 제한된다. 일반 글은 유효한 URL/내부링크/sitemap/GSC 관측으로 관리하고 검색 제출 성공을 색인 성공으로 표시하지 않는다.

## 9. 계산기·위젯·블로그 유입 설계

기존 v931 미통합 설계와 새 계획의 책임을 분리한다. v931은 주제 수요/계산기 레지스트리/공통 위젯을 설계, v975는 **글의 공식근거·검수·발행권한과 품질**을 담당한다. 두 설계를 합칠 때 같은 기능을 두 번 만들지 않는다.

계산기와 블로그 인라인 위젯이 같은 calculate() 순수함수/공식 버전/입력스키마/국가/적용연도/반올림/테스트 벡터를 사용해야 한다. 본문 AI가 실행 코드, 사용자 스크립트 또는 임의 JSX를 만들 수 없고, allowlist의 calculator_id만 참조한다.

예시 UX: ‘대출 원리금균등 vs 원금균등 차이’ 글 → 승인된 대출 계산기 임베드 → 사용자가 금액/기간/금리 입력 → 실제 상환액/총이자 출력 → 적용가정·정밀 오차 확인 → 관련 글과 전체 계산기 연결. 가입/지갑/주식 거래는 계산기 결과를 가리지 않는 선택형 행동으로 유지한다.

분석 이벤트: 공개글 조회, 출처 링크 열기, 위젯 화면 노출, 위젯 계산 완료, 전체 계산기 이동, 재방문/동의 후 구독. 민감한 연봉·대출 원금·개인 재산·계좌번호는 외부 분석 시스템에 보내지 않는다.

## 10. 중복 스케줄러·AI 장애·재시도·알림

발행 모드 네 단계:
1. **DISABLED:** 현재 상태 유지; 이전 API 503.
2. **DRAFT_ONLY:** AI/자료 수집을 하되 게시물 비공개.
3. **APPROVED_MANUAL_PUBLISH:** 승인·출처 유효한 특정 리비전만 운영자의 명시행동으로 공개.
4. **APPROVED_SCHEDULED_PUBLISH:** 인간이 승인한 건에 한해 미리 예약된 시각 실행, AI 무검토 자동공개는 여전히 금지.

운영 전제: 지정된 리더 1개, 명시적 스케줄 활성화 설정, DB advisory lock 또는 lease+fencing token, 종료 시 예약 해제. Test·섀도우·복제 서버는 외부 발행/색인 제출 0건이 정상이어야 한다. 승인/출처가 만료되면 예약도 차단한다.

실패 처리: 최대 3회 재시도, 지수 백오프+지터, 재시작/동시 실행에도 멱등키 1개 = 공개 결과 최대 1개, Dead Letter 큐로 이동하며 관리자에 재처리 증거 노출. 출처 공급 장애는 신규 글만 보류하고 기존 교육 글 제공은 중단하지 않는다.

모니터링: source_expired, unsupported_claim, duplicate_hold, review_queue_age, ai_timeout, publish_attempt, publish_committed, visible_public_read, SEO_submission_receipt, observed_gsc_clicks를 별개 수치로 저장한다. 디스코드 관리자 경고는 출처 오류/게시 실패/7일 이상 미발행처럼 의미별로 구분하며 원시 비밀키·개인정보 유출 금지.

백업: 운영 DB·감사 데이터/기존 글의 읽기 전용 백업 검증 후 신규 SQL로 전환, 롤백은 이전 프론트/백엔드 산출물로 하되 이미 발행된 이력을 잃지 않도록 해야 한다. 운영 레거시 JSON의 chmod 644 변경·직접 overwrite 금지.
