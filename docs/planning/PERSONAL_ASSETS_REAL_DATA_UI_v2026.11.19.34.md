# Personal Assets First: Desktop + Mobile Real-Data UI and Internal-Info Boundary — v2026.11.19.34
**Status:** Specification only; not implemented, tested, or deployed. [Detailed Korean specification](PERSONAL_ASSETS_REAL_DATA_UI_v2026.11.19.34.ko.md).
**Mandatory requirements:** Every signed-in member sees their own wallet assets, available money, holdings valuation, portfolio P/L, verified quests and transactions. Treasury/supply/platform operations belong to authorized admin-only routes. All visible figures, chart points, online counts, timestamps and success messages must come from authoritative authenticated Spring APIs and PostgreSQL ledger or verified business sources, never mocked/hardcoded demo values. Do not double-count transferred cash and stock/deposit positions. Explicitly distinguish portfolio valuation, wallet balance, available cash, realized/unrealized and time-weighted returns.
**Prohibited public content:** Spring Boot/framework versions, API and database names/URLs, server health/uptime/latency, synchronization/data-quality diagnostics, deployment details, ledger validation internals, raw errors/debug traces, hidden admin metrics. Remove from server output including HTML/JS/JSON and static assets, not merely CSS-hide. Admin diagnostics require server-side RBAC and audit.
**States:** Login gate, skeleton loading without fake numbers, verified zero vs unknown, delayed and partial failures, reattempt, permission denial, safe error messaging; transactional actions are successful only after durable receipts.
**Devices:** Desktop sidebar/grid, mobile 5-tab bottom bar, responsive 320/390/768/1440, accessibility, single floating support button, EN primary and KO second language.
**Images:** Reuse repository's existing route/desktop/mobile PNG design index. The 12 newly generated personal-asset concept images in the conversation are not yet transferred to this repo or mini-PC. Mockup text such as 'Real Data Operations Criteria' is an internal planning concept and MUST NOT be shown to members.
**Acceptance:** authenticated ledger-vs-UI financial proofs; zero fake values or public internal tech metadata; identity isolation and RBAC negative tests; API/browser/visual QA; independent isolated Spring Test and exact-SHA zero-downtime release gates. Documentation is not evidence of a release.
