## 1. 실제 물리 디스크와 마운트

미니PC에서 `lsblk`, `df`로 확인:
- `/dev/sdb1`: 물리 100GB / 실효 약 99GiB, Debian 루트 `/`, Docker·레거시 빌드·Git 작업공간. 정리 전 92%, 약 8.1GiB 여유.
- `/dev/sda1`: 물리 200GB / 실효 약 197GiB, `/srv/moneyverse-data`에 PostgreSQL·불변 릴리스·백업·이미지. 사용률 약 54~55%, 약 86GiB 여유.
- `/srv/moneyverse-tasks`는 데이터 디스크가 **아니라 시스템 루트 디스크**에 있는 약 25GiB 누적 테스트 작업공간.
- 실제 공개 운영 릴리스 v717 SHA `176ca04ecfbd673e7f1057cdf83a9b92ea8f8272`, 테스트 릴리스 v735.2 SHA `9618a2499328d207c9e34b969f6aa96121331749`. 권한 있는 읽기 전용 런타임 일치 검사에서 두 릴리스의 프론트·백엔드·매니페스트·외부 응답 SHA가 각자 일치. 구형 v600 프로세스 존재 자체는 공개 서비스가 v600을 사용한다는 근거가 아님.

## 2. 실제 정리 결과

오래된 작업공간의 **재생성 가능한 Next.js `.next` 빌드 캐시 15개만** 두 차례로 삭제. 실행 중인 프로세스와 경로를 검사했고 소스·Git 오브젝트·node_modules·운영/테스트 릴리스·백업·DB·회원 WLD는 삭제하지 않음.

시스템 디스크 사용량 **92,164,472,832 → 84,988,256,256바이트**, 여유 공간 **8,695,623,680 → 15,871,840,256바이트**, 사용률 **92% → 85%**. 회수 **7,176,216,576바이트(약 7.18GB, 6.68GiB)**. 15개 정확한 대상 경로와 전후 `df -B1` 결과는 `docs/worklog/host-cleanup-v749-evidence.txt`에 보존.

**85%도 아직 경고 상태**이므로 추가 용량 정책이 필요. 다른 작업자가 사용하는 작업트리나 복구용 파일을 무단 정리하지 않는다.

## 3. 두 디스크 활용 개발 표준

1. 새로운 브랜치·검증용 worktree는 여건상 `/srv/moneyverse-data/build-workspaces/`에 둔다. 이번 v749부터 실제 데이터 디스크에서 격리 작업 시행. 오래된 운영 Git 경로와 서비스 경로는 움직이지 않는다.
2. DB, WAL, 백업, 운영 릴리스는 기존 데이터 디스크에서 그대로 보호. **라이브 DB 이전, 볼륨/백업 삭제, 시스템 스왑 변경을 금지**한다.
3. 데이터 디스크의 남은 공간 전체를 개발에 사용하지 않는다. PostgreSQL 및 백업 증가량을 측정하고 예약 공간을 먼저 확보한다. 데이터 디스크 80% 진입 전 새 임시 빌드 적재 제한, 시스템 루트 85% 경고, 90% 초과 긴급 조사 기준을 제안한다.
4. 정리 순서: 소유자·브랜치·빌드 SHA·날짜·실행 프로세스 확인 → 재생성 가능한 캐시인지 판단 → 정확한 경로·용량 기록 → 허용 경로만 정리 → `df`·서비스 검증 → 결과 기록. 운영 릴리스·백업·WAL·DB 볼륨·다른 에이전트 작업트리를 일괄 삭제하지 않는다.
5. 실제 데이터 디스크와 시스템 디스크의 여유량을 각각 검사한 후 테스트 빌드를 실행한다. 마지막 정상 버전은 새 앱/세션/백엔드 승인까지 반드시 유지한다.

**개발된 검사 도구:** `node ops/storage/dual-disk-check.mjs [--json] [--strict]`. 읽기만 수행하며 서로 다른 파일시스템 장치 번호, 점유율, 경고를 표시한다. 삭제·파일 이동·서비스 재시작 기능이 없으며 `--strict`는 경고 시 코드 2를 반환한다. 장치 번호 차이만으로 물리 디스크 개수를 추론하지 않는다(물리 2개는 별도의 `lsblk` 증거). 실패 테스트(RED) 뒤 구현 통과 테스트(GREEN) **5/5** 확인.

### 사용자가 허용한 위험 검토와 검증 완화의 범위

문서화된 담당자·기간·영향·복구안·승인이 있으면 **비필수** 항목(기존 lint 경고, 경미한 화면 장식, 운영 코드에 영향 없는 콘텐츠 등)은 조건부 예외 검토가 가능하다. 단 **재정 직접 쓰기 권한, 초기 잔액 출처 미확인, 원장 보전, DB 스키마 호환, 백업/복구 불명, 금융 인증·권한, 세션 손실, 운영 공개 SHA 불일치**는 동등한 안전 검증 없이 예외 처리할 수 없다. 안전하게 기능을 일시 중단하고 나머지 기능을 유지하는 대안은 실제 영향 범위·롤백 근거가 있을 때만 평가한다.

## 5. 오류 대응·검증 기록

- 파일 권한 없이 실행한 운영/Test 배포버전 검사 시 `EACCES`가 있었으나, 승인된 읽기 전용 `sudo` 접근으로 다시 실행해 **양쪽 배포버전 일치 검사를 통과**시켰다.
- 격리 작업공간의 첫 금융 사전검사는 `pg` 패키지 링크 누락(`MODULE_NOT_FOUND`)이어서 결과를 믿지 않았다. 작업공간에서 기존 불변 v717 릴리스의 의존성만 참조하도록 하여 재실행했고 위 **7개 재정 차단 사유를 실제로 확인**했다.
- 운영 DB, 원장, 권한, Test/Prod 서비스, 기능 스위치, 배포 포인터는 변경하지 않았다.
- 현재 구분: **정리 실행 완료 / 도구 코드 및 단위 테스트 완료 / 디스크 정책 기획 / 재정 해결 미완료 / 앱 최신 소스 운영 승격 미실시**.
