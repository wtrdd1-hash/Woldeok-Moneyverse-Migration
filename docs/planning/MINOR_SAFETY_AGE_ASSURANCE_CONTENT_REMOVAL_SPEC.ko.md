## 0. 목적

Moneyverse는 계정, 커뮤니티 UGC, 가상 금융/게임 시스템, 알림과 향후 광고를 함께 제공한다. 따라서 단순한 “법률 검토 필요” 문구가 아니라 미성년자 안전과 연령확인에 대한 명확한 구현 계약이 필요하다.

이 문서는 개인정보 최소수집형 연령 상태, 필요한 경우의 법정대리인 동의, 연령별 기능/광고 제한, 긴급 콘텐츠 삭제 접수, 보존·파기, SEO 경계와 구현 완료조건을 정의한다.

이 문서는 제품·개발 지침이며 법률 자문이 아니다. 국가별 출시 판단은 **legal review required**로 유지한다.

## 1. 기본 원칙

1. 적법한 제품 모드를 결정하는 데 필요한 최소 연령정보만 수집한다.
2. 단순 연령대 확인 때문에 주민등록증 등 정부 ID, 생체정보, 정확한 생년월일을 기본 수집하지 않는다.
3. 더 강한 연령확인이 실제로 필요하면 증빙 흐름을 격리하고 가능하면 원본 증빙이 아니라 최소 결과만 보관한다.
4. 아동/청소년 상태를 참여율 또는 광고 타기팅 신호로 사용하지 않는다.
5. 연령이 불확실하면 개인맞춤광고나 무제한 소셜 기능보다 더 안전한 모드로 실패하도록 한다.
6. 미성년자 안전 제한은 보호목적 제한이므로 무제한 기본 플레이 정책의 정당한 예외다.
7. 연령확인은 인증·인가·악용방지·모더레이션·법정대리인 동의를 대체하지 않는다.

## 2. 계정 연령 상태 모델

불필요한 신원증빙 사본 대신 거친 정책 상태를 저장한다.

권장 상태:

- `age_state = unknown`
- `age_state = adult_confirmed`
- `age_state = teen_confirmed`
- `age_state = child_restricted`
- `age_state = guardian_consent_pending`
- `age_state = guardian_consent_verified`
- `age_state = verification_required`

권장 메타데이터:

- `age_policy_version`
- `jurisdiction_policy_code`
- `assurance_method`
- 필요한 경우 `assurance_provider_ref`
- `verified_at`
- 재확인이 실제로 필요한 경우에만 `expires_at`
- `guardian_consent_version`
- `guardian_consent_at`

이 필드는 공개 프로필이나 불필요한 일반 분석 이벤트에 노출하지 않는다.

## 3. 대한민국 정책 게이트

대한민국에서는 만 14세 미만 아동의 개인정보 수집·이용을 해당되는 경우 법정대리인의 확인된 동의가 필요한 법적 경계로 취급한다. 동의를 위해 필요한 법정대리인 정보도 최소한으로 요청하고 처리 근거와 보유기간을 문서화한다.

출시 전 기본정책:

- 필요한 법정대리인 동의 절차를 적법하게 운영할 수 없다면 해당 아동의 개인정보 계정 생성을 완료하지 않는다.
- 마케팅·행태광고 동의를 필수 계정 동의와 묶지 않는다.
- 연령/대리인 증빙을 관계없는 프로파일링에 재사용하지 않는다.
- 목적 달성 또는 보유기간 종료 시 증빙을 삭제하거나 불가역적으로 최소화한다.
- UI 숨김뿐 아니라 API 인가·접근통제 테스트에도 아동/대리인 상태를 포함한다.

## 4. 미국 정책 게이트

COPPA 적용과 actual knowledge 기준은 별도 출시 검토 대상으로 둔다. 13세 미만임을 알고 있는 사용자에 대한 개인정보 수집·이용·공개는 해당 COPPA 고지/부모 동의 요구를 따라야 한다.

2026년 2월 FTC 연령확인 정책문은 일정 조건에서 연령확인만을 위한 처리를 사전 부모 동의 없이 허용하는 집행정책을 제시하지만, 목적 외 사용 금지, 신속 삭제, 제한적 공개, 명확한 고지, 합리적 보안과 정확성 검토 등이 전제다. 이를 신원증빙 장기보관 허가로 해석하면 안 된다.

`COPPA 2.0` 등 계류 법안은 **monitor/reference**로 기록하고 실제 발효 전까지 시행법으로 취급하지 않는다.

## 5. 연령확인 UX

### 5.1 저데이터 우선 경로

국가·제품 결정을 위해 충분한 경우 연령대 또는 출생연도 수준의 입력을 우선한다. 답을 미리 선택하거나 성인 선택지를 시각적으로 유도하지 않는다.

필수 상태:

- 기본 입력폼;
- 연령정보 요청 이유;
- 입력 근처 개인정보 링크;
- 오류/미완료;
- 안전모드 결과;
- 법정대리인 동의 필요;
- 외부 연령확인 제공자 이동;
- 확인 실패/재시도;
- 지원/이의제기 경로.

제한된 미성년자에게 답변 변경을 반복 유도하는 등 다크패턴을 금지한다.

### 5.2 고강도 확인

실제로 필요한 경우에만:

- 개인정보·보안·업체 검토 후 제공자를 사용한다.
- 광고, 아이덴티티 그래프, 모델 학습 등 목적 외 재사용을 계약으로 금지한다.
- 기밀성·보안·삭제 기한을 계약에 포함한다.
- 가능하면 연령 임계값 통과/연령대 같은 최소 결과만 받는다.
- Moneyverse DB에는 신분증 이미지, 얼굴 템플릿, 생체 샘플을 기본 저장하지 않는다.

## 6. 미성년자 안전모드

법률 검토 전 기본 제한:

- `child_restricted` 계정 개인맞춤/행태광고 금지;
- 미성년자 활동 기반 광고용 판매·공유형 데이터 흐름 금지;
- 정확한 나이/생일 공개 금지;
- 보수적인 프로필 검색노출·DM 기본값;
- 차단/신고/접촉방지와 모더레이션 강화;
- 실제 금융수익처럼 보이는 마케팅 문구 금지;
- 거래횟수, 도박성 참여, 강박적 사용을 높이는 타기팅 유도 금지;
- 별도 부모·결제·법률 정책 승인 전 미성년자 실물결제 기능 금지;
- 구현 시 조용한 시간/알림 빈도 보호.

WDX/WLD가 실제 금융상품이 아닌 가상/게임 전용이라는 표시는 계속 유지한다.

## 7. 광고·수익화 영향

연령 상태는 수익화 게이트다.

`child_restricted` 등 고위험 상태:

- 개인맞춤광고: **OFF**
- 교차맥락 행동 프로파일링 광고: **OFF**
- 허용되는 스폰서 콘텐츠는 명확히 표시하고 문맥형 중심으로 운영
- 광고 측정도 최소 데이터 사용
- 매수/매도, 대출/상환, 신고/차단, 대리인 동의, 안전 CTA 인접 광고 금지
- 연령 게이트를 이용한 경제적 우위 판매 금지

수익 대시보드는 성인 적격 인벤토리와 제한 인벤토리를 분리해 측정하고 fill rate를 높이기 위해 개인정보 보호를 약화시키지 않는다.

## 8. 커뮤니티 콘텐츠 안전·삭제

일반 스팸/품질 신고와 별도의 긴급 유해콘텐츠 경로를 둔다.

최소 신고 유형:

- 동의 없이 공유된 성적/사적 이미지;
- 미성년자가 포함되거나 포함된 것으로 보이는 콘텐츠;
- 신뢰할 수 있는 위협 또는 doxxing;
- 사칭/계정탈취;
- 괴롭힘/스토킹;
- 정책상 필요한 자해 긴급 에스컬레이션;
- 법률정책으로 정한 불법콘텐츠.

### 8.1 TAKE IT DOWN Act 대응준비

미국 서비스에서는 적용 대상일 경우 유효한 요청의 친밀한 이미지/영상과 알려진 동일 사본을 법정 기한 내 삭제할 수 있도록 법률 검토된 절차를 준비한다.

구현 요구:

- 로그인 없이 접근 가능한 공개 요청폼;
- 접수시각과 변경불가 case ID;
- 최소한의 신청자/연락처 정보;
- 콘텐츠 위치와 정책상 필요한 구조화 진술;
- 고우선순위 모더레이션 큐;
- 판단·삭제 시각;
- 개인정보/보안 검토를 거친 동일사본 탐지;
- 이의제기/에스컬레이션;
- 금지 콘텐츠를 불필요하게 장기보관하지 않으면서 최소 법적/감사 증거 유지;
- 야간 포함 운영 runbook.

피해자가 요청을 증명하기 위해 추가 민감정보를 공개하도록 요구하지 않는다.

## 9. 보존·삭제

다음 항목별 보유기간 표를 만든다.

- 연령확인 결과;
- 확인 제공자 참조값;
- 대리인 연락처/동의증빙;
- 모더레이션 요청 데이터;
- 법률/보안상 정당한 경우 삭제콘텐츠 fingerprint;
- case 감사 이벤트.

원칙:

- 원본 연령확인 증빙은 Moneyverse가 기본 보관하지 않는다.
- 확인전용 데이터는 결과 확정 후 정당한 예외가 없으면 신속 삭제한다.
- 대리인 데이터는 승인된 동의·안전 기능에만 사용한다.
- 회원탈퇴/내보내기에 미성년자·대리인 레코드를 포함한다.
- 백업에도 최종 삭제/익명화 정책을 적용한다.
- 로그에 신분증 원본, 생체정보, 사적 이미지, 신고본문 전체를 기록하지 않는다.

## 10. DB/API 계약

권장 엔터티:

- `account_age_policy_state`
- `guardian_consents`
- `age_assurance_events`
- `safety_reports`
- `content_removal_cases`
- `content_removal_actions`

보안 요구:

- parameterized query/검토된 고정 DB 함수만 사용;
- 최소권한 role;
- actor-scoped read;
- 운영자 화면 기본 마스킹;
- 민감증거 접근은 목적·재인증·감사기록 필수;
- 재시도 가능한 신고 생성은 idempotent;
- 서버 권위 feature gate;
- 클라이언트의 `is_minor=false` 값을 신뢰하지 않는다.

## 11. 관리자 콘솔

일반 사용자 개인정보 브라우저가 아니라 목적별 큐를 제공한다.

필수 화면:

- 연령/대리인 확인 예외;
- 긴급 콘텐츠 삭제 큐;
- SLA/case 경과시간;
- 제한된 증거 미리보기;
- 조치 이력;
- 사유코드 결과;
- 법률검토/에스컬레이션 상태;
- 삭제/보존 타이머.

운영자가 입력 중인 폼은 자동새로고침으로 날리지 않는다.

## 12. 분석

개인정보 최소화 이벤트:

- `age_gate_started`
- `age_gate_completed`
- `age_gate_restricted`
- `guardian_consent_started`
- `guardian_consent_completed`
- `safety_report_submitted`
- `safety_report_triaged`
- `content_removed`
- `content_copy_removed`
- `content_removal_appealed`

정확한 생년월일, 대리인 연락처, 원본 증거, 민감 신고본문은 일반 analytics에 보내지 않는다.

KPI:

- 연령게이트 완료/오류율;
- 확인 오탐·수동검토율;
- 대리인 동의 완료시간;
- 긴급신고 접수확인 시간;
- 유효 삭제 처리시간;
- 동일사본 삭제 성공률;
- 이의제기/복구율;
- 제한계정 개인맞춤광고 노출사고(목표 0);
- 보존기한 삭제 성공률.

## 13. SEO·색인

공개 안전/개인정보 안내는 검색 가능하게 하고 개인 case/account 데이터는 절대 색인하지 않는다.

색인 후보:

- 안전센터;
- 아동·청소년 개인정보 안내;
- 신고 방법;
- 콘텐츠 삭제 요청 안내;
- 커뮤니티 기준;
- 부모/법정대리인 도움말.

noindex/인증 보호:

- 신고 상태;
- 증거 업로드 URL;
- 대리인 확인;
- 계정 연령상태;
- 모더레이션/관리자 큐;
- 비공개 이의제기.

공개 페이지는 canonical URL, 정확한 title/heading, 가능한 서버렌더링을 사용하고 화면에 실제 보이는 내용과 일치할 때만 구조화데이터를 사용한다. 안전 키워드 유입을 노린 저품질 대량 페이지는 금지한다.

## 14. 테스트와 완료조건

런타임 출시 전:

1. 연령상태 전이 단위테스트;
2. 대리인/미성년자 경계 API·BOLA 테스트;
3. 연령/신고/관리자 입력 SQL Injection 테스트;
4. 제한계정 개인맞춤광고 음성 테스트;
5. 서버 feature gate 우회 테스트;
6. 백업복원 포함 보존·삭제 테스트;
7. 신고 생성/중복/idempotency 테스트;
8. 긴급 삭제 SLA 모의훈련;
9. 모바일/데스크톱 접근성 QA;
10. 스크린리더 label, focus, keyboard, 색상 외 상태표현;
11. analytics 개인정보 payload 검사;
12. 비공개 route noindex/auth 확인.

실제 구현은 별도 개발 브랜치 → 격리 Test exact-SHA → backend/DB/API/UI/security 검증 → Production 순서로 진행한다. 이번 버전은 문서-only이므로 Test 배포가 필요 없다.
