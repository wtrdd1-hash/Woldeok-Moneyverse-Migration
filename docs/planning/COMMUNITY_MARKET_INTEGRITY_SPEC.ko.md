## 0. 목적

Moneyverse는 커뮤니티 토론, 클럽, 가상 WDX 시장이 연결된다. 따라서 단순 채팅 서비스나 단순 모의주식 서비스보다 한 단계 더 복잡한 위험이 있다. 사용자가 사회적 행동을 조직해 허위 시장 신호를 만들거나, 인위적 인기·거래량을 만들거나, 집단 신고로 다른 사용자를 괴롭히거나, 수익이 보장된다는 식으로 오도할 수 있다.

이 문서는 일반 커뮤니티 참여는 열어두면서 사용자와 가상경제를 보호하기 위한 제품·모더레이션·시장 무결성·감사 계약을 정의한다.

핵심 원칙은 **토론은 허용하지만 조직적 조작은 허용하지 않는다**이다. 사용자는 의견을 내고, 투자 가설을 공유하고, 반대 의견을 말하고, 학습모임을 만들고, 가상의 기업을 토론할 수 있다. 그러나 허위 가격신호·가짜 유동성·가짜 인기나 거래압박을 만들기 위한 조직적 행동은 허용하지 않는다.

## 1. 설계 원칙

1. 정상적인 게시물·댓글·신고 활동에는 임의의 일일 한도를 기본으로 두지 않는다.
2. 스팸·보안 제한은 진행 한도가 아니라 보호 제한이며 `DEFAULT_LIMIT_POLICY.md`에 따라 이유가 있어야 한다.
3. 모더레이션은 근거 기반·검토 가능·감사 가능해야 한다. 큰 제재를 하나의 설명 불가능한 점수만으로 결정하지 않는다.
4. 시장 무결성 보류는 가능하면 계정 전체보다 의심 기능만 좁게 제한한다.
5. 커뮤니티 인기도는 WDX 가격, 작업 보상, 대출조건, 시즌 보상에 직접 연결하지 않는다.
6. 신고는 신호이지 투표가 아니다. 집단 신고만으로 계정 정지·시장 정지·랭킹 변경을 하지 않는다.
7. 중요한 제재는 이유와 이의제기 경로를 제공한다.
8. 보안·개인정보 정책이 허용하는 범위에서 조치·감사 이력을 보존한다. 일반 공개 기록은 사용자가 삭제하거나 정책상 제거가 필요한 경우가 아니면 임의 개수 한도를 두지 않는다.

## 2. 커뮤니티 표면

초기 범위:

- 공개 커뮤니티 피드
- WDX 종목 태그 게시물
- 댓글/답글
- 클럽 피드
- 사용자 프로필·팔로우
- 반응·북마크
- 이벤트/시즌 토론
- 시장 학습일지
- 신고·모더레이션 큐

P0에는 사용자 간 금융권유에 악용될 수 있는 비공개 DM 기능을 새로 넣지 않는다. 이후 DM을 도입하려면 별도의 악용·개인정보 검토가 필요하다.

## 3. 데이터 모델

권장 `community_posts`:

- `id`
- `author_user_id`
- `scope` (`PUBLIC`, `CLUB`, `PROFILE`, `STOCK_TAGGED`)
- `stock_id` nullable
- `club_id` nullable
- `title`, `body`
- `visibility_status`
- `moderation_state`
- `created_at`, `edited_at`, `deleted_at`
- `content_version`

`community_comments`는 상위 게시물/댓글, 작성자, 내용, 모더레이션 상태, 버전·시간을 보존한다.

`community_reactions`는 참여 메타데이터일 뿐 WLD 발행이나 가격변동 원인이 아니다.

## 4. 정책 예시

### 허용

- “현재 게임 내 물류 이벤트 때문에 WDX-LOG를 긍정적으로 본다.”
- “내 가상 포트폴리오는 세 섹터로 분산했다.”
- “가상 이벤트 기록을 보고 WDX-BIO를 매도했다.”
- “우리 클럽은 시장 학습 퀘스트를 같이 분석 중이다.”

### 시장 무결성 위반

- 가격을 움직이기 위한 조직적 동시 매수/매도
- 자기거래·순환거래 공모
- 허위 거래량·호가잔량을 만들기 위한 주문
- 운영자나 시스템이 상승을 보장한다고 거짓말하기
- 운영자·가상기업 내부자 사칭
- 조작된 정산내역·스크린샷을 공식자료처럼 제시
- 연계계정으로 게시물 인기를 조작하면서 관련 매매 실행
- 외부 보상을 대가로 특정 거래·공모를 요구
- 연계계정·클럽을 이용해 무결성 보류를 우회

일반 안전정책에는 괴롭힘, 위협, 개인정보 공개, 혐오·표적공격, 스팸, 피싱/악성링크, 제재 회피, 봇 참여 조작, 악의적 집단 신고를 포함한다.

## 5. 종목 태그 게시물 표시

종목 태그 게시물에는 다음을 보여준다.

- 가상시장임을 알리는 표시
- 작성·수정 시간
- 작성자가 해당 WDX 종목 포지션을 보유했는지 여부를 정확한 보유수량이 아닌 불리언/범주형으로 표시
- 운영자/관리자 계정 여부
- 서비스 내부 시뮬레이션이라는 안내

정확한 WLD 잔액이나 주식수량은 사용자가 명시적으로 공개하지 않는 한 노출하지 않는다.

게시 후 포지션이 바뀌는 것 자체는 정상행동이다. 게시내용과 이후 거래가 다르다는 이유만으로 조작으로 판정하지 않는다.

## 6. 신고 시스템

신고 유형:

- 괴롭힘/표적공격
- 혐오/위협/개인정보 공개
- 스팸/플랫폼 조작
- 사칭/조작자료
- 시장조작 공모
- 사기/피싱/외부 권유
- 부적절한 콘텐츠
- 기타(설명 필수)

`POST /api/community/reports`

입력에는 대상 유형/id, 사유 코드, 선택적 설명, 사용자가 이미 볼 수 있는 관련 콘텐츠·거래 참조, idempotency key를 사용한다.

중복 재시도는 기존 결과를 반환한다. 동일 사용자가 동일 대상·사유로 반복 신고해 심각도가 인위적으로 증가하지 않게 합칠 수 있다.

신고 수만으로 자동 계정정지, 영구삭제, WDX 거래정지, 거래취소, 랭킹변경을 해서는 안 된다.

## 7. 상태머신

콘텐츠:

`VISIBLE -> FLAGGED -> LIMITED_PENDING_REVIEW -> VISIBLE | REMOVED`

커뮤니티 기능:

`NORMAL -> WARNED -> COMMUNITY_RESTRICTED -> SUSPENDED`

시장 기능은 별도:

`NORMAL -> WATCH -> TRADE_REVIEW_HOLD -> MARKET_RESTRICTED -> CLEARED`

커뮤니티 제한이 있다고 해서 구체적인 경제·보안 근거 없이 계정 전체 경제를 잠그지 않는다.

## 8. 제재 단계

1. 안내/경고
2. 스팸성 노출 제한
3. 콘텐츠 제거
4. 임시 게시/댓글 제한
5. 클럽 모더레이션 조치
6. 거래근거가 연결된 경우 임시 시장 검토 보류
7. 시장 기능 제한
8. 심각하거나 반복되는 플랫폼 악용 시 계정 정지
9. 가장 심각한 위반에 대한 영구 제한

명백한 폭주행위는 자동 임시 스로틀을 사용할 수 있지만 장기간·계정 전체 제재는 가급적 지속 가능한 근거와 검토를 요구한다.

## 9. 임의 게시 한도 없는 스팸 방지

정상 게시물은 기본 unlimited다. 보호는 다음으로 처리한다.

- API burst/token rate limit
- 중복 문구 유사도
- 반복 링크/도메인
- 계정 연령·위험신호
- 봇형 타이밍 패턴
- 대량 멘션·답글
- 참여조작 링
- 연계계정 클러스터

정상 사용자가 “오늘 게시 횟수를 다 썼습니다”를 보게 만들지 않는다. 자동 스로틀 시에는 진행한도가 아니라 비정상 활동을 일시적으로 늦춘다는 UX를 제공한다.

## 10. 시장 무결성 그래프

정당한 근거가 있는 신호만 연결한다.

- 사용자/계정
- 클럽 관계
- 공개 게시물/댓글/반응
- WDX 주문·체결 상대방
- 정책상 허용되는 연계계정 위험 식별자
- 개인정보 정책이 허용하는 기기/세션 위험신호
- idempotency/replay 이상
- 모더레이션·무결성 사건

그래프는 조사 보조도구이며 그 자체가 유죄 증거가 아니다.

## 11. 탐지 패턴

### 자기·순환거래

- 동일 위험클러스터의 매수·매도
- 반복 A↔B 체결
- A→B→C→A 순환
- 거래량은 크지만 순포지션 변화는 거의 없음
- 같은 콘텐츠/이벤트 시간 주변의 반복 패턴

### 펌프 공모

- 밀접하게 연결된 계정들의 거의 동시 강세 게시물
- 직후 동기화된 매수 폭주
- 홍보자의 빠른 매도
- 여러 종목·시즌에서 패턴 반복
- 연계계정의 참여도 조작

이는 검토 신호이며 자동 유죄판정이 아니다.

### 가짜 호가/유동성

지정가 주문 도입 시 다음을 탐지한다.

- 비정상 반복 주문/취소
- 체결 가능 시점에 사라지는 층형 주문
- 호가잔량을 꾸미는 연계클러스터
- 취소/체결 비율과 실제 가격영향을 결합한 패턴

### 악의적 집단 신고

논쟁, 클럽분쟁, 거래손실 직후 특정 계정군이 상대편을 집중 신고하는 패턴을 탐지한다. 악의적 신고 자체가 정책위반이 될 수 있다.

## 12. 설명 가능한 위험신호

예시 내부 지표:

- `trade_cycle_score`
- `counterparty_concentration_score`
- `content_coordination_score`
- `engagement_authenticity_score`
- `account_linkage_score`
- `burst_automation_score`
- `report_abuse_score`

설명 없는 하나의 `fraud_score`만 저장하지 않는다. 사유코드, 정책상 허용된 근거 요약, 모델/규칙 버전, 시간을 보존한다.

이 임계값은 시장·플랫폼 무결성을 보호하므로 Default Limit Policy상 허용되는 보호설정이다. 사용자 성장한도로 표시하지 않는다.

## 13. 보류와 정산

`TRADE_REVIEW_HOLD`는 의심상황을 악화시킬 수 있는 신규 WDX 행동만 우선 차단한다. 잔액·보유주식·게시물·관계없는 자산을 조용히 삭제하지 않는다.

이미 정산된 거래는 append-only 원장에 남는다. 확정된 무결성 사건으로 조정이 필요하면 명시적 운영정책과 보상거래(compensating transaction)를 사용하고 과거 원장행을 수정하지 않는다.

시즌보상이 조사와 연결되어 있으면 `PENDING_VERIFICATION` 상태로 보류할 수 있다.

## 14. 커뮤니티와 가격엔진 분리

P0/P1에서 다음은 WDX 가격엔진의 직접 입력이 될 수 없다.

- 반응 수
- 팔로워 수
- 조회 수
- 댓글 감성점수
- 클럽 인기
- 신고 수

미래에 커뮤니티 참여를 이용한 가상 이벤트를 만든다면 명시적으로 공지한 게임 이벤트여야 하고 영향범위와 입력을 서버에서 제한해야 한다.

## 15. 클럽 권한

클럽 토론·프로젝트는 클럽 명세에 따라 기본 unlimited다. 시장조작을 조직하는 경우 플랫폼 무결성 규칙이 적용된다.

클럽 운영자는 다음 권한을 갖지 않는다.

- 회원의 비공개 정확한 WLD/주식잔액 열람
- 플랫폼 제재 무효화
- 정산된 거래 취소
- 숨겨진 무결성 신호 열람
- 회원 자산 몰수

클럽 자체 모더레이션과 Moneyverse 플랫폼 제재는 별도 감사영역으로 관리한다.

## 16. 이의제기

중요 제재는 다음 이력을 가진다.

- enforcement id
- 정책 사유코드
- 사용자 설명
- 제출시간
- 검토자/결과
- 결정시간
- 필요 시 권한복원·보상조치

이의제기에 WLD 결제를 요구하거나 성장등급으로 접근권을 차등하지 않는다.

## 17. 관리자/모더레이터 콘솔

- 우선순위 신고 큐
- 원문/문맥 스레드
- 작성자 조치이력
- 관련 사건
- 별도 시장 무결성 근거 패널
- 게시·거래 타임라인 상관관계
- 사유코드 기반 조치
- 되돌릴 수 있는 임시조치
- 감사이벤트 미리보기
- 이의제기 큐
- 무결성 대시보드

고위험 조치는 기존 관리자 세션·재인증·TOTP·DB actor validation 계약을 따른다.

## 19. API 초안

커뮤니티:

- `GET /api/community/feed`
- `POST /api/community/posts`
- `PATCH /api/community/posts/:id`
- `DELETE /api/community/posts/:id`
- `POST /api/community/posts/:id/comments`
- `POST /api/community/posts/:id/reactions`
- `POST /api/community/reports`

사용자:

- `GET /api/me/moderation-actions`
- `POST /api/me/moderation-actions/:id/appeals`

관리자:

- `GET /api/admin/moderation/reports`
- `GET /api/admin/moderation/cases/:id`
- `POST /api/admin/moderation/cases/:id/actions`
- `GET /api/admin/integrity/cases`
- `GET /api/admin/integrity/cases/:id`
- `POST /api/admin/integrity/cases/:id/hold`
- `POST /api/admin/integrity/cases/:id/resolve`

중복 실행이 문제되는 변경 API는 idempotency를 적용한다.

## 20. 개인정보·근거 최소화

- 안전·무결성에 필요한 신호만 수집
- 일반 모더레이터·사용자에게 숨은 연계/기기 신호 비공개
- 공개 콘텐츠 근거와 민감 보안신호 분리
- 커뮤니티에는 정확한 자산 대신 범주형 공개
- 민감 사건근거의 보존·접근정책 정의
- 관리UI에서 무제한 사용자 데이터 export 금지

## 21. 분석지표

커뮤니티:

- DAU/WAU 작성자·열람자
- 활성 작성자당 게시/댓글 수(보상으로 사용하지 않음)
- 콘텐츠 1,000개당 신고율
- 신고 중 확정위반율
- 오탐/조치취소율
- 신고→첫검토 median/P90
- 반복 위반율
- 고유 신고자와 집단 신고 클러스터

시장 무결성:

- 자기/순환거래 신호율
- 반복 상대방 집중도
- 검토사건 대비 확정사건
- 임시보류 시간
- 이의제기/취소율
- 전체 WDX 거래 중 의심거래 비중
- 확정사건의 가격영향
- 무결성 검토로 보류/해제된 시즌보상

모더레이터를 단순 “시간당 처리건수”만으로 평가하지 않는다.

## 22. 소비처 연동

모더레이션을 돈내고 탈출하는 소비처로 만들지 않는다. 경고삭제, 이의제기 가속, 시장보류 해제, 유리한 모더레이션을 WLD로 살 수 없다.

경제적으로 중립인 커뮤니티 꾸미기 소비처는 허용한다.

- 게시판 프로필 테마
- 글 카드 외형
- 클럽 공지판 장식
- 아카이브 전시 프레임

예시 transaction type:

- `SINK_COMMUNITY_COSMETIC`
- `SINK_CLUB_NOTICE_DECOR`
- `SINK_ARCHIVE_DISPLAY`

실제로 시스템이 WLD를 제거하는 경우에만 hard sink로 집계한다.

## 23. 시즌 연동

시즌마다 다음을 추가할 수 있다.

- 시즌 토론 주제
- 시장 학습일지 챕터
- 시즌 아카이브 카드
- 클럽 토론 이벤트
- 시즌 시작 무결성 안내
- 경쟁 WDX 리그 전용 무결성 검증

조사 중인 랭킹 보상은 검증완료까지 보류한다. 커뮤니티 인기도는 리더보드 점수로 바꿀 수 없다.

D-14/D-7/D-3/D-1 안내에는 경쟁보상 검증절차를 명확히 보여주되 정상적인 고활동 사용자를 위협하는 표현은 사용하지 않는다.

## 24. 운영설정

코드 배포 없이 조정 가능한 설정:

- spam burst threshold
- duplicate-content similarity threshold
- risk-review threshold
- 자동 임시 스로틀 시간
- 모더레이션 큐 라우팅
- 정책 reason code
- 안내문구
- 종목 태그 토론 feature flag

설정 변경은 버전/감사를 남긴다. 위험 변경은 기존 관리자 step-up 보호를 적용한다.

## 25. 테스트

구현 출시 전 최소 검증:

- 정상 고활동 사용자가 임의 일일한도로 막히지 않음
- 봇형 burst는 제한됨
- 중복 신고 재시도는 1건으로 처리
- 집단 신고만으로 자동 차단되지 않음
- 게시물 수정 이력 보존
- 정확한 비공개 보유량 누출 없음
- 자기/순환거래 fixture가 검토 신호 생성
- 정상 고빈도 거래가 자동 유죄판정되지 않음
- 임시 시장보류가 의도 기능만 막음
- 정산 원장을 수정하지 않음
- 이의제기 취소 후 권한복원하되 감사이력 유지
- 권한 없는 모더레이터가 민감 신호 접근 불가
- 동시 관리자 조치로 중복제재되지 않음
- 클럽 운영자가 플랫폼 제재 우회 불가
- 커뮤니티 참여량이 가격을 직접 움직이지 않음

## 28. 참고 조사

이번 기획에서 확인한 외부 패턴:

- Discord Community Guidelines(2025-09-29 시행)는 신고·선제 탐지와 단계형 제재를 운영하며, 플랫폼 조작 안내에서도 스팸/자동화를 플랫폼 악용으로 다룬다.
- Discord 커뮤니티 모더레이션 자료는 큰 공개 커뮤니티에 일반 게시횟수 제한보다 anti-spam, 텍스트 필터, anti-raid 보호를 권장한다.
- TradingView는 아이디어·스크립트·댓글·메시지에 직접 신고 기능을 제공하고, Paper Trading 대회 계정을 일반 계정과 분리한다. 2026년 대회 규칙에는 지나친 거래 요청에 대한 시스템 보호 한도도 존재한다.
- FINRA의 pump-and-dump 안내는 소셜미디어·메신저 기반 투자 홍보 위험을 경고한다.
- SEC의 2025년 집행사례에서는 소셜미디어와 그룹채팅의 신뢰를 악용한 투자클럽 형태의 사기가 언급된다.

이 자료는 설계 참고이며 규정을 그대로 가져오는 것이 아니다. Moneyverse WDX는 서비스 내부의 가상시장이고 실제 증권으로 표현해서는 안 된다.
