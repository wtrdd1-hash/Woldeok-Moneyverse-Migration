# Responsive Spring-served UI with five existing locales — v2026.11.19.38
**Owner-approved scope:** desktop + mobile new responsive frontend based on existing dark navy/violet UI vocabulary. Existing 180 Next page components and ~290 exported HTML references are *not* certified migrated. This first independent release slice covers Home, Wallet, Stocks, Quests, Shop, Community, Support, Account; additional historical routes must retain existing behavior until separately migrated. Backend remains Spring Boot single runtime; no Node/Next runtime dependency for these new screens.

**Translation contract:** Existing authoritative source `frontend/src/lib/locale.ts` and `components/language-switcher.tsx` support `en, ko, ja, zh, vi`. Present manual Auto/English/한국어/日本語/简体中文/Tiếng Việt chooser on every new desktop and mobile screen, default to browser `navigator.languages` where supported and fallback English globally. Manual choice persists in `wdmv_locale` cookie and localStorage. Automatic resets override and follows current browser language. WLD finance ledger never changes through language selection; language is not money conversion. Text dictionary keys require 5 variants and no fallback on financial strings. Currency formatting uses a deterministic read-only display and cannot change amounts. Never translate company/user-provided names or IDs.

**Data rules:** Signed-out page displays login gate, not account money. Wallet summary `/api/v1/wallet/summary` and portfolio `/api/v1/stocks/portfolio` only after verified `/api/v1/auth/session`; public markets `/api/v1/stocks`, shop catalog `/api/v1/shop/public-catalog`, posts `/api/v1/board` populate real lists; all failures show unavailable state. Never use a fallback actor ID or client-provided `X-User-Id`. No synthetic total assets, unrealized P/L, fake index/chart/visitors, demo financial numbers or internal diagnostics. Quest API `/api/v1/progression` not tied to session in present backend; do NOT show it as personal user achievement until backend enforces ownership; use guest/pending notice and verified route link only. Support backend legacy `/api/v1/support` has fallback actor, so do not fetch or mutate it until member session enforcement is independently tested; use safe contact info/navigation.

**Security, usability:** Admin data not embedded in public HTML or JS. Admin entry only after server-verified session role and server must enforce RBAC. Restrict private member data caching, clear on logout or account switch; no user HTML injection. Mobile: 320/390/430 breakpoints, column flow, no doc horizontal overflow; quote/index table scrolls horizontally within wrapper; bottom five action tabs and floating help button separated by safe-area; min 44px touch, keyboard navigation, visible focus. Desktop 1024/1440 sidebar and gridded cards.

**Gates:** tests before implementation, then five-locale dictionary/selector tests, real Spring read-only Test, guest API nonleak, portable HTML/JS checks and preferably real browser responsive QA, CI, exact-SHA merge to main. Only then official immutable Test and zero-downtime Production per `docs/RELEASING.md`; no direct live file overwrites on concurrent mini-PC. Record any blocked prerequisites honestly. NO production deployment claims before evidence.
