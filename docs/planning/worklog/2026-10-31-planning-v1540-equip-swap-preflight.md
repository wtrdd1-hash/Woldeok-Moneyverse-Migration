### Problem, actual source, scope and alternatives
- Migration `114-economy-faucet-sink-and-shop-2.sql` `inventory_equip_item(p_actor,p_catalog_id,p_slot,p_equip)` checks quantity>0 and slot allowlist, then executes two UPDATEs. It does **not** validate item holding expiry, catalog category-to-slot compatibility or serialize all equipment changes per owner. The same migration declares eight slots (frame, background, effect, nameplate, title, badge_1/2/3), with no owner-slot uniqueness constraint. `profile_get_cosmetics` can display expired/zero-quantity equipped rows while migration 123 `shop_my_items_v2` filters them. These are source-level gaps, not evidence of exploitation.
- Existing `frontend/src/app/inventory/inventory-view.tsx` POSTs `/api/v1/shop/holdings/:catalogId/equip` with `slot=badge_1` for all badges, and no server-confirmed preflight. Nest `shop.controller.ts` POST is guarded by Session, Authenticated, Consent and CSRF; this existing write path must remain separately guarded. Current /inventory `apiOrNull || []` can falsely render outage as empty (#1977). F675-188/189/190 are unmerged Draft/OFF prerequisites.
- **Chosen V1:** a separate read-only readiness comparison for one selected already-owned candidate and one selected slot, reached from the F675-190 replacement candidate card via `Review swap / 교체 가능 여부 확인`. Alternative client-only validation is rejected because it trusts incomplete holdings; alternative automatic swap/write is rejected because the existing DB write invariants are unproven. Do not silently create a purchase, equip, upkeep payment, refund, mint, WLD transfer, notification or scheduled task. Never label a successful read as guaranteed successful equip.

### Member UX, permissions, states and contract
- Only authenticated, consent-current owner. Private route `/inventory/expiring/equipped-impact/replacements/preflight?candidateId=<uuid>&slot=<enum>` (server validated and never indexed); compare current slot occupant (if any), candidate's current catalog label, quantity, holding expiry, slot compatibility and an evidence timestamp. Current catalog name is not historical purchase name. Effect expiry and upkeep settlement are separate, unknown unless independently proven.
- CTA: `Review swap` opens a read-only confirmation panel; `Back to candidates`, `Refresh checks`. No `Equip now` action in V1; existing manual equip path remains separate and disabled from this panel until Backend B's write hardening, owner-slot uniqueness and exact-SHA acceptance are complete. For badges, respect selected badge_1/2/3; never default all replacements to badge_1.
- Status union `REVIEWABLE` (eligible for manual consideration, **not** a permission to equip), `BLOCKED_NOT_OWNED`, `BLOCKED_EXPIRED`, `BLOCKED_SLOT_MISMATCH`, `BLOCKED_DUPLICATE_EQUIPMENT`, `BLOCKED_SOURCE_INCONSISTENT`, `UNKNOWN_POLICY`. Fail closed: 400 invalid UUID/slot; 401 unauthenticated; 403 consent; 404 owner candidate absent (do not reveal foreign existence); 409 changed owner source or equipment conflict; 410 expired evidence; 429 rate; 503 upstream/DB failure. Distinguish verified empty occupant from unknown, unavailable or malformed response; never substitute an empty panel for 503. Null expiry = UNKNOWN, not permanent. No optimistic equip-success UI.
- Proposed Nest `GET /api/v1/shop/holdings/equip-preflight?candidateId=&slot=` with session/consent guards; Next server-only BFF `GET /api/v1/shop/holdings/equip-preflight` and Android `GET /app-api/v1/shop/holdings/equip-preflight` must have matching typed contract. No actor UUID from client. Response `{candidateId,slot,asOfUtc,validUntilUtc,status,reasonCodes,currentOccupant?,candidate:{name,category,quantity,expiresAtUtc},sourceStatus:'VERIFIED'}`; bounded data, no raw ledger or other owner's identifiers. `asOfUtc` and expiry in microsecond-accurate UTC; screen uses KST with explicit zone.

### DB, transaction, security, consistency, accessibility and telemetry
- New **proposed forward-only migration** (no number reserved; coordinate with B) defines `public.inventory_equip_preflight_v1(p_actor uuid,p_candidate uuid,p_slot text)` as `SECURITY DEFINER`, fixed `search_path=pg_catalog,pg_temp`, schema-qualified relations, owner predicate for all `user_items`, `REVOKE EXECUTE FROM PUBLIC`, `GRANT EXECUTE TO moneyverse_app` only; reassert deny direct app-role SELECT/INSERT/UPDATE/DELETE/TRUNCATE on private holdings and related tables. Never rewrite migration 114 or 123. Existing user_items owner/catalog PK, FK, quantity constraints remain; evaluate only justified owner+slot index with EXPLAIN (10,001 synthetic items) and no duplicate index. No new table, materialized state or financial DDL.
- Read-only, one statement timestamp and one consistent snapshot (one SQL statement, or READ ONLY REPEATABLE READ for multiple). Inspect **all** owner's equipped rows before filtering: duplicates per slot, NULL slot with equipped true, non-NULL slot with equipped false, quantity<=0, category/slot mismatch, expired equipped rows, candidate already equipped, candidate expiry, current slot occupant, source drift. Return evidence status, not a mutation authorization. A signed, server-generated evidence identifier may be displayed for diagnostics but MUST NOT be accepted as authorization by the existing equip POST. No cross-request transaction, lock, or promise of TOCTOU-free write. Fresh POST must independently revalidate after Backend B hardens the SQL write path.
- `validUntilUtc = min(asOfUtc+30 seconds, earliest relevant candidate/current holding expiry, relevant 7/30-day horizon boundary)`; a future horizon-entry boundary also invalidates cached evidence without any row write. If source changes or session generation changes, discard panel and require Refresh. No stale results on account switch, logout, consent revocation, offline, or browser back navigation. Bounded response <=16 KiB, per-actor rate budget and statement timeout, no sensitive params in logs. Avoid cache and referer leakage of candidate ID: prefer server-only POST-for-read BFF if URL logs cannot be suppressed, while Nest remains read-only GET with validated query; ensure CSRF semantics if using POST-for-read.
- Privacy and SEO: authenticated edge and app-api must emit `Cache-Control: private, no-store`, `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: no-referrer` for success/errors/redirects (#2012); no sitemap, public previews or analytics with UUIDs. 320px layout, 200% zoom, 44px controls, focus restore, keyboard/screen-reader semantic comparison, aria-live non-focus-stealing error/status, ko/en parity, WCAG 2.2 AA. Android must bind session generation, cancel in-flight requests and never disk-cache evidence.
- Admin: only aggregate adoption, reviewable/block/unknown breakdown, 409/410/429/503, p95 query latency, refresh rate and account-switch stale-response drops; suppress cohorts <20 distinct owners, no candidate IDs, item names, user IDs or exact timestamps. KPIs **targets**, not measured: 0 cross-owner disclosure, 0 misleading "equip succeeded" claims, 0 financial/holding writes, p95 <300ms under 10,001 synthetic items.
