## 2. Design alternatives and selection
**A — controller-by-controller patches only:** fastest for one bug; rejected as the sole solution because aliases, new endpoints, Next internal token and forgotten filters bypass scattered checks.
**B — central Spring authentication/authorization + service policy + defense-in-depth guards:** **selected**. A single trusted subject resolver and route-policy registry, with typed machine principals, explicit public exceptions, service/DB authorization and negative tests. Roll out behind verified Test and per-domain route ownership; do not switch global permitAll in Production before exhaustive route mapping, or legitimate traffic can fail.
**C — edge-only ACL or WAF:** useful as a temporary containment control, rejected as final security because direct origin, internal callers, other aliases and DB function misuse remain.

## 3. Trust zones and identity model
1. **Anonymous browser**: only explicit public methods/paths (health with minimal data, approved public content, login initiation, correctly signed webhooks via separate chain). No private response even as empty placeholder; unknown route = deny.
2. **Member browser (Next same-origin BFF)**: server-side verified DB-backed session, current consent, subject UUID from session and owner-scoped data checks; client-controlled actor, user-id, role and internal-token headers are ignored/stripped. HttpOnly/Secure/SameSite cookie semantics must match live Nest behavior; no token in browser JS.
3. **Admin browser**: same valid session + active ADMIN/SUPERADMIN role from database + explicit permission per operation. Admin UI access alone gives no backend authorization. Sensitive reads (system logs, member portfolio) require permission and fresh reauthentication as classified in route matrix.
4. **Privileged command**: admin subject plus server-issued Discord/Telegram one-time step-up challenge, bound to active session, user, specific action/scope and canonical amount/target digest. Recommended initial TTL <=5 min, single use, <=5 attempts and per-actor/IP rate limiting; confirm exact policy against existing approved OTP contract before implementation. No code in logs. Mint, issuance/retire, payroll, Treasury, sanctions, destructive backup/control, data export and security changes require fresh step-up; no retired two-approver flow reinstatement by default.
5. **Internal machine**: authenticated gateway/job identity (mTLS or protected, purpose-scoped rotating secret), explicit service permissions and network origin. **A machine token never substitutes for a human administrator session.** Where a human-initiated BFF action needs admin authority, forward verified user session/claims independently and check both subject and service permission. Never pass client-supplied x-internal-token onward.
6. **Android**: documented mobile authentication scheme and session/revocation parity; no implicit trust in client IDs, no cookie-CSRF exemption unless the client is actually non-cookie authenticated. Test same role and owner semantics as web.
7. **Signed third-party webhooks / bots / Socket.IO**: separate chains for Discord raw-body Ed25519 + timestamp/replay defense where supported; Telegram origin/signature policy and bot secret controls; socket handshake authenticates viewer and authorizes namespaces/events per actor, with no token in query logs. One active command/job owner and idempotent processing.

All consumers use one **subject/resource/action/assurance** decision contract: {subject type, authenticated actor, roles, session freshness, consent, resource owner, action, step-up receipt, machine identity, route owner}. Missing/unknown/DB unavailable -> denial and safe error; do not fall back to synthetic empty, hardcoded admin, user-selected actor, or token possession.

## 4. Route registry, policy enforcement and migration-safe behavior
- Generate method + normalized path + aliases for each Nest and Spring operation and every Next app-api/BFF rewrite, Android client, websocket and integration. Map audience PUBLIC/MEMBER/ADMIN/SUPERADMIN/MACHINE/WEBHOOK, owner rule, session type, CSRF, OTP, consent, response privacy, DB function, side effects, exact tests, release state and Nginx owner. **Fail CI on unmapped routes**, method drift, ambiguous prefix/regex routing, duplicated aliases, or route with weaker authority.
- Implement separate ordered SecurityFilterChain matchers for exact public, signed webhook, internal machine, browser member/admin and mobile as required. Central bearer/cookie authentication must validate cryptographic hash, DB session expiry/revocation and role; populate a trusted Spring SecurityContext. Routes not explicitly registered end in denyAll (or authenticated + an additional exact authorization policy where justified). No unverified success via bare headers or cookie presence. Enforce method permissions in service + reviewed DB function too.
- Apply @PreAuthorize or AuthorizationManager at service/handler boundary as defense in depth. Password reset, login, OTP status and other partially authenticated flows need precise public/prelogin privilege rather than blanket /auth/** permit.
- Typed result codes: 401 absent/expired/invalid identity; 403 authenticated but insufficient role/ownership/CSRF/step-up; 404 genuine unknown resource or deliberately masked foreign-resource per contract; 409 idempotency/conflict; 429 limits; 503 unavailable dependency with no partial write. Private errors MUST carry private/no-store/noindex; no PII in problem details.
- **Specific remediation:** SystemLogController and AdminUsersController/AdminEconomyController must use the shared, DB-verified user/admin subject; remove string-exists, cookie-exists, arbitrary Bearer and token-only admin shortcuts. AdminAuthService's service-token equivalence to admin must be removed. Validate absent, empty, random and once-valid/revoked headers/cookies across all path aliases. Legacy client and BFF forwarding must be adjusted before deploying the strict chain.

## 5. Browser, CSRF, CORS, session and step-up
- Restore session-bound CSRF for cookie-authenticated POST/PUT/PATCH/DELETE and any GET with side effects (change these GETs to safe read or explicit write). Use existing session CSRF hash/token contract, Origin/Referer checks, host/proxy validation, same-origin BFF forwarding; missing/mismatched/replayed after logout -> 403, no writes. Server-token webhooks/mobile with no ambient browser cookies may have **narrow documented exemptions** and independent signature/auth tests, not global disable.
- CORS allowlist only actual verified Production/Test web origins, methods/headers per route, Vary: Origin and no credentialed wildcard or reflected arbitrary origins. Prefer no cross-origin credentialed browser API at all behind Next BFF. OPTIONS requests must not bypass application authentication or return broad origin approval.
- Cookie/session regression: Secure, HttpOnly, SameSite, domain/path, rotation, logout, revocation, parallel tabs, session fixation, expiration, concurrent role demotion, Nest-to-Spring continuity and Android login/retry. Do not equate STATELESS Spring session policy with security when custom cookies are manually processed.
- OTP never disclosed via API response, audit, screenshot, logs or metrics; lock after bounded failures; deny if Discord/Telegram delivery is unavailable; verification creates a single-use DB receipt bound to transaction intent and current actor. Prevent duplicate processing on retry or failover.

## 6. Financial and database policy (non-negotiable)
- Monetary mutations call only approved SECURITY DEFINER settlement functions through reviewed least-privilege app principal. **No JPA repository.save direct balance fallback, hardcoded administrator ID, broad table grants, ad-hoc UPDATE, float money or generated zero-value success responses**.
- One fenced finance writer across Nest and Spring during coexistence; scheduler/bot exactly-once ownership. DB-enforced double-entry and idempotency; replay with same UUID key returns original receipt and never second settlement. Cross-role/cross-owner/expired OTP/replay/duplicate/pipeline-failure negatives run against isolated restored PostgreSQL clone in rollback-only transactions.
- Preserve ledger, account balances, audit, WLD supply, pending settlements and historical migrations; write additive, forward-only numbered migrations only when necessary, with checksum/ACL parity. A read 200 cannot establish financial finality.

## 7. Logs, infrastructure, secrets, operations
- **Logs viewer**: deny without verified admin session, explicit logs.read permission and fresh step-up for raw/export; redact credentials, session cookies, OTP, IP+PII and finance identifiers according to approved retention policy. Restrict sources to an enum, bounded 10–500 lines with maximum output bytes, bounded filter length and response time; no arbitrary file paths, shell, unit names or command arguments. The log-read service should have only required read access through dedicated helper/ACL, not broad OS privilege.
- **Network**: Spring REST 4550 and Netty 9092 on loopback or private isolated interface; exact Nginx public routes, Cloudflare/TLS and websocket upgrade, external ingress deny for internal endpoints, firewall verification from genuinely external network, not loopback alone. Keep legacy Node 4500 isolated until validated retirement and rollback.
- **Systemd**: dedicated unprivileged principal; NoNewPrivileges=yes, PrivateTmp=yes, ProtectSystem=strict, ProtectHome=yes, safe capabilities and writable StateDirectory/ReadWritePaths only. Test journald and upload/cache functionality after confinement; do not apply blindly.
- **Secrets**: eliminate literal application-secret defaults and inline unit secrets; protected per-service credentials/permissions; structured rotation with dual-key grace only where secure and supported, revocation after measured cutover, inventory leak checks. Never publish token values in GitHub, test logs, telemetry or ChatGPT.
- **Other**: strict actuator exposure (minimum health only externally), protect Swagger/API-docs/metrics, rate/body-size limits, request correlation without sensitive contents; pin dependencies, generate SBOM and check current supported Spring/Java and CVEs. Trace data-classification and audit retention to approved security master.

## 9. Release acceptance and evidence matrix
Mandatory route classes: anonymous read, member owner read/write, other-owner IDOR/BOLA, admin sensitive read/export, admin mutable command, OTP required financial/abuse action, internal job, signed webhook, Android, Socket.IO, Nginx aliases. For EACH class exercise anonymous, ordinary member, expired/revoked session, wrong role, valid admin, missing/forged machine credential, forged cookie/bearer, stale/missing/replayed CSRF or OTP, malformed inputs and unavailable DB. Assert status + absence of sensitive body + *no unauthorized DB mutation*, cache/noindex/no-referrer and audit redaction.
- Source-level CI: route registry 100% inventoried or explicit blocked; prohibit wildcard credentialed CORS, global CSRF disable, default permitAll, embedded secrets, privilege-through-token and unsafe DB direct writes; tests must fail before remediation then pass after.
- Runtime/Test: fresh exact main SHA and immutable artifact digest verified across Next, Spring, Nginx and Android where applicable; isolated PostgreSQL with effective app ACL (no direct financial DML), full suite including negative tests and real browser/Android with step-up.
- Production: same audited artifact SHA, independent off-host backup and restore rehearsal, staff canary, smoke + sessions + finance reconciliation, p95/p99/error metrics and rollback. **BLOCK** if any 502/unknown role/authorization bypass, mismatched SHA, secret leak, duplicate money write, unverified persistent session, missing rollback or unexpected Node/Java dual writer.
- Minimum security exit targets: **0 anonymous admin successes, 0 other-owner disclosures, 0 credential-only admin elevations, 0 CSRF bypasses on cookie writes, 0 unbalanced/duplicate financial settlements, 0 direct public access to internal-only ports, 0 secrets/OTP in logs**. These are targets, NOT observed current metrics.
- Do not call the migration or security 100% complete until every consumer/route/job is mapped and signed Test/Production evidence exists. The controller inventory 100% remains a separate metric.
