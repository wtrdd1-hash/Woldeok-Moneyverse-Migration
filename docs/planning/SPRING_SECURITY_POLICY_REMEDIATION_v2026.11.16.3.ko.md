## 1. 범위·실측·금지사항
- GitHub 최신 main 기준 NestJS 컨트롤러 파일 89개, Spring 파일 90개(기존 89개 대상에 신규 SystemLogController 추가). **컨트롤러 목표 수량 충족은 100% 기능/보안/트래픽 전환 증거가 아니다.** 현재 Spring OpenAPI 경로 853개, 작업 926개에는 별칭 및 추가 API가 포함되므로 NestJS 개수와 직접 나누지 않는다.
- Spring 4550과 소켓 9092가 모든 인터페이스에 바인딩되어 있으며, 기존 Node 4500 서비스와 전용 Node Discord 봇은 살아 있다. 과거 루트 implementation_plan v50–v53의 완전 퇴역 표현은 실측과 불일치. 기존 롤백 경로를 보존하고 AUTHORITY_DRIFT로 문서 관리한다.
- SecurityConfig의 모든 요청 허용 및 전역 CSRF 비활성화, 자격증명 허용 와일드카드 CORS는 소스에서 확인. CORS는 실서버에서 신뢰하지 않는 Origin 반사까지 관찰. systemd는 전용 제한 계정과 주요 격리가 충분하지 않다. 이 사실만으로 모든 컨트롤러의 인증을 뚫었다고 표현하지 않는다.
- 신규 SystemLogController는 값이 비어 있지 않은 임의의 x-internal-token 헤더만으로 관리자 확인을 빠져나갈 수 있다. **현재 운영에서 해당 신규 API는 404**이므로 실운영 악용 성공은 미확인이다.
- AdminUsersController/AdminEconomyController에는 Bearer 헤더나 쿠키의 **존재만** 확인하는 분기가 있고, AdminAuthService는 내부 서비스 토큰을 인간 관리자 권한처럼 취급하는 로직이 있다. 비밀 토큰 실제 값은 공개 기록에 담지 않는다. 운영 무인증 /api/v1/admin/users 401만으로 위조 Bearer/쿠키나 다른 별칭이 안전하다고 판정할 수 없다.
- 무인증 주식 포트폴리오는 Nest 401, Spring/내부 게이트웨이/운영 200으로 인증 계약이 어긋난다. 응답 본문을 수집하지 않았으므로 개인정보 노출이라고 단정하지 않는다.
- 공식 Test는 health 200이나 일부 선정 API 502로 정확 SHA 로그인·관리자·금융 검증이 막혀 있다. **보안 테스트를 위해 인증을 끄거나 임의 헤더를 허용하거나 금융 테이블에 직접 UPDATE 권한을 주거나 실제 WLD를 이동시키지 않는다.**
- 이 문서는 변경 제안이며 개발·보안 코드 변경, Test/운영 배포, 자격증명 교체, DB 변경/초기화 승인이 아니다. 앞선 사용자 허용은 QA 복구에 한정되어 있었다.

## 2. 대안 비교 및 결정
**대안 A: 컨트롤러마다 우회 조건만 수정** — 작은 결함에는 빠르지만 신규 API, 경로 별칭, 내부 토큰, Next 프록시의 다른 우회를 놓칠 수 있어 단독 채택 불가.
**대안 B: 공통 Spring 인증·인가 필터 + 업무 권한 검증 + DB 방어** — **채택 초안**. 중앙에서 신뢰된 주체를 식별하고 허용 경로를 등록한 뒤 서비스/DB에서 재검증한다. 운영에 일괄 차단 정책을 즉시 적용하면 정상 요청이 중단될 수 있으므로 완전 경로 수집과 Test가 선행되어야 한다.
**대안 C: Nginx/WAF만 차단** — 임시 차단에는 유효하나 내부 서비스/직접 백엔드/별칭/DB 오용까지 막지 못해 최종 해법이 아니다.

## 3. 신원 및 권한의 분리 모델
1. **비로그인 브라우저**: 명시적으로 공공 승인된 메서드·경로만 허용한다. 헬스는 최소 정보만, 서명된 외부 웹훅은 별도 체인으로 처리한다. 비공개 실패를 빈 배열 성공으로 꾸미지 않는다.
2. **일반 회원/Next BFF**: DB 검증 완료·만료/폐기되지 않은 활성 세션, 동의 상태, 그 세션에서 도출한 회원 UUID로 소유권을 검증한다. 클라이언트가 전송한 actor, user-id, role, internal token은 무시하거나 제거한다. 기존 HttpOnly/Secure/SameSite 쿠키·세션 연속성을 준수한다.
3. **관리자 브라우저**: 유효한 회원 세션 + DB의 현행 ADMIN/SUPERADMIN 역할 + 해당 기능의 명시적인 허가가 필요하다. 관리자 웹페이지에 접속했다는 사실만으로 API 권한이 생기지 않는다. 시스템 로그와 회원 자산 조회는 민감도에 맞는 재인증을 추가한다.
4. **중대 명령**: 관리자 세션에 더하여 Discord/Telegram 일회용 추가 인증을 사용한다. 인증 영수증은 **세션·사용자·행위·대상·금액 해시**에 묶고 1회 사용한다. 설계 기본 제안은 유효시간 5분 이내, 시도 5회 이내, 계정/IP 제한이며 실제 구현 전 기존 승인 OTP 계약과 대조한다. 조폐국·발행/소각·국고 지급·권한 변경·제재·백업 실행·로그 원문 내려받기 등에 적용한다. 과거 폐기된 2인 승인 절차는 임의로 부활시키지 않는다.
5. **내부 서비스**: 서비스용 인증(mTLS 또는 보호된 목적별 비밀키)과 제한된 작업 권한을 가진다. **서비스 토큰은 절대 인간 관리자 권한이 아니다.** 사람이 시작한 BFF 관리 작업은 별도 검증된 사용자 세션과 서비스 신원을 모두 확인한다. 브라우저에서 유입된 x-internal-token은 전달하지 않는다.
6. **Android**: 승인된 모바일 인증 방식·철회·소유권 계약을 유지한다. 실제 쿠키 기반 인증이라면 무조건 CSRF 예외를 주지 않는다. 계정 전환, 로그아웃, 재시도와 오프라인 캐시를 검증한다.
7. **외부 웹훅·봇·Socket.IO**: Discord는 파싱 전 원본 바이트 Ed25519 서명 검증 및 가능한 시각·재전송 검사. Telegram·봇은 출처 및 비밀정보 정책, 소켓은 핸드셰이크와 네임스페이스/이벤트별 회원 권한, 단일 배치·메시지 처리 소유권과 멱등성을 유지한다.

**공통 판정 계약:** 신원 종류 + 인증된 주체 + 역할 + 동의 + 세션 유효/재인증 + 자원 소유자 + 행동 + OTP 인증 영수증 + 내부 서비스 신원 + 경로 소유권을 검증한다. 정보 누락·DB 오류·미정 정책은 거부하며, 고정 관리자 UUID·빈 데이터 성공·헤더 존재만의 허용을 금지한다.

## 4. 경로 등록부 및 Spring 보안 강제
- Nest와 Spring의 메서드·정규 경로·별칭, Next app-api/BFF 재작성, Android 소비자, 웹소켓/외부 연동을 자동 수집한다. 공개/회원/관리자/최고관리자/기계/웹훅 권한, 소유권, 세션, CSRF, OTP, 동의, 개인정보·캐시, DB 함수, 부작용, 테스트, Nginx 라우트와 배포 상태를 연결한다. **미등록 경로·메서드·별칭·충돌이 있으면 CI 실패**.
- 명시 공개·외부 서명 웹훅·내부 기계·회원/관리자 브라우저·모바일에 순서가 있는 별도 Spring SecurityFilterChain을 적용한다. 인증 계층에서 세션 해시/유효기간/철회/DB 역할을 검증한 뒤 신뢰 가능한 SecurityContext를 만든다. 나머지 요청은 denyAll 또는 명시적 추가 정책으로 거부한다. 단순 문자열 헤더나 쿠키가 존재한다는 이유로 통과시키지 않는다.
- 서비스 메서드에는 AuthorizationManager/@PreAuthorize 등 2차 검증을 둔다. /auth/** 전체를 공개하지 않고 로그인 시작·OTP 상태·사전로그인 권한을 세분화한다. 별칭마다 동일 권한을 검증한다.
- 응답 계약: 401 신원 없음/세션 만료, 403 신원 있으나 권한·CSRF·OTP 부족, 404 진짜 미존재 또는 정책상 은닉할 타인 자원, 409 충돌/멱등, 429 제한, 503 의존성 장애. 비공개 성공/오류는 no-store·noindex·no-referrer, 개인정보 없는 오류 본문을 강제한다.
- **구체적 수정 대상:** SystemLogController, AdminUsersController, AdminEconomyController, AdminAuthService의 임의 문자열·쿠키·Bearer·서비스토큰 단독 관리자 허용을 제거하고 공통 DB 검증 관리자 주체를 사용한다. 기존 Next 세션 전달 경로를 먼저 Test에서 증명하고 경로 별칭 전부의 잘못된/철회된 신원 거부 테스트를 추가한다.

## 5. CSRF·CORS·세션·OTP
- 브라우저 쿠키를 사용하는 모든 POST/PUT/PATCH/DELETE에 세션 결합 CSRF 검증을 복구한다. 변경 부작용이 있는 GET은 안전한 GET으로 교정하거나 쓰기 요청으로 분리한다. 기존 DB의 csrf_hash/토큰과 Origin/Referer·호스트·프록시 검증을 연결하고 누락·위조·로그아웃 후 재사용은 403과 **쓰기 0건**을 보장한다. 쿠키 없는 서명 웹훅 및 인증된 모바일 기계 API만 별도 검증 후 좁게 예외 처리한다.
- CORS는 실제 운영/Test의 승인된 출처만 명시, 요청 메서드·헤더를 제한하고 Vary: Origin 설정. 자격증명이 있는 와일드카드와 임의 출처 반사는 제거한다. 원칙적으로 Next BFF의 동일 출처 요청을 사용한다. OPTIONS가 다른 인증 정책을 우회하지 않게 한다.
- 쿠키 보안, 세션 고정 공격, 로그아웃·철회, 다중 탭, 시간 경과, 권한 박탈, Nest→Spring 재시작 연속성 및 Android 계약을 모두 검증한다. Spring STATELESS 설정만으로 수동 쿠키 처리의 안전성을 인정하지 않는다.
- OTP 코드·토큰을 API 응답·로그·텔레메트리·스크린샷에 남기지 않는다. 인증 실패 횟수·유효시간·재전송·중복 요청을 통제하고 채널 불가 시 권한을 허용하지 않는다.

## 6. 금융 및 PostgreSQL 불변조건
- 돈을 움직이는 명령은 승인된 SECURITY DEFINER 금융 정산 함수만 호출한다. **JPA save() 직접 잔액 보정, 고정 관리자 ID, 광범위 테이블 GRANT, 임의 UPDATE, 소수 부동소수 계산 및 성공처럼 보이는 0원 응답 금지**.
- Nest와 Spring 공존 중 단일 활성 금융 작성자만 허용하고 스케줄러/봇에 중복 실행 방지 펜스를 둔다. DB의 복식부기·멱등키·원장 영수증을 유지한다. 같은 UUID 요청키의 재시도는 원 영수증 재조회로 제한하며 중복 발행·지급은 0건이어야 한다.
- 실제 운영 DB는 읽기 전용 진단만 가능. 실제 백업으로 독립 복원한 격리 PG17 테스트에서 잘못된 역할·타인계정·OTP 만료·중복·장애·롤백 음성 테스트 실시. 적용 완료 SQL 이력/체크섬을 변경하지 않고 필요 시 신규 순방향 번호로만 추가한다. 200 GET을 금융 정산 증명으로 취급하지 않는다.

## 7. 로그·서버·비밀정보·운영
- **관리자 로그 조회:** 유효한 관리자 사용자 세션 + logs.read 권한 + 원문 다운로드 등 고위험 읽기에 재인증을 요구한다. 비밀번호·세션·OTP·IP/회원 식별자·금융정보는 합의된 보존 정책에 따라 제거/마스킹한다. 조회 소스는 enum으로 고정, 10~500줄·최대 응답 바이트·검색어 길이·실행 시간을 제한한다. 파일명·쉘 명령·systemd 유닛 이름은 사용자 입력을 받지 않는다. 넓은 OS 권한을 주지 않고 제한된 전용 읽기 헬퍼/ACL 사용.
- **네트워크:** Spring REST 4550, Netty 9092는 로컬 또는 폐쇄망 바인딩, Nginx의 정확한 외부 경로와 Cloudflare HTTPS만 노출. 내부 IP 방화벽은 **실제 외부 관측지**에서 검증한다. Node 4500은 안전한 롤백 완료 전까지 내부 격리 유지.
- **systemd:** 전용 비특권 계정, NoNewPrivileges=yes, PrivateTmp=yes, ProtectSystem=strict, ProtectHome=yes, 필요한 StateDirectory/ReadWritePaths만 허용. 업로드·캐시·저널 접근이 막히는지 Test에서 검증한 뒤 적용한다.
- **비밀정보:** 소스의 상수형 비밀키 기본값, unit 내 평문 환경변수 제거. 서비스별 보호된 자격증명, 단계적 교체/폐기 및 유출 스캔. GitHub/로그/대화에 값 자체를 게시하지 않는다.
- **추가:** 외부 actuator 최소 health, Swagger/metrics 관리 접근 통제, 요청 크기·속도 제한, PII 없는 추적 ID, 유지관리되는 Spring/Java 버전·취약점 의존성/SBOM 점검, 백업·감사 보존 정책 준수.
