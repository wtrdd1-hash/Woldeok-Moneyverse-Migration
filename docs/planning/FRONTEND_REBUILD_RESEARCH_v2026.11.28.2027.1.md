# Initial product-led design research and direction — v2026.11.28.2027.1
Status: provisional design brief, not produced or approved visual artwork. Checked public references 2026-11-28 KST. These support implementation practices, not adoption of an external brand or layout.

- W3C WCAG 2.2 (https://www.w3.org/TR/WCAG22/): target AA, including focus not hidden under sticky navigation, accessible controls, contrast and reflow.
- Carbon data table guidelines (https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines): prioritize data width, meaningful density and table interactions.
- Chrome modern CSS layout guidance (https://developer.chrome.com/docs/modern-web-guidance/guides/css/css-layout?hl=en): use component-context container queries and global media queries; respect reduced-motion preference. Check browser support and provide fallback.

New design brief, to be validated against adopted integrated functional planning: an editorial economy workspace, not a game-themed template or generic SaaS dashboard. Prioritize meaningful hierarchy and trustworthy amounts. Explore a new restrained light neutral canvas (with deliberate dark counterpart if justified), deep ink, one distinctive action accent selected through contrast and prototype review; do not inherit any old palette. A consistent readable sans and tabular numeric typography, adaptive grid and varied content structures. Navigation follows actual user goals rather than an icon grid. Guest home explains the simulation and directs to real functions; member home surfaces the authenticated user's own balance, actionable next steps and genuinely useful account activity. Wallet/bank display exact amounts, obligations, transaction details and clear review/receipt flow; trading emphasizes market status, price/chart and order controls; shops distinguish catalog, purchase review and inventory; community and tools use distinct reading/task patterns; admin is a clearly separate operational workspace with verified access, real audit information and precise errors. Missing backend features must be visibly unavailable, never imitated. This is a proposed direction to test in R0, not a final palette, feature approval, or a requirement to use every proposed element. Preserve legally required disclosures, actual favicon, authenticated actor and financial contracts. Use explicit synthetic labels only in isolated prototypes.
