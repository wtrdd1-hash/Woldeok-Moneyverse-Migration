## 1. Gap selected this run

Moneyverse already specifies pre-signup value, intent-preserving signup, progressive first-week complexity, user-selected continuation, D1-D30 return reasons, social bonds, collections and long-term aspiration. The remaining retention gap is **whether users can clearly feel that they are becoming more capable, knowledgeable or expressive rather than merely becoming richer in WLD.**

The current public guide contains profession EXP/mastery language, but the dominant roadmap is still framed by WLD asset thresholds, deposits, stocks, business and becoming a `representative capitalist`. A user can therefore complete actions without receiving a coherent answer to: **what am I getting better at, what evidence proves it, and what is the next personally meaningful mastery step?**

This specification defines the consumer loop:

`meaningful action → legible evidence of improvement → user-chosen mastery thread → next attainable step → D1 recognition → D3 practice/application → D7 visible before/after → D14 depth choice → D30 durable mastery record → optional share/aspiration`

It does not introduce a new backend progression engine or reward contract.

## 2. Consumer promise

**“I can see what I am getting better at, why it matters, and what I can try next.”**

Mastery is not synonymous with wealth, time spent, feature count, casino volume, loan use or raw transaction frequency.

A valid mastery signal should primarily represent one or more of:
- demonstrated completion or skill;
- deeper understanding of a virtual-economy concept;
- a collection or curation milestone;
- profession depth;
- a project or business-management milestone;
- safe simulated-market learning or replay quality;
- constructive community/project contribution;
- season or world knowledge/history;
- deliberate creative or identity expression.

## 3. First 30 seconds, first 3 minutes and first session

### First 30 seconds
Do not ask a newcomer to understand a global score. Show one product promise, one proof/sample and one useful action. If a mastery preview is shown, describe it in plain language such as `complete one job to start your profession record`, not `raise account power`.

### First 3 minutes
After the user authors a starting intent, show one observable outcome tied to it. Examples:
- profession: `first task completed; 1/3 examples toward the next profession milestone`;
- collection: `first piece curated; choose the next set theme`;
- learning/replay: `you identified one market-event cause; compare another scenario`;
- project: `first bounded contribution recorded; see what part changed`.

Do not convert wallet balance growth into a proxy for competence.

### First-session closure
After the first meaningful result, offer one mastery continuation plus `later`/`finish for today`. The user should leave knowing either:
1. what improved;
2. what the next attainable step is; or
3. that nothing else is required today.

## 4. Mastery evidence model

Use consumer-visible evidence rather than opaque scores whenever possible.

### 4.1 Evidence types
- **Completion evidence:** a bounded task, chapter, set or project step is complete.
- **Understanding evidence:** a user correctly interprets or applies a concept in a safe simulation/replay.
- **Consistency evidence:** repeated useful actions across time without a punitive streak requirement.
- **Curation evidence:** the user intentionally assembles, restores or explains a collection/space.
- **Contribution evidence:** a club/community project visibly changed because of a safe contribution.
- **Reflection evidence:** the user can compare prior and current choices or outcomes.

### 4.2 Evidence quality rules
Evidence should be:
- comprehensible without opening a ledger or analytics screen;
- attributable to a user action, not fabricated engagement;
- resistant to trivial click/open farming;
- independent from raw WLD wealth where practical;
- reversible/private where identity or social exposure is involved;
- honest when no progress occurred.

## 5. Return ladder

### D1 — recognition before novelty
Show the exact mastery thread selected or created in the first session. Prioritize `continue what you started` over a generic feature carousel.

### D3 — application, not feature breadth
Offer one chance to use the same idea again in a slightly different context. If there is no meaningful adjacent step, keep the core thread available rather than inventing novelty.

### D7 — visible before/after
The user should be able to answer `what changed because I kept going?` through a simple before/after recap. Examples include profession milestone, completed collection chapter, project contribution, replay insight or season knowledge record.

### D14 — voluntary depth
Offer an optional harder variant, adjacent specialty, curation role or social contribution. `Not now` must not reduce rewards or status.

### D30 — durable mastery record
Create a durable record such as a profession chapter, collection exhibition, learning replay history, project record, season archive or public-safe badge that reflects earned meaning rather than purchased advantage.

## 6. Session design

### 1-3 minute quick check
- recognize current mastery thread;
- show one real change or one available next step;
- let the user act, defer or finish.

### 5-15 minute meaningful session
- complete one coherent practice or creation loop;
- surface evidence of improvement at the end;
- choose whether to deepen or stop.

### 30+ minute deep session
- curation, project work, strategy replay, collection building, world exploration or collaborative creation;
- preserve history/outputs so long sessions create durable artifacts rather than only more balance.

Do not increase ad load simply because a user entered a deep session.

## 7. Mastery and economy

The aspiration ladder should make users want WLD because it helps expression, restoration, collection, space, projects or optional prestige—not because wealth itself is labeled mastery.

Do not:
- rank mastery primarily by WLD balance;
- require deposits, loans, trading or casino activity to complete general onboarding/mastery;
- call profitable outcomes `skill` when luck or system-controlled movement materially contributed;
- sell mastery levels, leaderboard priority or simulated-market advantage for real money;
- use debt, losses or casino outcomes as a comeback trigger framed as `recover your mastery`.

Unlimited-by-default play remains compatible with diminishing rewards or evidence quality rules; do not hard-cap play solely to manufacture scarcity.

## 8. Social and viral loop

Shareable mastery should be an output, not an obligation.

Good candidates:
- completed collection chapter;
- profession milestone with a short explanation of what was done;
- educational replay summary;
- safe project contribution;
- season/world knowledge archive;
- curated personal space or exhibit.

The recipient should understand the artifact without logging in and get one relevant sample/CTA.

Never place session tokens, private balances, debt, exact portfolio positions, private memberships, moderation/security state or non-public social graph data in share URLs/cards.

Referral rewards must not be attached to raw badge views, shares or profile visits. If any reward exists, prefer bounded cosmetic/honor convenience after verified multi-day participation.

## 9. Acquisition, content and SEO

Mastery can improve acquisition only when public content has independent value.

Indexable candidates:
- substantial beginner explainers;
- reviewed virtual-company/world guides;
- educational simulated-market replays;
- collection/project retrospectives;
- season archives with real narrative/content depth;
- public-safe mastery guides that teach a concept rather than promote a score.

Do not generate thin pages for every user/level/badge/day/milestone combination. Personal mastery state, account progress, balances, portfolio, debt, casino state, recovery/security and moderation status remain private/non-indexable.

Organic funnel:
`search/discovery → useful learning/sample → authored mastery thread → signup/activation → D7 visible improvement → D30 durable record → optional share/contribution`

SEO success is not impressions alone; evaluate organic activation, D7/D30 and retained contribution.

## 10. Monetization

Protect the sequence:
`action → result → understand improvement → choose next step`.

Do not insert an interruptive ad, sponsor interstitial or subscription gate between a meaningful result and the explanation of what the user achieved.

Lower-risk monetization after repeated value may include:
- ad removal;
- non-P2W profile/space/exhibit cosmetics;
- optional archive/gallery presentation;
- transparent season cosmetics;
- clearly labeled sponsor content that is not confused with market, loan, buy/sell or reward actions.

Do not personalize prices upward because a user demonstrates attachment/mastery.

## 11. Funnel and cohort KPIs

Maintain existing core metrics and add:
- first-value → mastery-evidence comprehension rate;
- first-session mastery-thread selection rate;
- time-to-first-visible-improvement;
- `next step` comprehension rate;
- D1 exact-mastery-thread continuation;
- D3 same-thread application rate;
- D7 before/after comprehension and coherent-loop completion;
- D14 voluntary-depth adoption;
- D30 durable-mastery-record coverage;
- mastery artifact opt-in share → recipient activation → recipient D7;
- mastery-related user satisfaction signal;
- percentage of mastery recommendations that are deferred/hidden.

Do not use `features opened`, `WLD accumulated`, `casino volume`, `trades made` or `time spent` as standalone mastery success metrics.

Guardrails:
- abuse/fake-account rate;
- suspicious reward duplication;
- bot/macro evidence inflation;
- referral fraud;
- account-takeover signals;
- spam/report rate;
- privacy complaint rate;
- finance-like misunderstanding reports;
- youth-safety complaints;
- ad-induced churn.

## 12. Experiment backlog

### Experiment A — visible improvement vs reward-only result
Hypothesis: showing one clear before/after mastery signal after a meaningful action improves D7 continuation more than showing only WLD/EXP reward.
Target: newly activated users with one completed core-thread action.
Control: reward/result only.
Treatment: reward/result + plain-language improvement evidence + one next step.
Primary metric: D7 same-thread continuation.
Guardrails: confusion exit, support questions, reward-farming anomalies, finance-like misunderstanding.
Observation: at least one mature D7 cohort; use D30 before broad standardization.
Next: keep only if retained quality improves without pressure/abuse increase.

### Experiment B — one user-chosen mastery thread vs global score
Hypothesis: one authored mastery thread improves comprehension and D1/D7 return quality versus a global account-level framing.
Primary: D1 exact-thread continuation; D7 coherent loop.
Guardrails: hide/defer, churn, complaint rate.

### Experiment C — reflection recap vs generic weekly recap
Hypothesis: `what I tried → what changed → what I learned → next choice` creates stronger D14 intent than a generic activity list.
Primary: D14 voluntary-depth selection.
Guardrails: notification opt-out, privacy complaint, message fatigue.

### Experiment D — public artifact vs raw achievement share
Hypothesis: a contextual artifact with explanation produces higher recipient activation/D7 than a badge/score-only card.
Primary: recipient meaningful activation and D7.
Guardrails: spam/report, doxxing, PII leakage, referral fraud.

### Experiment E — monetization after mastery comprehension
Hypothesis: delaying interruptive monetization until after result comprehension protects D7/D30 while preserving eligible-user revenue.
Primary: D7/D30 retained contribution.
Guardrails: ad-induced churn, accidental clicks, session abandonment.

## 13. Security, abuse and privacy review

### HIGH — phishing/ATO via fake mastery or reward claims
Scenario: `your mastery reward is waiting`, `verify to preserve your level` or `claim progression` links imitate Moneyverse and harvest credentials.
Minimum conditions: canonical domain/brand consistency; growth messages never request passwords, OAuth codes or recovery codes; no secrets/session/recovery state in URLs.
Separate QA: required for external deep links, push/email or account-linking changes.

### HIGH — private-state leakage
Scenario: a mastery card exposes WLD/WDX, debt, casino history, private club membership, portfolio, social graph, moderation or security state.
Minimum conditions: private-by-default personalized state; public-safe allowlist; explicit opt-in for public artifacts; avoid sensitive analytics payloads.
Separate QA: required for public personalized surfaces.

### HIGH — bot/multi-account mastery farming
Scenario: accounts repeatedly perform low-cost actions to mint rewards, prestige or referral value.
Minimum conditions: do not reward raw opens/clicks/views/shares; measure meaningful downstream actions; keep existing eligibility, anomaly and ledger protections.
Separate QA: required for any new economy-linked mastery reward.

### HIGH — finance/casino manipulation masquerading as mastery
Scenario: profitable WDX trades, debt use or casino wins are framed as competence, encouraging chasing, collusion or market manipulation.
Minimum conditions: simulated/game-only disclosure; do not use profit/loss chasing as progression; preserve market-integrity/probability controls.
Separate QA/legal review: required before finance-adjacent mastery campaigns.

### MEDIUM — analytics overcollection
Scenario: detailed mastery/interest history becomes an unrestricted advertising profile.
Minimum conditions: collect only data needed for product measurement; do not freely export private economy/social history to ad/analytics partners; honor consent/legal boundaries.

## 15. Runtime Product Reality Audit — 2026-09-14

Verification: available for public web home, guide and announcements.

Observed:
- Home clearly says WLD/rewards are game-only virtual data and describes activity as recorded history.
- Home still emphasizes wallet/minigames/exchange/shop/quests as quick links and contains multiple sponsored placements.
- Guide exposes profession EXP/mastery, but the dominant roadmap is asset-threshold driven: seed WLD → saving → stocks/business → `representative capitalist`.
- Guide uses finance-like phrases such as compound interest, passive income, undervalued stocks and capital gains even though it also states the economy is virtual and no return is guaranteed.
- The first-day checklist ends with placing remaining WLD into a compound deposit.
- Public announcements remain a quiet state with sponsored inventory.

Conclusion: the public product currently shows **economic accumulation more clearly than skill/learning/curation mastery**. The visible-mastery loop in this specification is therefore an unverified growth hypothesis, not a claim about current runtime behavior.

## 16. Legal/policy notes

- WLD/WDX remain virtual/simulated/game-only and must not imply real investment, deposit, cash redemption or guaranteed return.
- Any child/teen expansion, personalized advertising, probability feature or real-money subscription change requires current legal/product review in Korea and the U.S.
- Advertising/sponsor labeling must remain clear and must not imitate buy/sell/loan/repay/reward controls.
- Subscription terms, renewal and cancellation must remain clear and easy to understand.

## 17. Next growth priority

Validate one narrow loop before expanding the system:

`one meaningful profession/collection/learning action → one plain-language mastery signal → one user-chosen next step → D1 recognition → D3 application → D7 before/after → D30 durable mastery record`

Do not expand global power scores, wealth-based mastery, mastery-linked WLD farming, profit/loss comeback pressure, public-sensitive progress cards or mastery-interrupting ads until this loop shows higher D7/D30 quality without worsening trust, abuse, privacy or finance-like misunderstanding.
