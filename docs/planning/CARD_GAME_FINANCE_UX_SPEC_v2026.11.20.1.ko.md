## 카드 구조 원칙
경제 서비스의 신뢰성을 우선하고 게임 성장을 부가한다. 홈은 대형 자산 카드, 작은 바로가기, 퀘스트, 시장·활동 및 공지의 비대칭 벤토 배치다. 카드에는 제목, 핵심 정보, 단위, 원천·기준시각, 상태, 설명, 권한에 따른 액션이 있어야 한다.
- 자산·지갑: 본인 실제 잔액, 통화, 기준시각, 내역. 미확인 수치를 0으로 위장하지 않는다.
- 주식·환율: 원천, 시세 시각, 지연·휴장 표시, 검증된 거래 진입만 허용.
- 퀘스트·경험치: 실제 목표 근거, 분자·분모 진행률, 수령 가능 여부, 지급 원장 증거.
- 인벤토리: 희귀도·수량·장착·아이템 만료와 효과 만료 구분·유지비·체납, 본인 권한 확인.
- 상점·경매: 실제 가격·재고·거래 확인, 오류 시 성공 표시 금지.
- 은행·국채·국고: 원장 기준 잔고·이자·만기·출처, 기능 이용 전 검증.
- 커뮤니티·뉴스: 작성자·검증·숨김·신고·게시 상태를 구분.
- 관리자: 실제 상태·시각·감사·권한·승인, 근거 없는 녹색 정상 표시 금지.

## 화면과 디자인 규격
11/18 기본색 배경 #0C1020, 카드 #151D32, 본문 #E9F1FF, 보조 #A8BCD8, 보라 #9C83FF, 파랑 #64B7FF. 골드는 퀘스트 보상, 녹색/적색은 사실 검증된 변화에 제한한다. 일반 카드, 대형 히어로, 수치, 액션, 진행률, 아이템, 리스트, 상세 등 카드 변형을 통합 관리한다. 숫자는 고정폭(tabular), 금액 단위와 출처·기준시각 필수. 전체 카드 클릭과 내부 버튼의 중첩 금지. 키보드·포커스·reduced-motion·명확한 텍스트 상태 필수.

반응형 검수는 320/360/390/430/768/1024/1280/1440/1920px이며 모바일에서는 카드 우선순위를 다시 배치한다. 컴포넌트에는 container query를 활용하고 차트·이미지 영역을 사전 확보해 레이아웃 밀림을 방지한다. 기본 언어 영어, 두 번째 한국어, 기존 지원 언어 유지. 브라우저 언어 자동 인식 + 사용자 수동 선택값 우선. 모든 화면에서 문의/채팅 접근은 하나로 통일하되 관리자 문의는 권한과 실제 전송 가능 여부를 분명히 구분한다.

## 코드 적용 조건
웹 UI 최종 구현은 Spring Boot MVC + Thymeleaf SSR 및 현대 CSS/점진적 JS다. 정적 Next 산출물을 Spring 네이티브 기능 완성으로 간주하지 않는다. 사용자의 금융 데이터는 소유자·세션·CSRF·권한을 검증하고 401/403/404/409/503 및 로딩/빈 결과/오류/지연 상태를 구분한다. /tools의 기존 기능 6종 보존 없이 대체 페이지를 운영으로 승격하지 않는다.
