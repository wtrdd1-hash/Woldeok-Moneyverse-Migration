## 1. 이번에 선택한 공백

최근 기획은 주간 복귀 콘텐츠, comeback, social proof, artifact 공유, 컬렉션 activation, D1/D7 ownership, D30~D90 재해석까지 상당히 구체화했다. 반면 더 앞단에는 아직 큰 공백이 남아 있다.

**검색이나 공개 콘텐츠로 들어온 사용자가 Moneyverse에서 답만 읽고 나가는 대신, 왜 자연스럽게 첫 의미 행동까지 이어지는가?**

이번 핵심 루프는 다음과 같다.

`검색/공유 의도 → 독립적으로 유용한 답 → 맥락형 게임 preview 하나 → 사용자가 직접 선택 하나 → 저장/이어가기를 위한 가입 → 첫 의미 행동 → D1 연속성 → D7 복귀 이유`

이는 기술 SEO 프로젝트나 랜딩페이지 대량생성 프로젝트가 아니라 `intent-to-play bridge` 기획이다.

## 2. 소비자 약속

**“찾아온 답을 먼저 충분히 얻고, 흥미롭다면 가입 전에 그 개념을 Moneyverse 안에서 바로 조금 체험해볼 수 있다.”**

사용자가 가입하지 않아도 검색의도는 충족되어야 한다. 전환은 정보를 숨겨 얻는 것이 아니라 제품 연관성을 보여줘서 얻는다.

금지:
- 답을 인증 뒤에 숨기기;
- 모든 organic visitor를 일반 홈/대시보드로 보내기;
- 은행·대출·주식·카지노·직업·상점·커뮤니티를 한 번에 노출하기;
- 키워드 변형별 얇은 페이지 수백 개 만들기;
- 보장수익, 안전한 이자, 확정 저평가, 손실복구 등 실제 금융상품처럼 보이는 표현;
- “지금 가입하지 않으면 손해” 같은 가짜 긴급성;
- 광고 클릭·로그인·지갑 열기·페이지 체류를 activation으로 계산하기.

## 3. 검색의도 클러스터

### A. 초보 학습
가상경제, 분산, 수요·공급, 복리 개념, risk/reward, 가상사업 운영 등의 설명.
연결: 30~90초 시뮬레이션 선택 또는 학습 replay.

### B. 가상기업 / 세계관
가상기업 변화 이유, 업종 관계, 시즌/세계 사건과 결과.
연결: 기업/테마 하나 follow, 가상 결과 비교, world thread 저장.

### C. 컬렉션 / 정체성
컬렉션 테마, 시즌 아카이브, 박물관/전시 이야기, 완성·큐레이션 아이디어.
연결: starter theme, favorite piece, display intention 선택.

### D. 직업 / 성장
직업 정체성, mastery path, 대표 활동 설명.
연결: 직업 의도 선택 또는 spendable reward 없는 대표 작업 preview.

### E. 시즌 / 이벤트 아카이브
무엇이 바뀌었고 왜 중요했는지, 시즌 종료 후 무엇이 남는지.
연결: 따라갈 thread 하나 또는 catch-up path 하나 선택.

개인계정, 잔액, 보유종목, 부채, 카지노 기록, 보안/복구 상태, 신고/제재 상태, referral claim, 얇은 개인 recap 페이지는 검색 유입 자산으로 만들지 않는다.

## 4. 첫 30초

적합한 organic visitor는 다음 네 가지를 이해해야 한다.
1. 검색한 질문의 답;
2. Moneyverse가 왜 이 주제에 독창적/직접적 맥락을 갖는지;
3. WLD/WDX 등이 실제 금융상품이 아니라 game-only 가상 데이터라는 점;
4. 전체 서비스를 배우지 않아도 지금 할 수 있는 행동 하나.

정보 우선순위:
`답 → 근거/맥락 → preview 하나 → 맥락형 CTA`.

## 5. 첫 3분

진입페이지에 맞는 저위험 preview 하나만 완료하게 한다.

예:
- 학습 콘텐츠 → 두 가상 선택지 중 하나를 골라 trade-off 설명 확인;
- 가상기업 페이지 → 기업/세계 thread 하나 저장하고 과거 cause/effect 보기;
- 컬렉션 페이지 → starter theme 또는 favorite exhibit 방향 고르기;
- 직업 페이지 → role intention을 정하고 대표 작업 확인;
- 시즌 아카이브 → 앞으로 볼 thread 하나 선택.

가입 전 preview에는 spendable WLD/WDX, 거래가능 자산, 대출 권리, 카지노 보상, 경쟁 우위를 지급하지 않는다.

## 6. 가입 이유

가입 CTA는 사용자가 방금 본 의도를 그대로 이어가야 한다.

예:
- “이 가상기업 thread를 저장하고 이어서 보기”
- “이 컬렉션 테마를 저장하고 첫 챕터 시작하기”
- “이 직업 경로를 저장하기”
- “방금 선택한 학습 replay를 이어가기”

OAuth 성공 자체는 activation이 아니다.

## 7. 첫 의미 행동

Activation 후보:
- 가상기업/world thread 하나 저장하고 다음 질문 설정;
- starter collection theme 및 첫 목표 선택;
- profession intention 및 첫 guided task 목표 선택;
- 교육 replay 완료 후 학습 선택 기록;
- 시즌 thread 하나 선택하고 다음 행동 설정.

Activation이 아닌 것:
- 로그인 성공;
- 약관 동의;
- 지갑 열기;
- WLD 잔액 보기;
- 광고 클릭;
- 일반 페이지 조회;
- referral code 입력만 한 상태.

## 8. Organic cohort의 D1~D30

### D1
처음 관심을 가진 정확한 주제/선택을 다시 보여준다. 목표는 “내 관심을 기억하고 있네”다.

### D3
전체 기능을 펼치지 않고 인접 심화 행동 하나만 제공한다.

### D7
원래 thread를 실제로 진행시킨다. 가상기업 변화, 컬렉션 진전, 직업 다음 단계, 시즌 변화, 학습 회고 등이 될 수 있다.

### D14
초기 검색의도를 더 넓은 identity/season arc 하나와 연결한다.

### D30
saved thread, collection chapter, profession path, learning history, season memory 같은 오래 남는 기록 하나가 있어야 한다.

검색의도별 cohort는 별도로 봐야 한다. 초보 학습 유입과 시즌 아카이브 유입을 하나의 평균으로 합치지 않는다.

## 9. 콘텐츠→제품 funnel

`적합한 노출 → organic click → 의도 충족 → contextual preview → authored choice → contextual signup → meaningful activation → D1 → D7 → D30 → LTV / retention-adjusted contribution`

분석 축:
- Google / Naver / direct / share;
- query 및 intent cluster;
- 신규/복귀;
- mobile/desktop;
- content type;
- preview 사용 여부;
- preview 후 가입 vs auth-first;
- 미성년/연령민감 cohort는 합법적이고 안전하게 측정 가능한 경우에만.

impression/CTR이 오르더라도 downstream activation과 retention이 내려가면 성공으로 보지 않는다.

## 10. KPI 추가

### Acquisition quality
- qualified organic landing sessions;
- answer completion / useful-depth proxy;
- organic visit → contextual preview;
- preview → authored choice;
- visitor → contextual signup;
- organic signup → meaningful activation;
- paid amplification 사용 시 fraud-adjusted CAC.

### Activation / retention
- content-assisted time-to-first-value;
- auth 전후 intent preservation;
- D1 exact-intent recognition;
- D3 adjacent continuation;
- D7 original-thread continuation/resolution;
- D30 durable-record rate;
- intent별 D1/D3/D7/D14/D30;
- organic LTV 및 retention-adjusted contribution.

### SEO quality
- 승인된 public-value page 중심 index coverage;
- query/page intent match;
- organic 유입 후 branded/direct return;
- thin/duplicate page ratio;
- spam/manual-action 경고;
- organic landing → activation → D7/D30.

### Trust guardrail
- fake signup/bot;
- referral fraud;
- spam/UGC report;
- phishing/ATO signal;
- privacy complaint;
- public/private leakage;
- finance-like claim complaint;
- accidental ad click;
- ad-induced bounce/churn;
- youth/privacy complaint.

## 11. 실험 backlog

### A. Answer-first vs auth-first
가설: 검색의도를 먼저 충족시키고 인증을 나중에 요청하면 signup 이후 activation 품질과 D7이 개선된다.
대상: 신규 organic visitor.
Control: 의미 preview 전에 auth wall.
Treatment: 완전한 유용한 답 + preview 하나 후 인증.
Primary: signup→meaningful activation, D7.
Guardrail: abuse, leakage, 성능, 혼란.
최소관찰: D7 cohort, 가능하면 D30 확인.

### B. Contextual CTA vs generic signup
가설: 진입의도를 CTA에 보존하면 auth 과정 이탈과 time-to-first-value가 개선된다.
Control: 일반 가입.
Treatment: 저장할 thread/theme/path를 명시한 CTA.
Primary: intent preservation, activation.
Guardrail: 오해, 피싱처럼 보이는 문구.

### C. Preview 하나 vs feature grid
가설: 의도에 맞는 preview 하나가 전체 기능 grid보다 first-session completion과 activation을 높인다.
Control: 지갑/직업/주식/상점/카지노/퀘스트 grid.
Treatment: preview 하나 + 다음행동 하나.
Primary: first-session completion, activation.

### D. 독창적 설명페이지 vs 템플릿 대량 페이지
가설: 적은 수의 깊은 페이지가 많은 키워드 템플릿보다 activation/D30과 검색 안전성이 높다.
Primary: organic→activation→D30, branded return.
Guardrail: thin/duplicate, spam signal, index quality.

### E. Value-before-ad vs early ad
가설: `답→preview→첫 선택` 구간을 광고/업셀로 끊지 않으면 retention-adjusted contribution이 개선된다.
Primary: D7/D30 + contribution margin.
Guardrail: ad churn, accidental click, CWV.

## 12. Google/Naver 정책 정렬

Google Search Central은 현재 helpful/reliable/people-first 콘텐츠를 강조하고 search-engine-first 대량생성을 경고한다. 2026-08-28 site reputation policy 업데이트도 제3자 콘텐츠가 호스트 사이트의 ranking signal을 빌려 검색순위를 조작하는 문제를 계속 다룬다. Public UGC에는 신고, spam 계정 탐지, 신뢰도 낮은 콘텐츠의 `noindex` 등을 권장한다.

Naver Search Advisor도 사용자를 돕는 콘텐츠, 정확하고 고유한 title/description을 권장하며 낚시성, 스크래핑, 저품질 템플릿 대량생성을 스팸 사례로 안내한다.

직접 채택:
- 검색유입이 없어도 직접 방문자가 유용하다고 느낄 콘텐츠만 발행;
- 겹치는 검색의도는 통합;
- substantive page마다 정확하고 고유한 title/description;
- UGC는 신뢰/가치 기준을 넘은 뒤에만 index 후보;
- public/private 검색경계 명확화.

채택하지 않음:
- 페이지 수 자체 KPI;
- 자동 키워드 확장;
- Moneyverse 도메인 권위를 빌리려는 sponsor/creator SEO inventory.

## 13. Product discovery 레퍼런스

Discord의 2026-08-20 game discovery 업데이트는 discovery/광고를 실제 retention에 중요한 gameplay event와 연결하는 방향을 보여준다. Moneyverse에는 `노출→실제 의미 행동→D7/D30` 평가 원칙만 채택한다.

Discord Official(2026-03-12)은 discovery/초대 링크에서 공식 profile·공식 server를 명확히 식별하는 신뢰 장치를 강조한다. Moneyverse public content와 share entry에서도 공식 도메인/브랜드 신호를 일관되게 유지한다.

Spotify의 2026 editorial/discovery 사례는 설명과 큐레이션이 발견 경험을 깊게 만들 수 있다는 방향성 참고로만 사용하며 성과 수치를 Moneyverse 예상치로 사용하지 않는다.

## 14. 수익화

수익화 순서는 다음이 기본이다.
1. 검색 질문 답변;
2. preview 전달;
3. 첫 의미 선택;
4. 이후 reviewed display/native ad, non-P2W cosmetic, 반복가치가 증명된 뒤 ad-free subscription 검토.

광고를 매수/매도/대출/상환 같은 민감행동이나 핵심 CTA처럼 보이게 하지 않는다.

구독은 중요조건을 결제 전에 명확히 고지하고, 명시적·충분한 동의를 받아야 하며, 해지는 간단해야 한다. 사용자의 archive/history/privacy control을 구독으로 잠그지 않는다.

## 15. 보안·개인정보·악용 검토

### High — public/private data boundary leakage
영향: 사기 표적화, stalking, 당혹감, 계정 공격.
시나리오: SEO/share page에서 잔액, WDX 보유/수익률, 부채, 비공개 관계, 계정나이, 보안/복구/제재 상태 노출.
최소조건: public-safe allowlist, personalization 기본 비공개, URL/metadata/analytics/share payload에 secret/session/recovery 값 금지, 공개 시 명시적 동의.
별도 개발/QA: personalized public landing 전 필요.

### High — SEO/UGC spam 및 악성링크
영향: 피싱·malware 노출과 검색 신뢰 훼손.
시나리오: 봇이 backlink/redirect/스팸용 profile/post/page 생성.
최소조건: raw signup/post/view에 WLD/WDX 경제보상 없음, 신고/삭제, indexing trust threshold, safe outbound-link policy, low-trust/thin 콘텐츠 noindex/unlisted.
별도 trust/security QA: broad UGC indexing 전 필요.

### High — 공식 콘텐츠 사칭 / phishing / ATO
시나리오: 가짜 guide/season/save-thread 메시지가 유사 로그인 페이지로 연결.
최소조건: 공식도메인/브랜드 일관성, 콘텐츠 내부 credential/OAuth code 요청 금지, 알림에 민감값 금지, 자산손실 긴급성 금지.
별도 QA: 외부 email/push/deep-link 전 필요.

### High — referral/fake-signup 조작
시나리오: bot/multi-account가 검색/referral conversion을 만들어 보상을 노리거나 성과를 부풀림.
최소조건: raw visit/click/signup 경제보상 금지, fraud-adjusted funnel, 향후 보상이 있더라도 검증된 downstream 참여 후 milestone 방식.

### Medium — tracking/privacy 과수집
검색의도와 게임행동의 결합은 관심사를 추론할 수 있다. 광고/분석 공급자에게 민감하거나 비공개인 economy/account field를 보내지 않는다. 미성년자·연령민감 이용자에 대한 tracking/ad personalization 확대 전 한국+미국 최신 legal/privacy review가 필요하다.

## 16. 법규·문구 주의

- WLD/WDX는 virtual/simulated/game-only이며 실제 투자·예금·증권·현금환전·보장수익을 암시하지 않는다.
- 금융 초보 콘텐츠는 Moneyverse simulation/game mechanics와 연결된 교육으로 표현하고 실제 개인 투자조언처럼 쓰지 않는다.
- sponsored/creator material connection은 필요한 경우 명확히 고지한다.
- public user artifact에는 공개 선택과 삭제/비공개 전환 경로가 필요하다.
- behavioral ads, youth-facing discovery, broad public UGC indexing, material referral reward 도입 전 한국/미국 launch-time review를 다시 한다.
- 미국 subscription/negative-option 정책은 계속 변화·집행 중이므로 최신 상태를 출시 직전 재검토한다.

## 17. Runtime Product Reality Audit — 2026-09-14

공개 runtime 접근 가능.

관찰:
- 홈은 WLD/보상이 game-only 가상 데이터라고 명확히 고지;
- 홈 shortcut은 지갑, 게임, 거래소, 상점, 퀘스트를 전면화하고 광고영역이 여러 곳 존재;
- 월간 공개소식은 준비 중이며 로비는 조용하게 보일 수 있음;
- `/announcements`는 공개 공지가 없지만 광고영역은 존재;
- `/guide`는 내용은 많지만 예금, 국채, 대출, 주식 시세차익/배당, 사업, 카지노, 자산성장 roadmap을 강하게 전면화;
- guide의 quick start는 검색의도별 pre-auth preview가 아니라 로그인→지갑부터 시작.

따라서 `유용한 답 → contextual preview 하나 → authored choice → contextual signup → meaningful action`은 현재 runtime에서 구현 확인되지 않은 성장 가설이다.
