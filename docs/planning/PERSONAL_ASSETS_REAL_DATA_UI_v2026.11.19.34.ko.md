## 0. 불변 원칙
1. **회원 첫 화면은 국고가 아니라 본인 자산**이다. 사용자 자산·출금가능액·보유주식 평가액·개인 손익·자산추이·거래·퀘스트가 중심이며 국고 원장·통화 발행량·서버 모니터링은 관리자 전용 관제 경로로 이동한다.
2. **전 기능 수치 실제 데이터 필수 (MUST):** 로그인 세션으로 식별한 본인 소유의 Spring Boot 서비스/실제 PostgreSQL 원장·정식 보유 포지션·체결내역·퀘스트 검증 이벤트·운영 서비스 지표에서 계산된 확정 데이터만 표기한다. 하드코딩 상수, 임의 샘플, mock, localStorage 금액, 더미 그래프, 날짜, 가짜 상태/온라인 인원/수익률, 근거 없는 'LIVE'나 '정상 운영 중' 표시 **금지**. 이미지 시안의 1,250,000 WLD 등은 **디자인 예시일 뿐** 사용자 잔액이 아니다.
3. **일반 사용자 기술 내부정보 노출 금지 (MUST NOT):** Spring Boot/Node/Next 프레임워크명과 버전, 런타임/빌드 SHA, API 이름·URL·포트, DB/원장 검증 알고리즘·동기화 상태·내부 갱신 로그·오류 스택, 서버 가용률, 내부 배포 단계, 디버그/상태 배지, 시스템 구성, 정책 진단, 관리자 운영 이벤트를 공개 화면·HTML·JS 하이드레이션·전송 JSON·접근 가능한 정적 리소스에서 제거한다. **단순 CSS 숨김 불허**. 관리자 전용 상세 진단은 서버 인증+RBAC+감사로그와 서버측 필드 필터가 모두 필요하다.
4. 사용자에게 필요한 경우에만 친절한 요약: `잔액을 불러오지 못했습니다. 다시 시도`, `최근 업데이트: HH:mm`, `현재 거래를 이용할 수 없습니다`; 원본 기술 오류·관리자 수치·내부 경로는 노출하지 않는다. '최근 업데이트'도 실제 성공 응답 기준으로만 표시. 법적으로 요구되는 거래 기준/이용 유의사항과 공개 경제통계는 권한 통제와 출처 표기를 별도로 적용.
5. **Spring Boot MVC + Thymeleaf 사용자 웹 프론트엔드 및 Spring API를 목표 런타임으로 설정**한다. 기존 Next.js 기획·소스를 운영 목표로 되살리지 않는다. 이 문서는 실제 구현 완료를 뜻하지 않는다. 영어 기본 언어, 한국어 필수 두 번째 언어; 화면별 번역 키/숫자 포맷/접근성 유지.

## 2. 자산 수치 정확성 계약
- `personal_total_asset = available_cash + reserved_cash + deposit_principal_and_accrued_value_if_authoritative + equity_market_value + 기타 실제 확정 자산 - 실제 부채`. 포함 범위는 명시된 DB 계정 분류표와 평가일 기준으로 확정한다. **주식 매수에 쓴 현금을 투자자산으로 다시 더하지 않는다**; 예치금 이동도 이중계상 금지. 현재 잔액·평가액·국고 잔액은 서로 다른 지표다.
- `equity_market_value = Σ(보유수량 × 시세)`. 시세 스냅샷 timestamp/통화/정지상태 포함; 시세 없을 때 과거 시세를 현재가라고 표시 금지.
- 평가손익, 실현손익, 기간 자산 변동, 입출금 효과를 분리한다. `period_return`은 자금 유입·유출 영향을 정리한 승인된 기준(예: TWR)을 기획·API 계약에 명기하고, 계산 결과·분모 0/음수·FX·수수료·소수점 반올림을 정의한다. 예시 이미지의 +2.41%는 계약 확정 전 실제 값으로 사용 금지.
- 모든 금액은 안전한 decimal/BigDecimal, 통화 코드 WLD, 평가시점, 데이터 신선도, 서버 계산 버전·기준을 내부 감사에 보존한다. 프론트엔드는 숫자를 임의로 생성하거나 잔액을 독립 계산하지 않는다.
- 백엔드 내부 예시 논리 API (확정 경로가 아님): `GET /api/v1/me/assets/summary`, `/me/assets/history?range=`, `/me/wallet/transactions`, `/me/stocks/positions`, `/me/quests`. **실제 Spring 컨트롤러/서비스에 존재하는 경로를 먼저 인벤토리하고 재사용**; 없는 경로를 있다고 전제하거나 구현 완료라 하지 않는다. 응답에 개인정보 최소화/서버 세션 신원 강제, pagination, asOf, sourceStatus, correlationId(로그 전용) 적용.
- 원장 검증이 보류된 잔액·발행·보상·체납/대출·미확정 거래는 성공이나 이용가능금액에 포함하지 않는다. 금전성 write는 DB 트랜잭션/멱등키/CSRF/인증/권한/수령 영수증 후 UI 확정.

## 3. 화면 컴포넌트별 상태·동작
- **PC:** 좌측 내비 + 상단 검색/언어/계정, 히어로 내 자산, KPI 4종, 24h/7d/30d/1y 기간 그래프, 빠른 거래, 보유종목·거래 리스트; 관리자 진입 메뉴는 RBAC 허용 계정에만.
- **Mobile:** 320–430px 단일 열 카드, 5개 하단탭(홈/지갑/투자/퀘스트/커뮤니티), 동일 데이터·액션, 금융 주요 수치 크게, 가로 표는 카드 변환 또는 컨테이너 내부 스크롤, 하단 safe-area, 44px 이상 터치 목표, 56px 단일 전역 문의 버튼과 하단바 겹침 금지.
- **미로그인:** 서버가 개인 데이터 조회 자체를 거부(401/403), 화면에는 로그인 안내만. 브라우저의 이전 계정 데이터 캐시/SSR 출력 금지.
- **로딩:** 스켈레톤은 숫자가 아닌 중립 형태. **빈 데이터:** `보유 종목이 없습니다`, 정확한 0은 실제 0 응답인 경우에만. **부분 실패:** 성공한 카드와 실패한 카드를 구분, 장애난 값은 `조회 불가` + 재시도. **지연/UNKNOWN:** 직전 성공시각·오래된 값 안내, 실시간 배지 제거. **403:** 권한 없음. **429/5xx:** 안전 안내. **금융 처리 중:** 중복 요청 차단, 확정 영수증 전 '완료' 금지.
- **개인정보:** 로그아웃/계정 전환시 화면·메모리·캐시 초기화, `Cache-Control: no-store` 개인 데이터, CORS/CSRF/권한 서버 측 적용, 민감정보를 HTML 속성·analytics·URL에 넣지 않는다.
- **사용자 상태 UI:** 배지 'LIVE/정상'은 실제 신선도·운영상태 검증된 경우에만 일반적인 사용자 표현으로 제공. 서버 패치버전/기술명/데이터 소스 API·데이터 품질 체크리스트는 화면에 출력하지 않는다.
