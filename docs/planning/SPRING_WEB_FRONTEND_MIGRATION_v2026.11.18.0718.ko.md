# Spring 웹 프론트엔드 전체 전환 — 사용자 범위 변경과 승격 게이트

## 문서 권위 및 사용자 결정

2026-11-18 사용자 지시는 기존의 **백엔드만 Spring 전환** 범위를 넓혀 **웹 프론트엔드도 Spring이 화면을 생성·제공하는 구조로 전환**하도록 명시했다. 이는 v2026.11.13.1의 Next.js 최종 유지 가정을 변경하지만 보안·금융·Android·복구·점진 전환 기준은 유지한다. 전환되지 않은 경로는 검증된 Next 런타임으로 유지한다. 브라우저의 동적 그래프·게임·접근성 상호작용에는 JavaScript가 필요할 수 있으며, Next SSR/BFF가 남아 있는 동안 '100% Spring 완료'라 표기하지 않는다.

## 2026-11-18 실측 P0

- Nginx `prod_frontend`와 `seo_release_frontend`가 Spring `127.0.0.1:4550`을 바라본다. Spring의 정적 `index.html`은 로딩 문구만 있는 임시 파일이며 `SpaWebMvcConfig`가 미전환 UI와 `/admin/*`에도 이 475바이트 파일을 HTTP 200으로 돌려주고 있다. 로컬 공개 Host로 `/`, `/guide`, `/admin/blog`에서 동일 현상을 실측했다.
- Next 별도 **시험 프로세스** 4522는 약 114KB의 실제 홈페이지를 반환했다. 이는 UI 아티팩트 존재 증거이지 승인된 운영 프로세스가 아니다. 검증되지 않은 임시 포트로 운영을 변경하지 않는다.
- 현재 `SecurityConfig`는 CSRF가 비활성화되고 `.anyRequest().permitAll()`이다. 세션·MFA·CSRF·권한 검사 완료 전에 인증/관리자/금융 화면 전환 및 운영 승격은 **금지**한다. 이번 후보에는 금융·인증 변경이 없다.

## 화면 목록과 실제 구현 범위

소스 `frontend/src/app/**/page.tsx` 기준 **178개** Next 페이지 중 `/admin` 경로 **39개**, 동적 세그먼트 경로 **33개**를 확인했다. 이 수치는 파일 개수이지 운영 정상 동작·고유 URL 개수가 아니다. [CSV 목록](SPRING_WEB_FRONTEND_ROUTE_INVENTORY_v2026.11.18.0718.csv)에 각 경로·전환 상태를 기입한다.

이번 코드는 읽기 전용 비회원 화면 **2개 후보**(`/`, `/guide`)와 검토 경로(`/spring-ui/home`, `/spring-ui/guide`)를 Spring MVC/Thymeleaf로 구현했다. 영어 기본·한국어 두 번째, 모바일 반응형, 가짜 잔액·성공 표시 없음, 무쿠키·외부 스크립트 없음. 운영 경로 전환 스위치 `moneyverse.web.spring-home-enabled`, `moneyverse.web.spring-guide-enabled`는 **기본 꺼짐**. 검토 경로는 `noindex,nofollow`/`private,no-store`. 임시 HTML 반환만으로 전환 완료라고 판단하지 않는다.

## 단계별 세부 계획

1. **P0 UI 복구/라우팅:** 실행 프로세스·릴리스 SHA 증거 보존 후 공식 격리 Test에 검증된 Next 복구 업스트림 구축. 아직 Next 소유인 경로에는 Spring 더미 HTML 200을 반환하지 않도록 Nginx 명시적 라우트 정리. 임시 452x 프로세스를 운영 대상으로 사용하지 않고, 승인된 이전 업스트림으로 즉시 복귀 가능한 상태 유지.
2. **P1 공개 화면:** 홈(사실 기반 데이터), 안내, 도움말/약관/콘텐츠, 계산기, SEO·다국어를 단계적으로 Spring으로 이식. 원본 UI와 320px, 200% 확대, WCAG 2.2 AA, sitemap/canonical/hreflang·이미지·수화 테스트. 이번 두 화면은 **초기 후보**이며 원본 UI 동등성은 아직 미확보.
3. **P2 사용자 기능:** 로그인/디스코드/OTP, 세션 재시작 보존, 쿠키/CSRF, 개인 캐시 방지·소유자 분리·업로드, 직업/지갑/보관함. API 실패를 잔액 0이나 빈 데이터로 오표시하지 않는다.
4. **P3 거래/금융/게임:** 주식 주문, 상점, 보상, 카지노, 은행, 채권, 국고, 사업, 작업 스케줄러, 소켓/봇, 관리자 승인. PostgreSQL 영수증·복식부기·BigInt·멱등성·정확한 권한을 검증하고 단일 기록 주체 유지.
5. **P4 관리자/앱/퇴역:** 관리자 39경로, 동적·언어별 페이지 전수 QA, Android API·이벤트 호환, 관측·복원·정확한 SHA 확인 후에만 Next 서비스 종료.

각 경로마다 소유 시스템, HTTP 메서드/호스트/언어, 기존 Next 핸들러, 신규 Spring 컨트롤러·템플릿, JS, 로그인·세션·CSRF, DB 읽기·쓰기, 보안·SEO·접근성, Android·소켓 영향, 정확한 SHA, QA 영수증, 되돌리기 스위치와 독립 검토자를 기록한다. `UNKNOWN`은 합격이 아니라 차단 상태로 취급한다.

## 시험과 무중단 승격 게이트

- 독립 브랜치/워크트리에서 작업해 Gemini 작업과 운영 main을 훼손하지 않는다. 시작·중간·종료마다 `origin/main` 재확인. 영문이 정본, 한국어가 두 번째 공식 문서.
- 단위시험과 실제 격리 루프백 HTTP/H2 Test로 HTML, CSS, 언어, noindex, 전환 스위치와 비금융 동작을 확인한다. 최종 SHA의 Gradle 전체 시험/bootJar는 별도로 검증하며, 내장 Test HTTP 성공을 공식 외부 Test 합격으로 오표시하지 않는다.
- 운영 승격 전에 공식 Test 정확한 SHA, nginx -t, 기존 프론트 프로세스·릴리스 서명, 모든 UI/API/관리자 경로 검증, 로그인/관리자 세션·MFA/CSRF 실사용 E2E, 개인정보·원장 무결성·DB 분리, 독립 백업 복구, 모바일/접근성/SEO, 자원 용량 및 신속 롤백 확인 필수.
- 순서: 공식 Test → 검증/독립 승인 → 소수 카나리 → 세션·페이지 검증 → 점진 확대. 건강한 기존 UI를 먼저 종료하지 않는다.
- **현재 운영 결론: HOLD.** 178경로 동등성, 공식 Test 프론트+엣지, 인증 실측, 전역 보안과 독립 복원 근거가 없으므로 운영 전환 완료나 전체 Spring 이관 완료를 주장하지 않는다.
