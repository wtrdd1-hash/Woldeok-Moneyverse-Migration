### Evidence, contradiction resolved and product scope
- Main `backend/src/auth/guards/admin.guard.ts` admits any nonempty current admin role, while `admin-session.guard.ts` invokes `touchAdminSession` (a session-side effect); `backend/src/support/support.controller.ts` exposes member/admin public messages and status only. Migration `196-user-admin-support-chat.sql` models public support threads/messages and `admin_current_roles(p_actor)`; it has no encrypted internal notes. Migration `062-audit-chain-integrity.sql` `admin_append_audit_event` inserts immutable audit rows. The v1344 spec's "no GET writes" and "audit every decrypted read" are mutually inconsistent without a precisely scoped audit exception; resolve explicitly below. A caller-supplied actor UUID alone is not proof of a live administrator session.
- Purpose: an operator can investigate a case with a private, encrypted, tamper-evident note and controlled redaction, without accidentally publishing it. Eligible user: currently authorized operator only. Member, approver-only, server_operator-only, logged-out, expired/idle-locked session, or revoked operator are denied. Entry remains `/admin/support` → thread → visually distinct **Internal notes** tab. Primary CTA **Add internal note**; secondary **View history**, **Redact with reason**, **Retry verification**. Plain-text body 1–2000 Unicode characters, reason 10–500, no attachments or public composer copy. Feature flag `support_internal_notes_v1` remains OFF.
- UX states: LOADING, VERIFIED_EMPTY, READY, SAVING, CHECKING_RECEIPT, SAVED, REDACTING, REDACTED, FORBIDDEN, SESSION_LOCKED, KEY_UNAVAILABLE, AUDIT_UNAVAILABLE, CONFLICT, STALE_RESPONSE, ERROR. An unverified/failed read must never render as zero notes. Thread switch/logout/role loss fences stale responses, clears decrypted memory and object URLs, and never sends a queued write without a fresh operator session. Admin responsive mobile web, keyboard focus and WCAG 2.2 AA, 44px targets, no private content in ARIA live announcements; member Android App API has no note route.

### Critical P0 access and trust boundary
- Every route must pass SessionGuard, AuthenticatedGuard, ConsentGuard, AdminGuard, AdminSessionGuard and a *fresh operator-only capability check*. The database `SECURITY DEFINER` entrypoint must independently verify the actor's currently active operator role and an authoritative, unexpired, open admin-session binding. Do not treat `p_actor` or an application-settable `SET LOCAL` GUC as an authenticated principal. Choose a DB-verifiable, short-lived, operation/thread/session-scoped proof issued only after the trusted session authority checks the real session; its verification secret must not be readable by `moneyverse_app`. If this cannot be proven against a compromised app role, the feature stays OFF and the residual trust boundary must be explicitly approved. Negative test direct `moneyverse_app` calls with forged operator UUID, forged session, replay, expired proof, role revoked between guard and DB lock; all must deny.
- Use separate, narrowly granted SECURITY DEFINER functions with fixed `search_path`, REVOKE EXECUTE FROM PUBLIC, no direct app DML on notes/events/audit/keys and no unrestricted decrypt endpoint. Database locks thread → note/revision in deterministic order; revalidate operator/session after acquiring the lock. Role changes and key access are fail-closed; 401 for expired/locked admin session, 403 for unauthorized role, 404 for cross-thread note existence concealment.
- Decryption is allowed only *after* successful current authorization and durable access-attempt audit. GET remains HTTP-safe and does not mutate notes, message status, financial tables or read receipts; it **does append a minimal security audit event** (or an equivalent guaranteed durable audit channel) for authorized plaintext access. Thus the previous blanket "GET DB writes = 0" acceptance criterion is replaced by "**zero business-data writes; one bounded append-only access-audit record per authorized decrypt attempt**." Audit failure yields 503 and **no plaintext**. The audit event means authorization/decrypt was attempted, not that the human viewed the content or the browser received it. An independent append of delivery outcome may be best-effort but cannot be falsely labeled proof of reading. No audit text, ciphertext, key ID or plaintext hash in telemetry.
- Exact order for authorized GET: validate session/operator → DB owner/thread scope and current role → durable access audit attempt → fetch sealed envelope → authorized KMS decrypt → return private,no-store plaintext. KMS unavailable, envelope mismatch, audit unavailable or role revoked ⇒ no plaintext, explicit retryable 503/401/403. A GET audit write may contend with the global audit chain: capacity/load and rate limiting must be measured before enabling.

### API, crypto, DB and failure contracts
- Preserve v1344 endpoints: `GET /api/v1/admin/support/threads/:threadId/internal-notes?limit=20&cursor=...` (max 50), `POST /api/v1/admin/support/threads/:threadId/internal-notes` and `POST /api/v1/admin/support/threads/:threadId/internal-notes/:noteId/redact`. POSTs require CSRF, current operator session, expectedVersion, UUID idempotencyKey, and an immutable request digest bound to actor/session/thread/note/action/normalized payload. Same key+digest returns the original receipt; changed payload or stale version fails 409/412. 422 validation, 429 rate, 503 audit/KMS/DB unavailable; never echo private payload in errors. Session-bound signed cursor expires <=15 minutes, includes thread/filter/snapshot keyset and key version, never text.
- Sealed body: approved envelope encryption AES-256-GCM with per-note data encryption key and unique 96-bit nonce; AEAD associated data binds tenant/purpose/schemaVersion/threadId/noteId/authorId/revision/keyVersion. Prevent ciphertext swapping between notes/threads and tampering of redaction status. Keep KMS key material and raw DEKs outside app SQL/DB. DB persists ciphertext, wrapped DEK reference, nonce, key version, authenticated-context version and integrity metadata; DB cannot assert plaintext validation or cryptographic verification merely by storing fields. Rotation is versioned and idempotent with old-key decrypt/read-back proof before retirement; backup restore MUST prove both current and historical key availability in an isolated environment.
- Redaction is an audited, monotonic state transition with immutable CREATE/REDACT events, reason, actor, timestamp, version and receipt. Redacted plaintext is never served again; do not promise deletion from old backups, external caches or historical copies. Per-note DEK destruction/crypto-erasure requires retention/legal-hold approval and restore tests. A redaction tombstone persists; retention expiration, legal hold and authorized purge are separate explicit operations. Never silently rewrite a previous audit event.
- SQL design: support_internal_notes with note/thread FK, sealed envelope metadata, revision BIGINT CHECK >=1, created_at, redacted_at, redacted_by; support_internal_note_events append-only with event kind CREATE/REDACT/ACCESS_ATTEMPT, actor/session binding digest, idempotencyKey, request digest, event revision and occurred_at. Enforce unique(actor,operation,idempotencyKey), unique(thread,revision) only if per-thread revision actually advances for every write, composite FK (thread_id,note_id) to prevent cross-thread linkage, redaction metadata pair CHECK, and index (thread_id,created_at DESC,id DESC). Access attempts may use existing immutable audit chain rather than duplicating access events; avoid double counting and lock inversion. Keep KMS calls outside DB transactions where possible, but recheck authorization and CAS at commit; clean up unused envelopes without ever reusing a nonce. Define timeout/commit-unknown receipt query before retry.
- No note IDs, count, author, body, ciphertext, presence flag or redaction metadata in member support endpoints, F675-127 transcript, notifications, search, SEO/sitemap, Android member App API, analytics, log traces, URLs or public caches. `Cache-Control: private, no-store`, `Vary: Cookie`, noindex/noarchive. However **do not assert a blanket legal exemption from a member's statutory personal-data access rights**: generic public transcript excludes internal operational notes by product contract, while a separately authenticated privacy request must trigger a documented legal/privacy review of whether the note contains that data subject's personal information and what disclosure/redaction/exemption is lawfully required. No automatic export of internal notes, no automatic denial without review.
- Admin read count, KPIs and SLA must use verified denominators only; unknown ⇒ UNKNOWN, not zero. k>=20 aggregated opt-in adoption, denied-access rate, decrypt/audit failure rate, redaction outcomes; no plaintext or operator league tables. Rate limits per operator/session/thread and audit-chain capacity, content retention policy and abuse monitoring are required.
