## 이전 지시와의 관계
기존 **관리자 일반 작업마다 반복되던 재인증 제거** 지시는 유지한다. 단, 이번 사용자 지시에 따라 **중요 관리자 페이지 접근 및 중대한 관리자 명령**에는 Discord 또는 Telegram에서 받은 1회용 OTP를 필수화한다. 기존 관리자 세션·권한·CSRF·원장 보호·감사 기록은 그대로 유지한다. 예전 15분 주기 전체 작업 재인증, 관리자 전용 구형 TOTP, 2인 승인은 복원하지 않는다.

## 위험도별 기준
| 등급 | 대상 | 요구 |
| --- | --- | --- |
| R0 | 공개 페이지, 일반 회원 기능 | 기존 로그인 정책 |
| R1 | 일반 관리자 조회·비민감 설정 | 관리자 세션/권한, 반복 OTP 없음 |
| R2 | 보안·계정 권한·금융 관리 콘솔·배포/비밀키 관리 등 중요 관리자 페이지 진입 | Discord 또는 Telegram OTP 성공 후 짧은 범위 제한 접근 |
| R3 | 국고 자금 생성·소각·지출, 국채·국민연금·건강보험 정산, 원장 보정, 데이터 대량 초기화, 관리자 권한 변경, 인증 정책 변경, 대량 삭제, 운영 승격/롤백, 키 회전 | **명령별 OTP 재인증** 후 최종 실행 |

중요 페이지에 진입할 때 받은 R2 승인은 그 안의 R3 명령 실행을 승인하지 않는다. 신규 민감한 관리자 변경 명령은 등급을 명시하기 전까지 R3로 본다.

## 인증 흐름
1. 기존 관리자 로그인과 서버 RBAC 검사 후, 관리자 고유 ID에 사전 등록하고 소유권을 확인한 Discord DM 또는 Telegram 개인 봇 채팅을 선택한다. 인증 요청에서 임의 수신 ID 입력을 허용하지 않는다.
2. 화면에 작업명·대상·금액 등 중요 영향과 선택한 수신처의 일부 마스킹 정보 표시. OTP는 공개 채널·그룹에 발송하지 않는다.
3. 암호학적으로 안전한 8자리 숫자 일회용 코드를 생성한다. DB에는 원문 대신 키 기반 해시/검증값과 관리자·세션·명령 인자 해시·목적·채널·만료·시도 횟수만 보관한다.
4. 선택한 Discord 또는 Telegram으로 코드를 보내고 관리자가 원래 사이트에서 입력한다. **3분 유효, 최대 실패 5회, 성공 1회 사용**, 동시 사용 원자적 차단. Discord/Telegram 중 **하나의 검증된 채널**이면 충분하다. 두 사람이 승인하는 구조가 아니다.
5. 서버에서 OTP·세션·RBAC·CSRF·요청 명령과 인자·멱등 키를 다시 확인한다. 인자가 바뀌면 기존 OTP는 무효. R3는 최종 백엔드 실행 경계에서 재검증한다.
6. 전송 장애·만료·오입력·세션 변경·잘못된 수신자·봇 중단 시 중요 접근/명령은 차단한다. 우회 코드나 테스트용 우회 경로를 운영에서 허용하지 않는다. 계정 복구는 별도 승인·감사 절차로 설계한다.

## 보안 및 모든 기획에 적용할 정정
- OTP 저장소와 봇 토큰은 서버 내부 및 비밀 관리 영역만 접근. 브라우저에서 DB 직접 접근 금지. 중요 인증 응답은 no-store/noindex/no-referrer.
- 코드 원문을 로그·텔레그램 운영 알림·디스코드 일반 경고·분석 데이터에 기록하지 않는다. OTP와 운영 경보 메시징은 서로 분리한다.
- 기존 금융 원장·국고 코어·SECURITY DEFINER 권한·2중 기장·멱등 처리는 OTP와 별개로 필수.
- 연결 계정 교체는 기존 인증 방식으로 재인증한 후 검증하고 관리자에게 별도 알림. 채팅 OTP는 피싱 방지형 인증이 아니므로 최고 위험 작업은 차후 WebAuthn 보완 검토.
- 반영 대상: 통합/프로젝트 마스터, 인증 보안, 관리자 페이지와 정책, 국고·조폐국·국채·국민연금·보험, 관리자 권한/대량 삭제, 디스코드·텔레그램, API·모바일, 운영승격, QA 및 보안 문서. 과거 기록은 삭제하지 않고 SUPERSEDED 표기.

## QA/승격 기준
Discord만 활성화한 관리자와 Telegram만 활성화한 관리자의 실제 수신·검증·명령 실행을 각각 확인한다. 세션만으로 중요 페이지/명령 접근 시 차단되어야 한다. API 직접 호출, 명령 인자 변조, 다른 관리자/세션/채널, 코드 재사용·만료·초과 시도·동시 제출·봇 장애·CSRF 우회 테스트 필요. 일반 관리자 R1에는 OTP가 뜨면 안 된다. 테스트 서버 실제 브라우저/백엔드 검증과 금융 원장 정합성 시험 후 운영 승격한다. **현재는 기획 정정이며 구현·검증·배포 완료가 아니다.**
