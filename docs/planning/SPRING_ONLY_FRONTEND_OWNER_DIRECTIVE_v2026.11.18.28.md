## Source hierarchy and explicit supersession
The owner explicitly directed that **the entire web frontend, not only the APIs, must be built and served through Java/Spring Boot**, with the previously approved new navy/violet design and inquiry/chat bubble on all pages, and every backend API verified and repaired, followed by production promotion. This **supersedes** the conflicting UI-runtime assumption in `INTEGRATED_PLANNING_MASTER.md` v2026.11.13.1, `PROJECT_PLAN.md` v2026.11.13.1 and later descriptions that say *retain Next.js/React as the production presentation runtime*. Their historical implementation notes are preserved for traceability, not silently rewritten.

- **Runtime authority:** Spring Boot (Java 17+, Spring MVC) owns every URL's HTML render, role/owner model and all backend API routing. No Node.js/Next.js runtime is allowed to remain necessary for serving public, member, login or administrative pages after the migration. Static CSS/JS/assets may be served from the Spring JAR and Nginx, but cannot depend on Next RSC/Flight or React hydration for basic function.
- **Templates:** prefer server-rendered Spring MVC + Thymeleaf reusable layouts, scoped actual source-backed page models and normal HTML forms. Optional progressive enhancement must retain working no-JS navigation and native form submit; no localStorage identity or client-supplied actor, forged financial balances or fallback SPA home pages. Four critical mobile widths + English default, Korean secondary, 200% zoom, keyboard/assistive tech and reduced motion must be verified.
