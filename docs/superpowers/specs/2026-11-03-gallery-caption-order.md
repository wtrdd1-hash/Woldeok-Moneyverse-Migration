# Bounded approved-gallery caption ordering (P1)

Purpose: allow public web and Android visitors to order the **latest 24 operator-approved published gallery photos** by their visible image description, without claiming a full-archive sort. Default publication order is unchanged. This is a bounded feature authorized by the recurring full-stack development brief.

Contract: GET `/api/v1/photos?sort=caption` and `/app-api/v1/photos?sort=caption` return the existing `{photos:[...]}` envelope. Only absent `sort` or the literal `caption` is accepted; duplicates/unknown query keys are 400. Database applies bytewise `C` ordering by `alt_text` then UUID after the approved-list SECURITY DEFINER function returns at most 24 rows. No new grants, table reads or migrations. Web `/gallery?sort=caption` provides an accessible GET selector, visible scope and noindex metadata. Android gateway must reject malformed, duplicated or incorrectly ordered success responses with 503, and mark query-specific responses no-store/noindex. Rollback is branch/feature removal; no persistent state changes.

Risk: sorting `C` bytes is deterministic but is **not locale-aware Korean dictionary order**. Scope remains latest 24 approved rows, not all photos. If upstream or PostgreSQL fails, surface unavailable, never a false empty list. No authenticated or financial operations are modified. Existing gallery default remains the compatibility baseline.
