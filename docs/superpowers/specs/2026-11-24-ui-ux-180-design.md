# 180-page UI/UX design brief

## Intended outcome
A cohesive, attractive, implementable design for every existing180design route, including40administrator routes, with equivalent desktop/mobile actions. The owner requests the actual designs and a GitHub PR, not a new production architecture. This document and generated screens are design review artifacts; implementation and rollout require subsequent review/Test evidence.

## Selected direction
Keep Moneyverse's navy/violet identity and the exact current favicon. Prefer disciplined, content-led screens to repeated giant hero cards. Home may have one restrained illustrated city scene. Dense finance and admin pages have compact headings and differentiated data tools.
Alternatives considered: color-only reskin leaves the observed workflow defects; unrelated new brand would lose the owner-approved identity. Selected: retain identity and redesign actual route-specific content/hierarchy.

## Tokens
Canvas #0c1020, surface #141b2e, elevated #1b2440, divider #2d3753, text #f3f5fc, secondary #b9c3d9, brand #a98aff. Positive #67d8b2, negative #ff9aab, caution #f6cf87. Color never carries financial direction alone.
Use local Noto Sans CJK for interface copy and tabular numerals for money. Main text15px/1.55, secondary13px, page titles28–36px; compact mobile headings24px. Spacing4/8/12/16/24/32. Rounded inputs10px and major panels16px encode hierarchy.

## Structure
Desktop:224px sidebar,64px topbar, max1240px content. Tablet: compact drawer; mobile: real forms/results/table-card alternatives,44px touch areas, five-link bottom navigation, safe-area padding. No dead mobile label-only substitutes.
Route families have distinct structures: admin data/operations; wallet/receipt; bank/pockets; stock market/detail/order; calculator; article/editor/gallery; chat; account/auth; game/work; guide/legal/status. Every route names actual fields, columns, actions and refusal/empty/error behavior.
Member and admin layouts imply verified roles only. Administrator designs must not place admin navigation in member views. Original92route contract is a different set and is not changed.

## Design data and honesty
Preview content is synthetic and prominently marked design-only. No actual account, balance, cookie, session or private message is read. No real endpoint is called, money moved or success receipt fabricated as runtime evidence. Charts use explicitly illustrative geometry, not current stock prices.
The final route specification distinguishes visual content from future server-bound contracts. Unknown real data is unavailable, not zero. High-risk actions use review/confirmation/reauthentication before actual success in a future implementation.

## State and language requirements
Every family defines loading, empty, error, session-expired, forbidden/disabled, confirmation, submitting and receipt-backed success. English is the documentation source; Korean is secondary. Preserve five-locale expansion rules; representative visible EN/KO/JA/ZH/VI rendering is required, with any incomplete full-copy translations explicit.
Screenshot coverage:180desktop1440 and180mobile390. Check each route at320/390/768/1100/1440 for document overflow and clipped actions. Keyboard focus, labels, reduced motion, safe areas and no unintended network access are part of artifact QA.
No automatic visual-baseline promotion: v10 assets/history remain, this improved collection is a review candidate until accepted.
