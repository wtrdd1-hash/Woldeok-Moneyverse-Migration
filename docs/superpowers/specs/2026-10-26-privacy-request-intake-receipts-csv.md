# Privacy request intake receipt CSV — bounded design

Scope: A logged-in member may download **only the most recent 30 intake records** from their own data-subject request list. This is an audit convenience, **not a GDPR/PIPA personal-data access package, a processed/completed request, or an exhaustive historical archive**. The existing `privacy_list_my_requests` SECURITY DEFINER function remains the sole data authority. The server derives the actor from the authenticated session and ignores client-provided user IDs. No new DB migration, table grants, ledger writes, account mutation, or external delivery.

The NestJS `GET /api/v1/privacy/requests/snapshot` endpoint returns `{scope:'recent_intake_receipts', limit:30, requests:[...]}` using `PrivacyRequestService.myRequests(actor,{limit:30})`, guarded by the existing session/auth/consent decorators. Next.js `/account/privacy/requests.csv` fetches that endpoint through the member session and fail-closes on unavailable auth, invalid fields, duplicate IDs, invalid ISO dates, excess rows, or CSV formula injection. CSV includes request ID/type/status/date/detail with BOM, bounded fields and no untrusted formula evaluation. Private `no-store`, `noindex`, `nosniff` headers apply to success/errors. A keyboard-accessible link appears only when the privacy center data is available.

Android `GET /app-api/v1/privacy/requests/snapshot` forwards session cookies, preserves the JSON contract, and applies private no-store/noindex on all outcomes.
