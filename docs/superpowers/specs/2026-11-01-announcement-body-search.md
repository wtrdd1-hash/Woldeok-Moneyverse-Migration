# Published announcement body search — minimal read-only design

Decision: reuse the existing bounded public.content_list_published_announcements(20) SECURITY DEFINER read. Add an optional `body` substring query (trimmed 1–80 characters, no controls/angle brackets, case-insensitive). It filters ONLY the already published 20-row snapshot, after existing sort, and does not search historical records. Existing `sort` remains composable. Reject duplicates and unknown keys at both Nest and Android gateways. Android verifies the entire response matches the requested substring, and returns 503 on an unverifiable HTTP 200. Web uses an accessible GET form and explains snapshot scope. Filtered pages and app responses are noindex/no-store. No migrations, direct table grants, authentication changes, writes, or financial changes. If source fails, do not fabricate a verified empty result. Preserve existing default unfiltered output.
