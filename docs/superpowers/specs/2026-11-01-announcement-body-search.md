# Published announcement body search — minimal read-only design

Decision: reuse the existing bounded public.content_list_published_announcements(20) SECURITY DEFINER read. Add an optional `body` substring query (trimmed 1–80 characters, no controls/angle brackets, case-insensitive). It filters ONLY the already published 20-row snapshot, after existing sort, and does not search historical records. An unmerged sort feature exists in Draft #2377; this branch does not import or depend on it. Reject duplicates and unknown keys at both Nest and Android gateways. Android verifies the entire response matches the requested substring, and returns 503 on an unverifiable HTTP 200. The canonical /announcements preserves its existing revalidate=60 and no-searchParams behavior (the current Next build classifies it dynamic even on the baseline); filtered results use a separate noindex dynamic /announcements/body route. Filtered pages and app responses are noindex/no-store. No migrations, direct table grants, authentication changes, writes, or financial changes. If source fails, do not fabricate a verified empty result. Preserve existing default unfiltered output.
