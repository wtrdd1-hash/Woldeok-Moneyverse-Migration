# Real-estate financial source-truth hold

The real-estate API must never claim a WLD payment, bid, ownership or accrued rent from a constant, clock-dependent sample, or in-memory array. A verified durable owner read and canonical ledger receipt are prerequisites for returning successful finance data. Until then the Nest and Next real-estate routes return explicit HTTP 503 with a stable error code, no fabricated receipts, and private no-store/noindex/no-referrer headers at the Next edge. Signed-out mutation requests remain 401. The browser displays unavailable rather than verified-empty or a synthetic balance. Existing unrelated space owner reads and the existing finance hold remain intact. The preferred alternative is fail-closed over a demo UI, because demo values resemble live financial positions and are not isolated from member actions.
