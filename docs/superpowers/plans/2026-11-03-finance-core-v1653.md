# Canonical approved Mint implementation plan

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement task-by-task.

**Goal:** Approved Mint orders create genuine balanced WLD ledger entries and immutable, replay-safe receipts, never standalone certificates.

**Architecture:** PostgreSQL SECURITY DEFINER command owns validation, locking, authoritative ledger and Mint receipt inside one DB statement/transaction. Nest supplies verified session actor via Admin+CSRF guards. Old unsupported issuance and retirement paths fail closed until one canonical money source/target is proven.

**Tech Stack:** PostgreSQL 17, PL/pgSQL, NestJS, Vitest, pnpm.

**Spec:** `docs/architecture/TREASURY_CORE.md`, `packages/database/migrations/244-central-bank-mint-separation.sql`.

## Global constraints
- No direct ledger primitive EXECUTE or account DML grant for app.
- No automatic issuance, fictional balances or historical money alteration.
- Source main must be re-fetched at midpoint; no rewriting existing migrations.
- User-requested permission concerns are tracked separately, not used as excuse to skip code implementation.

## Review focus
- Conflicting same-key replay; same-key concurrent callers; rollback on insufficient funds/malformed source; approval by proposer alone; expired/cancelled policy; read-only Guest/API origin denial.
