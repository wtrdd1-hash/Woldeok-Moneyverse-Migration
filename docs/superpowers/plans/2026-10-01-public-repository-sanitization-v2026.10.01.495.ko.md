## 목표

공개 저장소의 정보 노출을 줄이되 빌드, 데이터베이스, 릴리스, 테스트 정합성에 필요한 소스 파일은 삭제하지 않는다.

## 범위

1. 내부 업데이트 기록으로 명확히 분류된 파일을 공개 추적 트리에서 제거하고 재추적을 방지한다.
2. 내부 보안 증거와 상세 운영 기록은 공개 저장소 밖에 보관한다.
3. 보안/문서 기획에 공개 저장소 데이터 최소화와 Git 이력 포함 시크릿 스캔 요구사항을 추가한다.
4. 과거 광범위 스크립트 정리에서 삭제된 필수 비밀값 없는 DB 초기화 소스를 복구하고 migration parity를 검증한다.
5. 모바일 release signing 자격증명 fallback을 제거하고 debug 빌드가 release signing 설정을 사용하지 않도록 한다.
6. 유지/호환 문서에서 비공개 운영 게이트웨이의 불필요한 공개 참조를 제거한다.
7. 최종 검증 전 두 저장소의 최신 `main`을 다시 확인하고 동시 작업을 덮어쓰지 않는다.

## 안전 경계

- 발견된 자격증명 값, 비공개 호스트 설정, 상세 공격 증거를 공개 문서나 PR에 기록하지 않는다.
- 동시 브랜치가 활성인 상태에서 공유 Git 이력 재작성이나 강제 푸시를 하지 않는다.
- 공개 저장소에 과거 커밋된 자격증명 값은 노출된 것으로 취급하며 실제 사용 이력이 있으면 운영 측 회전을 후속 조치한다.
- 현재 트리에서 삭제해도 Git 과거 이력이 자동 소거되지는 않으므로 최종 보고에서 두 상태를 구분한다.
- 이 저장소 위생 변경은 Production 배포를 의미하지 않는다.

## 검증

- 추적 중인 내부 업데이트 문서가 0개다.
- 필수 DB 초기화 소스가 존재하고 migration-parity 테스트가 통과한다.
- 공개 문서 정책이 내부 기록을 공개 저장소 밖에 보관하도록 명시한다.
- Android 빌드 설정에 signing 비밀번호 fallback이 없고 debug가 release signing을 사용하지 않는다.
- 두 저장소 모두 `git diff --check`가 통과한다.
- 서버 저장소 test/lint/typecheck gate를 실행하고 실패가 있으면 모두 기록한다.
- Debian 호스트에 Android SDK가 있으면 Gradle 검증을 수행하고, 없으면 환경 제한을 기록한 뒤 브랜치 push 후 GitHub CI를 사용한다.
