# P0 P2P atomic receipt — Development B v503 (2026-10-24)

## Scope and evidence
Issue #1025: `WalletService.p2pTransfer` called idempotent ledger transfer and then independently wrote P2P metadata and a notification. Every replay wrote a second metadata row; the generic transfer emitted fresh websocket IDs for every replay. Read-only live schema inspection confirmed P2P table has no ledger transaction reference or request key, while notifications have a nullable dedupe key. **No live database was modified.**

## Decision
Create one forward-only `SECURITY DEFINER` function `wallet_p2p_transfer` with a key-scoped transaction advisory lock, ledger transaction, P2P row and deduplicated notification in the same transaction. Reject key reuse with different actor/recipient/amount/message/sticker. Keep legacy rows intact with nullable new columns and unique indexes. Revoke direct P2P DML from the application role. Provide `wallet_transfer_receipt` to suppress generic-transfer websocket replays.
