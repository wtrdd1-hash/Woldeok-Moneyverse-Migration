## 2. 코드로 확인한 재현 가능 원인
현재 GitHub 기본 `main`의 [대시보드 화면](https://github.com/wtrdd1-hash/Woldeok-Moneyverse-Migration/blob/main/frontend/src/app/dashboard/page.tsx)은 로그인 회원에 대해 아래 5개 API를 병렬 호출한다.
1. `GET /api/v1/wallet?recent=6` — 원장 잔액/거래
2. `GET /api/v1/stocks/watchlist` — 관심 종목
3. `GET /api/v1/stocks/portfolio` — 가상 주식 보유
4. `GET /api/v1/stocks/history` — 최근 거래
5. `GET /api/v1/stocks/alerts/events?limit=5` — 조건부 알림 발생 내역

- **WLD 값:** `wallet ? <Amount…> : '—'` 분기로 출력된다. 화면 `—`는 읽을 수 있는 지갑 데이터가 없을 때의 표시와 일치하지만, 운영 API의 구체적인 실패 원인은 이 코드만으로 판단할 수 없다.
- **관심 종목:** `watchlist?.stocks ?? []` 뒤 `String(watched.length)` 계산을 하기 때문에 API가 null이면 `0`이다.
- **보유 종목:** `portfolio?.holdings ?? []` 뒤 `String(holdings.length)` 계산을 하기 때문에 API가 null이면 `0`이다.
- **최근 알림:** `alertEvents?.events ?? []` 뒤 `String(events.length)` 계산으로 실패/빈 데이터가 같은 `0`으로 보일 수 있다.
- [API 보조 함수](https://github.com/wtrdd1-hash/Woldeok-Moneyverse-Migration/blob/main/frontend/src/lib/api.ts)의 `apiOrNull`은 예외를 포착해 null을 반환한다. 하단 상세 섹션에는 실패 문구 분기가 있으나, 요약 숫자에는 같은 실패 상태가 전달되지 않는다. **이는 코드상 확정된 상태 표시 설계 문제**다. 반면 실제 운영 요청이 실패했다는 사실은 아직 확정되지 않았다.
- [모바일 하단 내비게이션](https://github.com/wtrdd1-hash/Woldeok-Moneyverse-Migration/blob/main/frontend/src/components/mobile-bottom-nav.tsx)은 `fixed bottom-0 z-50` 및 safe-area 하단 패딩을 사용한다. 플로팅 위젯과 함께 본문 하단 공간이 충분한지 실제 뷰포트로 검증해야 한다.

**스프링 전환 주의:** 루트 DOCS_INDEX에는 Spring Boot 단일 런타임 전환 완료 설명이 있지만, 통합 기획 문서에는 예전 Next + 단계별 Spring 계획이 공존한다. 문서/소스 이력만으로 운영에서 어느 서버가 `/dashboard` 및 API를 제공하는지 단정하지 않는다. 반드시 Nginx 라우트, 실제 Spring 정적 번들·컨트롤러, 정확한 운영 SHA를 확인한다.

## 3. 위험 영향
- **금융 표시 정확성:** 잔액 미표시/주식 0은 사용자에게 자산 소실로 오인될 수 있음. 실제 원장 확인 전 소실/복구 모두 금지.
- **부분 장애 은폐:** 서로 다른 API 중 일부만 실패해도 숫자 0이 정상 조회처럼 나타나 원인 파악을 어렵게 함.
- **모바일 접근성:** 선물/채팅 위젯과 고정 네비가 카드·터치·키보드 포커스를 가릴 수 있음.
- **보안/개인정보:** 본인 데이터는 캐시 private/no-store, 검색 제외(noindex); 원본 개인 UUID·쿠키·토큰·금액을 공용 로그에 남기지 않음.

## 4. 구현 상세 인계 — 아직 미구현
1. 카드 상태 모델을 `loading / verified-value / verified-empty / auth-required / consent-required / unavailable / invalid-response`로 분리한다. HTTP 성공과 응답 구조 검증을 모두 마친 경우에만 확정 0을 표시한다.
2. WLD 카드: 실제 원장 기반 정수 문자열만 Amount로 표시. 원천 장애면 `잔액을 불러오지 못했습니다`, `새로고침`(실제로 작동) 제공. 실패를 `0 WLD`로 바꾸지 않는다.
3. 관심/보유/알림 카드: API 실패 시 `조회 실패` 또는 `—` + 재시도; 진짜 빈 목록과 오류를 분리한다. 한 API 실패로 나머지 성공 API까지 잘못 지우지 않는다.
4. Spring/BFF/정적 React 경계에서 인증 세션·동의·본인 소유 검증, 응답 타입·JSON 검증, 401/403/429/5xx/타임아웃 분리, 로그아웃/계정전환 시 응답 폐기, 개인 캐시·색인 차단.
5. 모바일 요약 그리드는 320px 글자·버튼 폭을 만족하는 선에서 카드 높이와 공백 축소. 2열 배치는 충분한 가독 폭을 확보할 때만 허용하며 200% 확대/긴 한글·영문에서 가로 스크롤 금지.
6. `bottom:0` 메뉴 높이 + `env(safe-area-inset-bottom)` + 선물/상담 플로팅 영역을 고려해 콘텐츠 하단 여유 확보. 카드 제목·값·CTA를 절대 가리지 않고 포커스/터치 영역 44px 이상 보장.
7. 네비게이션 기능은 유지하고 불필요한 전체 UI 리디자인은 피한다. 다국어 KO/EN, 대비, 스크린리더, 키보드 이동, 모션 감소 설정을 검증한다.
8. WLD 및 원장 숫자에 JavaScript Number 반올림 금지. 정수 문자열·BigInt, 읽기 전용 원천 검증만 사용하며 실제 금전 거래/보정은 이 장애 수정 범위가 아니다.
